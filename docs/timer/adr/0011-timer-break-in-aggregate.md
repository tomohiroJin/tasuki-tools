# ADR-0011: 休憩を復活させ、状態を集約に置く

- **ステータス**: Accepted（2026-10-16）
- **関連**: Issue #402 / 設計正本 [`2026-10-16-timer-break-design.md`](../../superpowers/specs/2026-10-16-timer-break-design.md) / v2.10 の撤去 [`2026-06-25-v2.10-switch-break-roster-fixes-design.md`](../../superpowers/specs/2026-06-25-v2.10-switch-break-roster-fixes-design.md) の #2 / [ADR 0002](./0002-decider-pure-domain.md)・[ADR 0003](./0003-server-authoritative-clock.md)・[ADR 0007](./0007-volatile-in-memory-state.md)

## 背景

v2.10 は休憩機能を撤去した。理由は 2 つあった。

1. **一時停止と休憩の違いが分からない**という実機の声。どちらも「時計が止まる」だけに見えた
2. **休憩が時計を止めず**、ルームの `onBreak` フラグだけを立てていたので、休憩の間の時間が消費済みになる食い違いがあった

撤去のあとも `BreakStarted` / `BreakEnded` / `break.start` / `break.end` と `breakEveryRotations` は定義として残り、受理されない dormant な状態が続いていた。
長時間のモブプロ・ペアプロでは集中が落ちるので、稼働時間か周回を条件に休憩を差し込みたい。

## 決定

- **休憩の状態を timer-core の集約（`session.break`）に置く。** ルームの `onBreak` は消す（wire の `Room.onBreak` は古い画面のために残し、`break.since !== null` から導く）。MUST
- **条件に達した交代の切れ目で休憩に入る**（既定は自動。ルームの設定で「知らせるだけ」にできる）。判定は交代が起きたか（`totalSwitches` が増えたか）で行い、`autoSwitch` の有無に依存しない。MUST
- **休憩は時計を止める。** `evolveBreakStarted` / `evolveBreakEnded` が時計を凍結・再開し、元の残りから再開する。MUST
- **休憩中は時計を動かす操作（`session.act`・`driver.assign`・`break.start`）を `decide` が一括して拒む。** 一覧ではなく規則で書く。MUST
- **「休憩する」ボタンは、休憩の条件を設定したルームだけが出す。** 条件「なし」（既定）のルームは今とまったく同じに動く。MUST
- 完成・中断で時計を止め、休憩を畳む（`evolveSessionEnded`）。それまでは完成後のロビーでも時計が走っていた
- 新しいシグナルは足さない。`suggest-break` シグナルは wire から消す。知らせは snapshot の `session.break` の変化から画面が検知する

### v2.10 への答え

| 撤去の理由 | 答え |
|---|---|
| 一時停止と休憩の違いが分からない | **見た目**: 休憩は全員の画面を覆いが占め、交代の円は隠れる（一時停止は盤面のまま）。**起き方**: 休憩は条件に達すると自分で入る（一時停止は人が押したときだけ）。**機能**: 休憩すると次の休憩までの数え直しが始まる。「休憩する」の添え書きで示す |
| 休憩が時計を止めない | 休憩の状態と時計を同じ `evolve` で変える。時計の凍結は `break-freeze.test.ts` が守る |

## 影響

- **構造上、食い違いが起きない。** 休憩の状態と時計が 1 つの集約の同じ `evolve` で変わる。ルームの別フラグと時計を別々に更新していた v2.10 以前の作りでは、これが食い違いの原因だった
- **回収の制約を受け入れる。** 回収役（`room-reclaimer.ts`）は名簿だけを見る。休憩中でも、全員が offline のまま `ROOM_IDLE_TTL_MS` を超えればルームは消える。揮発インメモリの方針（ADR 0007・憲法 III）どおりで、回収役が timer の状態を知るように依存の向きを変えることはしない。代わりに休憩中の人へ画面で伝える
- **書体の ext 層を、休憩を使うルームと、詳細設定を開いた人だけが取る。** 「休」「憩」は書体の base 層に無い。条件「なし」のルームの既定の画面（詳細設定を閉じた状態）には「休」「憩」を描かない。詳細設定を開くと「休憩の条件」の見出しが出るので ext 層を取る（利用者の明示の操作なので受け入れた・2026-10-16）
- 周回の数え方は「適格な席の数 × N」で、適格な席が 1 つ以下の輪では周回の条件は発火しない
- 休憩の判定は同期サーバー（`apps/tasuki-sync`）の交代の直後にかける。ドメインは在席を知らないので、適格な席の数は呼ぶ側が数えて渡す
