# ADR-0006: Result 型のエラー処理と Valibot 境界検証

- **ステータス**: Accepted
- **関連要件**: FR-010, FR-017, FR-023, FR-084, NFR セキュリティ（境界検証・境界正規化）

> **昇格**: 全体標準としては [docs/adr/0005](../../adr/0005-result-and-boundary-validation.md) が後継。timer 固有の詳細は本文のまま有効。

## 背景

ドメインは多くの拒否条件（空名・重複名・人数上限/下限・無効な交代間隔・権限不足・フェーズ競合）を
持ちます。例外で表現すると、どのエラーが起こり得るかが型に現れず、握り漏れが起きます。また WebSocket
の受信メッセージは外部入力であり、未知 type・過大サイズ・不正形式を境界で確実に弾く必要があります。
AI 由来テキストも信頼しないデータです。

## 決定

- **エラー処理**: `neverthrow` の `Result<T, E>` を用い、`decide` は例外を投げず
  `Ok(events)` / `Err(DomainError)` を返す。アプリケーション層が `Err` を受けて送信者へ `error` を返す。
- **境界検証**: front/server で共有する **Valibot** スキーマ（`schemas.ts`）で、全 WS メッセージを
  境界で一度だけ検証する。未知 type・余剰や不正・サイズ超過を即拒否。`config.set` も必ず
  `decide` のドメイン検証を通す。
- **境界正規化**: 表示名は検証だけでなく、境界で**正規形へ変換**する（`v.transform`）。
  以後は正規形しか内側へ流れない。呼び出し側ごとに `trim()` する方式は必ずどこかが抜ける
  （実際に `room.join` だけ素通りし、見た目が同じで文字列が違う名前が並んだ）。
  最大長は正規化の**前後で二重に**課す。NFKC は文字数を増やしうるため（最大 18 倍）、
  前段だけでは保存・配信される値に上限が効かない。
- **AI 出力**: `validateProblem` でお題構造へ検証してから使用し、失敗時は定型へ縮退する。

## 影響

- **利点**: 起こり得るエラーが `DomainError` 合併型として型に現れ、握り漏れを防げる。境界検証の
  スキーマが契約そのものとなり、front/server で同一物を共有するためズレない。
- **代償**: `Result` の連鎖で記述がやや冗長になる。スキーマ定義の保守コストが増えるが、契約の
  単一情報源として価値が上回る。
- 実装上の注意: Valibot の `object` は未知キーを strip するため、現状は「未知キーで弾く」のではなく
  「無視する」挙動。厳密な reject はセキュリティ強化（M4）で検討する。
