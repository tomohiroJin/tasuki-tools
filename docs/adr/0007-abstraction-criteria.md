# ADR-0007: 抽象の導入基準

- **ステータス**: Accepted（2026-08-10）
- **関連**: [#68](https://github.com/tomohiroJin/tasuki-tools/issues/68)（規範とアーキテクチャの確立、
  親 epic [#67](https://github.com/tomohiroJin/tasuki-tools/issues/67)）/
  [#20](https://github.com/tomohiroJin/tasuki-tools/issues/20)（本 ADR が昇格する判断の由来）/
  `docs/superpowers/plans/2026-08-05-bun-test-migration.md`（Task 3、20 行基準の実例）/
  `docs/constitution.md` 原則 X（抽象は実需で）

## 背景

Issue #20（timer-sync のテスト移行と、両 sync サーバーで共有できる `sync-kit` の
再評価）では、timer-sync と poker-sync の実装を並べて同じ形になった箇所を数えた上で、
`docs/superpowers/plans/2026-08-05-bun-test-migration.md` の Task 3 Step 2
（同ファイル 228 行目）で「**20 行に満たないなら抽出しない**」という基準を適用し、
共有パッケージ `sync-kit` としての抽出を見送った。同計画は続けて（231〜232 行目）

> ⚠ 利用者が 1 つしかないものを「将来のため」に抽出しない。
> `packages/ui` から伏せ札の裏模様を外したのと同じ判断基準を使う。

と記しており、これは `packages/ui` で「今は使っていないが将来使うかもしれない」
という理由だけでカードの裏模様を抽出候補として持っていたものを外した、過去の
別の判断と同じ基準の再利用だと明言している。

この 2 つの基準（利用者 1 つは抽出しない・20 行未満は抽出しない）は #20 という
個別の Issue の中でのみ記録されており、以後の抽象化の判断のたびに #20 を
探し当てないと参照できない。プロジェクト全体で繰り返し使う判断基準として、
横断 ADR へ昇格する。

## 決定

**次の 3 点を、抽象化・共通化を導入する際の基準とする。**

1. **利用者（呼び出し箇所）が 1 つしかないものを、将来のために抽出しない（MUST NOT）。**
   「いずれ 2 箇所目ができるかもしれない」という予測だけでは抽出しない。
   実際に 2 箇所目が現れてから抽出する。
2. **20 行未満の重複は抽出しない。** 抽出によって生まれる間接参照のコストが、
   重複を許容するコストを上回るとみなす。
3. **デザインパターンは、変更容易性を得るためだけに採る。** パターンの適用自体を
   目的化しない（過剰適用を避ける）。パターンを導入するのは、変更が現に困難に
   なっている実需があるときに限る。

## 影響

- DRY（Don't Repeat Yourself）は「コードの見た目の重複」ではなく
  **「知識の重複」**に限って適用する。同じ知識を 2 箇所が独立に持っていて、
  一方を直したときにもう一方が古いままになり得る場合にのみ DRY を適用し、
  たまたま似た形になっただけのコードは対象としない。
- 本決定は `docs/constitution.md` 原則 X「抽象は実需で」の根拠を
  記録するものである。
- **本 ADR の時点ではコード（`apps/` `packages/` `e2e/` `scripts/`）を
  変更しない。** #20 の `sync-kit` 見送り自体はすでに確定した過去の判断であり、
  本 ADR はその基準を全体規約として記録するのみで、新たな抽出・撤去は行わない。
