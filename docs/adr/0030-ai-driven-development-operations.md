# ADR-0030: AI 駆動開発の運用 —— 任せる範囲を決め、品質は機械的な検査で保証する

## 背景

Tasuki の柱の 1 つは「AI 駆動開発の実践場」である（憲法 前文）。実際の開発も、複数の AI エージェント
（手元の CLI・クラウドのセッション・サブエージェント）が、手元の端末・devcontainer・クラウドのコンテナと
いった別々の場所で行っている。

利用者の依頼（2026-10-31）は、**開発する場所がどこであっても品質を一定に保証でき、安心して AI に任せられる**
ようにすることだった。いまの規範は次の点でそこに届いていない（#483 の表）。

1. **AI に任せる範囲と、人が判断する点を決めた記録が無い。** `AGENTS.md` の「AI 運用規則」は 3 行で、
   禁止は本番デプロイだけだった。ADR の採択・秘密の扱い・外部への投稿などをどちらが決めるかは書かれていない
2. **品質の拠り所が文書の上で決まっていない。** CI（型・lint・単体・E2E・監査・変異）は揃っているが、
   「AI が終わったと言った」と「検査が緑だった」の区別を決めた規範は無い
3. **規則が文章だけで守られている箇所がある。** `docs/adr/0002` 決定 5 の「憲法の見出しと AGENTS.md の同期」は
   MUST だが、突き合わせるのは人の目だった。AI ツールの入口も `CLAUDE.md` 1 本だけで、他のツール向けの入口を
   足したときに正本が割れるのを止めるものが無い
4. **場所によって同じ検査が流せない。** 2026-10-30〜31 のクラウドのセッションでは、E2E のハーネスが
   同期サーバーのポートを固定で使うため別のセッションと衝突する・Playwright のブラウザの版が合わない・
   Node の版が `engines` を下回る・変異検査 `--changed` が全件に倒れて環境差で無関係のテストが落ちる、を観測した
5. **AI の報告の書式がばらつく。** 確かめたことと確かめられなかったことを分けて書く決まりが無く、
   読み手は「確かめた」の範囲を毎回本文から推し量ることになる

## 決定

### 1. 任せる範囲と、人が判断する点

**AI は、作業ブランチの上で完結し、検査で確かめられ、取り消せる作業を任されてよい**（MAY）。
コードと文書の変更・テストと検査の追加・ブランチへの push・draft の PR の作成がこれに当たる。

**次のどれかに当たる操作は、人の明示の指示か承認を待つ**（MUST）。

- **取り消せない、または取り消すのが重い**（本番へのデプロイ・データや履歴の削除・他人のブランチの履歴の書き換え）
- **外へ出る**（ISSUE・PR・コメントの投稿のうち依頼に含まれないもの・外部のサービスへの送信）
- **規範を変える**（ADR の採択（Proposed から Accepted へ）・憲法の改版・検査を弱める変更）
- **秘密と個人情報に触れる**（`docs/adr/0011` の分類「秘密」「資格情報」の値を読む・書く・移す）

具体的な操作の一覧は `AGENTS.md` の「AI 運用規則」に置き、ADR の改版なしに育てる（`docs/adr/0003` が
DoD の項目をガイドに置いたのと同じ書き分け。`docs/adr/0002` 決定 2）。**一覧に無い操作でも、上の 4 つに
当たると思えば人に聞く**（MUST）。一覧は判断の代わりではない。

**MUST NOT**: 検査を緑にするために、検査を飛ばす・無効にする・弱める（テストの skip・変異の宣言の削除・
走査対象の除外の追加）ことを、人の承認なしに行わない。

### 2. 品質の保証は機械的な検査で行う

- **MUST**: 「完了」の根拠は、エージェントの判断ではなく**機械的な検査の結果**と、原則 V の実経路での確認とする。
  「AI がそう言った」は根拠にならない
- **MUST**: 検査の一覧の正本は CI（`.github/workflows/ci.yml`）と `AGENTS.md` の「基本コマンド」に置く。
  ここには写さない（写すと検査を足すたびにずれる）。配置の決まりは `docs/adr/0009`
- **MUST**: 新しい規則を足すときは、**機械で守れるなら検査として足す。** 文章だけで守る規則は、
  検査にできない理由を書いてから置く（憲法 原則 VII・VIII）
- **MUST**: 手元で流せなかった検査は、**流せなかったと報告する**（決定 4）。CI が拾うとしても、
  流したことにはしない

**どこで開発しても同じ検査が同じ条件で流れる**ことを目標とする。いまは届いていない（背景 4）。
届かせる作業（E2E のポート・外部のものが無いときの止まり方・版の宣言と事前の確認・手元で CI と同じ検査を
1 つのコマンドで流す）は子 ISSUE に分ける（影響）。

### 3. 規則の正本は AGENTS.md の 1 か所に置き、ツールごとの入口は薄くする

- **MUST**: AI 向けの規則の正本は `AGENTS.md` とする。ツールごとのファイル（`CLAUDE.md`・`GEMINI.md`・
  `.github/copilot-instructions.md`）は **`AGENTS.md` へリンクで向ける数行の入口**に留め、規則を書かない
- **MUST**: `AGENTS.md` を直接読むツール（Cursor・Codex など）のために入口を足さない（入口が増えるだけになる）
- **MUST**: 入口と正本のずれは `scripts/audit-agent-entries.mjs`（CI の `docs` ジョブ）が見る。見るのは
  ①`AGENTS.md` の原則の見出しが憲法と一致する（`docs/adr/0002` 決定 5 の機械化）
  ②宣言した入口が追跡下にあり、正本へ向き、薄い ③宣言していない入口が無い、の 3 つ
- 入口の薄さは空でない行の数で測る。**数行の中に規則を書けば通る**。検査は歯止めであって証明ではない
  （`docs/adr/0003` 追記がゲートの検査について書いたのと同じ型の残余）

### 4. AI の成果の記録

- **MUST**: AI が作業を終えたときの報告（PR 本文・ISSUE へのコメント・会話での完了の報告）は、
  **変えたこと・確かめたこと・確かめられなかったこと**を分けて書く。確かめたことには、流したコマンドと
  結果を添える。確かめられなかったことには理由を添える（例: 環境に Caddy が無く E2E を流せなかった）
- **MUST**: 決定は ADR に、要求は ISSUE に、教訓は振り返りに残す（憲法 原則 VIII）。会話の中にだけ残った
  決定は、決定として扱わない
- コミットと PR の書式（Conventional Commits・PR テンプレートの DoD）は既存のとおり。AI の作業であることの
  表示（共同作者の行など）は各ツールの既定に従い、ここでは決めない

### 5. 複数のエージェントで分担するとき

- **MUST NOT**: 同じブランチ・同じ作業ツリーを、2 つのエージェントが同時に書き換えない。並行に進めるときは
  ブランチか作業ツリー（`git worktree`）を分ける（同じ作業ツリーでの衝突は変異検査で実際に起きた。`docs/adr/0029` 背景）
- **MUST**: 敵対的なレビューは、**実装したのとは別のエージェント**が、実装した側の結論ではなく差分とコードを
  渡されて行う。結論を渡すと、レビューはそれを追認しやすい
- レビューの指摘は、検査（テスト・変異・実画面の計測）で再現してから直す。再現できない指摘は、
  再現できなかったと記録する（決定 4）

### 6. マニフェストと憲法の関係

- マニフェスト（[`docs/ai-manifesto.md`](../ai-manifesto.md)）は、**AI と開発するときの価値観を 1 枚にまとめた要約**
  である。**新しい義務を持たない。** 各項目は憲法の原則か ADR を指す。食い違ったら憲法・ADR が正しく、
  マニフェストを直す
- **憲法は今回は改版しない。** 決定 1〜5 は「誰が決めるか・どう記録するか」という運用であり、何を守るかは
  既存の原則（I・V・VII・VIII・IX・XI）で足りている。#483 の「2 つの場所で試す」振り返りで、原則の不足が
  実際に見つかったときに改版を検討する（原則 X「抽象は実需で」と同じ考え方）

### 退けた案

| 案 | 退けた理由 |
|---|---|
| 憲法に「XII. AI に任せる範囲」を足す | 決定 6。運用の決まりは変わりやすく、憲法の重さに合わない。原則の不足はまだ実測されていない |
| 人が判断する操作の一覧を ADR に書く | 操作は増える。足すたびに ADR を改版することになる。基準を ADR に、一覧を `AGENTS.md` に置く（決定 1） |
| ツールごとに規則を書き分ける | 正本が割れる（憲法 原則 VIII）。ツールの違いは入口の置き場の違いだけにする |
| 入口を symlink にする | Windows と一部のツールで追えない。リンクで向ける数行のファイルなら、どこでも読め、検査もできる |
| 入口のずれを検査しない（レビューで見る） | 背景 3。見出しの同期は MUST なのに人の目だけで守っていた |

## 影響

- `AGENTS.md` の「AI 運用規則」を、作業の始めと終わり・報告の書式・人に聞く操作・禁止事項に広げる
- `GEMINI.md`・`.github/copilot-instructions.md` を `CLAUDE.md` と同じ形の入口として足す
- `scripts/audit-agent-entries.mjs` を CI の `docs` ジョブに足す（決定 3）。変異 632 がその照合を守る
- `docs/README.md`・`AGENTS.md` の文書地図にマニフェストを載せる
- **次の作業は子 ISSUE に分ける**（#483 のメモ。この ADR の方針に沿って進める）:
  1. E2E のハーネスのポートを固定にせず、外部のもの（Caddy・Playwright のブラウザ）が無いときに分かりやすく止める
  2. 開発環境の版（Node・pnpm・Bun・Chromium・Caddy）を 1 か所で宣言し、合わないときは検査の前に止める
  3. 手元で CI と同じ検査を 1 つのコマンドで流す（速い段と全件の段。#481 と合わせて設計する）
  4. 繰り返す手順をリポジトリの中のスキルか手順書にする（敵対的レビュー・実画面での確認・変異の足し方ほか）。
     `docs/superpowers/` を出力先にしている外部のスキル運用との分担もそこで決める
  5. AI ツールの設定（権限・フック）で、本番デプロイのコマンドを機械的に止める
  6. 2 つの違う場所で同じ ISSUE を任せて振り返り、結果をこの ADR・規則・スキルに戻す
