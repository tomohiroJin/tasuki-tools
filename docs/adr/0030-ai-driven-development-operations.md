## 背景

Tasuki の柱の 1 つは「AI 駆動開発の実践場」である（憲法 前文）。実際の開発も、複数の AI エージェント
（手元の CLI・クラウドのセッション・サブエージェント）が、手元の端末・devcontainer・クラウドのコンテナと
いった別々の場所で行っている。

利用者の依頼（2026-10-31）は、**開発する場所がどこであっても品質を一定に保証でき、安心して AI に任せられる**
ようにすることだった。いまの規範は次の点でそこに届いていない（#483 の表）。

1. **AI に任せる範囲と、人が判断する点を決めた記録が無い。** `AGENTS.md` の「AI 運用規則」は 3 行で、
   禁止は本番デプロイだけだった。ADR の採択・秘密の扱い・外部への投稿などをどちらが決めるかは書かれていない
2. **品質の拠り所が文書の上で決まっていない。** CI（型・lint・単体・E2E・監査・変異）は揃っているが、
   「AI が終わったと言った」と「検査が緑だった」の区別を決めた規範は無い
3. **規則が文章だけで守られている箇所がある。** `docs/adr/0002` 決定 5 の「憲法の見出しと AGENTS.md の同期」は
   MUST だが、突き合わせるのは人の目だった。AI ツールの入口も `CLAUDE.md` 1 本だけで、他のツール向けの入口を
   足したときに正本が割れるのを止めるものが無い
4. **場所によって同じ検査が流せない。** 2026-10-30〜31 のクラウドのセッションでは、E2E のハーネスが
   同期サーバーのポートを固定で使うため別のセッションと衝突する・Playwright のブラウザの版が合わない・
   Node の版が `engines` を下回る・変異検査 `--changed` が全件に倒れて環境差で無関係のテストが落ちる、を観測した
5. **AI の報告の書式がばらつく。** 確かめたことと確かめられなかったことを分けて書く決まりが無く、
   読み手は「確かめた」の範囲を毎回本文から推し量ることになる

## 決定

### 1. 任せる範囲と、人が判断する点

**AI は、作業ブランチの上で完結し、検査で確かめられ、取り消せる作業を任されてよい**（MAY）。
コードと文書の変更・テストと検査の追加・ブランチへの push・**依頼された作業の** draft の PR の作成がこれに当たる
（依頼に含まれない PR を立てるのは、下の「外へ出る」に当たる）。

**次のどれかに当たる操作は、人の明示の指示か承認を待つ**（MUST）。

- **取り消せない、または取り消すのが重い**（本番へのデプロイ・データや履歴の削除・他人のブランチの履歴の書き換え）
- **外へ出る**（ISSUE・PR・コメントの投稿のうち依頼に含まれないもの・外部のサービスへの送信）
- **規範を変える**（ADR の採択（Proposed から Accepted へ）・憲法の改版・検査を弱める変更）
- **秘密と個人情報に触れる**（`docs/adr/0011` の分類「秘密」「資格情報」の値を読む・書く・移す）

具体的な操作の一覧は `AGENTS.md` の「AI 運用規則」に置き、ADR の改版なしに育てる（`docs/adr/0003` が
DoD の項目をガイドに置いたのと同じ書き分け。`docs/adr/0002` 決定 2）。**一覧に無い操作でも、上の 4 つに
当たると思えば人に聞く**（MUST）。一覧は判断の代わりではない。

**MUST NOT**: 検査を緑にするために、検査を飛ばす・無効にする・弱める（テストの skip・変異の宣言の削除・
走査対象の除外の追加）ことを、人の承認なしに行わない。

### 2. 品質の保証は機械的な検査で行う

- **MUST**: 「完了」の根拠は、エージェントの判断ではなく**機械的な検査の結果**と、原則 V の実経路での確認とする。
  「AI がそう言った」は根拠にならない
- **MUST**: 検査の一覧の正本は CI（`.github/workflows/ci.yml`）と `AGENTS.md` の「基本コマンド」に置く。
  ここには写さない（写すと検査を足すたびにずれる）。配置の決まりは `docs/adr/0009`
- **MUST**: 新しい規則を足すときは、**機械で守れるなら検査として足す。** 文章だけで守る規則は、
  検査にできない理由を書いてから置く（憲法 原則 VII・VIII）
- **MUST**: 手元で流せなかった検査は、**流せなかったと報告する**（決定 4）。CI が拾うとしても、
  流したことにはしない

**どこで開発しても同じ検査が同じ条件で流れる**ことを目標とする。いまは届いていない（背景 4）。
届かせる作業（E2E のポート・外部のものが無いときの止まり方・版の宣言と事前の確認・手元で CI と同じ検査を
1 つのコマンドで流す）は子 ISSUE に分ける（影響）。

### 3. 規則の正本は AGENTS.md の 1 か所に置き、ツールごとの入口は薄くする

- **MUST**: AI 向けの規則の正本は `AGENTS.md` とする。ツールごとのファイル（`CLAUDE.md`・`GEMINI.md`）は **`AGENTS.md` へ向ける数行の入口**に留め、規則を書かない
- **MUST**: 取り込み（行頭の `@AGENTS.md`）を解するツール（Claude Code・Gemini CLI）の入口は、取り込みで向ける。
  **リンクは案内であって読み込みではない。** リンクだけだと、正本を開くかどうかがエージェント任せになる
  （#485 のレビューで、Claude Code のセッションが読み込んだのは `CLAUDE.md` の 1 行だけだった）
- **MUST**: どの面（エディタ・コードレビュー・クラウドのエージェントなど）でも `AGENTS.md` を直接読むツール
  （Cursor・Codex など）のために入口を足さない（入口が増えるだけになる）。
  Copilot は使わないので入口を置かない（改定 2026-11-04・#507。下の追記）
- **MUST**: 入口と正本のずれは `scripts/audit-agent-entries.mjs`（CI の `docs` ジョブ）が見る。見るのは
  ①`AGENTS.md` の原則の見出しが憲法と一致する（`docs/adr/0002` 決定 5 の機械化）
  ②宣言した入口が追跡下にあり、正本へ向き（リンクか取り込み）、薄い（行数と文字数）
  ③ツールが規則として読む置き場（どの階層の `CLAUDE.md`・`AGENTS.md`・`AGENTS.override.md`・`.claude/rules/` ほか）に、
  宣言していない入口が無い
  ④スキル（`.claude/skills/<名前>/SKILL.md`）が手順書（`docs/guides/procedures/`）へ向く薄い入口である、の 4 つ
- 入口の薄さは空でない行の数と文字数で測る。**上限の中に規則を書けば通る**。ツールが入口を実際に読み込むかも
  見ない。検査は歯止めであって証明ではない
  （`docs/adr/0003` 追記がゲートの検査について書いたのと同じ型の残余）

**改定（2026-11-01・#489）**: 上の「見るのは」を「3 つ」から「4 つ」に改め、④を足した。決定（正本を 1 か所に置き、
入口は薄くし、ずれは検査で見る）は変えていない。検査が見る範囲という現況の記述を、#489 で足した検査に合わせた
（`docs/adr/0002` 追記（#258）の「改定節つきの本文訂正」）。

**改定（2026-11-04・#507）**: 上の決定 3 の本文から Copilot の入口を外した。直した箇所は次の 2 つ。
①入口の例から .github の下の copilot-instructions.md を除いた（改定前は `CLAUDE.md`・`GEMINI.md`・.github の下の copilot-instructions.md の 3 つ）。
②「Copilot は面によって `AGENTS.md` を読むかが分かれる（版で変わる。2026-10-31 時点では確かめていない）ので、
.github の下の copilot-instructions.md を置く。全部の面が読むと分かったら外す（#491 の試しで確かめる）」を、
「Copilot は使わないので入口を置かない」に置き換えた。理由は下の追記。本文が現況（入口が無い・確かめる予定が無い）と
食い違う嘘になるため、`docs/adr/0002` 追記（#258）の「改定節つきの本文訂正」で直した。決定（正本を 1 か所に置き、
入口は薄くし、ずれは検査で見る）は変えていない。
なお、この改定と下の追記、影響欄（採択時の記録）で消したファイルを名指しする箇所は、バッククォートを外して書いた（意味を変えない表記の変更。
リンク検査が実在しないパスとして拾うのを、例外表を増やさずに避けるため。`docs/adr/0009` の追記が旧名を書かないのと同じ型）。

#### 追記（2026-11-04・#507）: Copilot の入口を、確かめずに外した

- #491 の試しの 2 つの場所はどちらも Claude Code だったので、Copilot の各面（エディタ・コードレビュー・クラウドの
  エージェントほか）が `AGENTS.md` を読むかは**確かめられなかった**（振り返り
  `docs/retrospectives/2026-11-02-issue-491-two-place-trial.md` の申し送り 10）
- 利用者が Copilot を使っておらず、使う予定も無いと決めた（2026-11-04）。使う時が来たときは版も面も事情も
  変わっているので、いま確かめても役に立たない。そのため**各面が `AGENTS.md` を読むかを確かめないまま**、
  .github の下の copilot-instructions.md と `scripts/audit-agent-entries.mjs` の入口の宣言を外した。
  「読むと分かったから外す」ではなく、「使わないから外す」である
- **MUST**: Copilot を使い始めるときは、**その時点の版で各面が `AGENTS.md` を読むかを確かめ**、読まない面があれば
  入口を足す（決定 3 の「直接読まないツールにだけ入口を足す」に従う。足すときは `ENTRY_FILES` に宣言する）
- .github の下の copilot-instructions.md は検査の候補の置き場（ツールが規則として読む場所）に残してある。
  黙って戻されたら「宣言されていない入口」として止まる
- 影響欄は採択時の記録なので、中身は書き換えていない。消したファイルの名前のバッククォートだけを外した（表記だけの変更。上の改定のなお書き）
- この追記は規範を足すので、採択は PR のマージで利用者が行う（利用者は 2026-11-04 に、この PR の変更を、マージに先立って会話の中で承認した）

#### 追記（2026-11-01・#489）: スキルも同じ考え方で薄い入口にする

- **MUST**: 繰り返す作業の**手順**の正本は `docs/guides/procedures/` の手順書とする（ガイドの一部。`docs/adr/0002` 決定 2）。
  ツールのスキル（`.claude/skills/<名前>/SKILL.md`）は**手順書へ向ける薄い入口**に留め、手順を書かない。
  規則の正本を `AGENTS.md` に置き、`CLAUDE.md` ほかを薄い入口にしたのと同じ考え方である
- **MUST**: スキルの形は機械で見る（上の④。`scripts/audit-agent-entries.mjs`）
  - 本文: 追跡下の手順書へのリンクを持ち、空でない行の数と文字数が上限の中にある
  - frontmatter: `name`（ディレクトリ名と同じ。小文字・数字・ハイフン）と `description`（上限 200 字）の 2 つだけを、
    1 行に 1 つずつ、YAML が同じ文字列に読むと言い切れる形で書く
  - 置き場: `SKILL.md` 以外のファイル（スクリプト・参照文書）を置かない
  - 権限を前もって許すキー（`allowed-tools` など）を入口に置かないのは、知らないキーを拒むことで担う
- **スキルを持たないツールでも、手順書だけで作業できる**ように手順書を書く。スキルは近道であって、唯一の入り口ではない
- 共有のスキルは `.claude/` を丸ごと無視したまま、ファイル単位の `git add -f` で追跡する。無視を外すと、手元にだけ置いた
  個人のスキルが未追跡として現れ、変異検査が起動を拒む（#493 のレビューで再現。`.gitignore` のコメント）
- **外部のスキル運用（`superpowers:*` ほか）との分担**: リポジトリに固有の手順（検査のコマンド・ポート・変異の宣言の表のように、
  リポジトリの中身を知らないと書けないもの）は手順書に持ち込む。どのリポジトリでも同じ汎用の進め方は外に残し、使うかどうかは
  作業する側が選んでよい。**外のスキルを使わなくても、このリポジトリの規則と手順書だけで作業を終えられる**ことを保つ。
  設計文書の置き場（`docs/superpowers/`。`docs/adr/0002` 決定 4）は、外のスキルを使ったかどうかに依らない。
  外のスキルの指示とこのリポジトリの規則が食い違ったら、このリポジトリの規則が正しい
- 残余: 検査は形を見るだけで、description が手順書の中身と合っているかや、ツールがスキルを実際にどう読むかは見ない。
  frontmatter の読み方は js-yaml 4.3.2 との突き合わせで裏づけたが、ツール自身の読み方では確かめていない

### 4. AI の成果の記録

- **MUST**: AI が作業を終えたときの報告（PR 本文・ISSUE へのコメント・会話での完了の報告）は、
  **変えたこと・確かめたこと・確かめられなかったこと**を分けて書く。確かめたことには、流したコマンドと
  結果を添える。確かめられなかったことには理由を添える（例: 環境に Caddy が無く E2E を流せなかった）
- **MUST**: 決定は ADR に、要求は ISSUE に、教訓は振り返りに残す（憲法 原則 VIII）。会話の中にだけ残った
  決定は、決定として扱わない
- コミットと PR の書式（Conventional Commits・PR テンプレートの DoD）は既存のとおり。AI の作業であることの
  表示（共同作者の行など）は各ツールの既定に従い、ここでは決めない

### 5. 複数のエージェントで分担するとき

- **MUST NOT**: 同じブランチ・同じ作業ツリーを、2 つのエージェントが同時に書き換えない。並行に進めるときは
  ブランチか作業ツリー（`git worktree`）を分ける（同じ作業ツリーでの衝突は変異検査で実際に起きた。`docs/adr/0029` 背景）
- **MUST**: 敵対的なレビューは、**実装したのとは別のエージェント**が、実装した側の結論ではなく差分とコードを
  渡されて行う。結論を渡すと、レビューはそれを追認しやすい
- レビューの指摘は、検査（テスト・変異・実画面の計測）で再現してから直す。再現できない指摘は、
  再現できなかったと記録する（決定 4）

#### 追記（2026-11-03・#504）: レビューをいつ行うか、先行する PR をどう確かめるか

#491 の試し（`docs/retrospectives/2026-11-02-issue-491-two-place-trial.md` の罠 1・罠 4）で、上の決定が
「行うなら別のエージェントで」しか決めていないために、二つの空白が実害になった。決定そのものは変えない。

- **MUST**: **誤字・リンク・記録の状態の書き換えだけの変更を除く、すべての変更**は、**終わりを報告する前に**、
  実装したのとは別のエージェントの敵対的レビューを通す。PR を立てるかどうかに依らない（会話だけで終わる作業も含む）。
  対象は除外だけで決める（列挙は漏れる。製品コード・検査・規範文書・設計文書・設定のどれも入る）。除外は、
  読み違えても規則や挙動が変わらない変更に限る。別のエージェントを起こせない環境のように、通せない理由が本物のときは、
  終わりの報告の**前に**人へ聞く。「PR が無い」「時間が無い」は理由にしない（罠 1 は「PR を作っていないので未実施」と
  書いて終わった）。根拠: 手元版はレビューを通さずに終わりを報告し、
  レビューを 2 回通したクラウド版が直した穴のうち 2 つが残った。レビューは頼まれたときにしか行われなかった
- **MUST**: **同じ ISSUE の開いた PR・マージ済みの PR・リモートの枝を確かめる。** 確かめる時は始めと、
  PR を立てる前・終わりを報告する前（具体は `AGENTS.md`）。途中で見つけても、続ける前に人へ伝える。根拠: 手元の AI は同じ ISSUE をクラウドの PR が片付けたと途中で気づいたが、伝えずに続けた。
  並行して同じ ISSUE を進めるか、捨てるかは、AI が決める点ではない（決定 1「規範を変える」「外へ出る」の隣の、
  作業の重複という取り消しにくい無駄の判断として人に返す）
- 操作の一覧は `AGENTS.md` の「AI 運用規則」に置く（決定 1 と同じ書き分け）
- **機械化は、先行 PR の確認だけ検査にする**（決定 2 の「機械で守れるなら検査として足す」）。当初は「検査にできない」と
  書いたが、事実と合わなかった。検査は「止める」のでなく「知らせる・聞く」形にすれば、番号を書いた場合に限り書ける。
  引き方は 1 つ（`scripts/lib/prior-work.mjs`）にして、次の 2 か所が使う
  - **`pnpm check:fast`**（`scripts/local-check.mjs`）: 今のブランチ名の番号で引き、最初と最後の一覧に知らせを出す。止めない。
    ブランチに番号が無い・gh が無い・未認証・ネットワークが無いときは、失敗でなく「未実行」と理由を出す
  - **Claude Code のフック**（`gh pr create` の直前。判定は `scripts/lib/prior-pr-hook.mjs`、配線は `docs/adr/0032` の追記）:
    番号はブランチ名と `--title` の両方から取り、先行があれば人に聞く
  - 引き方の方針: 番号の完全一致で絞る（本文の数字、例えば「2,480 件」に当たる）、検索の上限に当たったら切れていると見る、
    枝は `git ls-remote` で直接引き `git fetch` で共有の参照を消さない（`scripts/lib/base-freshness.mjs` の方針）、
    自分の枝とその PR は除く。具体のコマンドは `AGENTS.md`（人が手で確かめるときの操作の正本）
  - 残余（検査は歯止めであって証明ではない。決定 3 と同じ型）:
    - **知っているのに伝えない**ことは防げない。フックは聞く（人が承認すれば進む）だけで、check:fast は知らせるだけである
    - ブランチ名から番号を取るのは `<type>/<番号>-…` と `issue-<番号>` の 2 つの形だけで、それ以外は「番号なし」で未実行になる
      （`claude/trial-491-cloud-480` のような枝も番号なし）。ISSUE でない数字で無関係な PR を挙げるより、確認を抜ける方を選んだ
    - 番号を書かない枝名・題・本文は拾えない。範囲の書き方（例: 「#504〜#509」）は `#504` として当たる
    - PR を立てない作業には check:fast の知らせだけが届く。check:fast を流さず `gh pr create` もしない作業には何も届かない
    - フックは Claude Code の面だけで働く（他のツールは `AGENTS.md` の規則のみ）。`disableAllHooks` で切れる
    - gh の認証とネットワークが要る。クラウドのセッションで gh が使えるかは確かめていない
  - 「途中で見つけたら伝える」は気づいた時点の行動で、検査の対象が無い。`AGENTS.md` の規則で守る
- **レビューを通したかの検査は足さない。** 通したかは会話やエージェントの内部にしか残らず、リポジトリの状態から読めない。
  PR 本文に「レビュー」の節を求める検査は、①PR を立てない作業に届かない ②対象外（誤字・リンク・記録の状態の書き換え）かどうかは
  判断で、機械では決められず、対象外の PR にまで空の節を求めて形だけ埋めさせる ③書いてあることが本当かは見られない
  （③は決定 3 が受け入れた「歯止めであって証明ではない」と同じなので、退ける理由は①②）。
  当面は `AGENTS.md` の規則と報告の書式（決定 4。レビューの事実を「確かめたこと」に書く）で守り、
  破られたと分かったら再検討する
- この追記は規範を足すので、採択は PR のマージで利用者が行う

### 6. マニフェストと憲法の関係

- マニフェスト（[`docs/ai-manifesto.md`](../ai-manifesto.md)）は、**AI と開発するときの価値観を 1 枚にまとめた要約**
  である。**新しい義務を持たない。** 各項目は憲法の原則か ADR を指す。食い違ったら憲法・ADR が正しく、
  マニフェストを直す
- **憲法は今回は改版しない。** 決定 1〜5 は「誰が決めるか・どう記録するか」という運用であり、何を守るかは
  既存の原則（I・V・VII・VIII・IX・XI）で足りている。#483 の「2 つの場所で試す」振り返りで、原則の不足が
  実際に見つかったときに改版を検討する（原則 X「抽象は実需で」と同じ考え方）

### 退けた案

| 案 | 退けた理由 |
|---|---|
| 憲法に「XII. AI に任せる範囲」を足す | 決定 6。運用の決まりは変わりやすく、憲法の重さに合わない。原則の不足はまだ実測されていない |
| 人が判断する操作の一覧を ADR に書く | 操作は増える。足すたびに ADR を改版することになる。基準を ADR に、一覧を `AGENTS.md` に置く（決定 1） |
| ツールごとに規則を書き分ける | 正本が割れる（憲法 原則 VIII）。ツールの違いは入口の置き場の違いだけにする |
| 入口を symlink にする | Windows と一部のツールで追えない。リンクで向ける数行のファイルなら、どこでも読め、検査もできる |
| 入口のずれを検査しない（レビューで見る） | 背景 3。見出しの同期は MUST なのに人の目だけで守っていた |
