# ADR-0025: 幅の段・器・段組み・ボタンを部品層で揃える

- **ステータス**: Accepted（2026-10-08）
- **関連**: #316・設計正本 `docs/superpowers/specs/2026-10-08-responsive-layout-design.md`・ADR 0022（部品層）・ADR 0023 決定 4（timer は要素層を読まない）

## 背景

PC の幅で画面が狭く、ボタンの形と並びが画面ごとに違っていた（利用者のフィードバック・2026-09-26）。5 つの幅で撮った洗い出しでは、器の幅が画面ごとに 680px〜1152px に散り、幅の境目は 5 種類（rem と px が混在）、ボタンの形はアプリごとに別々だった（設計正本 §2）。

## 決定

1. **幅の段の境目は `40rem`・`64rem`・`90rem` の 3 つだけ。** 範囲構文（`(width >= 40rem)`）で書き、`min-width` / `max-width` / px / em を書かない。JS の判定も同じ問い合わせ（`matchMedia('(width >= 64rem)')`）を使う。コンテナクエリは対象外（部品の内側の並び替えは箱の幅で決めてよい）。`scripts/audit-ui-components.mjs` が守り、外すときは `ui-exempt:` で理由を書く
2. **器は部品層の `.ui-page` の 3 段から選ぶ。** 読む・入力する画面は `--prose`（40rem）、選ぶ・一覧する画面は既定（72rem）、区画を並べる道具の部屋は `--wide`（96rem）。要素層の `.page` は消す
3. **段組みは `.ui-workspace` の操作の面（`-main`）と脇（`-side`）の 2 区画で組み、長い文章は読む面（`.ui-reader`）とシート（`.ui-drawer`）で見せる。** 脇は既定で左・22rem、`--side-end` で右、`--reader` で操作の面と釣り合う幅の読む面にする。DOM は狭い幅で見せたい順に書き、広い幅で並べ替えるのは部品の CSS だけで行う。読む面は 64rem 以上で画面の高さに収まり本文だけがスクロールし、64rem 未満では本文を 3 行で切ってシートに全文を出す。区画に何を置くかは画面が決める。脇が無ければ操作の面だけの 1 列になる。2026-10-08 に利用者の実物の確認を受けて、3 区画（左脇・主・右脇）から改めた（理由は設計正本 §9）
4. **ボタンの見た目は部品層の `.ui-button`（形 1 つ・役割・大きさ 3 段）だけが持ち、要素層の `button` は見た目を持たない。** 役割は主（既定）・副（`--secondary`）・控え（`--quiet`）と、取り消せない操作（危険）。危険は使う画面が 1 つの間は画面の CSS が持ち、2 画面目が使うときに部品へ置く（ADR 0022 決定 2）。押せる大きさは 44px 以上（`--sm` は擬似要素で当たりを広げる）。札の上のボタンの色は部品が持つ
5. **操作の並びは `.ui-actions` で組み、主は常に最後に置く。** 1 つの並びに主は 1 つまで。狭い幅では縦に積み、主の操作が画面の外へ流れる画面だけが下端に留める（`--dock`。`position: sticky` で、並びを置いた範囲の中でだけ留まる）
6. **timer に要素層を読ませない判断（ADR 0023 決定 4）は維持する。** ボタンの見た目が部品層から来るので、要素層を読ませる理由が無い
7. **文字の大きさの 5 段は役割で当てる。** 画面の見出し（h1）は xl、区画の見出し（h2）は lg の象牙・700（字間を詰めない・大文字にしない・罫を引かない）、小見出し（h3）は base・700、本文と項目のラベルは sm〜base、添え書き・小さな印は xs。金の字間の広い大文字は小さな印にだけ使う。h1〜h3 は要素層が持ち、timer は画面のクラスで同じ段を当てる。2026-10-10 に利用者の指摘（区画の見出しが項目のラベルより小さく見える）を受けて決めた（設計正本 §11）

## 影響

- 新しい画面は器の段と区画を選ぶだけで、幅と並び替えを書かずに済む。ボタンは役割と大きさを選ぶだけで済む。使い方は `packages/ui/README.md` の「画面を組む」
- 段の境目が 3 つになり、画面ごとの細かな調整（420px・720px）は近い段へ寄った。寄せた結果は設計正本 §6 の撮影で確かめる
- 4 つ目の器の段や境目が要るときは、README の選び方に当てはめて足りない理由を書き、この ADR に追記する
