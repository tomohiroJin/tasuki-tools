## 背景

うちわけは、ルームの全員が同じ画面で「いまやっていること」を切り替え、区切りごとの時間を積み上げ、
終わりに作業名ごとの合計と時系列を Markdown でコピーして持ち帰る道具である。長く蓄積する道具（工数管理）の前段に徹し、
記録はサーバーにも端末にも残さない。

この道具が動いていても失敗とみなす形が 2 つある（設計 §2）。誰が切り替えたかがどこかから分かること、
合計と内訳が食い違うことである。前者は「誰が何に何時間使ったか」を集める道具への転用につながる。

共通ルーム（#95）・お題（#91）・ルーレット（#94）・進行タイマー（#429）・チェックイン（#406）で、新しいサーバーを立てずに
接続の種類（`?tool=`）だけでツールを足せることが分かっている。一方、うちわけは予定を持たない区切りの列を持ち、
後から時刻を直す操作（調整・分割・上書き）があり、既存の集約（timer の交代の輪・agenda の予定つきのステップの並び）とは形が違う。

実測と経緯の正本は設計正本に置く。ここには決定だけを書く。

## 決定

### 決定 1（設計 §4）: 独立したツールとして足し、規則は 8 つ目の文脈 `packages/track-core` に置く

timer にも agenda にも足さない。新しいサーバーは立てず、接続の種類 `?tool=track` を足す（綴りの正本は
`apps/tasuki-sync/src/application/tool-id.ts`）。公開パスは `/track/`、画面は `apps/track-web`。

`track-core` は **`room-core` を含むどの `@tasuki/*` にも依存しない（MUST NOT）**（`docs/adr/0026` 決定 1 と同じ）。
依存は `valibot` と `neverthrow` だけで、依存の向きの正本は `scripts/audit-dependency-direction.mjs` の `ALLOWED` とする。

### 決定 2（設計 §6）: 誰が操作したかを、状態・フレーム・書き出し・ログのどれにも持たない

- **コマンドのスキーマに、操作した人を表す項目を置かない（MUST NOT）。** `v.strictObject` が余計な項目を拒むので、送っても通らない
- **ドメインの関数へは、コマンドの中身と時計だけを渡す（MUST）。** 接続の ID は「うちわけとして在席しているか」を名簿で確かめるためだけに使い、状態へ渡さない
- **写しは全員に同じものを配る（MUST）。** 受け手ごとの出し分けを持たない（出し分けの口があると、そこに個人の情報を載せる余地ができる）
- うちわけのハンドラと全員切断の停止は**ログを書かない（MUST NOT）**（作業名は利用者の入力。`docs/adr/0012`）

区切りが持つのは、種類（作業／休憩）・作業名・始まりと終わりの位置・全員の切断で閉じた印だけである。

### 決定 3（設計 §4.1）: 区切りの位置は単調時計の時刻軸で持ち、壁時計は表示のために 1 つだけ持つ

- **時刻軸は、そのルームのうちわけの状態を最初に置いた時点を 0 とする ms の整数で、サーバーの単調時計で測る（MUST）。**
  壁時計は NTP の調整で戻りうるので、間隔の計測に使わない（MUST NOT。`docs/adr/0027` 決定 2 と同じ理由）
- 基準は記録が空でも持ち、記録を消しても変えない。後からの追加で、位置は負の値も取りうる
- **壁時計は、時刻軸の 0 に当たる時刻（`epochWallMs`）を 1 つだけ持つ。** 画面と Markdown の「HH:MM」は `epochWallMs + 位置` で表す。
  `docs/adr/0027` 決定 3 は絶対時刻を配らないが、うちわけは「何時から何時まで」が持ち帰る中身なので、表示のための 1 つに限って配る
- **画面へは、送る時点の時刻軸の位置（`nowMs`）と、取り消しの残り時間を配る（MUST）。** 単調時計の値そのものは wire に載せない（MUST NOT）。
  画面は受け取ってからの経過を足して描き、刻みの加算では経過を求めない
- ドメインは `Date` も環境の時計も読まない。暦の計算（日付の表記）は ms の算術で行い、時間帯は呼ぶ側が渡す

### 決定 4（設計 §4.2・§4.3）: 区切りは重ならず、短すぎる区切りは残さない

区切りは開始の昇順で重ならず、計測中の区切りはあっても最後の 1 つだけで、閉じた区切りは最短の長さ以上である。
この不変条件は、計測の遷移も手直しも保つ（MUST）。性質テスト（`packages/track-core/tests/track-invariant.test.ts`）が固定する。

- **閉じる時点で最短の長さに満たない区切りは、捨てる（MUST）。** 切り替えなら、新しい区切りが捨てた区切りの始まりを引き継ぐ（押し直しは付け替えになる）
- **後からの追加は、その範囲を新しい区切りで上書きする。** 削った残りが最短に満たないときは、その端切れを新しい区切りへ含める
- **調整は、隙間をはさんだ隣へ食い込めない。** 接している境界は隣ごと動く。動かせる範囲は 1 つの関数（`adjustRangeOf`）が決め、判定と画面のボタンが同じ規則を使う
- 休憩は区切りの種類であり、一時停止という状態は持たない。区切りの間の隙間は「止めていた時間」で、どの合計にも入らない
- 上限の値の正本は `packages/track-core/src/limits.ts` とする。ここへ数値を写さない

### 決定 5（設計 §4.3）: 取り消しは直前の 1 操作の写しで行い、番号で指す

- **取り消せるのは、開始・切り替え・停止と、記録を消す操作だけである。** 手直しは取り消しの対象にしない

> 改定: 取り消しの対象に「離れていた間の休憩」（`track.away`）を足した（2026-11-26・#476。末尾の追記の決定 2）
- その操作の直前の区切りの列を 1 つ写しておく。ほかの操作で状態が変わったら写しを捨てる（定番の固定・解除だけは捨てず、取り消しても定番は戻さない）
- **取り消しは、その操作に振った番号（`rev`）で指す（MUST）。** 番号が違う取り消しは何もしない（古い画面の取り消しが、別の操作を巻き戻さない）
- 期限は単調時計で測り、予約は持たない。配るときに残りを計って載せる
- **取り消しても、区切りの番号は使い回さない（MUST）。** 使い回すと、古い画面の手直しが別の区切りに当たる

### 決定 6: 表現は直接遷移関数 ＋ `Result` を採る

`docs/adr/0016` 決定 1 が MUST とする「どちらを採ったかと理由の記録」がこれである。状態は小さく、イベントの履歴・再生の要求が無い。
取り消しは直前の状態の写し 1 つで足りる（`docs/adr/0007` 基準 3）。`room-core`・`topic-core`・`roulette-core`・`agenda-core` と同じ。
遷移は `Result` を返し、エラー値は判別子 `code` だけを持つ（`TrackError`。`scripts/audit-domain-error-shape.mjs` に登録する）。
拒む場合が無い遷移（取り消し・全員切断の停止・問いかけを下ろす・記録を消す）は状態をそのまま返す。
**状態が変わらないときは同じ参照を返し**、サーバーは参照の比較で「全員へ配るか、送り主にだけ返すか」を決める。

### 決定 7（設計 §4.3）: 全員の切断は名簿の全員の不在で数え、猶予を置いてから、最後の切断の時刻で閉じる

- **「全員」は、名簿の全員が不在（どの道具・玄関にも接続が無い）であることで数える（MUST）。** アイドルの回収と同じ数え方である。
  うちわけの接続だけで数えると、画面を閉じて作業を続ける間に記録が止まる
- 名簿が配られるたびに（組み立ての `onRosterBroadcast` の口）数え直す。全員が不在になったら、その時刻を覚えて猶予を待つ
  （`docs/adr/0028` 決定 11 と同じ考え方。再読み込み・瞬断で閉じない）
- 猶予の後も不在のままなら、計測中の区切りを**覚えた時刻**で閉じ、印を付け、再開の問いかけを立てる
- **猶予の予約と状態は、ルームの破棄へ渡す必須の依存にする（MUST）**（省略可にすると、配線から落ちてもテストが緑のまま残る。`docs/adr/0027` 決定 2 と同じ）

### 決定 8: うちわけを操作できるのは track の接続だけである

`docs/adr/0027` 決定 8 と同じ。**うちわけのコマンドは track の接続のスキーマ（`TrackCommandSchema`）にだけ置く（MUST）。**
コマンドは `v.strictObject` で余剰の項目を拒む。受けるフレーム（`TrackFrameSchema`）は非 strict にし、後から足す項目は任意にする。
ハンドラは「うちわけとして在席しているか」を名簿で確かめる（2 段目の守り）。接続の受理は `onConnect` を通す。

### 決定 9: お題のフレームを track の接続にも配り、うちわけはお題を読むだけにする

`docs/adr/0021` 決定 2（宛先はツールを問わない）に従う。お題の配信先は道具の一覧から導かれるので、track は一覧に足すだけで宛先に入る。
画面は自分のスキーマより先に `TopicFrameSchema` で見分ける（同決定の MUST）。
うちわけはお題を書き換えない。お題のタイトルを切り替えの候補の先頭に出すだけである（お題を複数件にしたときの扱いの検討〈#448〉を待たない）。

## 却下した案

| 案 | 退けた理由 |
|---|---|
| timer に足す | timer は交代の輪が中心で、作業名の列という別の関心が集約に混ざる（決定 1） |
| agenda に予定なしのモードを足す | agenda の核（予定の合計・押し巻き）が意味を失うモードになる（決定 1） |
| 区切りに、切り替えた人を持たせる | 「誰が何に何時間」を集める道具への転用につながる。持たなければ、漏れる経路も無い（決定 2） |
| 区切りを壁時計の時刻で持つ | NTP の調整で戻りうるので、長さがずれる（決定 3） |
| 一時停止の状態を持つ | 止めていた時間の意味が決まらない。休憩の区切りにすれば、合計に入らない時間として記録に残る（決定 4） |
| 取り消しを操作の履歴として持つ | 要るのは直前の 1 操作だけで、写しを 1 つ持てば足りる（決定 5・`docs/adr/0007`） |
| 後からの追加を隙間にだけ許す | 切り替え忘れは区切りの途中に起きる。上書きにすれば 1 回で直せる（決定 4） |
| 全員の切断を track の接続だけで数える | 画面を閉じて作業を続ける間に、記録が止まる（決定 7） |
| 猶予を置かずに閉じる | 1 人で使っているときの再読み込み・瞬断で区切りが閉じる（決定 7） |

## 影響

- ルームの持ち物に、うちわけの状態が加わる。状態は揮発インメモリで、再起動・デプロイ・アイドルの破棄で記録が消える（`docs/timer/adr/0007`）。
  利用者が持ち帰る手段は Markdown のコピーだけである
- **データ分類**: 作業名・定番の作業名は利用者由来のテキストで、人の名前や案件の名前が入りうる。`docs/adr/0011` 決定 1 の
  「個人に紐づく」に置く（同 ADR の 2026-11-23 の追記）。区切りの時刻と長さも作業名と組になるので同じ扱いにする
- **コマンドの頻度の上限は設けない。** お題・ルーレット・進行タイマー・チェックインと同じ扱いで、効くのはメッセージの大きさの上限と `limits.ts` の上限である
- **書体**: 画面の文言に要る字を base 層へ足した。base 層は全アプリが読むので、配布では全アプリが対象になる（`deploy/track/NOTES.md`）
- **配布の順序**: 同期サーバー（timer の配布）が先、画面が後（`docs/adr/0026`）。新しいアプリなので、初回は root の作業（web root と Caddy の断片）がある
- 端末への保存・CSV・戻ってきたときの問いかけは、この決定の範囲に含めない（#476 の後の段）

## 追記（2026-11-26・#476 第 2 段）: 端末への保存は押したときだけ、離れていたことは端末だけが知る、通知に作業名を出さない（Proposed）

> 冒頭のステータス（Accepted・2026-11-23）は、この追記より前の決定を指す。この追記は Proposed で、採択は利用者が行う。

- **設計**: [`2026-11-26-track-phase2-design.md`](../superpowers/specs/2026-11-26-track-phase2-design.md)（数の正本は設計の §5b とコードの定数。ここへ数を写さない）
- **変える既存の決定**: 「影響」の最後の行（後の段は範囲外）を、下の決定 1〜3 で置き換える。決定 5 の取り消しの対象を、追記の決定 2 で広げる。
  作業名の正規化に、表示名の第 1 層と同じ見えない字を落とすことを足す（設計 §2 の A1。決定 1〜9 の中身ではなく、`label.ts` の規則の追加）。
  ほかの決定 1〜9 は変えない

### 追記の決定 1: 端末への保存は、利用者が押したときだけ、その端末の IndexedDB に残す

- **自動では残さない（MUST NOT）。** 「この端末に残す」を押した人の端末にだけ、その時点の写しを 1 件残す。
  ルームの全員の作業名が入るので、押していない人の作業名が黙って誰かの端末に溜まる形を作らない（原則 XI）
- 残すのは区切りの列と表示用の壁時計の時刻だけで、ルーム名・ルームのコード・定番・接続の情報は残さない
- 件数に上限を置き、保存先と消える条件（ブラウザが消す場合を含む）を押す所の近くで示す（FR-13）
- 残した記録を見る画面は、ルームに接続しない（timer の `?view=history` と同じ。見ているだけの人を名簿に載せない）
- **データ分類**: 作業名は「個人に紐づく」の段のまま。端末に残す分は `docs/adr/0011` の 2026-11-26 の追記で「端末に残してよい」段として扱う。
  サーバーには何も残らない（原則 III は変わらない）

### 追記の決定 2: 離れていたことは端末だけが知り、サーバーへは時刻の位置だけを送る

- 戻ってきたときの問いかけ（FR-27）は、ページの非表示を見た端末だけで出す。**誰が離れていたかを状態・フレーム・ログに持たない（MUST NOT。決定 2 と同じ）**
- 選ばれた結果は `track.stop { atMs }` か `track.away { fromMs }` で送る。**`track.away` を決定 5 の取り消しの対象に足す。**
  どちらも全員の画面に取り消しの帯を出す。FR-27 の後半「全員に通知してから反映」は、「反映し、全員の画面に取り消せる知らせを出す」に変えた
- 受け入れること: `track.away` の結果は全員に見えるので、少人数なら誰かが離れていたことは推せる。本人が選んで送る操作で、手で休憩を足すのと同じ程度の情報として受け入れる。誰が送ったかは今までどおり載せない
- 足す wire の項目は任意にする（`docs/guides/architecture.md`「wire に足す項目は、任意にする」）

### 追記の決定 3: 通知とミニ表示はブラウザの API を使い、依存を足さない

- 通知（Notification API）は既定で切。押した人だけに許可を求める。**通知の文に作業名を出さない（MUST NOT）**（ロック画面ほか、画面の外に出るため）
- ミニ表示（Document Picture-in-Picture）は対応ブラウザでだけ出し、非対応のブラウザへ代わりの道を作らない
- ブラウザの API への触れ方は web の端末 I/O の層（`apps/track-web/src/platform/` ほか）に置く（`docs/adr/0015` の 2026-11-14 の追記の表）

### 退けた案

| 案 | 退けた理由 |
|---|---|
| 計測のたびに端末へ自動で残す | 他の参加者の作業名が、本人の知らないまま誰かの端末に溜まる |
| 離れていたことをサーバーへ知らせ、全員に問いかける | 誰が離れていたかが状態に入る（決定 2） |
| 問いかけの結果を、全員の承認を待って反映する | 誰かが応じるまで記録が止まる。取り消しの帯で足りる |
| 端末の保存を玄関の「記録を見る」へ直接載せる | 道具を横断する一覧は #671 の決め（`docs/adr/0017` の境界） |
