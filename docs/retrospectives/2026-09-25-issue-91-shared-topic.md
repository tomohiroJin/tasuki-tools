## 踏んだ罠（事実と再発条件）

### 1. `--tools ""` だけでは `claude -p` のツールが閉じなかった

**事実**: `docs/adr/0012` D10 は「子プロセスが使える組み込みツールを明示的に閉じる」ことを求めていた。
本番と同じ CLI 2.1.178 で、起動時に報告されるツールの一覧を実測した（設計正本 §10・PR #310 の本文）。
**`--tools ""` だけでは `["LSP"]` が残った。** 利用者設定（`~/.claude` で有効にしたプラグイン）が足すツールで、
`--settings '{}'` も `--strict-mcp-config` も止めなかった。空の HOME で流すと 0 個になる —— **結果が本番の HOME の中身に左右される**。
`--disallowedTools LSP` を足すと空になるが、名前の列挙なので次に足されるツールを取りこぼす。
採用したのは `--setting-sources "" --tools ""` で、LSP を足すプラグインが入った HOME のままで空になり、OAuth の認証も通る。

**再発条件**: 「閉じる指定」をドキュメントの記述や手元の 1 回の試行で決めるとき。**閉じたかどうかは、
子プロセス自身が報告する一覧で、本番と同じ HOME・同じ env で数える**まで分からない。
変異（m77・m84）が、この指定を外すと単体テストが赤になることを守っている（`docs/adr/0012` の追記）。

### 2. 書体の常用の層に無い字が、設計の UI の言葉に入っていた

**事実**: 設計正本 §5.4 は「掲げる」「本文」と書いていた。`packages/ui/src/tokens/fonts.css` の
`zkgn-{400,500,700}-base` の `unicode-range` に当てると、**「掲」と「本文」の 2 字が 3 つの太さすべてで外れた**
（設計正本 §10.1）。画面では「このお題にする」「お題を下ろす」「説明（なくてもよい）」と言い換えた。
PR 1 の topic-core の文言も 3 件外れていた（`GENERATION_COOLDOWN`「少」・`AI_UNLOCK_FAILED`「違」・`RATE_LIMITED`「多」）。
timer の同じコードの文と揃えるのはやめた（利用者の承認）。**振る舞いの名前（EARS の「掲げる／下ろす」）は残し、画面の言葉だけを変えた。**

**再発条件**: 設計の段で UI の言葉を決め、**書体の層に当てずに**実装へ下ろすとき。外れた字が 1 つでも画面に出ると、
拡張の層（数百 KB）を引く。いまは `apps/topic-web/tests/copy-fits-font-base.test.ts` と
`rendered-text-fits-font-base.test.tsx` が守る（前者は `copy.ts` しか見ないので、画面へ直書きした文言は後者が拾う ——
PR 2 の計画の「検出力の検証」）。PR 3 の timer・poker の新しい文言も同じ形で測っている。

### 3. 撤去する旧実装に、誰も知らない欠陥が 2 つ埋まっていた

**事実**:

- **押していない端末は、中断でも完成記録を作っていた。** 旧い条件は `next.problem && ctx.endType !== "abort"` で、
  `endType` を「中断」にするのは押した本人の端末だけだった。計画の段ではコードを読んだ見込みだったが、
  旧実装に一時テストを当てて実在を確かめてから直した（設計正本 §10.2・コミット `203a7f4`）。
  いまは終わり方を snapshot から導く（`sessionRecords` が増えていれば完成）
- **1 本のハブの接続が、2 つのルームの名簿に同時に載った。** 計画は「両方に載るなら止まって利用者へ報告する」としていた。
  実測は **3 回とも「A と B の両方に載り、A のお題も届き続ける」**だった（設計正本 §10.2・コミット `f9c0d94`）。
  お題の接続（`topic-handlers.ts` の `handleJoin`）が既に同じ判断をしていたので、ハブの 2 度目の `room.join` / `room.create` を
  `INVALID_COMMAND` で拒むように直した。変異は m108・m110

どちらも、**撤去や配信先の拡大が「いまの振る舞いを保つ」前提で計画されていた**ところから出た。
保つべき振る舞いのほうが壊れていた。

**再発条件**: 旧実装を消す・広げる計画を、**旧実装の振る舞いを測らずにコードの読みだけで**書くとき。
消す直前の旧実装に一時テストを当てれば、欠陥があるかどうかは 1 回で分かる。

### 4. 実画面でしか出なかった欠陥

**事実**（いずれも設計正本 §10.1 / §10.2・各 PR の本文）:

- **PR 2**: 定型バンクの本文は Markdown なのに、お題ツールが素の文字列で出していた（記法がそのまま見える）。
  長いタイトルが札からはみ出していた。どちらも実画面で見つけ、同じ PR で直した
- **PR 3**: poker の本文のリンク（`--coal`）が、暗い地（`--felt-900`）の上で約 1.03:1 だった。
  topic-web から写した Markdown の色一式が明るい地を前提にしていたので、本文を象牙の札（`.topic-body`）に載せた
- **PR 3**: poker に文字のコントラストの走査（`e2e/specs/poker-a11y.spec.ts`）を新設し、**アサーションを書く前に 1 回探索した**ところ、
  お題とは無関係の既存の見出し「参加者（N人）」「あなたのカード」が **3.92:1** で AA を割っていた。
  PR 2 の申し送り（「poker の h2 も同じ見込み。poker には走査が無い」）が当たった。`--felt-900` の地を与えて直した
  （トークンの値からの計算で約 6.4:1）

**再発条件**: 移植した部品の**前提（地の色・入力の形）**を、移植先で測らないとき。単体テストは色も記法も見ない。

### 5. 撤去の途中の課題が、型と wire を別々に動かすと赤になった

**事実**: PR 3 の計画は、timer-web の撤去（`hasAiKey` の送信を外す）とサーバーの撤去（`TimerState` から項目を落とす）を、
timer-core の型の撤去と別の課題に置いていた。そのとおりに進めると、**途中の課題で型検査が赤になり、実機の参加が落ちる**。
着手前の点検で見つけ、型と wire を同じ課題で動かす順に組み替えた（コミット `c840f2c` の本文「Task 9 まで残す方針」・`5d2bcaf`）。

**再発条件**: 撤去を「層ごと」に分けるとき。**型を持つ層と、その型で wire を読み書きする層は、同じ課題で動かす**。

## 検査の穴（緑のまま壊れていたものは何か・なぜ緑だったか）

### 2. 変異検査が拾ったもの・変異の作り直し

  振り分け・配信先・在室判定のツール）。ブランチの変更で当たらなくなった m36 を作り直した（PR #310 の本文）
- PR 2: m87〜m95。**m94 / m95（Markdown の無限ループ）はテストの時間切れでは落ちない** —— JS のスレッドが返らないので `testTimeout` が

  96 件すべてが検出される（コミット `d415496`）。**m107（行区切りの正規化）は m94 / m95 と違い無限ループにならない** ——
  共有の解析で見出しの判定と段落の停止条件を同じ正規表現へ揃えたので、前進の保証はいま到達しない（保証だけを外す変異は等価変異）

**途中を赤で進めると決めたなら、どの課題で緑に戻すかを計画に書く**（この PR では書いてあった）。

## 実画面での確認（2026-09-25）

PR 3 の仕上げとして、`pnpm dev` の実経路（<http://localhost:5175/>）を Playwright で通した。
**利用者を 3 人（別々のブラウザ文脈）にした**: 1 人目がお題ツール（後から同じ文脈で timer のタブも開く）、2 人目が timer、3 人目が poker。

| 確かめたこと | 結果 |
|---|---|
| お題ツールで定型から作る → timer のロビーと poker にタイトルと本文 | 期待どおり。本文の見出し・箇条書き・コードは要素として描かれ、記法の字（`##`・`-`・`` ` ``）は残らない。poker は「説明を見る」を開くまで本文を出さない |
| 書き直す → 追従、下ろす → 消える | 期待どおり。timer・poker・お題ツールのどれにも「同期できていません」は出ない |
| お題を掲げたまま timer を開始 → セッション画面にお題 → 完成 | 期待どおり。両方の端末の完了画面に記録が出て、両方の端末の履歴にタイトルが 1 件ずつ残る |
| お題を下ろしてもう 1 本完成 | 履歴に「お題なし」。削除ボタンの名前は「（完了日時） に完了した「お題なし」の記録を削除」 |
| 押していない側の端末で見る中断 | 押していない端末も「セッション終了（中断）」を出し、どちらの履歴も増えない（旧実装の欠陥が消えたことの実画面での確認） |
| 完了画面で再読込 | 履歴の件数は変わらない（二重に保存しない）。見出しは「セッション完了」・記録の統計は出ない（受容の範囲） |
| timer の書体 | `document.fonts` で読み込んだ面はすべて `loaded`。`error` は 0 |

**見て分かり、最終レビューの修正で直したこと**: 定型バンクの本文の後半（「満たすこと:」「最初のテストの例:」「ヒント:」）は、timer-core の
旧い項目を PR 1 で本文 1 本へ畳んだときの形のままで、**テストの例がコードの囲みに入っていなかった**。記法の字が残るわけではないが、
段落として描かれるので字下げが消えていた。お題の内容の問題で、描画の欠陥ではない。PR 3 の最終レビューの修正で、33 件の
テストの例を変換スクリプトで機械的に囲みへ入れた（`packages/topic-core/src/topic-bank.ts`。検査は同パッケージの `tests/fallback.test.ts`）。
AI の生成の指示（`packages/topic-core/src/prompt.ts`）も、テストの例を囲みに入れるよう直した。
