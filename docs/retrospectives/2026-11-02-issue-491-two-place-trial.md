## 踏んだ罠

### 1. 敵対的レビューを通さずに終わりを報告した（手元）

- **事実**: 手元は、実装・単体・E2E・変異・実画面の確認まで済ませて終わりを報告した。敵対的レビューは「PR を作っていないので未実施」として、確かめられなかったことに書いた。
  後から壊して確かめると、`Hand.tsx` の問いを天気の固定文にしても、添え書きに `display: none` を付けても、`tests/hand.test.tsx` の 10 件はすべて通った
- **原因**: `AGENTS.md`「作業の終わりに」が求めるのは、検査を流すことと報告の書式だけである。敵対的レビューは手順書とスキルにあるが、
  **いつ行うかを決めた規則が無い**（`docs/adr/0030` 決定 5 は「行うなら別のエージェントで」だけを決める）。
  クラウドでは、#491 を担当したセッションがレビューを依頼したので通った。場所の差ではなく、誰かが頼んだかの差だった
- **再発条件**: 実装したエージェントが自分の検査だけで終わりを報告し、外から頼まれない限りレビューが行われないとき

### 2. 設計文書の「書き換えない」節を、両方の場所で書き換えた

- **事実**: 両方とも設計 `2026-10-28-checkin-checkout-design.md` の §5 に手を入れた。§12 の冒頭は「§1〜§11 は書き換えない（決定当時の記録）」としている。
  クラウドはレビューで指摘されて戻した。手元は書き換えたまま終えた
- **原因**: 決まりが §12 の冒頭にあって、§5 を読んでも目に入らない。#480 の「決めること」が「設計 §5 の見直し」と書いており、§5 を直すことが求められているように読める
- **再発条件**: 規範の文書の中に、その文書自体の直し方の決まりが離れた節に書かれていて、ISSUE が古い節の見直しを求めるとき

### 3. 測る幅が段の境目の手前を外した（両方）

- **事実**: 両方とも、最初は #480 の完了条件の 5 つの幅（320・390・768・1280・1920px）だけを測った。
  クラウドではレビューが 628〜639px で「持ち帰れなかっ／た」と割れるのを見つけた。手元は欄の幅を 8rem に固定したので、計算の上では割れない（112.3px < 128px）。ただし、その帯は測っていない
- **原因**: 字の大きさのトークンは画面の幅で連続して変わる（`--font-size-sm` は流体）。段の切り替え（40rem）の手前で、字が大きくなるのに箱はまだ狭い帯ができる。
  `live-check.md` の「よく測るもの」には段の境目の前後の比べ方が書いてあるが、完了条件の幅だけを測る進め方を止めるものではない
- **再発条件**: 流体の字の大きさと、段で切り替わる箱の幅の組み合わせを、完了条件に挙がった幅だけで確かめるとき

### 4. 後の側の AI が、もう片方の成果物に行き当たっても止まらなかった（手元）

- **事実**: 手元の AI は、変異の ID を選ぶとき（`45f18457` のコミットより前）に、クラウドのブランチと main に入った #502 を見た。
  そのまま実装を続け、PR を作る直前に「同じ機能がもうマージされている」と報告した。利用者は手元の版を消した
- **原因**: `AGENTS.md`「作業の始めに」は「同じブランチ・作業ツリーを別のエージェントが触っていないか」を確かめよとしているが、
  **同じ ISSUE を別の枝が先に片付けた場合**も、**作業の途中で気づいた場合**も書いていない。
  加えて、手元の AI は #491 を読んで試しだと知っていたので、重なりを「試しなので続けるもの」と受け取った（計画の「分かっている漏れ」が実際に起きた）
- **再発条件**: 同じ ISSUE を複数の場所・セッションで並行して扱い、途中で他方のマージに気づいたとき

### 5. 変異検査の全件が手元で終わらない・止めると変異が見える

- **事実**: 変異の宣言を足した枝では、`check:fast` の `mutation-check --changed` が全件（522 件）に倒れた。手元は 9p の上で 1 件 1〜2 分かかり、約 30 分で止めた。
  止めた直後は `apps/poker-web/src/hooks/useSync.ts` に変異 18 が当たったままに見えたが、`mutation-check` の親のプロセスを止めると、終了の処理で戻した（手で戻す必要は無かった）。
  #491 の準備（罠 9）では、**シェルだけを落とした**ため戻らず、変異とロックが次の起動まで残った。止め方によって結果が違う
- **原因**: `--changed` は宣言の表を触ると、機構の変更として全件に倒れる（`docs/guides/development.md`）。9p の遅さは依存の実体を逃がしても、変異検査の作業ツリーのコピーと vitest の起動には残る
- **再発条件**: 手元の 9p マウントで変異を足した枝の `check:fast` を流すとき

### 6. 高負荷で vitest のワーカーが起動せず、失敗に見えた（手元）

- **事実**: `check:fast` の単体で、`@tasuki/sync-client` が「Failed to start forks worker … Timeout waiting for worker to respond」で exit 1 になった。
  単独で流し直すと 51 件すべて成功した
- **原因**: vitest の forks のプールが、ワーカーの起動の応答を決まった時間だけ待つ。機械の負荷が高いと起動が間に合わず、
  そのファイルは**走らないまま**失敗として数えられる（テストの失敗ではない）。手元の作業記録で既に知られていた罠で、`docs/` には書かれていない
- **再発条件**: 変異検査や E2E と並んで単体を流し、機械の負荷が高いとき

### 7. クラウドで E2E と変異検査を流せる環境が揃わなかった

- **事実**: クラウドの実装役は Chromium 1248 を取れず（`cdn.playwright.dev` が 403）、Caddy も無く、手元で E2E を流せなかった。
  レビュー役は、依存を共有した `node_modules` の symlink を `mutation-check` が未追跡ファイルとして拒み、パッチを手で当てて代えた。
  Vite の配信の許可の範囲で書体が 403 になり、許可を足して測り直した
- **原因**: #487 の版の宣言と事前の確認は、合わないことを正しく止めた。しかし、揃える経路（ブラウザの取得・Caddy の導入）がクラウドのプロキシの内側で使えない
- **再発条件**: クラウドのセッションで E2E・変異検査を流すとき

### 8. 一時ファイルを作業ツリーに置き、ステージしかけた（手元）

- **事実**: 比較のモックアップ（`apps/checkin-web/mockup-480/`）と一時 spec（`e2e/specs/tmp-480-sweep.spec.ts`）を作業ツリーに置いた。
  `git add apps/checkin-web` でモックアップがステージされ、コミットの前に気づいて外した
- **原因**: 一時 spec は E2E のハーネスで動かすために作業ツリーの中に要る。`live-check.md` は測るスクリプトを外に置くよう書いているが、モックアップのページと一時 spec の置き場は決めていない
- **再発条件**: 実画面の比較のためにリポジトリの部品を読み込む一時ページを作り、ディレクトリ単位で `git add` するとき

### 9. 準備のセッション（PR #501）で踏んだもの

PR #501（#491 の準備）で、計画を書いたクラウドのセッションが観測した 5 件。PR の本文は正本ではないので、事実もここに写す。

- **Bun の版がクラウドのコンテナで合わない**: 環境は 1.4.4、`toolchain.json` は 1.4.3。`check-toolchain` は正しく止めたが、案内の `curl -fsSL https://bun.sh/install` がプロキシで 403。
  再発条件は、クラウドのコンテナの Bun が宣言（`toolchain.json`）と違うとき。`npm i bun@<版>` なら入った
- **clone の `origin/main` が古い**: クラウドの clone の `origin/main` が `73e4f91`（当時の main より約 10 コミット前）を指していた。`git fetch origin main` で直る。`--changed` と `check:fast` は基準の古さを見ないので、取り込み済みのコミットの変異まで選んで長く走った。
  再発条件は、クラウドの clone を fetch せずに `--changed` を流すとき
- **shellcheck がクラウドのコンテナに無い**: `check:fast` の quality が失敗になる。`check-toolchain` の宣言の外にある道具が無いとき
- **止めた変異検査が変異を当てたまま残った**: `tail` へのパイプの先で走る変異検査を、シェルを落として止めた。変異検査はしばらく走ってから途中で終わり、`apps/timer-web/index.html` の変異とロックを残した。次の起動で `mutation-check` が「異常終了していました」と検知して戻した。罠 5（親のプロセスを止めて、終了の処理で戻った）とは止め方が違う。再発条件は、変異検査を親のプロセスごとではなくシェルだけ落として止めるとき
- **検査をパイプの先に置いて失敗を見落とした**: `node scripts/audit-plan-gate.mjs | tail -1 && git commit …` で、計画のゲートの失敗（Constitution Check の節が無い）が `tail` の終了コードに隠れ、失敗した状態（`dbab427`）を push した。次のコミット（`890ab31`）で直した。
  再発条件は、`set -o pipefail` なしで検査をパイプにつなぐとき

## 検査の穴

### 1. 添え書きを見た目から消しても単体テストが通る

- **緑のまま壊れていたもの**: 手札の札の下の名前と意味が見えない状態（`display: none`・`hidden`・CSS で隠す）
