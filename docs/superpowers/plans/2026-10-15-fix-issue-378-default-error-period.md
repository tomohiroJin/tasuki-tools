# #378 既定のエラーの文言の句点がツールで違う 実装計画

**Goal:** コードの分からないエラーに出す既定の文言を、timer・poker・お題・ルーレットで同じにする。

**Architecture:** timer-core の `DEFAULT_ERROR_MESSAGE` から句点を外し、「操作を完了できませんでした」にそろえる。

## 前提の実測

- timer だけが「操作を完了できませんでした。」、ほかの 3 つ（`poker-core/src/error-messages.ts`・`topic-web/src/copy.ts`・`roulette-web/src/copy.ts`）は句点なし。E2E（`e2e/specs/notices-a11y.spec.ts`）も句点なしを前提にしている。
- 既定の文言を固定している画面のテスト・E2E は、timer には無かった（コメントだけ）。
- 4 つは 1 つの定数を共有できない。core は `@tasuki/*` に依存せず（`docs/adr/0017`）、#362 も文言を `packages/protocol` に置くことをスコープ外にした。topic・roulette の写しは web アプリの `copy.ts` にある。

## 決めること

- 句点 → **なしにそろえる。** ほかの 3 つ・E2E、および #362 で正本を 1 つにした接続層の文言（「コマンドの形式が不正です」など。poker・お題・ルーレットの画面では既定の文言と並んで出る）がすでに句点なし。変わるのは timer の画面と、ハブが `errorMessageFor` で既定の文言を引いて wire に載せる場合（玄関はそれをそのまま出す。例: `ROOM_LIMIT_EXCEEDED`）だけで、どちらも句点が 1 字減るだけ。timer の `ERROR_MESSAGES` の各文は句点付きのまま残るので、timer の中では既定の文言だけが句点なしになる。これは受け入れる（Issue の EARS は「どのツールでも同じ既定の文言」）。
- 置き場 → **1 か所にはしない。** 上の依存の制約による。代わりに、core の 2 つを `apps/tasuki-sync/test/default-error-text.test.ts`（両方の core を取り込める唯一の場所）が、web の 2 つをそれぞれの `tests/copy.test.ts` が同じ文で固定する。
- 書体の base 層: 文字を減らすだけなので、新しい字は増えない。
