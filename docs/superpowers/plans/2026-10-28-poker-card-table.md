# poker の隠しモード・トランプのポーカー（#403）実装計画

**Goal:** 「全員 ☕ → 開く → 再投票 → 全員 ☕ → 開く」で、入口を踏んだ投票者の全員に 5 枚を配り、1 回のチェンジのあと全員の手と役を一斉に開く。札は SVG で本物のトランプに寄せる。

**Architecture:** 入口の構えとゲームは poker の集約ルート `Round` に持ち、保管・配信・破棄の経路は見積もりと同じ 1 本を通す。入口の判定・配る・チェンジ・開くはドメイン（`packages/poker-core`）の純関数で、乱数は注入する。秘匿は既存の受信者別の投影（`snapshot.ts`）に乗せる。画面のテーブルと札の SVG は遅延読み込みの別の塊に置く。

**Spec:** [`docs/superpowers/specs/2026-10-28-poker-card-table-design.md`](../specs/2026-10-28-poker-card-table-design.md)（以下「設計」）。E-n・G-n・D-n は設計の項目番号。

**改訂**: 初版の計画（コナミコマンドと見出しの入口・チェンジなし・文字の札）は、利用者の確認（設計 §10）で作り直した。初版で入れたコードは、役の判定（`hand-rank.ts`）と札の型（`playing-card.ts`）を残して置き換える。

## タスク

### Task 1: ゲームの状態遷移（poker-core `card-game.ts`）

- テスト先行: 配る（G-1・G-2）、チェンジ（G-4・G-5・G-6）、全員済みで開く（G-7）、抜ける（G-8）、もう一度（G-9）
- 勝ち負けの比較（`compareHands`）を消す

### Task 2: 入口と見積もりとの関係（poker-core `round.ts`）

- テスト先行: 構えと解除（E-1〜E-5）、1 人のルーム、最中の見積もりの拒否（G-11）、見積もりに戻る（G-10）、退出（G-8）
- 開票・切断・退出のあとに通す 1 つの関数（自動公開 → 入口の判定 → 全員済みの判定）

### Task 3: 境界と投影（poker-core `protocol.ts`・`snapshot.ts`・`error-messages.ts`）

- テスト先行: 3 コマンドの受理と拒否、`table` の省略・受理、開く前の秘匿（G-3・G-12）、開いたあとの手と役

### Task 4: 同期サーバー（tasuki-sync）

- テスト先行（実プロトコル越し）: 入口で始まる（2 人・1 人）、手が本人にしか届かない、全員チェンジで開く、見積もりに戻る
- 開票・切断・退出の 3 つの経路で同じ関数を通す

### Task 5: 画面（poker-web）

- 初版の入口（コナミコマンド・見出し）を撤去
- テスト先行: テーブルの出し分け、チェンジの選択と送信、開いたあとの帯、札の SVG（各ランクのマークの数・絵札・角の文字・読み上げ）、文言の書体
- 札の SVG（`PlayingCardSvg.tsx`）・テーブル（`CardTable.tsx`）は遅延読み込み

### Task 6: E2E（`e2e/specs/poker-card-table.spec.ts`）

- 2 人: 入口 → チェンジ → 開く → 見積もりに戻る。1 人: 入口で始まる

### Task 7: 変異と文書

- 変異（入口の判定・秘匿・チェンジ 1 回・最中の見積もりの拒否・画面の出し分け）
- ws-protocol 契約・data-model・ADR-0011 の分類表
- `pnpm test`・検査系・`mutation-check --id`
