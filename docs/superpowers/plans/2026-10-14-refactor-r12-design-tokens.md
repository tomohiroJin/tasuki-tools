## 2. この Issue でやること・やらないこと

### やること

1. **押せる大きさのトークン `--tap-target: 2.75rem` をトークン層（`shape.css`）に足す。** `packages/ui/tests/tokens.test.mjs` で値を先に固定する。`2.75rem` の 9 か所を `var(--tap-target)` へ置き換える（`calc()` の中も）
2. **トークンと同じ単位・同じ値の直書きだけを置き換える**
   - 余白 158 件を `var(--space-*)` へ
   - 角丸 2 件（poker `10px` → `--card-radius`、timer `0.75rem` → `--radius-lg`）
3. **置き換えないもの**は、そのまま残す（判断 3）。件数と理由は PR とこの計画の台帳に書く
4. **検査の規則を足す**（`audit-ui-components.mjs`）: 画面の CSS の余白・角丸・押せる大きさの宣言で、**トークンと同じ単位・同じ値の直書き**を落とす。刻みに無い値と単位の違う値は対象外。外すときは既存の `/* ui-exempt: 理由 */`。直書きを 1 つ戻して赤を見る
5. **比べる**: 基準のコミット（着手時の main）と並べた比較で、差 0 件を確かめる（判断 1）
6. `packages/ui/README.md` にトークンと検査の規則を書く

### やらないこと

- 刻みに無い値を近いトークンへ丸めること（見た目が変わる。Issue のスコープ外）
- 単位の違う値（`px` ↔ `rem`）をトークンへ置き換えること（判断 3）
- timer の色の別名の層と `reset.css` に手を入れること（判断 4）
- 新しい色・新しい部品の追加

### 判断していただきたいこと

## 3. 振る舞いを保つ方法

- **値が同じものだけを置き換える**（単位も同じ）。置き換えの前に、トークンを局所で上書きしている所（`--space-*`・`--radius-*` を `:root` 以外で宣言している所）が無いことを確かめる（あれば、その範囲の置き換えは見た目が変わりうるので外す）
- **比べる**: 判断 1 の仕組みで、基準と並べて差 0 件
- 画面のテスト・`pnpm e2e`（CI）・`audit-ui-components.mjs`・`audit-timer-classes.mjs`・`packages/ui` のテスト

## 4. タスク

1. トークンの局所の上書きが無いことを確かめる（`grep`）。基準のコミットを決めて台帳（この計画の §6）に書く
2. `--tap-target` を足す（`tokens.test.mjs` を先に赤 → 緑）。`2.75rem` の 9 か所を置き換える
3. 余白 158 件を置き換える（timer はファイルごとにコミット。置き換えは機械で行い、置き換えた件数をファイルごとに数えて合わせる）。角丸 2 件
4. 単位の違う直書き（`8px` 1・`44px` 4）に `ui-exempt` を付ける
5. 検査の規則を足す（自己テストを先に。直書きを 1 つ戻して赤）
6. 比較の仕組みを戻し、利用者の手元で流してもらう手順を PR に書く（判断 1）。差 0 件を確かめてから消す
7. `packages/ui/README.md`・この計画の台帳と実施の記録

## 5. 変異の ID

**新しい ID は足さない。** CSS の値の置き換えに掛かる変異のパッチがあれば、ID と意味を変えずに当て直す。

## 6. 台帳（承認した差・例外）

- **基準のコミット**: `4adcf75`（#371 の PR #391 の先頭。#372 の作業はこの上に積んだ）
- **トークンの局所の上書き**: 無い（Task 1）。`--space-*`・`--radius-*`・`--card-radius`・`--tap-target` を宣言しているのは
  `packages/ui/src/tokens/shape.css` の `:root` だけ。TS / TSX からカスタムプロパティとして書いている所も無い（`grep`）
- **承認した差**: 無い
- **置き換えた件数**（レビュー後）: 押せる大きさ 12 宣言（幅・高さ 5・押せる範囲を広げる `inset` の `calc()` の中 7。§1 の「9 か所」は
  幅と高さを 1 か所に数え、`inset` を数え漏らしていた）・余白 157 件（timer 156・poker 1）・角丸 1 件（timer `invite-panel.css` の `0.75rem` → `--radius-lg`）・
  要素層 `reset.css` の余白 1 件・部品層 `button.css` の余白 1 件（`padding-inline: 1rem`）
- **残した直書き（理由）**
  - 負の余白 1 件（timer `session.css` の `margin-inline: -1.5rem`）: トークンに負の値は無い。`calc(-1 * var(--space-5))` に
    すると読みにくくなるだけで得が無い
  - 刻みに無い余白 49 件（timer 36・poker 13）: 近いトークンへ丸めると見た目が変わる（やらないこと）
  - 単位の違う直書き: 角丸の `8px` 1 件（poker）・押せる大きさの `44px` 4 件（roulette 3・timer `roster-panel.css` 1）。
    判断 3 のとおり置き換えない。**`ui-exempt` は付けていない**（Task 4 を取りやめた）。検査の規則は単位も同じ値だけを
    落とすので、この 5 件はそもそも違反にならず、`ui-exempt` を付けると「何も免除していない申告」として検査が落とす
  - 刻みに無い角丸: `6px` 2・`calc(infinity * 1px)` 7・`0` 2・`inherit` 1
  - poker の参加者の札（`.participants li`）の角丸 `10px`: 値は `--card-radius` と同じだが、`--card-radius` は
    トランプの札の形の役割の名前。参加者の札を寄せると、札の形を変えたときに一緒に変わる（`/code-review` の指摘で
    戻した。検査の尺度にも `--card-radius` を入れない）
  - timer の `base.css` の `clamp()` の上限 `2.75rem`: 字の大きさで、押せる大きさとは別物
- **記録だけにしたもの（判断 4）**: timer の色の別名の層（`base.css` の `:root` のカスタムプロパティ 44 個）・
  timer の `reset.css`（414 行）。方針は判断 4 の表のとおり

### 比べた結果

**ビルドした CSS を基準と並べ、トークンを値へ戻して突き合わせた。** 5 アプリ（timer・poker・topic・roulette・landing）
とも、差は `--tap-target` の宣言を除いた跡の空行 3 行だけで、ほかは文字単位で一致した。

1. 基準 `4adcf75` を別の作業ツリーに取り、両側で `vite build --minify false` する（圧縮すると宣言の並びと一括指定の
   畳み方が値の書き方で変わり、比べられない）
2. 両側の CSS の `var(--space-N)` などを、トークン層の値（`0.25rem` など）へ文字列で戻す。`--tap-target` の宣言と注釈を除く
3. `diff` する

この比べ方が言えるのは「**計算前の宣言が、トークンを値へ戻すと基準と同じ**」こと。トークンを局所で上書きしている所が
無いので（上）、計算後の値も同じになる。判断 1 で予定した `e2e/parity`（計算後の値と画素）は流していない（実施の記録）。
