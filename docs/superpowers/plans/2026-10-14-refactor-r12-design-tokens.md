**注意（単位）**: トークンは `rem` で、`px` の直書きを `rem` のトークンへ置き換えると、**利用者が既定の文字の大きさを変えたときに見た目が変わる**（16px の既定では同じに見える）。Issue の「8px で `--radius-md` と同じ」「44px と 2.75rem」は既定の文字の大きさでだけ成り立つ。

## 2. この Issue でやること・やらないこと

### やること

1. **押せる大きさのトークン `--tap-target: 2.75rem` をトークン層（`shape.css`）に足す。** `packages/ui/tests/tokens.test.mjs` で値を先に固定する。`2.75rem` の 9 か所を `var(--tap-target)` へ置き換える（`calc()` の中も）
2. **トークンと同じ単位・同じ値の直書きだけを置き換える**
   - 余白 158 件を `var(--space-*)` へ
   - 角丸 2 件（poker `10px` → `--card-radius`、timer `0.75rem` → `--radius-lg`）
3. **置き換えないもの**は、そのまま残す（判断 3）。件数と理由は PR とこの計画の台帳に書く
4. **検査の規則を足す**（`audit-ui-components.mjs`）: 画面の CSS の余白・角丸・押せる大きさの宣言で、**トークンと同じ単位・同じ値の直書き**を落とす。刻みに無い値と単位の違う値は対象外。外すときは既存の `/* ui-exempt: 理由 */`。直書きを 1 つ戻して赤を見る
5. **比べる**: 基準のコミット（着手時の main）と並べた比較で、差 0 件を確かめる（判断 1）
6. `packages/ui/README.md` にトークンと検査の規則を書く

### やらないこと

- 刻みに無い値を近いトークンへ丸めること（見た目が変わる。Issue のスコープ外）
- 単位の違う値（`px` ↔ `rem`）をトークンへ置き換えること（判断 3）
- timer の色の別名の層と `reset.css` に手を入れること（判断 4）
- 新しい色・新しい部品の追加

### 判断していただきたいこと

| # | 論点 | 推す案 | 理由 | 退ける案 |
|---|---|---|---|---|
| 1 | 比べる仕組み | **#321 の `e2e/parity` を戻し、基準（着手時の main）と並べて比べる。流すのは利用者の手元**（このクラウドの環境は Playwright の版が合わず流せない）。差 0 件を確かめてから、比較の仕組みは消す（#321 と同じ） | CSS の値を置き換えるので、これまでの Issue と違い「画面のテストと e2e で代える」が効かない。`e2e/parity` は計算後の値と画素を 5 つの幅で比べる、この用途の仕組み。#321 で 28 状態 × 5 幅の実績がある | 静的な論証だけで済ませる（`var()` が同じ値に解けることは言えるが、トークンを局所で上書きしている所があれば外れる）・CI で毎回流す（1 回約 28 分） |
| 2 | 比較を流す範囲 | **#321 と同じ timer の 26 状態に、poker・topic・roulette の主な画面を足す**（置き換えが 1 件以上ある画面） | 置き換えの 99% は timer。ほかのアプリは数件なので、その宣言が効く画面だけを足せば足りる | 全アプリ全画面を新しく目録にする |
| 3 | 単位の違う直書き（`8px` の角丸・`44px` の押せる大きさ） | **置き換えない**。`/* ui-exempt: px で書いている（rem のトークンにすると文字の大きさの設定で変わる） */` を付けて残す | Issue は「見た目は変えない」。既定の文字の大きさでは同じでも、設定を変えた利用者には違って見える | `rem` のトークンへ置き換える（文字の大きさを変えた利用者の見た目が変わる。変えるなら別の Issue で、利用者が承認したうえで） |
| 4 | timer の色の別名の層（44 個）と `reset.css`（414 行） | **件数と方針を記録するだけにする**（Issue の案）。方針は「別名は使う側を順に部品層の色へ置き換えたときに消える。`reset.css` は要素層へ寄せると見た目が変わる恐れが大きいので、別の Issue で比較の仕組みと一緒に扱う」 | 置き換えると見た目が変わる恐れが大きい。#316 の決定 D8 も timer の初期化は据え置いている | この Issue で手を入れる |

## 3. 振る舞いを保つ方法

- **値が同じものだけを置き換える**（単位も同じ）。置き換えの前に、トークンを局所で上書きしている所（`--space-*`・`--radius-*` を `:root` 以外で宣言している所）が無いことを確かめる（あれば、その範囲の置き換えは見た目が変わりうるので外す）
- **比べる**: 判断 1 の仕組みで、基準と並べて差 0 件
- 画面のテスト・`pnpm e2e`（CI）・`audit-ui-components.mjs`・`audit-timer-classes.mjs`・`packages/ui` のテスト

## 4. タスク

1. トークンの局所の上書きが無いことを確かめる（`grep`）。基準のコミットを決めて台帳（この計画の §6）に書く
2. `--tap-target` を足す（`tokens.test.mjs` を先に赤 → 緑）。`2.75rem` の 9 か所を置き換える
3. 余白 158 件を置き換える（timer はファイルごとにコミット。置き換えは機械で行い、置き換えた件数をファイルごとに数えて合わせる）。角丸 2 件
4. 単位の違う直書き（`8px` 1・`44px` 4）に `ui-exempt` を付ける
5. 検査の規則を足す（自己テストを先に。直書きを 1 つ戻して赤）
6. 比較の仕組みを戻し、利用者の手元で流してもらう手順を PR に書く（判断 1）。差 0 件を確かめてから消す
7. `packages/ui/README.md`・この計画の台帳と実施の記録

## 5. 変異の ID

**新しい ID は足さない。** CSS の値の置き換えに掛かる変異のパッチがあれば、ID と意味を変えずに当て直す。
