## Constitution Check

憲法（[`docs/constitution.md`](../../constitution.md) v2.1.4）のコンプライアンスゲート。設計正本の番号（K）で根拠を指す。

| 原則 | 判定 | 根拠 |
|---|---|---|
| I. テスト駆動開発 | 通過 | 全タスクが「先に書く赤いテスト」から始まる。残る人の分布は「1 回で決める」の抽選と同じ表で比べる（オラクルは今の `drawPicks`） |
| II. 技術選定は ADR を通す | 該当なし | 新しい依存・技術を足さない。決定は ADR 0026 への追記に留める |
| III. 揮発インメモリと単純運用 | 通過 | 回（`round`）はルームの揮発メモリに置き、再起動で消える（K4）。永続化しない |
| IV. 境界の型安全 | 通過 | 新しいコマンドは `v.strictObject`。フレームの新しい項目は省略可（非 strict）。残る人は wire に載せない（K3） |
| V. 実画面検証 | 通過 | モックで利用者の承認を得てから画面に入る。「1 回で決める」の舞台を前後で撮り比べる（K10） |
| VI. 依存は内向き | 通過 | `roulette-core` の依存は変えない |
| VII. 検査は壊して確かめる | 通過 | 変異 320〜339 を足し、1 本ずつ当てて赤を見る |
| VIII. 記録が正本 | 通過 | 決定は ADR 0026 の追記、設計と実測は設計正本、実装で外したことは設計正本へ戻す |
| IX. 小さく回す | 通過 | モック → PR（core ＋ 同期サーバー）→ PR（画面）。作業の枝が 1 本に決まっているときは同じ PR に積み、コミットで分ける |
| X. 抽象は実需で | 通過 | 2 つ目の遊び方が来たので、ここで初めて「決め方」の列挙を作る（multi-pick spec M1 が待っていた実需） |
| XI. 秘密と個人情報を持ち込まない | 通過 | 新しいログを足さない。名前をログへ出さない |

**逸脱なし。** Complexity Tracking での正当化を要する項目はない。

## 0. 取り決め

- **着手の前提**: spec §10 の Q1〜Q5 に利用者の答えがあること。推奨と違う答えなら、spec を直してからこの計画を直す
- **順番**: モック（コミットしない）→ 利用者の承認 → core ＋ 同期サーバー → 画面 → E2E ＋ 文書
- **「1 回で決める」の回帰を最優先で守る**（K10）: #94・#401 複数人決定のテストの期待値の値を変えない（足した項目の書き足しは可）。舞台を 320・768・1440 で前後比較し、画素まで一致することを確かめる
- 変異の ID は **320〜339**（#401 の「1 人ずつ抜く」に割り当てる。並行する枝とぶつからないよう、計画に先に書いておく）
- 文言は spec §2 の base 層の実測から取る。「減」「勝」は使わない
- コミットはタスクごと。閉鎖キーワードを書かない（#401 は目押しモードが残る）

## 2. タスク（core ＋ 同期サーバー）

### タスク 1 決め方の状態とコマンド
- **変えるファイル**: `packages/roulette-core/src/{types,roulette,schemas,errors,error-messages}.ts`
- **先に書く赤いテスト**: `mode` の既定が `once`・`setMode` が `once`/`knockout` 以外を拒む・回の途中は `ROULETTE_ROUND_IN_PROGRESS`（`setPickCount` も同じ）・スキーマが `roulette.mode.set` を strict で受ける

### タスク 2 回を始めて 1 人ずつ抜く（`startKnockoutSpin`）
- **先に書く赤いテスト**（`tests/knockout.test.ts`）:
  - 最初の押下で回が始まり、`wheel` が凍結され、残る人が `drawPicks(k)` と同じ結果になる（偽の乱数の全組の表・オラクルは今の `drawPicks`）
  - 抜ける人は残る人以外から引かれる（`randomInt` が常に 0 でも残る人は抜けない）
  - 残りが k 人になったら回が閉じ、`drawn` が「1 回で決める」と同じ形で更新される
  - 回の途中は `drawn` が変わらない
  - 回転中の押下は `ROULETTE_SPINNING`
- **変異**: 残る人を抜けうる候補に入れる・回を閉じても `drawn` を更新しない・回の途中で `drawn` を書く

### タスク 3 wire に残る人を出さない（`toView`）
- **先に書く赤いテスト**: 回の途中の `toView` に残る人の ID が**どの項目にも**現れない（JSON を文字列にして探す）・回が閉じた後は結果として出る
- **変異**: `toView` に `survivors` を載せる

### タスク 4 途中の入退室とやめる（`pruneRound`・`abortRound`）
- **先に書く赤いテスト**: 途中で入った人は回に入らない・残りの人が抜けたら回から外れる・残る人が抜けたら残りから一周の規則で引き直す・残りが k 人以下になったら回を閉じる・やめると `round` が消え `drawn` は変わらない
- **変異**: 残る人が抜けても引き直さない

### タスク 5 同期サーバー
- `roulette.spin` を `mode` で分ける・`roulette.mode.set`・`roulette.round.abort` の分岐・名簿の変化で `pruneRound`
- **先に書く赤いテスト**: 2 つの接続に同じ人が同じ順で抜ける・回の途中の全フレームに残る人が出ない（送ったフレームを文字列で探す）・ほかのツールから新しいコマンドを送ると拒まれる
