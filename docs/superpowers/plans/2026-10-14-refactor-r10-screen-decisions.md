## 2. この Issue でやること・やらないこと

### やること

1. **timer の `Session.tsx`**: 導出を `ui/session-view.ts` へ出す
   - 名前の組（いまのドライバー・次・ナビ）と、ナビの添字（**今の計算のまま**。#374 で直す）
   - 急ぎか（閾値 10 秒の定数ごと）・進み具合の割合
   - 輪の大きさ（PC 460 / 300、スマホは幅から `Math.min(340, Math.max(248, vw - 82))` と `224/340` の比）。**JS のまま出すだけ**（CSS へ移すのは #372）
   - 時計の導出（`elapsedMs`・`secondsLeft` を間隔で抑える）は既に timer-core の関数を呼ぶだけなので、抑える 1 行だけを出す
2. **timer の `RosterPanel.tsx`**
   - 代理の追加と改名の状態機械を、1 つの純粋な reducer（`ui/name-request.ts`）にする。状態は「送った名前（正規形）」と「拒んだ理由（打った文字・正規形・通し番号）」、動きは「送る・名簿に現れた・やめる」。名簿に現れたかと、理由がまだ生きているかの判定（`conflictsWithExisting` を呼ぶ）も同じモジュールの純粋関数にする。**reducer を 2 つの `useReducer` で使う**（代理・改名）
   - ドライバーと見学の振り分けと、巡回順の並べ替えを `ui/roster-order.ts` へ出す（Issue のスコープ外の注記どおり、並べ方は変えない）
   - `MiniButton` は描画の部品なので純粋判断ではないが、ファイルを分ける（`components/MiniButton.tsx`）。中身は変えない
3. **poker の `RoomPage.tsx`**: 残った 3 つの判断を `src/room-view.ts` へ出す（`router.ts`・`connection-notice.ts` と同じ純粋判断の層）
4. **topic の `CurrentTopic.tsx`**: `filled`・`draftBlank` の判定と、書きかけの有無が変わったときに選ぶタブを `topic-view.ts` へ寄せる。描画中に前の値と比べて状態を直す React の型（`wasFilled`）は画面に残す（判断だけを出す）
5. PR に、大きくなった画面の行数を前後で書く

### やらないこと

- ナビの計算を直すこと（#374）
- 輪の大きさを CSS へ移すこと（#372）
- 名簿の並べ方を変えること（サーバーと食い違わないと 2026-10-13 に確かめてある。出すだけ）
- マークアップ・CSS・文言に触ること

### 判断していただきたいこと

|---|---|---|---|---|

## 3. 振る舞いを保つ方法

- **画面のテストを期待値を変えずに通す。** 足りないところは Task 1 で先に足す
- **純粋関数のテストは、移す前の式をそのまま表に写す**（境界の値: 残り 10 秒と 11 秒・輪の幅 248 / 340 の境・輪が 1 人・ナビが無効・次が null）
- **変異**: m55〜m59 を ID と意味を変えずに当て直し、1 本ずつ当てて `RosterPanel.duplicate-proxy.test.tsx` が赤になることを確かめる。最後に `node scripts/mutation-check.mjs` で全件を確かめる（**走らせている間は作業ツリーに触らない**）
- **実経路**: `pnpm e2e`（CI）
