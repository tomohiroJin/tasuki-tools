# #405 poker で見積もりが割れたら、最大と最小を出した人に話してもらうよう促す 実装計画

**Goal:** 開票後、数値の札の最大と最小がデッキの並びで 2 段以上離れていたら、結果の節に最大と最小を出した人の名前と札を示し「どう見たかを話してもらいませんか」と誘う 1 行を出す。

**Tech Stack:** TypeScript（`packages/poker-core`・`apps/poker-web`・vitest）

## 前提の実測（2026-10-15 / main `f043c07`）

- 開票後の集計は平均と最頻値だけ（`packages/poker-core/src/stats.ts` の `computeStats`）。同期サーバーが `snapshot.ts` で計算し、wire の `round.stats` で届ける。
- 開票後は全員の票が `participantId` つきで届く（`round.votes`）。表示名は `snapshot.participants` から引ける。
- 結果の節（`apps/poker-web/src/components/Results.tsx`）は集計だけを持ち、席の札がめくれ終わってから現れる（#348 D5）。

## 決めたこと

1. **判定は画面で、受け取った票から計算する。** wire（`RoundStats`）と同期サーバーは変えない。判定そのものは純粋関数として `poker-core` に置き、web が呼ぶ（原則 VI）。`stats` を広げる道は、wire の前方互換（`docs/poker/adr/0004`）と同期サーバーまで巻き込むわりに得るものが無いので取らない。
2. **「割れた」の定義。** 数値の札の最大と最小が、デッキの並び（`0 1 2 3 5 8 13 21`）で **2 段以上** 離れていること（2026-10-15 にオーナーと合意。閾値は定数 `SPREAD_MIN_STEPS`）。`?` と `☕` は判定に入れない。数値の票が 2 票未満なら割れていない。比（最大 ÷ 最小）は 0 の札で壊れるので使わない。
3. **最大・最小が複数人いるとき**は全員の名前を出す。ルーレットとの連携はしない（スコープ外）。
4. **名指しの圧への配慮。** 文言は「理由を説明してください」ではなく「どう見たかを話してもらいませんか」という誘いにする。警告の色は使わず、集計と同じ調子の 1 行にする。文言は書体の base 層に収める（テストで確かめる。最初の案の「札」「小」「考」「聞」は base 層に無く、テストが赤になったので言い換えた）。

   > 見積もりが割れました。いちばん上の 8 を出した あお・しろ と、いちばん下の 2 を出した きい に、どう見たかを話してもらいませんか。
5. **出す時機。** 集計と同じ（めくれる公開では最後の札がめくれた後。最初から公開済みなら待たない）。
6. **#92（T シャツサイズ）は考えない。** 判定は数値の札だけを見る。

## 実画面検証で見つけたこと（Task 4）

- E2E の基盤（実ビルド・Caddy・同期サーバー）で 3 人のルームを立て、8・2・8 と 5・8・5 を出して、幅 1280 と 375 の画面を撮って見た。割れたときだけ集計の下に 1 行出て、割れないときは出ない。
- **幅 375 で名前が途中で折れた**（「き／い」「あお・／しろ」）。名前を 1 人ずつ `inline-block` の塊にして直した（テスト U10）。折れるのは区切りの「・」の位置だけになった。1 行に収まらない長い名前だけは、塊の中で折る。
- `prefers-reduced-motion` では、促しの行が待たずに出る（不透明度 1）。
- 回帰として `e2e/specs/poker.spec.ts` に、2 人が 8 と 2 を出して両方の画面に促しが出るシナリオを 1 つ足した（タグなし・`local` 専用）。
- この実行環境の Chromium は 1194 版で、`@playwright/test` が求める 1248 版と合わない。検証のときは作業用のディレクトリから 1194 版を 1248 版の名前で指して流した（リポジトリは変えていない）。
