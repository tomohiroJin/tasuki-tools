# #375 ルームのコードがぶつかり続けたときに既にあるルームを上書きしうる 実装計画

**Goal:** ルームのコードを引き直しの上限まで引いても空いたコードが得られなかったとき、既にあるルームを上書きせず、作成者へ失敗を返す。poker の無限の引き直しも同じ方針（上限と失敗）にそろえる。

**Architecture:** `apps/tasuki-sync/src/application/create-room.ts` に `pickFreeCode`（上限 `MAX_CODE_ATTEMPTS = 6` 回・最初の 1 回を含む）を置き、空かなければ `err("ROOM_LIMIT_EXCEEDED")`。poker の `generateRoomId`（`poker-handlers.ts`）も同じ定数で打ち切り、`undefined` なら `server-busy` で断る。

## 前提の実測

- 引き直しは「最初の 1 回 ＋ 5 回」。6 回とも使用中なら、最後のコードのまま名簿を組み立て、呼び出し側（timer の `commit`・ハブの `saveRoster`）が既にあるルームを上書きしていた（`test/create-room.test.ts`・`test/handlers.room.test.ts` の赤で再現）。
- 起こりやすさ: 接尾辞は 8 桁（32 種＝約 1.1×10^12）、ランダムのコードは 6 桁（31 種＝約 8.9×10^8）。ルーム数の上限（`maxRooms`）の下では 1 回ぶつかることさえまず起きない。ルーム名つきでも、候補の幅は接尾辞が決めるので狭くならない（slug は同名のルームどうしを同じ名前空間に置くだけ）。上限は「codeGen の故障など、起きないはずのことが起きたときに止まる」ためのもの。
- poker の `for (;;)` は、候補が尽きると止まらなかった（変更前のコードで新しいテストを流すと終わらないことを確かめた）。

## 決めること

- エラーコード → **既存の `ROOM_LIMIT_EXCEEDED` を流用する。** 「いまはルームを作れない」という同じ答えで、画面（timer・玄関）は既定の文言を出す（`ROOM_LIMIT_EXCEEDED` は timer の文言の表 `ERROR_MESSAGES` に無く、`error-code-coverage.test.ts` の `INTENTIONALLY_NOT_SHOWN`）。新しいコードを足すと、語彙・文言・網羅テストの更新が要るのに、利用者に見えるものは変わらない。
- poker → **そろえる。** 上限は timer・ハブと同じ `MAX_CODE_ATTEMPTS`、失敗はルーム数の上限と同じ `server-busy`。空いた ID は**切り離しより先に**引く（ルーム数の上限と同じ理由: 拒否で元のルームから追い出さない）。
