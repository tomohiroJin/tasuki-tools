## 3. 振る舞いを保つ方法

**「変更前と同じ」は次の 4 つで見る。**

1. **表の中身**: 移す前と後で `MUTATIONS` を読み込み、`JSON.stringify` が文字単位で同じことを見る（一回きりの確かめ。コミットしない）
2. **全件の出力**: 基準（着手時の `origin/main`）と移した後で `node scripts/mutation-check.mjs` を全件流し、結果の表（ID・ラベル・対象・判定の各行と件数）が同じことを見る。所要時間の行は比べない
3. **選び方**: `--changed` の表題（全件に倒すか・選んだ件数）が、宣言だけを書き足した枝で基準と同じく「機構が変わった」で全件に倒れること（判断 2）。表のファイルが機構の一覧に入ることは Task 1 の自己テストが見る
4. **汚れの検査**: 表のファイルに未コミットの変更がある状態で `--id 1` が拒まれないこと（基準で `mutation-check.mjs` の表に未コミットの変更があるときと同じ）

## 4. タスク

1. **特性テストを先に足す**（`scripts/mutation-check.test.mjs`）
   - ID が正の整数で、重複しない
   - 入口の import 文から導いた機構の一覧（`mechanismFilesFrom`）に、表の置き場が入る（移す前は赤。移した後に緑）
   - 汚れの検査の除外の定数に、表の置き場とパッチの置き場が入る（定数を出すのは入口の変更。除外の中身は移す前と同じなので、移す前は表の置き場の項目だけが赤）
   - 足したテストの赤を確かめる（ID を 1 つ二重にする・除外から 1 つ外す）
2. **基準を取る**: 着手時の `origin/main` で `MUTATIONS` の JSON と全件の結果の表を手元に書き出す（コミットしない）
3. **移す**: 表の注釈と表を、行の範囲で機械的に切り出して新しいファイルへ移す（手で写さない）。入口に import を足し、汚れの検査の除外に新しい置き場を足す。入口と自己テストの取り込みを直す。Task 1 のテストが緑になること
4. **比べる**: §3 の 1〜4
5. **壊して確かめる**（憲法 VII・Issue の完了条件）。**変異検査を流している間は作業ツリーを触らない**
   - 表を空にする（`export const MUTATIONS = [];`）→ 「変異が 0 件です」で止まる
   - 宣言を 1 件消す → 全単射のずれ（パッチが余る）で止まる
   - 汚れの検査の除外から表の置き場を外し、表に未コミットの変更を作る → 実行が拒まれる
   - それぞれ戻して緑
6. **文書**: 手引き（判断 2 の書き直し・宣言の置き場・汚れの検査の除外）、入口の注釈、この計画の実施の記録
7. 全検査（lint・`pnpm test`・監査・スクリプトの自己テスト）・変異検査（全件）・`/code-review`・`/security-review`
