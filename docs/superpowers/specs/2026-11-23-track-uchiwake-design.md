## 1. 何のための道具か

モブ・ペア・勉強会の最中に、**ルームの全員が同じ画面で「いまやっていること」を切り替え**、区切りごとの時間を積み上げる。
終わりに、作業名ごとの合計・割合と時系列を Markdown でコピーして持ち帰る。

- 持ち帰った先は、日報・ふりかえり・各自の工数の道具である。この道具は長く蓄積しない。その前段に徹する（調査 3 §6）
- 誰が押したかを残さない。「誰が何に何時間」を集める道具にしない（原則 XI・調査 1 §7.3）
- 必要な回だけ開いて使い捨てる。毎日続けることを前提にしない（調査 3 §4）

名前は **「うちわけ」**、公開パスは **`/track/`**、接続の種類は **`?tool=track`**（利用者・2026-11-23）。

## 2. 目標・対象外・失敗の形

**目標**

- 切り替えは 1 回の操作で済む。名前を付けずに始められ、後から付けられる
- 止め忘れ・切り替え忘れを、その場でも後からでも直せる
- 全員に同じ内訳が見える。合計は丸める前の値から計算する
- 終わりに Markdown を 1 回コピーすれば、そのまま貼れる

**対象外（この PR では作らない。利用者・2026-11-23）**

- 端末への保存（FR-13）・CSV（FR-14）・戻ってきたときの問いかけ（FR-27）・通知・映す画面と操作する画面の分離・割合のグラフ・ミニ表示
- 予定と実績の比較（agenda の範囲。#676）・ポモドーロ（timer の範囲）
- 同時に並行する区切り・プロジェクトやタグの階層・点数や目標・共有リンク

> 改定: 対象外の 1 行目の項目は第 2 段で作る（2026-11-26・#476）。`2026-11-26-track-phase2-design.md` の §1

**失敗の形（動いていても失敗とみなす）**

- 誰が切り替えたかが、フレーム・状態・ログのどこかから分かる
- 合計と内訳が食い違う（丸めた値を足している・休憩が割合に混ざる・手直しの後で区切りが重なる）
- 裏のタブ・再読み込み・再接続の後で、経過が実際の時間とずれる
- 作業名や記録の中身がサーバーのログに出る

### 4.1 時刻の持ち方

- **時刻軸**: そのルームのうちわけの状態を最初に置いた時点（最初に誰かがこの道具を開いた時点）を 0 とする ms の整数。サーバーの**単調時計**で測る（`docs/adr/0027` 決定 2 と同じ理由）。基準は記録が空でも持ち、「記録を消す」でも変えない（空の記録にも「抜けを足す」を使える）。後からの追加で、負の値も取りうる
- **壁時計は表示のためだけに 1 つ持つ**: 時刻軸の 0 に当たる壁時計の時刻（`epochWallMs`）。画面と Markdown の「HH:MM」は `epochWallMs + 位置` を端末の時間帯で表す。間隔の計算には使わない
- **画面へは「送る時点の時刻軸の位置」（`nowMs`）を配る**（`docs/adr/0027` 決定 3 の形）。画面は受け取ってからの経過を足して描く。単調時計の値そのものは載せない
- 経過は開始位置との差で求め、刻みの加算では求めない。表に戻ったら `track.sync` で取り直す（agenda と同じ）

### 4.2 状態

```ts
type SegmentKind = "work" | "break";

interface Segment {
  readonly id: string;            // "g-1", "g-2", …（作った順の通し番号）
  readonly kind: SegmentKind;
  readonly label: string;         // 正規化済み。"" は名前なし。休憩はいつも ""
  readonly startMs: number;       // 時刻軸の位置
  readonly endMs: number | null;  // null = 計測中（最後の 1 つだけ）
  readonly autoClosed: boolean;   // 全員の切断で閉じた印
}

interface TrackState {
  readonly epochMono: number;          // 単調時計。時刻軸の 0（状態を最初に置いた時点）
  readonly epochWallMs: number;        // 同じ時点の壁時計
  readonly segments: readonly Segment[]; // 開始の昇順・重ならない
  readonly nextSeq: number;
  readonly pinned: readonly string[];  // 定番
  readonly rev: number;                // 状態が変わるたびに +1（取り消しも +1。期限切れでは進めない）
  readonly undo: UndoSlot | null;      // 直前の 1 操作ぶんの写し・その操作の rev・期限
  readonly resumeOffer: boolean;       // 全員の切断で閉じた後、再開を尋ねている
}
```

**不変条件**（性質テストで固定する）

1. 区切りは開始の昇順で、重ならない（前の終わり ≤ 次の始まり）
2. 計測中（`endMs === null`）の区切りは、あっても最後の 1 つだけ
3. どの区切りも長さが `MIN_SEGMENT_MS` 以上（計測中は除く）
4. 作業の合計 ＋ 休憩の合計 ＝ 区切りの長さの総和（隙間は数えない）
5. 区切りは `MAX_SEGMENTS` 件以下、定番は `MAX_PINNED` 件以下

区切りの間の**隙間**は「止めていた時間」で、どの合計にも入らない。

### 4.3 操作（コマンド）

コマンドは track の接続のスキーマにだけ置き、`v.strictObject` で余剰の項目を拒む（`docs/adr/0027` 決定 8 と同じ）。
**状態が変わらないときは同じ参照を返し**、サーバーは送り主にだけいまの状態を返す。

| コマンド | 振る舞い |
|---|---|
| `track.start { label, kind, backMin? }` | 開始と切り替えを兼ねる。計測中の区切りがあれば `t = いま − backMin` で閉じ、同じ `t` から新しい区切りを始める。計測中の区切りと種類・作業名が同じなら（`backMin` があっても）何もしない。休憩の `label` は受けても空にして持つ |
| `track.stop { backMin? }` | 計測中の区切りを `t` で閉じる。計測していなければ何もしない |
| `track.undo { rev }` | `rev` が取り消せる操作の番号と一致し、期限の内なら、その操作の直前の状態へ戻す。それ以外は何もしない |
| `track.segment.set { id, label, kind }` | 名前と種類（作業／休憩）を付け替える。計測中の区切りにも使える |
| `track.segment.adjust { id, edge, atMs }` | 区切りの始まりか終わりを `atMs` へ動かす。隣の区切りと接していれば、境界ごと動かす（隣も同じだけ伸び縮みする） |
| `track.segment.split { id, atMs, label, kind }` | 区切りを `atMs` で 2 つに分け、後半に名前と種類を付ける |
| `track.segment.insert { startMs, endMs, label, kind }` | その範囲を新しい区切りで**上書きする**。重なった区切りは削る・分ける・消す |
| `track.segment.remove { id }` | 閉じた区切りを消す（その時間は隙間になる） |
| `track.pin { label, pinned }` | 定番に固定する／外す |
| `track.offer.dismiss` | 再開の問いかけを下ろす |
| `track.clear` | 記録（区切りの列）を消す。定番は残す |
| `track.sync` | いまの状態を送り主へ返す |

**さかのぼり**（`backMin`）は `BACK_MINUTES` のどれか。`t` が計測中の区切りの始まり以前、または直前の区切りの終わりより前になるときは拒む（`TRACK_BACKDATE_TOO_FAR`）。

**短すぎる区切りは残さない**（候補の連打で普通に起きる）

- 閉じる時点で長さが `MIN_SEGMENT_MS` に満たない区切りは、捨てる。切り替えなら、新しい区切りが捨てた区切りの始まりを引き継ぐ（押し直しは「付け替え」になる）。停止・全員の切断なら、その区切りは無かったことになる

**手直しの制約**

- 位置は「いま」より先へ置けない。「いま」から `MAX_LOOKBACK_MS` より前へも置けない
- **調整**（adjust）: 「接している」は、前の終わりと次の始まりが同じ位置のこと。接している境界は隣ごと動く。隙間をはさんだ隣へ食い込む移動、どれかの区切りが `MIN_SEGMENT_MS` を下回る移動、順が入れ替わる移動は拒む（`TRACK_INVALID_RANGE`）。画面は動かせる範囲（core の純粋関数で求める）に ± のボタンを収め、隙間を使い切った所で止める。接している境界から隙間を作る操作は置かない（消すか、上書きで足りる）
- 計測中の区切りの終わりは動かせない（止めるか、さかのぼって切り替える）
- **分割**（split）: 前半・後半のどちらかが `MIN_SEGMENT_MS` を下回る位置は拒む。計測中の区切りも分けられ、後半が計測中になる
- **上書き**（insert）: 重なった区切りを削る・分ける・消す。削った残りが `MIN_SEGMENT_MS` に満たないときは、その端切れを新しい区切りへ含める（分単位で入れた時刻と ms の境界のずれで、端切れを残さない）。計測中の区切りの中にも置け、そのとき後ろの残りが計測中のまま続く
- 操作の結果が `MAX_SEGMENTS` を超えるときは拒む（`TRACK_FULL`）
- `autoClosed` の印は、その区切りの終わりが動いたら（調整・上書き）外す。分割では後半が引き継ぐ

**取り消し**（FR-21）

- 取り消せるのは、時間を動かす操作（`track.start`・`track.stop`）と `track.clear`（書き手の判断 J2）
- その操作の直前の区切りの列と問いかけを 1 つ写しておく。期限は `UNDO_WINDOW_MS`、単調時計で測る。区切りの番号（次に振る番号）は写さず、取り消しても戻さない（番号を使い回すと、古い画面の手直しが別の区切りに当たる）
- 写しは、その操作に振った `rev` を持つ。`track.undo { rev }` はこの番号と照らす（状態の `rev` とは別に持つ）
- ほかの操作で状態が変わったら、写しを捨てる（「直前の 1 操作」だけ）。全員の切断による自動の停止でも捨てる。定番の操作（`track.pin`）だけは写しを捨てず、取り消しても定番は戻らない（写しに定番を含めない）
- 期限の予約は持たない。配るときに残り時間を計って載せ、画面が残りを数えて下ろす
- 切り替えを取り消すと、前の区切りは**閉じなかったものとして**計測中へ戻る（時刻軸で持つので、時間は途切れない）

**全員が切断したとき**（FR-24）

- 「全員」は**名簿の全員が不在**（どの道具・玄関にも接続が無い）で数える。アイドルの回収（`room-reclaimer.ts`）と同じ数え方にする。track の画面だけを閉じて timer を見続けている間は、計り続ける
- 名簿が配られるたびに（組み立ての `onRosterBroadcast` の口）数え直す。全員が不在になったら、その時刻を覚えて猶予（`TRACK_AUTO_STOP_GRACE_MS`・単調時計）を待つ。猶予の内に誰かが戻れば何もしない（再読み込み・瞬断で閉じない。`docs/adr/0028` 決定 11 と同じ考え方）
- 猶予の後も不在のままなら、計測中の区切りを**覚えた時刻**で閉じ、`autoClosed` の印と `resumeOffer` を立てる
- 戻った人の画面に問いかけを出す。帯に出す名前と時刻は、最後の区切り（印の付いた区切り）から引く。「再開する」は、その区切りと同じ名前・種類の `track.start` を送り、新しい区切りをいまから始める（離れていた間は隙間になる）。「このまま」は `track.offer.dismiss` で問いかけを下ろす。どちらも全員に効く
- `resumeOffer` は、定番の操作を除く、状態を変えるどの操作でも下りる（対象の区切りが消えた後に問いかけを残さない）
- 猶予の予約は、ルームの破棄とサーバーの停止で必ず消す（破棄の束の必須の依存にする）

> 改定: `track.stop` に任意の `atMs` を足し、`track.away` を足して取り消しの対象に入れた（2026-11-26・#476）。`2026-11-26-track-phase2-design.md` の §4 C3〜C5

### 4.4 写し（フレーム）

全員に同じ写しを配る（受け手ごとの出し分けは無い）。

```ts
interface TrackView {
  epochWallMs: number;
  nowMs: number;                 // 送る時点の時刻軸の位置
  segments: SegmentView[];       // Segment と同じ項目
  pinned: string[];
  rev: number;
  undo: { rev: number; kind: "start" | "stop" | "clear"; remainingMs: number } | null;
  resumeOffer: boolean;
}
```

受けるフレームのスキーマは非 strict にし、足す項目は任意にする（`docs/guides/architecture.md`「wire に足す項目は、任意にする」）。

> 改定: `undo.kind` に `"away"` を足した（2026-11-26・#476）。`2026-11-26-track-phase2-design.md` の §4 C4・C5b

### 4.5 集計・候補・Markdown（純粋関数）

- **集計** `totalsOf(view, nowMs)`: 作業名ごとの合計（降順）・作業の合計・休憩の合計・全体。割合は作業の合計を分母にし、休憩を含めない。名前なしは 1 行にまとめる
- **作業名の正規化**: 受け取った時点で NFKC ＋前後の空白の除去を掛け、その結果を保管する。同じ名前かどうかは保管した文字列の一致で決める。制御文字は拒む（agenda の `hasControlChars` と同じ規則）
- **候補** `candidatesOf(view, topicTitle)`: お題のタイトル → 定番 → 最近使った作業名（新しい順）を、重複を除いて `MAX_CANDIDATES` 件まで。全員が同じ写しとお題を持つので、数字キーの対応は全員で同じになる。お題のタイトルは作業名と同じ正規化を掛け、`MAX_LABEL` を超える分は切り詰める（お題の上限のほうが長い）。制御文字を含む・空になるタイトルは候補にしない。重複は切り詰めた後の文字列で見る
- **Markdown** `toMarkdown(view, nowMs, tzOffsetMin)`（FR-25）:
  1. 見出し（日付と時間帯）
  2. 表: 作業名・合計（h:mm）・割合（整数の %）。合計の降順。最後に作業の合計・休憩・全体
  3. 時系列の一覧: 「HH:MM–HH:MM 作業名」。日付をまたぐ区切りには日付を添える。全員の切断で閉じた区切りには印を添える
  - h:mm は 1 分未満を切り捨てる。割合は丸める前の値から計算する。丸めのため、行の和が合計と 1 分・1% ずれうることを表の下に 1 行で注記する
  - 作業名の `|` と Markdown の記号は逃がす（timer のまとめ〈#408〉・poker の記録〈#645〉の作法に合わせる）

> 改定: 作業名の正規化で見えない字を落とし、候補から計測中と同じ作業名を外した（2026-11-26・#476）。`2026-11-26-track-phase2-design.md` の §2 A1・A3

### 4.6 上限と既定値

値の正本は `packages/track-core/src/limits.ts` とする。文書へ数を写すのはこの表だけにする。

| 定数 | 値 | 根拠 |
|---|---|---|
| `MAX_LABEL` | 80 | 利用者の決め 11 |
| `MAX_SEGMENTS` | 200 | 同上（5 分ごとに切り替えて 16 時間分） |
| `MAX_PINNED`・`MAX_CANDIDATES` | 9 | 数字キー 1〜9 |
| `BACK_MINUTES` | 1・5・10・15 | 利用者の決め 11 |
| `UNDO_WINDOW_MS` | 10 秒 | 利用者の決め 7 |
| `LONG_RUNNING_NOTICE_MS` | 90 分 | 利用者の決め 11 |
| `MIN_SEGMENT_MS` | 1 秒 | 書き手の判断 J5（長さ 0 の区切りを作らない） |
| `MAX_LOOKBACK_MS` | 24 時間 | 書き手の判断 J5 |
| `TRACK_AUTO_STOP_GRACE_MS`（サーバーの設定） | 60 秒 | 書き手の判断 J4 |

## 5. 画面

器は `.ui-page--wide`。広い幅では 2 段（左: いま・切り替え／右: うちわけ・時系列）、狭い幅では上から順に並べる（`packages/ui/README.md`「画面を組む」）。

```text
┌ うちわけ ─────────────────────── ← 玄関へ ・ 招待 ┐
│ [全員が離れたので「実装」を 11:02 で止めました  再開する / このまま ] │ ← 問いかけ（あるときだけ）
│ [「実装」が 90 分続いています。切り替え忘れではありませんか         ] │ ← 知らせ（あるときだけ）
├──────────────────────────┬─────────────────────────┤
│ いまやっていること             │ ここまでのうちわけ                 │
│   実装                         │ ▇▇▇▇▇▇▇▇▇▇▇▇▇▁▁▁▁▁▁▁▁▁▁░░░░ │ ← 割合の帯（色だけに頼らない）
│   0:42:15                      │ 実装        1:12:40   58%         │
│   [止める] [休憩にする]         │ 調べもの    0:31:05   25%         │
│   [切り替えを取り消す  残り 7 秒] │ （名前なし） 0:21:10   17%         │
│                                │ 作業の合計  2:04:55               │
│ 切り替える                      │ 休憩        0:15:00               │
│   [作業名を入力        ] [切り替える] │                              │
│   いまから ▾（1・5・10・15 分前） │ 時系列                [抜けを足す] │
│   1 お題: FizzBuzz   ☆         │ 10:00–10:31 調べもの      [直す]   │
│   2 実装             ★         │ 10:31–10:46 休憩          [直す]   │
│   3 調べもの          ☆         │ 10:46–      実装（計測中） [直す]   │
│   …9 まで                      │                                    │
│                                │ [Markdown でコピー] [記録を消す]     │
└──────────────────────────┴─────────────────────────┘
この記録はルームの全員に見えます。ルームを閉じると消えます。
```

- **始まる前**: 「開始」を大きく 1 つ。入力欄は空でよい。説明は 1 行（切り替えるたびに押す・終わったら Markdown で持ち帰る・ルームを閉じると消える）
- **候補**: 番号つきのボタン。押すとその名前へ切り替える。星で定番に固定・解除する
- **「直す」**: その行を開いて、名前・種類（作業／休憩）・始まりと終わり（時刻の入力と ±1 分・±5 分）・「ここで分ける」・「消す」を出す。名前なしと、全員の切断で閉じた区切りは目立たせる
- **「抜けを足す」**: 作業名・種類と、時間の指定（「始まりと終わり」か「始まりと長さ」）
- **「記録を消す」**: 押す前に確かめる。消した後も 10 秒は取り消せる
- **キーボード**（FR-26）: 入力欄にフォーカスが無いとき、1〜9 で候補へ切り替え・S で止める・C で直前の作業名を再開する。IME の変換中のキーは拾わない（PR #627 と同じ）
- **タブタイトル**（FR-22）: 計測中は「作業名 h:mm｜うちわけ」。1 分ごとに変える。止まっているときは元の題
- **読み上げ**: 経過を毎秒読ませない。`aria-live` は切り替え・停止・知らせだけに使う
- **文言**: 書体の base 層に収める（各アプリの `copy-fits-font-base` の試験と同じ守り）。利用者が入れた作業名はこの限りでない
- 接続の告知・入室の門・招待は共通の部品を使う（`@tasuki/web-kit/room`・`@tasuki/invite-ui`）

**玄関の札**（書き手の判断 J7）: 7 枚目。左上の一語「内訳」・名前「Uchiwake」・説明「何に何分使ったかを記録する」・意匠は積み上げた帯。並びの末尾に置く。

## 6. データの分類と守り（原則 XI・`docs/adr/0011`）

- **作業名は「個人に紐づく」に置く**（agenda のステップ名と同じ。人の名前や案件名が入りうる）。揮発のみ・ログへ出さない・配信はする
- 区切りの時刻と長さは作業名と組になるので、同じ扱いにする
- **誰が操作したかは、状態にもフレームにもログにも載せない。** ハンドラはログを書かない。接続の ID は在席の確認にだけ使い、状態へ渡さない
- 定番の作業名も同じ分類。ルームの破棄で状態ごと消す
- コマンドの頻度の上限は足さない（お題・ルーレット・agenda・checkin と同じ扱い）。効くのはメッセージの大きさの上限と `limits.ts` の上限
- 端末には何も保存しない（この PR の範囲）

> 改定: 端末への保存を足した（2026-11-26・#476）。`2026-11-26-track-phase2-design.md` の §3

## 7. 受け入れ基準（EARS）

FR の番号は #476 のコメントの一覧に合わせる。利用者の決め（§3）で変わった所は、変えた後の形で書く。

- **FR-1・20** 利用者が開始を押したとき、システムはサーバーの時計で新しい区切りを始め、ルームの全員の画面に同じ経過を示さなければならない。作業名が空なら「（名前なし）」の区切りとして始めなければならない。名前のない区切りがある間、システムは時系列でそれを目立たせ、件数を添えて名前を付けるよう促さなければならない
- **FR-2** 計測中に利用者が別の作業名を選んだとき、システムは 1 回の操作で、いまの区切りをその時刻で閉じて新しい区切りを始めなければならない
- **FR-3・22** 計測している間、システムはいまの作業名・区切りの経過・作業名ごとの合計を表示し、タブの題を「作業名 h:mm｜うちわけ」に保たなければならない
- **FR-4・15** システムは候補を 9 件まで、お題のタイトル・定番・最近使った作業名の順に示さなければならない。利用者は作業名を定番に固定・解除できなければならない
- **FR-6** ある区切りが 90 分続いたとき、システムは操作を妨げない知らせを画面に出さなければならない
- **FR-7** 利用者は、閉じた区切りの名前・種類の付け替えと、始まり・終わりの調整ができなければならない。調整の結果、区切りが重なったり長さが 1 秒を下回ったりしてはならない
- **FR-8・25** 利用者がコピーを押したとき、システムは表（作業名・合計・割合）と時系列の一覧を Markdown でクリップボードに書き込まなければならない。書き込みに失敗したら、選べる欄に同じ文を示さなければならない
- **FR-9** システムは、状態・フレーム・書き出し・ログに、操作した参加者の表示名や ID を含めてはならない
- **FR-10** 同期サーバーは記録を永続化してはならず、記録の内容をログに書いてはならない。ルームの破棄とともに捨てなければならない
- **FR-11・21** 利用者が「記録を消す」を確かめて押したとき、システムは全員の画面から記録を消さなければならない。開始・切り替え・停止・消す操作の後 10 秒間は、全員の画面に「取り消す」を示し、押されたらその操作の直前の状態へ戻さなければならない

  > 改定: 取り消しの対象に「離れていた間の休憩」（`track.away`）を足した（2026-11-26・#476）。`2026-11-26-track-phase2-design.md` の §4 C4

- **FR-12** 作業名が 81 字以上のとき、または操作の結果の区切りが 200 件を超えるとき、システムはその操作を拒み、上限を示さなければならない
- **FR-16** 利用者は、開始・切り替え・停止を「いまから」のほか 1・5・10・15 分前からにできなければならない。前の区切りの始まりを越える指定は拒まなければならない
- **FR-17** 利用者は、区切りを途中の時点で 2 つに分け、後半に別の作業名を付けられなければならない
- **FR-18** 利用者は、過去の範囲に区切りを後から足せなければならない。時間は「始まりと終わり」でも「始まりと長さ」でも指定できなければならない。足した範囲に区切りがあれば、足した区切りで上書きしなければならない
- **FR-19** システムは、点数・目標の達成度・良し悪しの色分けを出してはならない
- **FR-23** 利用者が「休憩にする」を押したとき、システムは休憩の区切りを始め、休憩を作業名ごとの合計と割合から外して別に表示しなければならない
- **FR-24** ルームの接続が 0 のまま猶予を過ぎたとき、計測中の区切りがあれば、システムは最後の接続が切れた時刻でその区切りを閉じ、印を付けなければならない。その後に入った利用者へ、再開するかを尋ねなければならない
- **FR-26** 入力欄にフォーカスが無いとき、利用者が 1〜9 を押したら対応する候補へ切り替え、S で止め、C で直前の作業名を再開しなければならない

**非機能**（調査 1 §10.3 から採るもの）

- 表示の誤差は ±1 秒以内。表に戻って 1 秒以内に正しい値を出す
- 再読み込み・再接続では、サーバーの写しから元に戻る。切れている間は接続の告知を出し、操作を押させない
- 全操作をキーボードで行える。押せる部品は 24×24 CSS px 以上。動きを減らす設定に従う。色だけに頼らない
- 320px の幅で溢れない
- 描き直しは表示する秒が変わるときだけ（agenda の `use-local-clock` と同じ考え方）

## 9. 退けた作り方

| 案 | 退けた理由 |
|---|---|
| timer に足す | timer は交代の輪が中心で、作業名の列という別の関心が集約に混ざる（調査 1 §3） |
| agenda に「予定なしモード」を足す | agenda の核（予定の合計・押し巻き）が意味を失うモードになる（調査 1 §3） |
| 新しい文脈として足す（採る） | roulette・agenda・checkin の先例がある。新しく要るのは集約 1 つで、時計・ルーム・お題・コピーの部品はある |
| 一時停止の状態を持つ（調査 1） | 「止めていた時間」の意味が決まらない。休憩の区切りにすれば、合計に入らない時間として記録に残る（利用者の決め 2） |
| 区切りを壁時計の時刻で持つ | NTP の調整で戻りうるので、長さがずれる（`docs/adr/0027` 決定 2） |
| 取り消しを操作の履歴として持つ | 要るのは直前の 1 操作だけ。写しを 1 つ持てば足りる（`docs/adr/0007`） |
| 後からの追加を隙間にだけ許す | 切り替え忘れは区切りの途中に起きる。上書きにすれば「10:20〜10:40 は別の作業だった」を 1 回で直せる |
| 全員の切断を track の接続だけで数える | track の画面を閉じて作業を続ける間に、記録が止まる |

## 10. 書き手の判断の一覧（利用者が読んで確かめるもの）

| # | 判断 | 理由 |
|---|---|---|
| J1 | 区切りを消す操作（`track.segment.remove`）を足す。FR には無い | 手直しの画面に、足し間違えた区切りを消す手段が要る。取り消しは 10 秒しか効かない |
| J2 | 取り消しの対象に「記録を消す」を入れる。手直し（名前・境界・分割・追加・削除）は入れない | 消すのは誰でも押せて全員に効く。手直しは意図した操作で、もう一度直せる |
| J3 | 種類（作業／休憩）は名前の付け替えと一緒に変えられる | 「その間は休憩だった」を後から直せる |
| J4 | 全員の切断に 60 秒の猶予を置く | 1 人で使っているときの再読み込み・瞬断で、区切りが閉じて問いかけが出るのを防ぐ |
| J5 | 区切りの最短は 1 秒。手直しで置ける範囲は「いま」から 24 時間前まで | 長さ 0 の区切りと、際限なく過去へ伸びる記録を作らない |
| J6 | 「再開する」は、いまから新しい区切りを始める（離れていた間は数えない） | 離れていた間を作業に数えると、止めた意味が無くなる |
| J7 | 玄関の札は「内訳」・「Uchiwake」・末尾に置く | ほかの札の名前が英字なので揃えた。「内訳」が書体の base 層に無ければ、実装で別の一語にする |
| J8 | 「記録を消す」は区切りだけを消し、定番は残す | 定番は記録ではなく設定に近い |
| J9 | C キーは「直前の作業名」を再開する。計測中は、いまの区切りと違う名前のうち最も新しい作業。止まっているときは、最後の名前のある作業。該当が無ければ何もしない | Toggl の「続ける」と同じ意味にする |
| J11 | 1 秒に満たない区切りは残さない（切り替えなら付け替えになる）。上書きで出た 1 秒未満の端切れは新しい区切りへ含める | 連打と、分単位の入力と ms の境界のずれで、見えない区切りを作らない |
| J12 | 調整は、隙間をはさんだ隣へ食い込めない。画面のボタンは隙間を使い切った所で止まる | 「どこまで押せるか」を画面で分かるようにし、黙って隣を削らない |
| J13 | 時刻軸の基準は、ルームで最初にこの道具を開いた時点に置き、記録を消しても変えない | 空の記録にも後から区切りを足せる。基準が無い状態を作らない |
| J14 | 計測中の区切りも分割でき、後半が計測中になる | 「◯分前から」の 4 つの刻みに無い時刻で切り替え忘れを直せる |
| J15 | 定番の操作は取り消しの写しを捨てず、取り消しでも戻らない | 定番は時間の記録と関係が無い |
| J16 | お題のタイトルは 80 字で切り詰めて候補にする | お題の上限（200 字）のほうが長く、そのままでは押して拒まれる |
| J17 | 名前のない区切りは、時系列の順のまま目立たせ、件数を添えて名前を付けるよう促す。先頭へは並べ替えない（調査 3 の FR-20 の後半を、この形に変えた） | 時系列の一覧は時刻の順で読むもので、並べ替えると前後の区切りとのつながりが切れる |
| J18 | 分けるときの後半の種類は作業にする。休憩にするには、分けた後で付け替える | 分ける欄の入力を、時刻と名前の 2 つに保つ |
| J19 | 区切りを 1 つ消す操作は、確かめを挟まずに送る | 消した時間は「抜けを足す」で足し直せる。全部を消す「記録を消す」は確かめる |
| J20 | 段組みは、操作（いま・切り替える）を幅の狭い脇の区画に、表と時系列を広い区画に置く | 表と手直しの欄が幅を要る。DOM の順は「いま → 切り替える → うちわけ → 時系列 → 持ち帰り」で、狭い幅と読み上げの順はそのまま |
| J21 | 「いつから」（◯分前から）は、止める・休憩にする・切り替える・候補のボタンに効き、1 回使うと「いまから」へ戻る。キーボードはいつも「いまから」 | さかのぼりは気づいたその場の 1 回のための指定で、残すと次の切り替えまで巻き込む |
| J10 | 実装は Fable 5.2 で行う。レビューは別のエージェントに頼む | 利用者の希望（2026-11-23）。ふだんの「実装役は Sonnet」はこの作業では採らない |
