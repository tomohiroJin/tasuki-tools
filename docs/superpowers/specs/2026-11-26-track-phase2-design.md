## 2. A 手直しの残り

| # | 決め |
|---|---|
| A1 | 作業名の正規化（第 1 段 §4.5）で、表示名の第 1 層（`packages/room-core/src/display-name.ts` の `INVISIBLE_FORMAT`・`docs/adr/0011` の 2026-09-21 の追記）と同じ字（ゼロ幅の空白・向きを変える字・BOM ほか）を**落とす**。落とした結果が空なら名前なしと同じに扱う。ZWJ（U+200D）と字形選択子（U+FE0F ほか）は落とさない（絵文字が崩れる。表示名と同じ理由）。`track-core` はどの `@tasuki/*` にも依存しないので、字の集合は写し、写しであることと正本の場所を注記する。agenda のステップ名は変えない（別の道具の振る舞いを変えるので、この ISSUE の外）。**表示名の第 2 層（伏せて比べる層）は持ち込まない**: U+200E・U+200F・U+00AD・U+3164 ほか字形を持たない字の一部は残り、見た目が同じ作業名が合計で別の行になりうる。表示名の第 1 層と同じ範囲に揃えることを優先し、これは受け入れる（作業名はなりすましの対象にならない） |
| A2 | 「記録を消す」の後のフォーカスは「開始」のボタン（計測中なら「切り替える」）へ移す。**移すのは、消した結果の写し（記録が空）が届いてから**。届かない（拒まれた・切れた）ときは、元の「記録を消す」のボタンへ戻す |
| A3 | 計測中の区切りと同じ作業名の候補は、**候補の一覧に残すが、切り替えのボタンとしては押せない形（「計測中」と示す）にし、数字キーを割り当てない**。星（定番の固定・解除）はそのまま使える（計測中の作業を定番にする・外す道を残す）。数字キーは、押せる候補だけに上から 1〜9 を振る。候補の数の上限（`MAX_CANDIDATES`）は、押せる候補の数に掛ける（計測中の 1 件は上限に数えない） |
| A4 | 抜けを足す欄で、時刻を前日として読む振る舞い（いまの `positionBefore`）は**残す**（0:10 に「23:00–23:30」、8:00 に「18:00–07:30」を足せるように）。直すのは次の 3 つ: (1) 前日として読み替えた入力が手元の検査（いまより後・最短に満たない・順）で拒まれるときは、**理由がどれでも**「前日の時刻として読んだ」ことを添える。始まりと終わりが両方とも前日に読み替わって順が逆のときは、順の誤りとして示す (2) **押す前に、読み取った範囲と長さを欄の中に出す**（前日に読んだ端には前日と添える。「終わり」で指定しても「長さ」で指定しても同じ）。11:20 に「11:30–11:00」と入れて 23.5 時間になる、のような思い違いは、長さで拒まず、この表示で本人が気づけるようにする（抜けを足すのは上書きで取り消しも効かないが、夜をまたぐ正当な長い抜けを拒まないため） (3) サーバーが拒んだとき（件数の上限ほか）の文は今のまま |
| A5 | 端を合わせる時刻の入力（分の単位）: (1) 秒の欄の無い入力で、範囲の端と同じ分を入れたら、秒の端数つきの端へ寄せて受ける。**秒の欄のある入力（「10:10:00」）は寄せない**（入力の文字列で見る） (2) **寄せる先の端が「いまから 24 時間前」（`MAX_LOOKBACK_MS`）で決まるときは寄せない**（その端は時間とともに動き、送るまでの間にサーバーの側で範囲の外になる） (3) 時刻を前日・同じ日・翌日のどれで読むかは、**範囲に収まる読み方のうち、いまの位置（動かす前の端）に最も近いもの**で決める。収まる読み方が無ければ拒む（日をまたぐ最初の区切りの始まりを前日の時刻で動かせ、始まりを 12 時間より前の前日の時刻へも動かせる。終わりより後の時刻は範囲に収まらないので 23 時間の区切りにならない） |

## 3. B 端末に残す・CSV

| # | 決め | 理由 |
|---|---|---|
| B1 | 利用者が「この端末に残す」を押したときだけ、その時点の写しを 1 件として残す。自動では残さない | FR-13 は「選んだ場合」。誰が押したかを残さない道具なので、他の参加者の作業名が黙って端末に溜まるのを避ける（原則 XI） |
| B2 | 残すのは、区切りの列（作業名・種類・始まり・終わり・印）・`epochWallMs`・残した時刻。ルーム名・ルームのコード・定番は残さない。**計測中の区切りは、残す時点の位置（手元の時計の `nowMs`）で閉じた形で残す**（開くたびに伸び続けない）。残した時刻は `epochWallMs + nowMs`（時刻軸から求めた壁時計）で持つ | 振り返りに要るのは内訳だけ。ルームの識別子は人を辿る手がかりになる |
| B3 | 上限は `MAX_SAVED_RECORDS`（値は §5b）。超える保存では、いちばん古い 1 件を消す（押す所の近くで先に示す） | 上限の無い保存を作らない |
| B4 | 見る所はうちわけの中の「この端末の記録」（`/track/?view=saved`）。**timer の `?view=history` と同じく、`?room=` の有無を問わず開け、接続しない**（`room.join` を送らない。見ているだけの人を名簿に載せない。先例は `apps/timer-web/src/sync/use-timer-entry.ts`）。経路の判定は `parseRoomRoute` の前で `view=saved` を見る。玄関の「記録を見る」への掲載は #671 の決めに任せる | ルームが消えた後に見るための保存なので、ルームの中でしか開けないと意味が無い。道具を横断する一覧は #671（`docs/adr/0017` の境界） |
| B5 | 一覧（残した日時・全体の時間・名前のある作業名の種類の数）→ 開くと表と時系列（読むだけ）・Markdown でコピー・CSV で保存・1 件ずつ消す・全部消す（確かめる）。**「全部消す」が消すのは、そのとき一覧に見えていた記録だけ**（一覧を読んだ後に別のタブで残した記録は消さない）。ルームの画面から「この端末の記録」へは**新しいタブで開く**（同じタブで移るとルームの接続が切れ、1 人なら全員の切断の停止が起きる） | 持ち帰りの前段に徹し、編集はさせない |
| B6 | 押す所の近くに短く、保存先と消える条件を示す: この端末のブラウザにだけ残る・ほかの人には見えない・ブラウザのデータを消すと消える・**ブラウザによっては、しばらく開かないと消える**（Safari は操作の無いまま 7 日でサイトの保存を消す。FR のコメントの端末保存の節） | FR-13 |
| B7 | IndexedDB（DB 名 `tasuki-track`・ストア 1 つ）。timer の `records/indexeddb.ts`・`stored-record.ts` の作りを写し、共有化はしない。**記録に版を持たせ、読むときは境界で形を検める（`docs/adr/0005`）。読めない記録は一覧から外し、上書きも削除もしない。保存・読み出しの失敗は例外で画面を落とさず、知らせに出す** | 原則 X（3 つ目の使い手が出たら寄せる） |
| B8 | CSV は 1 行 = 1 区切りで、**先頭に見出しの行を置く**。列は `start_date,start,end_date,end,minutes,kind,label,auto_closed`。`start_date`・`end_date` はそれぞれの日付（端末の時間帯・日をまたぐ区切りで終わりの日付が分かるように）・`start`/`end` は `HH:MM`・`minutes` は小数 2 桁・`kind` は `work` か `break`・`auto_closed` は `true` か `false`・名前なしは空。計測中の区切りは書き出す時点で切る。RFC 4180（CRLF・**値はすべて `"` で囲み**、中の `"` は二重にする）・UTF-8 BOM・`=` `+` `-` `@` タブ・CR・LF で始まる値は先頭に `'` を付ける（FR-14）。全角の `＝＋－＠` は作業名の正規化（NFKC）で半角になるので、別に扱わない | 表計算や各自の工数の道具へ移すには、合計より区切りの行が使える。合計は表計算で出せる |
| B9 | CSV はファイルとして保存する（`track-YYYYMMDD-HHMM.csv`。時刻はルームの画面では時刻軸から求めた壁時計、「この端末の記録」では残した時刻）。ルームの画面と「この端末の記録」の両方に置く。ダウンロードの URL はすぐには手放さない（ブラウザによっては取得の前に無効になる） | CSV はクリップボードより保存で使われる |

- CSV の組み立ては `packages/track-core` の純粋関数にする（Markdown と同じ置き場）
- **データの分類**: 作業名は「個人に紐づく」の段のまま。端末に残す分は、表示名・前に作ったルーム名（`docs/adr/0011` の #633 の追記）と同じ「端末に残してよい」段として扱う（`docs/adr/0011` の 2026-11-26 の追記）

## 4. C 離れていたとき

| # | 決め | 理由 |
|---|---|---|
| C1 | ページが非表示 → 表示に変わったとき、**次のすべてを満たせば**問いかけを出す: (1) 非表示だった長さが `AWAY_PROMPT_MIN_HIDDEN_MS`（値は §5b）以上 (2) 計測中の区切りの長さが `LONG_RUNNING_NOTICE_MS` 以上 (3) **非表示になった時と戻った時で、計測中の区切りの id が同じ**（離れている間に誰かが切り替え・停止していない） (4) 非表示になった位置が、その区切りの始まりより後 (5) **非表示の間に一度もミニ表示（Document PiP）の窓が開いていなかった**（開いている間に元のタブが隠れるのは離れたことにならない。窓を閉じてから戻る場合もあるので、戻った時点の窓の有無ではなく、非表示の間に開いていたかを端末で覚える。窓は `window.documentPictureInPicture` の `enter` の知らせと `window` で見る） (6) **計測中の区切りが作業である**（休憩が長く続いたときには出さない。休憩を休憩で上書きすると区切りが割れるだけになる） | FR-27 の条件だけでは、タブを一瞬切り替えただけでも、ほかの人が切り替えた後でも、ミニ表示で作業している間でも出る |
| C1b | 長さと位置の測り方: 非表示になった位置は、その時点の手元の時計（`use-track-clock` の値）で取る。戻ったら `track.sync` を送り、届いた写しの `nowMs` から非表示になった位置を引いて長さとする（スリープ中に端末の単調時計が進まない環境があるので、サーバーの時刻軸で測る）。判定は写しが届いてから行う | 裏のタブ・スリープの後で経過がずれない |
| C2 | 問いかけは、戻ってきたその人の画面にだけ出す。非表示になった時刻は端末だけが持ち、状態にもフレームにも載せない。**ほかの人が作業を続けていたかもしれないので、問いかけは提案であり、既定の選択は「そのまま残す」**（押さずに閉じれば何も送らない） | FR-27 は「その利用者に」。誰が離れていたかをサーバーに持たせない（原則 XI・`docs/adr/0038` 決定 2） |
| C3 | 3 つの選択: 「そのまま残す」= 何も送らない。「離れた時刻で切る」= `track.stop { atMs }`（非表示になった位置）。「その間を休憩にする」= `track.away { fromMs }`（非表示になった位置からいままでを休憩で上書きし、計測中の区切りは後ろで同じ名前のまま続く） | 既存の上書きの規則で足りるが、取り消しの対象にするため、名前の付いた 1 つの操作にする |
| C4 | 反映した上で、全員の画面に取り消しの帯（`UNDO_WINDOW_MS`）を出す（`undo.kind` に `"away"` を足す。`stop` は既に対象）。**FR-27 の後半「全員に通知してから反映」を「反映し、全員の画面に取り消せる知らせを出す」に変えた**（第 1 段の J17 と同じく、FR の文を変えたことを明記する） | 反映を全員の応答で待つと、誰かが応じるまで記録が止まる |
| C5 | `atMs`・`fromMs` の制約: 計測中の区切りの始まりより**後**・**いまから `MIN_SEGMENT_MS` 以上前**・**いまから `MAX_LOOKBACK_MS` 以内**（計測中の区切りは長さに上限が無いので、始まりより後でも 24 時間より前になりうる。手直しの範囲と揃える）。外れたら、どの条件でも `TRACK_BACKDATE_TOO_FAR` で拒む（`track.ts` の `backMin` の判定と同じ関数を通し、その関数に lookback の判定を足す。`backMin` は 15 分までなので振る舞いは変わらない）。計測していなければ `track.stop`・`track.away` とも何もしない（今の `stop` と同じ）。`stop` に `atMs` と `backMin` が両方あれば、**スキーマで拒む**（`INVALID_COMMAND`。valibot の `check` で） | 既存の拒み方に揃え、二通りの読みを作らない |
| C5b | 画面の `frameUndoKind`（`apps/track-web` の写しの読み）は、知らない値を `"start"` に畳む今の作りを直し、`"away"` を読めるようにする。帯の文は `away` 用を足す | 直さないと「切り替えを取り消す」と出る |
| C6 | 通知（Notification API）は既定で切。うちわけの画面で「長く続いたら通知する」を押した人だけ、許可を求め、ページが非表示のときに FR-6 の知らせを通知でも出す。**1 つの区切りにつき 1 回**（区切りの id で覚える）。設定は端末ごと（localStorage） | 許可は押したときにだけ求める。timer の `platform/notify.ts` の作りを写す |
| C7 | 通知の文に作業名を出さない（「同じ作業が 90 分続いています」の形） | 通知はロック画面ほか画面の外に出る。作業名は「個人に紐づく」 |

- wire に足すのは、`track.stop` の任意の `atMs` と、新しいコマンド `track.away { fromMs }`、写しの `undo.kind` の値 `"away"`。受ける側のスキーマは非 strict のまま（第 1 段 §4.4）
- **受け入れたこと（原則 XI）**: `track.away` を選ぶと、全員の画面の取り消しの帯と時系列に「この時刻から休憩」が出る。2 人で使っていれば、どちらかが離れていたことは推せる。これは本人が選んで送る操作で、手で休憩を足す（第 1 段の「抜けを足す」）と同じ程度の情報である。誰が送ったかは今までどおり載せない
- 映す画面（§5 D2）が名簿に載っている間は、全員の切断の停止（FR-24）は起きない。映す画面を開いたままの間は、ルームが使われているとみなす（意図どおり）

| VI 依存は内向き | CSV は core の純粋関数。ブラウザの API は web の `platform/` |
| VII 壊して確かめる | 帯を予約して変異を足す |
| VIII 記録が正本 | この文書と ADR の追記 |
| IX 小さく回す | 4 本に分け、独立に戻せる |
| X 抽象は実需で | 端末保存・通知は timer から写し、共有化しない |
| XI 秘密と個人情報 | 誰が押したか・誰が離れていたかを持たない。通知に作業名を出さない。端末に残すのは押したときだけ |

## 8. 検証の時間の見積もり

- 各 PR: track-core・track-web の単体（約 1 分）・全件の `pnpm test`（約 3〜5 分）・E2E 全件（約 3〜5 分）・変異の `--changed`（約 10〜20 分）
- C は同期サーバーのテストが加わる（約 2 分）
- 4 本でまとめて 1.5〜2 時間の検査（E2E を順に流すため並列にできない分を含む）
