## 2. A 手直しの残り

| # | 決め |
|---|---|
| A1 | 作業名の正規化（第 1 段 §4.5）で、表示名の第 1 層（`packages/room-core/src/display-name.ts` の `INVISIBLE_FORMAT`・`docs/adr/0011` の 2026-09-21 の追記）と同じ字（ゼロ幅の空白・向きを変える字・BOM ほか）を**落とす**。落とした結果が空なら名前なしと同じに扱う。ZWJ（U+200D）と字形選択子（U+FE0F ほか）は落とさない（絵文字が崩れる。表示名と同じ理由）。`track-core` はどの `@tasuki/*` にも依存しないので、字の集合は写し、写しであることと正本の場所を注記する。agenda のステップ名は変えない（別の道具の振る舞いを変えるので、この ISSUE の外） |
| A2 | 「記録を消す」の後のフォーカスは「開始」のボタンへ移す（抜けを足す・区切りを消すの後と同じく、次に押すものへ） |
| A3 | 計測中の区切りと同じ作業名・種類の候補は、候補から外す。数字キーの対応は外した後の並びで決める（全員が同じ写しを持つので、全員で同じになる） |
| A4 | 抜けを足す欄で、終わりがいまより後なら、前日へ読み替えず「いまより後には置けない」として拒む。前日として読むのは「始まり > 終わり」のときだけで、結果が手直しの範囲（24 時間）に収まるときに限る |
| A5 | 時刻の入力（分の単位）は、範囲の端の分を受ける。下限・上限と同じ分を入れたら、秒の端数つきの端へ寄せる（± のボタンと時刻の入力で届く範囲を揃える）。最初の区切りの始まりに終わりより後の時刻を入れたら、前日ではなく拒む |

## 3. B 端末に残す・CSV

| # | 決め | 理由 |
|---|---|---|
| B1 | 利用者が「この端末に残す」を押したときだけ、その時点の写しを 1 件として残す。自動では残さない | FR-13 は「選んだ場合」。誰が押したかを残さない道具なので、他の参加者の作業名が黙って端末に溜まるのを避ける（原則 XI） |
| B2 | 残すのは、区切りの列（作業名・種類・始まり・終わり・印）・`epochWallMs`・残した時刻。ルーム名・ルームのコード・定番は残さない | 振り返りに要るのは内訳だけ。ルームの識別子は人を辿る手がかりになる |
| B3 | 上限は 50 件。超える保存では、いちばん古い 1 件を消す（押す所の近くで先に示す） | 上限の無い保存を作らない |
| B4 | 見る所はうちわけの中の「この端末の記録」（`/track/?view=saved`）。玄関の「記録を見る」への掲載は #671 の決めに任せる | 道具を横断する一覧は #671（`docs/adr/0017` の境界）。先に track の中で閉じておけば、#671 は読むだけで済む |
| B5 | 一覧（残した日時・全体の時間・作業名の数）→ 開くと表と時系列（読むだけ）・Markdown でコピー・CSV で保存・1 件ずつ消す・全部消す（全部は確かめる） | 持ち帰りの前段に徹し、編集はさせない |
| B6 | 押す所の近くに 1 行で、保存先と消える条件を示す（この端末のブラウザにだけ残る・ブラウザのデータを消すと消える・ほかの人には見えない） | FR-13 |
| B7 | IndexedDB（DB 名 `tasuki-track`・ストア 1 つ）。timer の `records/indexeddb.ts` の作りを写し、共有化はしない | 原則 X（3 つ目の使い手が出たら寄せる） |
| B8 | CSV は 1 行 = 1 区切り。列は `date,start,end,minutes,kind,label,auto_closed`（日付と時刻は端末の時間帯・分は小数 2 桁・計測中の区切りは書き出す時点で切る）。RFC 4180・UTF-8 BOM・`=` `+` `-` `@` タブ・CR で始まる値は先頭に `'` を付ける（FR-14） | 表計算や各自の工数の道具へ移すには、合計より区切りの行が使える。合計は表計算で出せる |
| B9 | CSV はファイルとして保存する（`track-YYYYMMDD-HHMM.csv`）。ルームの画面と「この端末の記録」の両方に置く | CSV はクリップボードより保存で使われる |

- CSV の組み立ては `packages/track-core` の純粋関数にする（Markdown と同じ置き場）
- **データの分類**: 端末に残す作業名は「個人に紐づく」のまま（`docs/adr/0038` の 2026-11-26 の追記）

## 4. C 離れていたとき

| # | 決め | 理由 |
|---|---|---|
| C1 | ページが非表示 → 表示に変わり、非表示だった間が 10 分以上で、かつ計測中の区切りの長さが `LONG_RUNNING_NOTICE_MS`（90 分）以上のとき、問いかけを出す | FR-27 の条件だけでは、タブを一瞬切り替えただけでも出る |
| C2 | 問いかけは、戻ってきたその人の画面にだけ出す。非表示になった時刻は端末だけが持ち、状態にもフレームにも載せない | FR-27 は「その利用者に」。誰が離れていたかをサーバーに持たせない（原則 XI・`docs/adr/0038` 決定 2） |
| C3 | 3 つの選択: 「そのまま残す」= 何も送らない。「離れた時刻で切る」= `track.stop { atMs }`（非表示になった位置）。「その間を休憩にする」= `track.away { fromMs }`（非表示になった位置からいままでを休憩で上書きし、計測中の区切りは後ろで同じ名前のまま続く） | 既存の上書きの規則で足りるが、取り消しの対象にするため、名前の付いた 1 つの操作にする |
| C4 | 反映した上で、全員の画面に 10 秒の取り消しの帯を出す（`undo.kind` に `"away"` を足す。`stop` は既に対象） | 「全員に通知してから反映」を、取り消せる知らせとして満たす。反映を全員の応答で待つと止まる |
| C5 | `atMs`・`fromMs` の制約は `backMin` と同じ（計測中の区切りの始まりより後・いまより前・`MAX_LOOKBACK_MS` の内）。`stop` は `atMs` と `backMin` を同時に受けない | 既存の拒み方（`TRACK_BACKDATE_TOO_FAR`）に揃える |
| C6 | 通知（Notification API）は既定で切。うちわけの画面で「長く続いたら通知する」を押した人だけ、許可を求め、ページが非表示のときに FR-6 の知らせを通知でも出す。設定は端末ごと（localStorage） | 許可は押したときにだけ求める。timer の `platform/notify.ts` の作りを写す |
| C7 | 通知の文に作業名を出さない（「同じ作業が 90 分続いています」の形） | 通知はロック画面ほか画面の外に出る。作業名は「個人に紐づく」 |

- wire に足すのは、`track.stop` の任意の `atMs` と、新しいコマンド `track.away { fromMs }`、写しの `undo.kind` の値 `"away"`。受ける側のスキーマは非 strict のまま（第 1 段 §4.4）

## 5. D 見せ方

| # | 決め | 理由 |
|---|---|---|
| D1 | 映す画面 `/track/?view=display`: いまの作業名（大）・経過・作業名ごとの合計の表・時系列の帯。押せる部品を置かない。ルームの画面に「映す画面を開く」を置く | 会議室の画面に映し、手元で操作する使い方。読むだけにすれば取り違えない |
| D2 | 映す画面は通常の接続で入り、送るのは `track.sync` だけ。名簿には普通の参加者として載る | 新しい種類の接続を作らない（wire 不変） |
| D3 | ミニ表示（Document Picture-in-Picture）は、対応ブラウザでだけ「小さな窓で出す」を出す。中身はいまの作業名・経過・「止める」「休憩にする」「直前を再開」。非対応なら出さず、代わりの道を作らない | 別のタブで作業しながら切り替えられるのが本題（調査の第 2 段） |
| D4 | 時系列の帯（横軸 = 時刻。作業・休憩・隙間を並べ、色だけに頼らない）をルームの画面と映す画面に置く。割合の帯（第 1 段）は残す。円グラフは足さない | 「いつ何をしていたか」はいま一覧でしか見えない |
| D5 | 時系列の帯は動かさない。描き直しは 1 分ごと | 毎秒の描き直しと動きを避ける |
