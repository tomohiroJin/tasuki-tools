# 会の始まりと終わりの札（#406 第 1 段）— 設計

- **日付**: 2026-10-28・**実測時点**: main `6b977cd9`（#447 段 2 のマージ後）
- **Issue**: #406（2026-10-26 に「会の始まりと終わりの道具」へ書き直した提案）
- **決め方**: 2026-10-27〜28 の利用者との壁打ちで決めた。利用者が決めたことは「利用者」、統括（設計の書き手）が決めたことは「統括の判断」と明記する。統括の判断は §9 に一覧する

## 1. 何のための道具か

**困りごと（利用者の言葉から）**

- チェックインが無いので、会の始まりの区切りが無い
- 小さい打ち合わせは振り返らないので、チェックアウトが欲しい
- スクラムイベントを一日続けると、まじめな話だけが続く。打ち合わせがだらだら延びる

**使う場（利用者）**

- 同じ部屋のスクラムイベント。テーブルを囲み、1 台のモニターに映して進める。dev 5・PO 1・SM 1・AC 1 の 8 人ほどで、各自がノート PC を持っている
- リモートの朝会・打ち合わせ

**道具の役割（利用者）**: 全員が絞り込んだ札から 1 枚を伏せて出し、一斉に開き、**誰がどれを出したか（匿名なら分布）を見せるところまで**。開いた後に話すか、すぐ次へ進むかは使い手に任せる。

**コンセプト（利用者）**: **1〜2 分ですぐ終わる。** そのためにやり方をある程度の数だけ用意し、選んでもランダムでも決められるようにする。

## 2. 目標・対象外・失敗の形

**目標**

- 会の入口（チェックイン）と、イベントの一つ一つの終わり（チェックアウト）に、1〜2 分で差し込める
- poker と同じくらい**スタイリッシュで格好いい**こと。デザインはこの道具で重要な要素（利用者）
- 札は直感で選べる。札に説明を書かない（利用者）

**対象外（第 1 段）**

- モニターに映した人の手札が見えてしまう問題への対処。運用でカバーする（見学者としてシークレットウィンドウで入り、それを映すなど）。poker にも同じ問題があり、道具をうまく使うのは使い手に任せる（利用者）
- アイスブレイク（いったん外す・利用者）
- 結果の保存と持ち出し（Tasuki は保存しない・[実際の利用シーン]の方針）
- 自由記述の札
- 時間の制限（残り時間の表示など）。短さは札の少なさと自動で開くことで担保する（統括の判断）
- チェックインの「持ち帰りたいもの」とチェックアウトの「持ち帰れたか」を組にして振り返る仕組み（統括の判断・始まりの結果を終わりまで覚えておく仕組みが要るため。結果を残さない方針とも当たる）

**失敗の形（これが起きたら、動いていても失敗）**

- 匿名のやり方で、誰が何を出したかがどこかから分かる（画面・通信・切り替えのどれでも）
- 開くまでに、他の人の出した札が分かる
- 札に説明の文が並び、直感で選べない
- poker より見劣りする、事務的な見た目

## 3. やり方（10 種・利用者が決めた）

各やり方は、お題（問いの文）・札（4〜5 枚）・凡例（札ごとの短い意味）・既定の公開の仕方を持つ。
札の**名前**（下の「札」の列）は凡例と読み上げに使い、札の顔には出さない。

### チェックイン

| やり方 | 札 | 既定 |
|---|---|---|
| 今日の天気 | 晴れ／くもり／雨／雷 | 名前つき |
| 元気メーター | 1／2／3／4／5 | 匿名 |
| いま頭の何割がここに？ | 2 割／5 割／8 割／10 割 | 名前つき |
| この打ち合わせで持ち帰りたいもの | 決めたい／知りたい／相談したい／聞くだけ | 名前つき |
| 今日の役割 | 聞き役／質問役／まとめ役／盛り上げ役 | 名前つき |

### チェックアウト

| やり方 | 札 | 既定 |
|---|---|---|
| ROTI（時間に見合ったか） | 1／2／3／4／5 | 匿名 |
| 持ち帰れたか | 持ち帰れた／半分／持ち帰れなかった | 名前つき |
| 一番よかったこと | 決まった／話せた／知れた／特になし | 名前つき |
| 今の気分 | すっきり／もやもや／くたくた／わくわく | 名前つき |
| 次の打ち合わせは | このままで／短く／人を絞る／無くてもいい | 匿名 |

お題の文と凡例の言い回しは実装者が書いてよい。モックアップで使った例: 天気は「今日のあなたの空模様は？」・凡例「晴れ 絶好調／くもり まあまあ／雨 ちょっと沈み気味／雷 荒れ模様・余裕がない」。ROTI は「この時間、使った分の価値はありましたか？」・凡例「1 時間のむだ … 5 来てよかった」。

**文言は書体の base 層に収める（MUST）。** 2026-10-28 の実測で約 30 字が base 層に無かった。**言い換えず、base 層を作り直して字を足す**（利用者が選んだ・計画 Task 3.0）。 「雷」などの漢字が base 層に無いと、ext 層（約 210KB）を読みにいく。既存アプリの `copy-fits-font-base` の試験と同じ形で守る。base 層に無い字は言い換える（意味が変わる言い換えは利用者に見せる）。

## 4. 1 回の流れ（利用者が承認）

1. ルームの中で 6 つ目の札を開く
2. 「チェックイン」か「チェックアウト」を選び、その中のやり方を**選ぶ**か**ランダム**で決める。ランダムは選んだ側の 5 つから引き、いまのやり方は除く（除くのは統括の判断）
3. 全員の画面にお題・凡例・手札が出る。各自が 1 枚を伏せて出す。開く前なら出し直せる。**見学者**は札を出さず、場を見るだけ
4. 札を出す人が全員出したら、自動で一斉に開く。待たずに開くこともできる
5. 開くと、名前つきのやり方は「誰がどれを出したか」を、匿名のやり方は分布だけを見せる
6. 「もう一回」（同じやり方で新しい回）か「別のやり方」で次へ進む。結果は残さない

**操作は参加者の誰でもできる（利用者・参加者は対等が今の目標）。** やり方を選ぶ・ランダム・公開の仕方を切り替える・待たずに開く・もう一回・別のやり方の全部。見学者も操作はできる（統括の判断・poker で見学者が公開できるかに揃える。実装者は poker の現状を見て揃える）。

## 5. 見た目（利用者が選んだ方向）

モックアップ（手元の `/workspaces/claym/local/Tasuki/.superpowers/brainstorm/2155059-1793111181/content/` の `cards-v1.html` と `reveal-v1.html`。git の対象外）を正本の絵とする。

- **卓と札は poker の言葉遣い**: 羅紗の地（`--felt-*`）、象牙の札（`--ivory` 系の地・真鍮の細い二重枠）、金のアクセント（`--gold-*`）。トークンは `packages/ui` のものだけを使う（生の色を書かない）
- **札の顔は絵だけ（利用者が A を選んだ）**。字を添えない。数のやり方は数字（Fraunces のイタリック）が絵の代わり。絵は細い墨の線に金を一点差す線画（モックアップの天気の 4 枚の作り）。10 種の残りの絵柄は実装者が同じ作りで描く
- **意味はお題と一緒に出す（利用者）**: お題の枠の中に、上から小見出し（`CHECK-IN`／`CHECK-OUT` と、やり方の名前）・問いの文（大きく）・凡例の 1 行。札の名前は読み上げ（`aria-label`）にも使う
- お題の枠の右上に、公開の仕方（名前つき／匿名）の切り替えと「別のやり方」
- 席の列（モックアップどおり、手札の上）に、伏せて出された札の並び（席ごとの伏せ札と名前・まだの席は点線の枠）と「6 / 8 人が出しました」。その下に手札を置く
- 選んだ札は浮き上がり、金の縁取りと淡い光
- **開いた後は「札ごとに寄せる」（利用者が B を選んだ）**: 札の種類ごとの山（並びはやり方の札の順・0 枚の札も点線の枠と 0 で残す）。山の下に大きな数字（Fraunces）・札の名前・名前つきなら出した人の名前の小札。**一番多い山は金の縁と淡い光**（同数なら全部）。下に 1 行の要約（例「晴れが 3 人」）
- **匿名は同じ形から名前を外したもの（利用者が C の方向を選んだ）**。山の高さと数だけ
- **開く動き**: 伏せ札が 90ms ほどずつずれて裏返り（Y 軸の回転）、山に積まれ、最後に数字と名前が出る。全体で 2 秒以内。`prefers-reduced-motion` では動かさず、開いた形をすぐ出す
- 見出しは共通の部品 `RoomHeader`（`packages/invite-ui`・通常の見た目）
- 幅は 320〜1920 で崩さない。狭い幅では山を 2 列に折り返し、手札は折り返す。手札の札は当たり 44px 以上

デザインの細部（間隔・影・動きの曲線）は実装者に任せる。ただし**統括の撮影で poker と並べて見劣りしないか**を確かめ、利用者に実画面で見せる段を計画に入れる。

## 6. 匿名の守り方（MUST）

匿名は画面で隠すのではなく、**サーバーが送らない**ことで守る。

- 開く前: どの受け手にも、他人の札の中身を送らない。送るのは「出した／まだ」だけ。自分の札は自分にだけ送る（poker の受け手ごとの投影 `packages/poker-core/src/snapshot.ts` と同じ考え方）
- 匿名で開いた後: 送るのは札ごとの枚数だけ。誰が出したかは送らない
- **公開の仕方は、その回で誰かが札を出したら（または開いた後は、札が 0 枚でも）次の回まで変えられない**（統括の判断・匿名のつもりで出した札が、後から名前つきに切り替えられて晒されるのを防ぐ）。画面では切り替えを押せなくし、サーバーも拒む。**変えたら回の番号 `seq` を進める**（PR の自動レビュー・統括の判断。前の公開の仕方を見て押した札は古い回の操作として無視される）
- **出した人が少ないうちに匿名で開いたときの推測は、使い手に任せる（利用者・2026-10-28）**。たとえば 8 人中 1 人だけが出した状態で「待たずに開く」と、伏せ札の並びから誰の札か分かる。最低人数・注意の一言などの仕組みは作らない。§2 の失敗の形「誰が何を出したかが分かる」は、道具が中身と名前を結びつけて送る・見せることを指し、この推測は含まない
- **公開の仕方の切り替えは、その回かぎり**。「もう一回」「別のやり方」の新しい回は、やり方の既定に戻る（統括の判断・既定が匿名の ROTI を誰かが名前つきにしたまま次の回に入ると、匿名のつもりで出した人が晒されるため）

## 7. 作りの枠組み（統括の判断・先例に従う）

先例は roulette（ADR 0026）と agenda（ADR 0027）。

- **独立した道具として足す**。規則は新しい文脈 `packages/checkin-core`（仮の名前）に置き、`room-core` を含むどの `@tasuki/*` にも依存しない。依存は `valibot` と `neverthrow` だけ
- 新しいサーバーは立てず、接続の種類 `?tool=<id>` を足す（綴りの正本は `apps/tasuki-sync/src/application/tool-id.ts`）。状態はサーバーの揮発インメモリ。ルームの破棄で消す（破棄へ渡す状態は必須の依存にする）
- 画面は `apps/<id>-web`。玄関の札（`apps/landing/src/tools.ts`）の 6 枚目に足す
- コマンドは `v.strictObject` で検証し、札はやり方の札の集合に含まれるものだけを受ける
- 名簿・在席は共通ルーム（`room-core`）のものを使う。**見学者は `room-core` に無く poker が自前で持っている**（`packages/poker-core/src/round.ts` の `Round.spectators`・`set-spectator`）ので、**この道具も自前で持つ**（統括の判断・poker の見学者を共通へ移すのは別の仕事で、この道具の目的に要らない）。poker で見学者の人も、この道具では札を出す人として入り、自分で見学に切り替える。見学は poker と同じく、ルームの中の「見学する／投票に加わる」の切り替えで選ぶ（poker #419 の `set-spectator`・入るときの指定は持たない。利用者 2026-10-28）。運用の「見学者として入って映す」は、シークレットウィンドウで入って「見学する」を押す
- **「全員」はこの道具を開いている人だけ**（poker の `isPresentIn(p, TOOL_POKER)` と同じ・統括の判断）。ハブや他の道具の画面にいる人は数えない。開く前に入ってきた人は出せる。抜けた人は数から外す。E1 の「ルームの全員」もこの道具を開いている全員の意味
- ADR を 1 本足す（0028）

**名前（統括の判断・変えてよい）**: ツール ID は `checkin`、道具名は英語の既存の並びに揃えて **Check-in Cards**、札の左上の一語は「始終」、1 行の説明は「会の始まりと終わりに札を出し合う」。

**PR の分け方の目安**（agenda の先例）: 1. 文脈とコマンドの形 → 2. サーバーの経路 → 3. 画面 → 4. 玄関の札・配備資材・E2E。分け方は計画で決める。

## 8. 受け入れ基準（EARS）

- **E1** 参加者がやり方を選んだとき、ルームの全員の画面に、そのやり方のお題・凡例・手札が出る
- **E2** 参加者がランダムを押したとき、選んでいる側の 5 つのうち、いまのやり方以外から 1 つが選ばれ、全員に同じやり方が出る
- **E3** 札を出す人が全員出したとき、全員の画面で一斉に開く
- **E4** 参加者が「待たずに開く」を押したとき、出していない人がいても開く
- **E5** 開く前は、どの受け手への送信にも他人の札の中身を含まない
- **E6** 匿名のやり方で開いたとき、どの受け手への送信にも、誰がどの札を出したかを含まない
- **E7** その回で誰かが札を出した後（または開いた後）、公開の仕方を変える操作は拒まれる
- **E8** 名前つきで開いたとき、札ごとの山の下に、その札を出した人の名前が出る
- **E9** 見学者には手札が出ず、見学者は「全員出したか」の数に入らない
- **E10** 開く前に出し直したとき、最後に出した札だけが数えられる
- **E11** 「もう一回」で、同じやり方の新しい回が始まり、前の回の札は誰にも残らない
- **E12** `prefers-reduced-motion` のとき、開く動きを出さずに開いた形を出す
- **E13** 画面の文言は書体の base 層に収まる

## 9. 統括の判断の一覧（利用者が読んで確かめるもの）

1. 時間の制限を付けない（§2）
2. 「持ち帰りたいもの」と「持ち帰れたか」の組は第 1 段に入れない（§2）
3. ランダムはいまのやり方を除く（§4）
4. 見学者も操作できる。poker の現状に揃える（§4）
5. 公開の仕方は、その回で誰かが出したら変えられない（§6）
6. 名前: ID `checkin`・道具名 Check-in Cards・一語「始終」（§7）
7. 匿名で開いた後、自分の札がどの山かも示さない（§6 の「枚数だけ」から）
8. 公開の仕方の切り替えはその回かぎりで、新しい回は既定に戻る（§6）
9. 見学者はこの道具が自前で持つ。poker の見学者とは別（§7）
10. 「全員」はこの道具を開いている人だけ（§7）
