## 1. 目的

モブプロ・ペアプロを長く続けると集中が落ちる。**稼働時間か周回を条件に、休憩を差し込む**。
休憩の条件を「なし」にしたルームは、今とまったく同じに動く（画面・書体の取得も含む）。

v2.10 は「一時停止と休憩の違いが分からない」という実機の声で休憩を撤去した。当時は休憩が時計を止めず、
休憩の間の時間が消費済みになる食い違いもあった。本設計はこの 2 つに答える（§2・§5）。

## 2. 決定（利用者と合意したもの）

| # | 論点 | 決定 |
|---|---|---|
| D1 | 条件に達したとき | 既定は**交代の切れ目で自動的に休憩に入る**。ルームの設定で「知らせるだけ」にも切り替えられる |
| D2 | 休憩の長さ | 「休憩を終える」を押すまで続く。休憩に入ってからの経過を数え上げて表示する |
| D3 | 経過時間の数え方 | 稼働時間（`accumulatedElapsedMs`・一時停止中は数えない）。休憩のたびに 0 から数え直す |
| D4 | 周回の数え方 | 前の休憩からの交代回数が「適格な席の数 × N」に達したら |
| D5 | 手で休憩する | 休憩の条件を設定したルームでだけ、セッション中は常に「休憩する」を出す。誰でも押せる。終了も誰でも |
| D6 | 見せ方 | 休憩中は全員の画面を休憩の覆いで占める（一時停止は盤面のまま時計が止まる／休憩は盤面がどく） |
| D7 | 設定 | ロビーの「詳細設定」だけで変える。条件 = なし（既定）／経過時間（30・45・60・90 分、既定 60）／周回（1〜4 周、既定 2）。入り方 = 自動（既定）／知らせるだけ |
| D8 | 作り方 | 休憩の状態を timer-core の集約（`session`）に入れる。ルームの `onBreak` は消す |
| D9 | 文言と書体 | 「休憩」の語を使う。「休」「憩」は書体の base 層に無いので、**条件が「なし」のルームの既定の画面（詳細設定を閉じた状態）には描かない**。詳細設定を開くと「休憩の条件」の見出しが出るので ext 層を取る（利用者の明示の操作なので受け入れた・2026-10-16） |
| D10 | 回収との関係 | 全員が offline のまま回収の時間（`ROOM_IDLE_TTL_MS`）を超えたらルームは消える。仕組みは変えず、休憩中の人に伝える（§6.5） |

**v2.10 への答え**: 一時停止と休憩は、3 つの点で違う。

1. **見た目**: 一時停止は盤面のまま時計だけが止まる。休憩は全員の画面を覆いが占め、交代の円は隠れる
2. **起き方**: 休憩は条件に達するとタイマーが自分で入る（D1）。一時停止は人が押したときだけ止まる
3. **機能**: 休憩すると、次の休憩までの数え直しが始まる。「休憩する」の添え書きでこれを示す

時計を止める作りは、v2.10 に残した `evolveBreakStarted` / `evolveBreakEnded` を使う。これは時計を正しく凍結・再開する（`break-freeze.test.ts` が守っている）。

## 3. ドメイン（`packages/timer-core`）

### 3.1 集約

`SessionState` に `break` を足す。

```ts
interface BreakState {
  /** 休憩に入った時刻（epoch ms）。休憩中でなければ null */
  since: number | null;
  /** 前の休憩（またはセッションの開始）の時点の値。判定の基準 */
  baseline: { elapsedMs: number; switches: number };
  /** 「知らせるだけ」で最後に知らせた時点の値。知らせていなければ null */
  suggestedAt: { elapsedMs: number; switches: number } | null;
}
```

wire（`schemas.ts` の snapshot）には、画面が要る分だけを `session.break?: { since: number | null; suggestedAtSwitches: number | null; suggestedAtElapsedMs?: number | null }` として載せる（計画の段で確定。`suggestedAtElapsedMs`〔知らせた時点の稼働の累計〕は PR #416 の再レビューで足した。現状維持の交代は回数を進めないので、回数だけでは帯の出し入れと 2 回目以降の知らせを判定できない。後から足したのでそれ自体も任意で、無ければ画面は帯を出さない）。`baseline` は画面が使わないので載せない。**この項目は任意にする**。理由は、`deploy.sh timer` が web を先に配るので、新しい画面と古いサーバーが並ぶ窓ができるため。`previousDriverIndex` と同じ判断である。

### 3.2 判定

`isBreakDue(agg, policy, eligibleSeats): boolean` は純粋関数とする。

- `trigger: "none"` なら常に偽
- `elapsed` なら、`accumulatedElapsedMs − 基準.elapsedMs ≥ every × 60_000` のとき真
- `rounds` なら、`totalSwitches − 基準.switches ≥ eligibleSeats × every` のとき真。**`eligibleSeats ≤ 1` なら常に偽**（輪が 1 人だと交代回数が増えないため。`evolve.ts` の現状維持の交代）
- 基準は、自動なら `baseline`、知らせるだけなら `suggestedAt ?? baseline`。知らせても休まなかった場合は、次の間隔ぶん経ったときにもう一度知らせる（交代のたびには知らせない）

`eligibleSeats`（適格な席の数）は呼ぶ側が渡す。席が適格かどうかは名簿の在席で決まり、それを知っているのはアプリ層だからである（`advanceDriver` が不適格な添字の集合を受け取るのと同じ形）。

### 3.3 イベント

| イベント | 集約への効果 |
|---|---|
| `BreakStarted`（既存） | 時計を凍結（既存）。`since = now`、`baseline` を今の値で書き直し、`suggestedAt = null`。**一時停止中なら `isPaused` を解く**（止まっている状態を 2 つ重ねない） |
| `BreakEnded`（既存） | `since = null`（**早期 return の経路でも必ず**）。凍結した残り時間から再開（既存） |
| `BreakSuggested`（新規） | `suggestedAt` を今の値で書く |
| `SessionCompleted` / `SessionAborted` | **時計を止め、休憩の状態を畳む**（§3.5） |
| `SessionStarted` | 休憩の状態を初期化する（`since = null`・`baseline = いまの稼働時間と交代回数`・`suggestedAt = null`）。開始は回数と稼働の累計を畳まないので、基準を 0 にすると、引きずった集約に START が届いたとき開始直後に条件を満たす（PR #416 のレビュー・2026-10-16） |
| `SessionReset` | 集約を作り直すので、休憩の状態も初期値（`baseline = 0/0`）に戻る |
| `PhaseSet` | `phase === "session"` なら集約を変えない。**それ以外（ロビーへ戻るなど）では、完成・中断と同じく時計を止めて休憩を畳む**。休憩中にロビーへ戻ると休憩の状態が残っていた（PR #416 のレビュー・2026-10-16） |

`stopWithoutDriver` の注記（`evolve.ts` の「休憩中かどうかは集約に無く、ルームの `onBreak` が持つ」）は書き換える。
`sessionHasStarted` は、START と同じミリ秒で休憩に入った場合に備えて、`break.since !== null` も見る。`aggregate.ts` に置き、`evolve`（運転中の席を外したときの直前のドライバー）と `decide`（開始前の `break.start` の拒否・§3.4）が共有する。

### 3.4 コマンド（`decide`）

- `break.start`: 休憩中でなければ `BreakStarted`。休憩中なら `OnBreak` で拒む。**セッションが始まっていない（`sessionHasStarted` が偽。時計が一度も走っていない）なら `PhaseConflict` で拒む**。通すと `break.end` が `SessionStarted` を経ずに時計を走らせる（PR #416 のレビュー・2026-10-16）
- `break.end`: 休憩中なら `BreakEnded`。休憩中でなければ拒む
- **休憩中は、時計を動かす操作をすべて拒む**。規則は「`break.since !== null` なら `session.act` の全種と `driver.assign` を `OnBreak` で拒む」で、一覧では書かない（START・RESTART も含む）
- 休憩中も通すもの: `break.end`、名簿の操作（出入り・並べ替え・代理・一時離脱）、メモ、`session.complete` / `session.abort`、`session.reset`（「最初から」。集約を作り直すので休憩の状態も初期値に戻り、休憩を終えて先頭から走り出す。実装の段で裁定・2026-10-16）

「セッション中か」は集約が phase を持たないので `decide` では判定できない。`break.start` の phase の事前条件と `config.set` の拒否は、アプリ層の事前条件（`apps/tasuki-sync/src/application/room-commands/preconditions.ts`）に置く（§4.4）。

### 3.5 完成・中断で時計を止める（既存の欠陥の修正）

いまは `SessionCompleted` / `SessionAborted` が集約に触らない。そのため完成したあとのロビーでも時計が走り、`reconcileSchedule` が自動交代を予約する（検証役が実測。START → 60 秒 → complete → `phase.set setup` で `{phase:"setup", running:true}` のまま `schedule 240` が呼ばれた）。休憩を入れると、これがロビーを休憩の覆いで埋める欠陥に育つ。**ここで直す**。

### 3.6 設定

```ts
interface BreakPolicy {
  trigger: "none" | "elapsed" | "rounds";
  every: number;          // elapsed なら 30/45/60/90、rounds なら 1/2/3/4
  mode: "auto" | "suggest";
}
// TimerConfig
break?: BreakPolicy;      // 無ければ trigger: "none" と同じ
```

- 選択肢の表（`BREAK_ELAPSED_MINUTES` / `BREAK_ROUNDS`）を定数で持ち、`SessionConfigSchema` で組み合わせごとに検証する。**room.create は `decide` を通らないので、検証はスキーマに置く**
- `decideConfigSet` の白リストに `break` を足す（足さないと黙って落ちる）
- `TimerConfig.breakEveryRotations` は消す。ルームの設定はサーバーのメモリにしか無く（端末の `localStorage` は個人の通知設定だけを持つ）、配布でルームが消えるので、旧値を引き継ぐ問題は起きない。古い画面が `breakEveryRotations` を送ってきても、`v.object` が未知のキーを捨てる

### 3.7 不変条件（`properties.test.ts`）

- 時計が走っているなら、休憩中ではない（`clock.running ⇒ break.since === null`）
- 休憩中なら、一時停止ではない（`break.since !== null ⇒ !isPaused`）

## 4. 同期サーバー（`apps/tasuki-sync`）

### 4.1 判定をかける場所

交代の経路を数え上げるのではなく、**交代の切れ目が来たか**という仕組みで判定をかける。

- 共通の関数 `maybeBreakAfterSwitch(before, after, now)` を置く。呼ぶのは、`handleRoomCommand` の事後処理（`applyAfterEffects`）のあと、コミットの直前と、`autoSwitch` のコミットの直前である
- この関数は、**交代の切れ目が来たときだけ** `isBreakDue` を見る。切れ目は「`totalSwitches` が増えた」または「時計が走っていて `accumulatedElapsedMs` が増えた（交代の再アンカー・やり直しで稼働時間を確定した）」
  - 手での交代・強制指名・スキップの繰り上げ・自動交代・不在の繰り上げを、経路を名指しせずに覆う
  - **経過時間の判定は、現状維持の交代でも走る**（1 人の輪や他が全員不適格の輪で、経過時間の休憩が来るように。現状維持の交代は回数を増やさないが、時計を再アンカーして稼働時間を確定する。PR #416 のレビュー・2026-10-16）
  - 並べ替え・名簿の出入り・メモの更新では、判定は走らない（どちらの値も動かさない）。一時停止・休憩・ロビーへの戻りは時計を止めるので、切れ目に当たらない
- 条件が「なし」なら、適格な席を数えずに返す。適格な席の数は周回の条件のときだけ数える
- `phase !== "session"` なら判定しない
- 適格な席の数は `computeIneligibleIndices` から出す

判定が真のとき:
- **自動**: 交代したあとの集約に `BreakStarted` を同じ `now` で当てる。次の人の残り時間は満タンのまま凍結され（`freezeRunningClock` の加算は 0）、時計が止まるので `reconcileSchedule` が予約を解除する
- **知らせるだけ**: `BreakSuggested` を当てる

### 4.2 休憩明けの繰り上げ

`break.end` の事後処理で、現ドライバーが `computeIneligibleIndices` に入っていれば（一時離脱・切断・名簿から抜けた）、`advanceDriver` で次の適格な人へ繰り上げる。そのうえで予約し直す。

休憩中は時計が止まっているので、不在の繰り上げ（`presence.ts` の不在タイマー）と `driver.skip` の繰り上げは何もしない。休憩明けにこの再評価を 1 回通すので、取りこぼさない。

### 4.3 シグナル（計画の段で改訂・2026-10-16）

**新しいシグナルは足さない。** 計画の段で現物を読むと、画面は `switch` シグナルを使っていなかった（`dispatch.ts` の `onSwitchSignal` に配線が無い）。交代の知らせ（`use-switch-alert.ts`）は、snapshot の `currentIndex` と名前の変化から検知している。休憩の知らせも同じく、snapshot の `session.break` の変化から検知する（§5.6）。

- `switch` シグナルの配信は今のままにする（読み手が居ないので、休憩に入る交代で止めても何も変わらない）
- 既存の `suggest-break` シグナル（読み手も書き手も居ない）は wire から消す
- 誰が休憩を始めた・終えたかは、既存の `notice`（FR-077）に `break-started` / `break-ended` を足して出す。古い画面がこの `notice` を受けると契約に合わず捨てるが、捨てたのが `signal` なので画面は古くならない（`stale-frame.ts` の表。`console.warn` が 1 行出るだけ）

### 4.4 事前条件

- `break.start` / `break.end` は `phase === "session"` のときだけ受け付ける
- **`config.set` は `phase === "session"` なら拒む**。いまは一時停止中や休憩中に間隔を変えると、凍結した残り時間が満タンで上書きされる。設定はロビーだけで変える（D7）ので、拒んでよい
- 拒否の文言は、既存の内部エラーの文言の流儀（#381 でそろえたもの）に合わせる

### 4.5 片付け

- ルームの状態の `onBreak` を消す。wire の `Room.onBreak` は残すが、`break.since !== null` から導く。古い画面がこれを必須で読むので、窓の間は残す必要がある
- `apply-room-level-event.ts` の `BreakStarted` / `BreakEnded` の case を消す（集約が持つので）
- `build-domain-command.ts` で `break.start` / `break.end` を通す
- `scheduler-sync.ts`・`handlers.ts` の「休憩は撤去した」という注記を書き換える

### 4.6 回収（変えない）

回収の仕組み（`room-reclaimer.ts`）は名簿だけを見る。休憩中のルームでも、全員が offline のまま `ROOM_IDLE_TTL_MS` を超えれば消える。これは揮発インメモリの方針（憲法 III）どおりの振る舞いとして受け入れる。回収役が timer の状態を知るように依存の向きを変えることはしない。伝え方は §5.4。

## 5. 画面（`apps/timer-web`）

### 5.1 ロビーの設定（`SessionConfigPanel` の「詳細設定」）

- 「休憩の条件」で、なし／経過時間／周回を選ぶ
- なし以外を選ぶと、間隔と入り方（自動／知らせるだけ）が現れる。「促」が base 層に無いので、「促す」という語は使わない
- 周回のときは「約 N 分ごと」の目安を添える。N は交代間隔 × 適格な人数 × 周回数で、3 分交代・2 人・1 周（約 6 分ごと）のような組み合わせに気づけるようにする

### 5.2 セッション画面

- 「休憩する」は、条件が「なし」以外のときだけ操作帯に出す。添え書きは「次の休憩までを数え直します」とする
- 操作帯が折り返したときの `scroll-padding`（`packages/ui/src/elements/reset.css`）の崩れは、実画面で確かめる

### 5.3 休憩の覆い（`break.since !== null` の間、全員の画面に出す）

- 中身:
  - 見出し「休憩中」
  - 経過の数え上げ（`now + clockOffset − since`）
  - 「休憩明けは X さん」
  - 「休憩を終える」
  - 回収の警告の 1 行（§5.4）
  - 「完成」と、自分の「一時離脱」
- 交代の残り時間の円は隠す
- `use-now-tick` を広げて、休憩中も時刻を更新する（いまは時計が止まると更新も止まる）
- **初期フォーカスは見出しに置き、Esc では何もしない**。共有メモに入力していた Enter が「休憩を終える」を押してしまうのを防ぐ。覆いはサーバーの状態から出しているので、手元では閉じられない
- 色はトークンだけで書く。コントラストの走査に休憩中の画面を足す

### 5.4 回収の警告

- 覆いに常に 1 行出す: 「全員がこの画面を閉じると、しばらくしてルームは消えます。」。回収までの時間はサーバーの環境変数で変わるので、数は書かない
- 自分以外の全員が offline の間は、この 1 行を「あなたが最後の一人です。この画面を閉じると、しばらくしてルームは消えます。」に切り替え、`beforeunload` の確認を登録する
- ブラウザの仕様上、`beforeunload` の文言は既定の「このサイトを離れますか？」になり、こちらの文は出せない。覆いの 1 行がその説明を担う
- **届かない場面**: スマホでブラウザごと落とされたときと、スリープで切れたとき。この 2 つは受け入れる

### 5.5 知らせるだけの帯

- 休憩中でなく、かつ `suggestedAtSwitches === totalSwitches` と `suggestedAtElapsedMs === clock.accumulatedElapsedMs`（いまの切れ目で知らせた）のときに、画面の上部に帯を出す。`suggestedAtElapsedMs` が無い snapshot（古いサーバー）では出さない。文言は「休憩の時間です」と「休憩する」
- シグナルからではなく snapshot から導く。こうすると、再接続した人や途中で入った人にも帯が出る
- 次の切れ目で帯は消える。交代は `totalSwitches` を進め、現状維持の交代（1 人の輪・他が全員不適格）は回数を進めないが稼働の累計を確定するので、どちらでも一致が崩れる（PR #416 の再レビュー・2026-10-16）
- 一時停止でも累計が確定するので帯は消え、再開後は次の切れ目まで出ない。受け入れた（知らせはもう出ている。「休憩する」は操作帯に残る）

### 5.6 知らせ方

- snapshot の `session.break.since` が null から値へ変わったとき（入った）と、値から null へ変わったとき（終わった）、`suggestedAtElapsedMs` が新しい null でない値に変わったとき（知らせた。1 回目も 2 回目以降も）に、`notify.enabled` に従ってチャイムを鳴らす。`osNotify` なら OS 通知も出す。初回の描画（休憩中・知らせた後の再接続）では鳴らさない
- 知らせが交代と同じ snapshot に重なったとき（運転者が替わった）は交代のチャイムが鳴るので、休憩の知らせはチャイムと振動を出さず OS 通知だけにする。現状維持の交代で知らせたとき（運転者が替わらない）は交代のチャイムが鳴らないので、休憩の知らせがチャイムと振動も出す
- 休憩に入る交代では、`use-switch-alert` を発火させない。チャイムが 2 回鳴る・全画面の知らせが 2 枚重なる、を防ぐ
- 読み上げ（`use-discrete-announcement`）は「休憩に入りました。休憩明けは X さん」「休憩が終わりました。ドライバーは X さんです」の 2 つで、交代の文より優先する。終わりの文に運転者を含めるのは、休憩明けの繰り上げ（§4.2）が同じ snapshot で運転者を替え、交代の文が出ないため（PR #416 のレビュー・2026-10-16）
- 休憩中の時刻の更新は 1 秒ごと（覆いの経過は秒単位）。走行中は 200ms

### 5.7 書体

- 休憩の文言をすべて列挙し、base 層外の字は「休」「憩」だけであることを単体検査で守る。形は既存の `*fits-font-base*` と同じにする
- 条件が「なし」のルームの既定の画面（詳細設定を閉じた状態）には「休」「憩」を描かないことも、検査で守る（セッションの画面は文字と `title`・`aria-label`・`placeholder` 属性まで見る）。E2E の「書体は常用の層だけを取る」（`e2e/specs/timer-a11y.spec.ts`）は既定のルームで今のまま通る
- ロビーで詳細設定を開くと「休憩の条件」の見出しが出るので、条件「なし」のルームでも ext 層を取る。利用者の明示の操作なので受け入れた（2026-10-16・総合レビューの裁定）

実測（2026-10-16・`packages/ui/src/tokens/fonts.css` の zkgn-400-base）:

- base 層に無い字: 休・憩・促・目・安・誰・区・服・小・気・転・換
- base 層に収まる語: 「ブレイク」「止める」「再開」「終える」「経過」「周回」「自動」「知らせる」「時間」「交代」「全員がこの画面を閉じると、しばらくしてルームは消えます。」「あなたが最後です」

## 6. 振る舞い（EARS）

- 休憩の条件が「なし」のとき、システムは今と同じように交代を続け、休憩の表示も操作も出さないこと
- 休憩の条件が「経過時間」で入り方が「自動」のとき、前の休憩からの稼働時間が設定した時間に達したあとの最初の交代で、システムは時計を止めて全員の画面を休憩の表示にすること
- 休憩の条件が「周回」で入り方が「自動」のとき、前の休憩からの交代回数が「適格な席の数 × 設定した周回」に達した交代で、システムは時計を止めて全員の画面を休憩の表示にすること
- 入り方が「知らせるだけ」のとき、条件に達した交代で、システムは時計を止めずに全員の画面へ休憩の知らせを出すこと
- 休憩の条件を設定したルームのセッション中に参加者が「休憩する」を押したとき、システムは時計を止めて全員の画面を休憩の表示にすること
- 休憩中、システムは交代の残り時間を消費せず、時計を動かす操作を拒むこと
- 参加者が「休憩を終える」を押したとき、システムは休憩に入る前の残り時間から交代のタイマーを再開すること。現ドライバーが適格でなければ、次の適格な人へ繰り上げてから再開すること
- 休憩中、システムは一時停止とは違う表示（盤面を覆う表示）で、休憩中であることを全員に示すこと
- 休憩中に自分以外の全員が offline のとき、システムはその人に、画面を閉じるとルームが消えることを示すこと
- 交代で休憩に入ったとき、システムは交代の知らせを出さず、休憩の知らせだけを出すこと
- 完成または中断したとき、システムは時計を止め、休憩の状態を畳むこと

制約: 全員が offline のまま `ROOM_IDLE_TTL_MS` を超えたルームは、休憩中でも消える（§4.6）。
