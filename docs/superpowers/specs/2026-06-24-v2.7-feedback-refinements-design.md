# v2.7 実機フィードバック リファインメント 設計

- 日付: 2026-06-24
- 対象: `tdd-mob-pro-timer/apps/web`（core/サーバー変更なし）
- 種別: バグ修正＋UX改善＋新機能（v2.6 実機フィードバック5点）
- 方針: 方針A（既存パターン準拠の的を絞った改修）。音源生成は v2.6 の「ffmpeg＋同梱mp3」を踏襲し、TTS は AivisSpeech 呼び出しを追加。

## 背景（v2.6 実機フィードバック）

1. **バグ: 自然交代（タイマー）で音/通知が出ない。手動スキップでは出る。**
2. 音設定の導線がわかりにくく気づかれなかった。
3. チャイムが単音で気づきにくい。もう少し一定時間続く感じに。
4. movie プロジェクトの TTS で「ドライバー交代です」を男声/女声で流したい（新機能）。
5. 参加者一覧の見た目がごちゃごちゃ。整理する。

## 根因確定（#1）

`Session` は `key={room.code}` で交代時に再マウントせず（`prevIndexRef` 保持）、手動スキップも自然交代も同じ `SWITCH`。`useSwitchAlert` の検知 effect は両方で走る。差は「直前にユーザー操作があるか」だけ：
- `platform/sound.ts` の `playTones` は呼び出し時に `if (suspended) void ctx.resume()` するが **resume を await せず**にオシレーターをスケジュールする。
- 交代間隔（数分）中にユーザー無操作だと**ブラウザが AudioContext を自動 suspend**。自然交代発火時、resume 未完了のまま `osc.start` され**無音**。
- 手動スキップは直前のクリック（ユーザー操作）で context が running のため鳴る。
- ファイル音（HTMLAudioElement）は sticky activation で idle 後も再生されるため、この経路の影響を受けない。

## ユーザー確定事項

- #1: 修正必須。既定音をファイル音にして二段構えで堅牢化。
- #2: 歯車をラベル付きボタン化＋ポップオーバー拡大・状態明示＋ロビーにも設定＋初回案内（全部）。
- #3: 単音を減らし「デパート呼び出し風／メロディ／持続音」へ。

- 既定音: デパート呼び出し風。

## #1 交代音バグ修正（最優先）

### 設計
- `platform/sound.ts` の `playTones` を **async 関数**化し、`getSharedAudioContext()` 取得後に `if (ctx.state === "suspended") await ctx.resume()`、その後で `const now = ctx.currentTime` を取得しオシレーターをスケジュールする。resume 失敗時は try/catch で従来どおり黙って無視。
- 呼び出し側 `playChime` は `play(volume)` を呼ぶだけ（戻り値の Promise は `void` で握りつぶす＝発火しても待たない）。`Chime.play` の戻り値型は `void`（内部 async の fire-and-forget）。
- 既定音をファイル音（`department`）にすることで、synth の suspend 経路を通らずに「自然交代で鳴る」を即達成（#3 と連動）。
- 実機検証で「通知（オプション）」の挙動（オーバーレイ＝assertiveSwitch、OS通知＝document.hidden）も自然交代で確認する。

### 単体テスト
- `playTones`（間接的に `playChime`）が AudioContext 無し環境（jsdom）で例外を投げない（既存）。
- `playChime(id, volume)` の no-throw・registry 整合（既存を維持）。
- 注: 実際の「suspend→resume後発音」は jsdom で検証不可。**実機検証で担保**（自然交代で既定ファイル音＋synth 音の両方が鳴ること）。

## #2 設定の発見性

### 設計
- `StatusStrip`: 歯車アイコンのみ → **「🔔 通知」ラベル付きボタン**（lucide Bell＋テキスト）。`NotifySettings` のトリガーを差し替え。
- `NotifySettings` ポップオーバー: 幅を拡大（w-64→w-80 程度）、先頭に**現在状態を大きく明示**（「通知: ON / 音: 呼び出しチャイム」など）。
- **ロビーにも通知設定**: ロビーの「ルーム」タブ（開始ボタン近傍）に通知設定カードを出す。`NotifySettings` の内側 UI を `NotifySettingsPanel`（純粋表示＋onChange）に抽出し、ポップオーバー（StatusStrip）とロビーカードの両方から再利用する。
- **初回案内**: 初回セッション開始時に一度だけ「交代を音で知らせられます（通知）」の軽いヒント（dismiss 可、`localStorage` キー `tdd-mob:notify-hint-seen:v1` で抑制）。`local-prefs.ts` に seen フラグの get/set を追加。

### 単体テスト
- `NotifySettingsPanel`: ON/OFF・音選択・音量・試聴が onChange/playChime を正しく呼ぶ（既存 NotifySettings テストを Panel ベースに移植）。
- ロビーに通知設定が表示される（Lobby テストに1ケース）。
- 初回ヒント: seen=false で表示、dismiss で seen=true 保存、seen=true で非表示（フックまたはコンポーネントの単体テスト）。

## #3 チャイム刷新（気づきやすい・持続）

### 設計
- `scripts/gen-sounds.sh` を拡張し、ffmpeg で以下を追加生成（既存同様コミット）:
  - `department.mp3`: デパート呼び出し風（ピンポンパンポーン・4音 上昇下降、約1.3秒）。
  - `melody.mp3`: 4〜6音の短いメロディ（約1.3秒）。
  - `sustained.mp3`: 持続トーン（緩い2回パルス＋減衰、約1.8秒）。
- `CHIMES` registry を整理（最終8種・全 `isReady:true`）:
  1. `department`「呼び出しチャイム」(file・**既定**)
  2. `melody`「メロディ」(file)
  3. `sustained`「持続トーン」(file)
  4. `voice-male`「音声（男声）」(file・#4)
  5. `voice-female`「音声（女声）」(file・#4)
  6. `chime-up`「上昇2音」(synth)
  7. `chime-down`「下降2音」(synth)
  8. `bell`「ベル」(file・既存)
- 削除: `soft`（小音量単音）, `ping`, `knock`（単発で気づきにくい）。対応 mp3（ping/knock）も削除。
- `DEFAULT_NOTIFY_PREFERENCES.soundId` を `"department"` に変更（既存ユーザーの保存値が削除済み id の場合、`playChime` の未知 id フォールバックで `department` が鳴るよう、フォールバック先を既定 soundId に合わせる）。

### 単体テスト
- registry が最終8種・id ユニーク・全 isReady。`soft`/`ping`/`knock` は含まない。
- `playChime("soft", v)`（削除済み id）が例外なくフォールバック再生される。
- 既定 soundId が `"department"`。

## #4 TTS音声アナウンス（新機能）

### 設計
- `scripts/gen-voices.sh`: **AivisSpeech（http://127.0.0.1:10101）** に対し
  `POST /audio_query?text=ドライバー交代です&speaker=<styleId>` → `POST /synthesis?speaker=<styleId>`（body=audio_query の JSON）で wav を取得 → ffmpeg で mp3 化。
  - 男声・女声の2スタイルで生成し `apps/web/public/sounds/voice-male.mp3` / `voice-female.mp3` に保存。
  - 候補スタイルID: 男声=`morioki`(497929760)、女声=`fumifumi`(606865152)。**生成後に実機で性別・明瞭さを確認し、不適なら別スタイルIDへ差し替え**（スクリプト先頭の変数で切替可能に）。
  - エンジン非稼働環境では生成不可だが、**生成物（mp3）はコミット**するためアプリ実行時にエンジン依存はない（オフライン再生可）。スクリプト冒頭でエンジン応答を確認し、未稼働なら明示エラーで停止（既存 mp3 は保持）。
- registry にファイルチャイム `voice-male`/`voice-female` を追加（#3 の registry に含む）。

### 単体テスト
- registry に `voice-male`/`voice-female` が存在し isReady（#3 のテストに含む）。
- 実発音は実機検証（男声/女声で「ドライバー交代です」が鳴る・性別が妥当）。

## #5 参加者一覧の整理

### 設計
- `RosterPanel` を**セクション分割**して描画:
  - 「ドライバー」セクション: rotation 内の参加者。**現ドライバーを最上部**、以降は rotation 順。
  - 「見学」セクション: rotation 外の参加者。
- 各行を**情報の階層化**: 名前を主役（`text-base` 程度・太め）。順番番号・在席ドット・役割は控えめなメタ（小さめ・低彩度）に。在席「オンライン」テキストチップは廃しドット＋`sr-only` に集約。役割は host/viewer のみ小バッジ、editor は無表示（既定のため）。現ドライバー行は朱の枠＋「▶ 今」を維持。
- 操作（改名/一時離脱/復帰/譲る/外す/並べ替え）は**維持**（折りたたみはしない）。2段目に控えめ配置の現行方針を踏襲。
- 既存 props（participants/rotation/currentDriverName/各ハンドラ）は不変。並べ替えの index 計算（rotation 内位置）も不変。セクション分割は描画時の振り分けのみ。

### 単体テスト
- ドライバー/見学のセクション見出しが出る。
- 現ドライバーがドライバーセクションの先頭に来る。
- 在席「オンライン」テキストチップが無くなり、presence は `sr-only`＋ドットで提供される（a11y 維持）。
- 既存の操作（改名/離脱/並べ替え）テストが維持される（セレクタ更新は最小限）。

## 影響範囲とリスク

- **core/サーバー変更なし**。すべて `apps/web` 内。
- **新規バイナリ資産**: `public/sounds/{department,melody,sustained,voice-male,voice-female}.mp3`（生成・コミット）。削除: `{ping,knock}.mp3`。
- **localStorage**: `NotifyPreferences.soundId` 既定変更（`department`）＋初回ヒント seen フラグ追加（後方互換・既定補完）。削除済み id の保存値はフォールバックで安全。
- **AudioContext**: `playTones` を async 化（resume を await）。`playChime`/`playSwitchChime` の同期シグネチャは維持（内部 fire-and-forget）。
- **抽出**: `NotifySettings` から `NotifySettingsPanel` を抽出しロビーと共用（DRY）。
- リスク: AivisSpeech のスタイルが男声/女声の想定と異なる可能性 → 生成後に実機で確認・差し替え。自動再生ポリシーはブラウザ差あり → 実機（Chrome/Firefox/Safari 系）で自然交代の発音確認を完了条件に含む。
