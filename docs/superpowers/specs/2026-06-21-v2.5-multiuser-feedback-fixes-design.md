# v2.5 複数人利用フィードバック対応 設計

- 日付: 2026-06-21
- 対象: `tdd-mob-pro-timer`（`apps/web` 中心・core への追加は最小）
- 種別: UX 改善（複数人での実利用フィードバックに基づく 5 件の修正）
- 方針: **既存パターンに沿った的を絞った改修**（方針 A）。象徴ビジュアル `TeamOrbit` は維持し、可読性の弱点を追加レイヤーで補う。

## 背景

複数人での実利用フィードバックで、以下 5 件の問題が判明した。いずれも「機能不足」というより
「既定値・配線・見せ方」の問題であり、core の状態機械やサーバー同期の変更はほぼ不要。

| # | フィードバック | 本質 |
|---|---|---|
| 1 | 交代時にブラウザが隠れていると気づけない。音などで知らせて | 強い交代通知が**ルーム設定で既定 OFF**＋OS 通知が**未配線**。背面タブでは Web Audio が抑制されることも |
| 2 | 言語・お題を必ず選ばせるが要らないときもある | UI の `disabled={!room.problem}` が**お題を事実上必須化**。core は START にお題を要求していない |
| 3 | 共有メモは基本プレビュー、編集は一部だけ | 全員が**初期 edit モード**で誰も読まない／編集者がプレビューに戻さず**更新が気づかれない・目立たない** |
| 4 | 順番と誰が選ばれているか分かりにくい | `TeamOrbit` は綺麗だが**並び順が追えない**・**「自分の番がいつ来るか」が見えない**・現ドライバー強調が弱い |
| 5 | ドライバーへの参加方法が分かりにくい | 参加後 editor だが rotation 外（見学状態）。**ドライバー加入が 2 段階目**で気づかれない |

## 全体方針（YAGNI）

- core/サーバーへの変更は **#2 の `SessionConfig.problemEnabled`（任意 boolean 1 個）のみ**。他はすべて `apps/web` 内。
- 個人の通知設定は**ルーム設定と独立した自分のデバイス設定**として `local-prefs.ts` に持つ。
- ロビーで決まる「お題なし」「ドライバー宣言」は**ルーム/参加者状態に反映**して全員で一致させる。

---

## #1 交代通知（個人設定・既定 OFF・5 種チャイム・背面 OS 通知）

### 要件
- 通知は**個人ごとの任意設定**。既定 **OFF**。`localStorage` に永続。
- **5 種**のチャイムから選択（合成音と音声ファイル再生の混在）。試聴できる。
- **タブが隠れている時（`document.hidden`）だけ** OS デスクトップ通知も発火。
- ルーム設定 `assertiveSwitch`（全員に適用する全画面オーバーレイ）とは**独立**。

### 設計
- `prefs/local-prefs.ts` に新キー `tdd-mob:notify:v1` を追加:
  ```ts
  interface NotifyPreferences {
    enabled: boolean;      // 既定 false
    soundId: string;       // 既定 "chime-up"
    osNotify: boolean;     // 既定 true（enabled 時のみ意味を持つ）
  }
  ```
  `loadNotifyPreferences()` / `saveNotifyPreferences()`（破損時は既定にフォールバック、既存の言語プール実装と同じ堅牢さ）。
- `platform/sound.ts` を**名前付きチャイム registry**に拡張:
  ```ts
  interface Chime { id: string; label: string; play(): void; }
  export const CHIMES: Chime[]; // 全 5 種
  export function playChime(soundId: string): void;
  ```
  - **既定の 5 種 = 合成音 4＋音声ファイル 1**:
    1. `chime-up`（上昇 2 音・合成・既定）
    2. `chime-down`（下降 2 音・合成）
    3. `bell`（ベル・減衰長め・合成）
    4. `soft`（低音量ソフト正弦・合成）
    5. `voice`（音声ファイル・`public/sounds/voice.(mp3|ogg)`）
  - 音声ファイルは `HTMLAudioElement` で再生。**アセット未配置でも合成 4 種で完全に成立**し、`voice` は配置されるまでドロップダウンで「（準備中）」と無効表示にする。アセット入手後に有効化（合成/ファイルの比率はこの方針で固定。追加が来たら registry に足すだけ）。
  - `vibrateSwitch()` は併用維持（iOS Safari は vibrate を無視するため音と併用が前提）。
- `platform/notify.ts`（現 deprecated）を配線して有効化:
  - `requestNotificationPermission()` を**設定 ON 時に一度だけ**呼ぶ。
  - `notifyDriverChange(name)` は `document.hidden === true` のときだけ `new Notification(...)` を出す（前面時は音＋オーバーレイで足りるため OS 通知は出さない）。
- `ui/use-switch-alert.ts` を改修:
  - 交代検知のゲートを `assertiveSwitch`（ルーム）→ **個人設定 `enabled`** に付け替え。
  - 検知時: `playChime(soundId)` ＋ `vibrateSwitch()` ＋（`osNotify && document.hidden`）`notifyDriverChange()`。
  - 全画面オーバーレイ（`SwitchAlert`）は従来どおり**ルーム設定 `assertiveSwitch`** で出す（視覚的割り込みはホストの方針、音/OS 通知は個人の方針、と役割分離）。
- 操作 UI: `StatusStrip` に歯車ボタン → 小さなポップオーバー（`useFocusTrap` 流用）。
  - ON/OFF トグル・チャイム選択ドロップダウン・「試聴」ボタン・OS 通知 ON/OFF。
  - ON 化時に通知許可を要求。拒否されたら「OS 通知は許可されていません（音と振動は有効）」と表示。

### 単体テスト（例）
- `loadNotifyPreferences` の既定・破損フォールバック。
- `playChime("unknown")` が例外を投げない（黙って無視）。
- `useSwitchAlert`: enabled=false なら無音、enabled=true で currentIndex 変化時に再生関数が呼ばれる（モック）。
- `notifyDriverChange`: `document.hidden=false` では Notification を作らない。

## #2 お題なし開始（ルーム単位・コア最小追加）

### 要件
- 「お題が要らないとき」は**お題・言語の選択を要求せず**に開始できる。
- その状態は**ルーム単位**（ホストが決め、全員に一致して見える）。

### 設計
- core: `aggregate.ts` の `SessionConfig` に `problemEnabled?: boolean`（既定 true）を追加。`schemas.ts` の config スキーマにも `v.optional(v.boolean())`。`config.set` は既に `Partial<SessionConfig>` を受けるため**コマンド追加不要**。START 処理は元々お題非依存なので変更なし。
- `apps/web` Lobby:
  - 「お題・設定」タブに「**お題を使う／使わない**」トグル（host が `config.set({ problemEnabled })`）。
  - `problemEnabled === false` のとき: お題セクションと言語選択を隠し、ヒント文「お題なしで進めます」。
  - 開始ボタンの活性条件を `problemEnabled ? !!room.problem : true` に変更（お題なしなら常に開始可）。
- `apps/web` Session: `problemEnabled === false`（または `problem == null`）のときお題エリアを畳む。

### 単体テスト（例）
- config スキーマが `problemEnabled` を受理し、未指定でも valid。
- 開始ボタン活性ロジック: `problemEnabled=false` で `problem=null` でも活性。

## #3 共有メモ プレビュー優先＋更新の可視化

### 要件
- 既定は**全員プレビュー**（編集権がある人も最初は読む側）。
- 編集は「編集」ボタンによる**明示的な能動アクション**。
- メモが**更新されたら目立つ**（ハイライト＋読み上げ通知）。

### 設計
- `ui/components/SharedMemo.tsx`:
  - 初期モードを内容有無に関わらず `"preview"` 固定（空のときは「まだメモはありません」プレースホルダ＋「編集」ボタン）。
  - editor+ は preview 時に「**編集**」ボタンを表示。押下で edit に入り、blur/「プレビューに戻る」で `onCommit`。
  - **更新ハイライト**: `note` prop（サーバー snapshot 由来）が前回値と変わったら、カードを短時間ハイライト（朱の枠 1.5s）＋ `aria-live="polite"` で「共有メモが更新されました」。
    - 自分の編集による更新で鳴らないよう、直近に自分が commit した値は抑制（`lastCommittedRef` と比較）。
  - `useState` 初期値固定の罠を解消: `note` 変化に追従しつつ、編集中（mode==="edit"）はドラフトを保持。

### 単体テスト（例）
- 初期表示が常に preview（内容あり/なし両方）。
- `note` が外部更新されたら「更新されました」アナウンスが出る。
- 自分の commit 直後の同値更新では更新アナウンスを出さない。

## #4 順番・現在・「自分の番がいつ来るか」（1＋2＋3）

### 要件
- 並び順（1→2→3…）が**直感的に読める**。
- 現ドライバーの**強調を強める**。
- **各人が「自分の番がいつ来るか」を知れる**（自分基準を特に強調）。

### 設計
- 新コンポーネント `ui/components/RotationLineup.tsx`（`TeamOrbit` の**直下に常時表示**）:
  - rotation 順に番号付きで横（モバイルは折返し）に並べる。各エントリに「自分の番がいつ来るか」を注記:
    - 現ドライバー: `▶ 今`
    - 次: `⟶ 次`
    - それ以降: `あと N 人`＋交代間隔から概算した `約 M 分後`（`intervalSeconds × N` から算出、一時停止中は概算を抑制）。
  - **自分の行を特に強調**（朱の枠＋「あなた」バッジ）。先頭に自分基準サマリ「**あなた: あと N 人・約 M 分後**」（自分が今ドライバーなら「あなたの番です」）。
  - 離脱中/見学中の状態も色＋テキストで併記（開始後の各人の状況が一目で分かる）。
- `TeamOrbit` の現ドライバー強調を増強（②）: Crown ＋朱発光を一段強く。並び順自体はストリップに委ね、オーブは「今・次」の視認に集中。
- 既存 `RosterPanel`（番号付き・現ドライバーハイライト済み）は管理操作の場として維持。Lineup は「読む」ための軽量表示として役割分担。

### 単体テスト（例）
- N 人で currentIndex を動かしたとき各エントリの「あと N 人」が正しい（循環）。
- 「自分」の位置と「約 M 分後」が intervalSeconds から正しく算出される。
- 一時停止中は「約 M 分後」を出さない。

## #5 ドライバー参加導線（参加時宣言を必須化＋セッション中の強化）

### 要件
- 参加時に**ドライバー/見学を必ず選ばせる**（デフォルトなし・選ぶまで参加不可）。
- セッション中、rotation 外の人に**目立つ加入導線**を出す。
- 開始後の各人の状況を見やすく（#4 の Lineup と連携）。

### 設計
- `ui/Join.tsx`:
  - 「**どう参加しますか？**」セグメント（`ドライバーとして参加 / 見学で参加`）を追加。**初期未選択**。
  - 参加ボタンは「名前あり **かつ** 役割選択済み」で活性（未選択時は無効＋ヒント）。
  - 「ドライバーとして参加」選択時、参加成功直後に rotation 加入（`member.add` 相当）を自動送信。見学はそのまま rotation 外。
  - ドライバー宣言の有無を `local-prefs` の既定にも反映（次回の初期選択ヒント。ただし必ず明示選択は維持）。
- `ui/Session.tsx`:
  - rotation 外（見学中）の自分に、`SelfDriverToggle` を**空状態バナーとして強調**（「あなたは見学中です。交代の輪に入りますか？ → ドライバーに加わる」）。控えめなトグルから、気づける常設バナーへ格上げ。
- Setup（ホスト作成フロー）はホストが最初の rotation メンバーになる既存挙動を維持（宣言 UI はゲスト参加者向け）。

### 単体テスト（例）
- Join: 役割未選択では参加ボタン無効。
- Join: 「ドライバー」選択で参加すると member.add 相当が送られる。
- Session: rotation 外のとき加入バナーが表示され、加入後は消える。

## 影響範囲とリスク

- **core 変更**: `SessionConfig.problemEnabled` 追加のみ（後方互換・既定 true）。既存ルーム/スナップショットに影響なし。
- **サーバー**: 変更なし（config.set 経由）。
- **localStorage**: 新キー追加のみ。既存 `preferences:v1` に影響なし。
- **デザイン**: `TeamOrbit` は維持。Lineup は追加レイヤーで象徴ビジュアルを壊さない。
- **アセット依存**: #1 の音声ファイル系チャイムは public/sounds 配置が前提。未配置でも他チャイムで成立するよう縮退設計。
- テスト: 各項目に単体テストを追加。全体で `pnpm test` 緑・`pnpm build` 緑・typecheck 緑・実機目視（複数タブでの交代通知・お題なし開始・メモ更新・Lineup・参加導線）を完了条件とする。
