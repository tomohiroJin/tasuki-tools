## F1 — 一時停止の残量凍結（#2a）

**要件**:
- F1-1: セッション稼働中に一時停止すると、タイマーは**押下時点の残量で停止**する（満タンに戻らない）。
- F1-2: 再開すると凍結した残量から続行する。

**設計**: `packages/core/src/evolve.ts` の `evolveSessionPaused` を変更。停止前の残量 `remaining = max(0, secondsLeftAtAnchor − (now − anchorServerTime)/1000)` を算出し、`secondsLeftAtAnchor = remaining`・`anchorServerTime = now` を設定（`running=false`・`accumulatedElapsedMs` 加算は維持）。`secondsLeft` は停止中 `secondsLeftAtAnchor` を返すため、これで正しい残量が出る。`evolveSessionResumed` は既に `anchorServerTime=now`・`running=true` を設定するため、凍結値から正しく継続する（変更不要）。

**影響**: `evolve.ts`（`evolveSessionPaused`）。core 内で完結。

---

## F2 — 休憩でタイマーを止める（#2b）

**要件**:
- F2-1: 休憩開始でタイマーが**実際に停止**する（一時停止と同じく残量凍結）。`onBreak` フラグは UI 表示用に維持。
- F2-2: 休憩終了でタイマーが凍結残量から再開する。

**設計**: `evolveBreakStarted`/`evolveBreakEnded` を新設し、`evolve` の switch で `BreakStarted`→`evolveBreakStarted(agg, now)`（F1 と同じ残量凍結＋`running=false`）、`BreakEnded`→`evolveBreakEnded(agg, now)`（再開＝`running=true`・`anchorServerTime=now`・`runningSince=now`）に割り当てる。`onBreak` フラグ自体はルームレベル（handlers の `applyRoomLevelEvent`）で従来どおり設定する（集約には載らない）。

**整合**: handlers の `reconcileSchedule` は `room.clock.running && !room.onBreak` で判定済みなので、休憩中は running=false かつ onBreak=true となり自動交代は止まる（二重防御・回帰なし）。

**影響**: `evolve.ts`（BreakStarted/BreakEnded を no-op から実装へ）。core 内で完結。handlers/UI は不変。

## F3 — リセット = 最初から再スタート（#3）

**要件**:
- F3-1: リセットで現セッションを**先頭ドライバー・タイマー満タン・走行状態**に戻す（お題・メンバー・設定・rotation 順は維持、`currentIndex=0`、`driverCounts`/`totalSwitches` は 0 にクリア）。
- F3-2: リセット後そのまま計測が続行され、session 画面で詰まらない。

**設計**: `evolve.ts` の `SessionReset` 適用を変更。現状 `initialAggregate(config)`（running=false）を、走行状態にする:
```
const fresh = initialAggregate(buildConfigFromReset(agg));
return { session: fresh.session, clock: { ...fresh.clock, running: true, anchorServerTime: now, runningSince: now } };
```
phase は変更しない（session のまま）。handlers の `reconcileSchedule` が running=true で自動交代タイマーを再アームする（既存経路）。

**影響**: `evolve.ts`（`SessionReset` ケース）。core 内で完結。

**注**: `EndSessionZone` のリセットは確認ダイアログ付きの host 操作。文言を「最初から再スタート」に合わせて見直す（web・任意）。

## F4 — モブ順のランダム化＋セッション中の並べ替え（#1）

**要件**:
- F4-1: host は rotation を**ランダムに並べ替え**できる（`member.shuffle`）。**サーバー権威**で順列生成。
- F4-2: セッション**非稼働時（ロビー）は全体をシャッフル**（先頭も変わる）。**稼働中は現ドライバーを現役に保ち**、残りをシャッフルする（現ドライバーがいきなり変わらない）。
- F4-3: セッション中の参加者一覧にも**手動並べ替え（ChevronUp/Down, host）**を出す（ロビーと同等）。

**設計**:
- core: 新コマンド `member.shuffle`（host 限定）。decide は**順列を入力**として受ける純粋関数にし、新イベント `MembersShuffled { order: number[] }`（`order[i]` = 新 i 番目に来る旧インデックス）を生成。evolve `evolveMembersShuffled` が rotation・driverCounts を `order` で並べ替え、`currentIndex` を「旧 currentIndex の参加者が新配列で来る位置」に remap。
- sync handlers: `member.shuffle` を host 限定で受け、**サーバーが順列を生成**（非稼働=全体 Fisher–Yates／稼働中=現ドライバー固定で残りをシャッフル）して `decide` に渡す。`Math.random` はサーバープロセスで使用可。
- web: `RosterPanel`（セッション）に host 用 ChevronUp/Down（`onMoveRotation`）を露出。ロビー/セッション両方に「ランダム」ボタン（host）→ `member.shuffle` 送信。

**影響**: `decide.ts`/`evolve.ts`/`schemas.ts`/`events.ts`（core）、`handlers.ts`（sync）、`RosterPanel.tsx`/`Session.tsx`/`Lobby.tsx`/`App.tsx`（web）。

**非対象**: シャッフルのアニメーション演出。

## F5 — 完了記録の履歴ビュー（#5）

**要件**:
- F5-1: 端末ローカル(IndexedDB)に保存済みの完了記録を**一覧表示する画面**を追加（お題タイトル/言語/難易度/所要時間/交代回数/日時）。
- F5-2: 既存の保存経路（自動＋明示）は維持。読み出しは既存 `loadRecords()` を使う。
- F5-3: 各記録の削除（既存 `deleteRecord()`）と、空状態（記録ゼロ）の案内を含む。
- F5-4: 履歴画面への導線（Setup または Summary から「記録を見る」）。

**設計**: 新コンポーネント `apps/web/src/ui/History.tsx`（`loadRecords()` で一覧取得・`deleteRecord()` で削除・EmptyHint で空状態）。App に `mode: "history"` を追加し、Setup/Summary から遷移。記録の保存・スキーマ（`CompletionRecord`）は不変。

**影響**: `App.tsx`（mode 追加・導線）、新 `History.tsx`、`Setup.tsx`/`Summary.tsx`（導線ボタン）。`records/indexeddb.ts`（`loadRecords`/`deleteRecord` は既存・変更なし）。

**非対象**: エクスポート/インポート UI（`records/io.ts` は既存だが本件では繋がない）。サーバー同期（記録は端末ローカルのまま）。

## 段階化（実装の単位）

性質で2グループに分かれるが、規模は中程度のため**1計画**でまとめて実装する（順序: core ドメイン → sync → web）:
1. **core/sync（F1/F2/F3/F4 ドメイン）**: 一時停止凍結・休憩凍結・リセット再スタート・shuffle コマンド。TDD でドメイン不変条件を固める。
2. **web（F4 UI/F5/F6）**: ランダム/並べ替え UI・履歴ビュー・既定7分。

完了条件: **全テスト緑（現 574 を維持/増加）・typecheck 緑・build 緑・production バンドル426**。フロント変更は dev 実機目視（接続/履歴/リセット/一時停止/休憩の挙動）。

## 横断的な決定・非対象

- 揮発インメモリ・サーバー権威タイマー・secret-zero・端末ローカル記録の既存設計は維持。
- 非対象: シャッフル演出、記録のエクスポート/インポート UI、記録のサーバー同期、大規模デザイン刷新。
