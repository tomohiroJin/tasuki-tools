## 1. 目的と方針

### 1.1 利用者の言葉（2026-09-27）

> 今の修正の仕方だとプルダウンという共通するデザインを別々に画面毎に作成してしまうことになり、デザインシステムの構築として思わしくない。また、他の部品についてもあわせて新しい画面が作られても統一感のある画面にしていかなければならない。

設計の対話で、利用者は方針を次のように述べた。

> もともと、各機能毎に画面はそれぞれのものとして、別々に考えるがデザインシステムとしての基礎部品は共通の利用できる状態のものを用意していけるように考えていた。あくまで使うかどうかは機能側の表現しだい。
> 最初から全ての部品を使うのではなく、DRY にする必要がある共通部品は一緒にする方針。
> 各機能は別々とはいえ、基本的には同じデザインシステムをベースとして統一感がある画面にしたい。

> 共有部品があっても機能側の見た目が大事なので必ずしも共通部品を使いなさいにしなくても良い。あくまで複数の画面で共通される部品として考えられる場合だけで、できる限り共有していく方針が良い。

> Tailwind については timer しか利用していないので今後外そうと思います。（→ #321 を起票）

### 1.2 方針

- **画面は機能ごとに別々に考える。** どう表現するかは機能側が決める
- **統一感は 2 段で支える。**
  1. **全画面が必ず従う土台**: トークン（色・余白・角丸・影・書体・文字の大きさ 5 段）
  2. **使ってよい共通部品**: 見た目の語彙を CSS のクラスとして `@tasuki/ui` の部品層に置く
- **既定は「共有部品を使う」。強制はしない。** 機能側が独自の見た目にしたいときは、その規則のそばに理由を 1 行書けば外れてよい（D9）。理由の中身は審査しない
- **CSS の部品を共有し、React の部品は各アプリに置く。** React の描画を共有するかは、実需が出た部品ごとにその Issue で判断する（Markdown の描画は #315）
- **部品層は Tailwind に依存しない。** #321 の前後どちらでも同じ定義のまま使える

### 1.3 利用者の判断（2026-09-27・検証の後）

| 論点 | 判断 |
|---|---|
| ADR 0007 基準 2（20 行未満は抽出しない）の扱い | **デザインシステムの部品には当てない。** 条件は「同じ見た目の知識を持つ」と「2 画面以上が使う」の 2 つ（D1） |
| ボタンと `.page` の段（#316 との境界） | **境界を引き直す。** #320 は部品層の仕組み・規則・検査と §2.1 の部品を作る。ボタンと最大幅・段組みの段は、#316 が実画面の洗い出しの結果を見て部品層に足す |
| Markdown の CSS とお題の札 | **CSS は #320 で共有し、React は各アプリのまま。** `.md-*` の CSS と象牙の札の見た目を部品層に入れる。Markdown の描画（React）を共有するかは #315 が、札の配置は #314 が決める |
| 外すときの申告 | **規則のそばに `/* ui-exempt: 理由 */` と書く。** 理由は審査しない。検査は「理由が空」と「何も免除していない書き込み」だけを落とす（`scale-exempt:` と同じ作法） |

## 3. 実測した事実（main `7d4a203`）

- `@tasuki/ui` は `tokens/`（4 アプリ）と `elements/`（timer 以外）の 2 層。`exports` は `.`・`./tokens.css`・`./elements.css`・`./base.css`・`./controls.css`・`./card.css`
- poker・玄関・お題ツールは CSS の先頭で `@import '@tasuki/ui';` を書く。timer は `main.tsx` で `import "@tasuki/ui/tokens.css";` を `./index.css` より先に読む（CSS から `@import` すると Tailwind が展開して書体の `url()` が壊れる。#297）
- timer の Tailwind 4 の preflight とユーティリティは `@layer` の中にある。レイヤーの外の規則は詳細度によらずそれらに勝つ。`!` つきのユーティリティは timer に 0 件
- poker とお題ツールの `Markdown.tsx` は、5 行目の注釈（「poker-web では」と「topic-web では」）を除いて同一。`.md-*` の CSS も同形。timer の `Markdown.tsx` は別実装（Tailwind）
- 要素層の `:focus-visible` は `outline: 2px solid var(--gold); outline-offset: 3px;`。玄関とお題ツールの入力欄は自前で `offset: 2px`。timer は要素層を読まず、自前の `:focus-visible` が `var(--signal)`（= `--gold-bright`）
- timer の `--panel-2` は `--felt-700`、一覧のホバーは `--panel-hover`（= `--felt-lift`）。通知音と声のプルダウンは `text-sm px-2 py-1.5`（14px）で、通知音の方は `h-8` の試聴ボタンと横に並ぶ
- エラーの色: 玄関 `--rose-bright`・お題ツール `--rose-pale`・poker `#f0b5a4`。`--rose-bright` は felt-950 上 6.58:1・felt-800 上 4.95:1（`palette.css` の注記）で、felt-700 上では約 3.55:1（お題ツールの注釈）
- 接続の帯とエラーは、E2E の a11y 走査のどのシナリオでも表示されない（お題ツールの注釈）
- postcss（8.5.25）は vite 経由で全 web アプリの依存木にある。postcss-selector-parser（7.1.5）は stylelint の木にだけある。**どちらもルートの `package.json` には無く、`scripts/` から素の node では解決できない**（`.pnpm-virtual` に巻き上げがあるので、NODE_PATH を積むランナーの中では解決できてしまう）
- `packages/ui/tests/typography-scale.test.mjs` は `packages/ui/src` 配下の CSS を全部走査し、一括指定の `font:` を禁じ、直値の `font-size` には同じ行の `scale-exempt:` を求める
- CI の `audit-*` の段は、ci.yml に 1 本ずつ手で書かれている。**ci.yml に行があるかを確かめるテストは無い**
- 各アプリの `index.html` は読み込み中の地として生の色（`#071f18`・`#f5efdd`）を持つ。`apps/landing/tests/index-html-loading-placeholder.test.ts` がトークンとの一致を見ている

## 4. 決定

### D1. 共有の条件（ADR 0007 の適用を狭める）

部品層に部品を置く条件は次の 2 つ。**ADR 0007 基準 2（20 行未満は抽出しない）はデザインシステムの部品には当てない。**

1. **同じ見た目の知識を持つ**（片方だけ直すと画面の見た目がずれる、または a11y が割れる）
2. **2 画面以上が使う**（同じ PR で 2 画面以上に当てる。ADR 0007 基準 1 と同じ）

理由: 基準 2 は「抽出による間接参照のコストが重複のコストを上回る」ことを前提にしたロジックの基準である。見た目の部品では、数行の重複でも片方だけ直ると統一感が崩れる。エラーの色がすでに 3 画面で別々になっている（§3）。

### D2. `packages/ui/src/components/` を新設する

```
packages/ui/src/
  tokens/      ← 全アプリ（変更なし）
  elements/    ← timer 以外（変更なし。素の要素）
  components/  ← 新設。全アプリが読める。`.ui-` で始まるクラスだけを定義する
    index.css  ← まとめ読み
    field.css  ← 入力欄の系（PR 1）
    …          ← 部品ごとに 1 ファイル
```

- `exports` に `"./components.css": "./src/components/index.css"` を足す
- `src/index.css` の読み込み順は **tokens → elements → components**。poker・玄関・お題ツールは読み込みを変えずに部品を使える
- timer は `main.tsx` で `tokens.css` の次・`./index.css` の前に `import "@tasuki/ui/components.css";` を置く（#321 までの暫定。#297 と同じ理由）

### D3. 命名

- 部品は `.ui-<部品>`、部品の中の要素は `.ui-<部品>-<部分>`、変化形は `.ui-<部品>--<変化>`（例: `.ui-banner--unreachable`・`.ui-note--error`・`.ui-invite-url`）
- **すべて `ui-` で始まる。** アプリ固有のクラスと衝突せず、マークアップを見ただけで共有部品と分かる。総称の修飾クラス（`.is-error` など）はアプリ側の同名の規則が部品へ漏れるので使わない
- 既存のアプリの修飾（`.unreachable`・`.secondary` など裸のクラス）は変えない
- §2.1 の名前は仮。各 PR で確定する

### D4. 部品と画面の役割分担

- **部品が持つもの**: 見た目と、見た目に関わる知識（16px の下限・`base-select`・AA のための不透明な地）
- **画面が持つもの**: 配置（幅・並び・外側の余白）と、画面固有の上書き。**配置もクラスで書く**（D8 の検査は要素型のセレクタを見るため）
- **フォーカスのリングは部品が持たない。** 色と太さは要素層の `:focus-visible`（timer は自前）が持つ。部品は `outline` 系の性質を書かない。例外は、一覧の選択肢の既定の枠を消す `.ui-select option` の `outline: none` だけ（選択の目印はホバーの地が担う。D6）
- 部品は `box-sizing: border-box` を自分で書く（要素層の `*` や Tailwind の preflight に頼らない）

### D5. 部品層は `@layer` を使わない。上書きは詳細度と読み込み順で決まる

- Tailwind のレイヤー構造に合わせた仕掛けを入れない
- 部品のセレクタは詳細度 (0,1,0)〜(0,2,0) に収める。画面側の上書きは、同じ詳細度なら後に読む画面の CSS が勝ち、子孫セレクタ（`.topic-panel input` = (0,1,1)）なら読み込み順によらず勝つ。**したがって写しの消し忘れは読み込み順では救えない。** 写しは置き換える PR で消し、D8 の検査が見張る
- **Tailwind が残っている間**: 部品の規則は timer のユーティリティに必ず勝つ。timer で部品を当てる要素からは、同じ性質のユーティリティを外す。#320 で timer に当てるのは**プルダウン 2 つだけ**（#319 の写しの解消）

### D6. つまみ（画面が変えてよい値）

- つまみは部品の規則の中で**宣言しない**。既定値は `var(--ui-field-bg, var(--felt-950))` のように `var()` の第 2 引数で持つ。部品の規則で宣言すると、画面の `:root` や容器での指定が継承に負けて黙って効かない
- 画面は `:root` か容器でつまみを宣言する（timer は `apps/timer-web/src/index.css` の `:root`）

**入力欄の系の値**

| 項目 | 決定 | つまみ |
|---|---|---|
| 欄と一覧（`::picker(select)`）の地 | 規則は「欄は面より沈める」。既定 `--felt-950`。欄と一覧は必ず同じつまみを読む | `--ui-field-bg`（timer は `var(--panel-2)`） |
| 一覧の選択肢のホバー | 規則は「地より一段明るい面」。既定 `--felt-700` | `--ui-field-hover`（timer は `var(--panel-hover)`）。**地と同じ色にすると選択の目印が消える**ので、地を変える画面はホバーも変える |
| 字の大きさ | `1rem` に固定（`/* scale-exempt: iOS の自動拡大を避ける 16px の下限 */`）。一括指定の `font:` は使わず、`font-family`・`font-weight`・`line-height`・`letter-spacing` を個別に `inherit` する | 出さない |
| 選択肢の余白・スクロールバー | お題ツールの値（余白 `--space-2` / `--space-4`・つまみ `--gold-edge`・溝 `--felt-900`） | 出さない |
| プレースホルダ | `--ivory-faint`（玄関の値） | 出さない |

`::picker(select)` を含むセレクタは**一覧に他のセレクタと同居させない**（`::picker` を知らないブラウザは一覧ごと規則を捨て、欄の地まで消える）。未対応のブラウザでは素の `<select>` に欄の規則だけが効く（いまのお題ツールと同じ縮退）。

**告知・一言の値**

| 項目 | 決定 |
|---|---|
| エラーの色 | `--rose-pale`（felt-700 上で約 5.91:1）。玄関の `--rose-bright` は felt-700 の面では AA を割る |
| 接続の帯の地 | お題ツールの形（不透明な `--felt-950`・下線 `--rose-edge`・unreachable は太い `--rose-bright` の下線と太字）。poker の半透明の地は、sticky で下を象牙の札が通ると割れうる（poker の値を felt の上だけで計算すると 4.87:1 で割れないが、札の上は測っていない）。**PR 2 で表示させて実測する**（§9） |

### D7. 見た目が変わる画面（受け入れる変化）

| PR | 画面 | 変化 |

## 5. 検査

検査は **`scripts/audit-ui-components.mjs`** 1 本と自己テスト `scripts/audit-ui-components.test.mjs` に集める（stylelint の既成の規則は、偽陽性を消す最短の設定がそのまま穴になることを実測した。`selector-max-type` の `ignoreTypes: ['select']` で素の `select {}` が通るなど）。既存の `audit-*` と同じく素の node で走り、CI の同じ段で流す。

### D8. 走査対象

- **実体から導出する**（ADR 0014 決定 1）: `apps/*` と `packages/*` の追跡下にあるスタイルのファイル全件から、`packages/ui/src/tokens/` と `packages/ui/src/components/` を除いたもの（以下「画面の CSS」）。部品層は別に `packages/ui/src/components/` 全件（以下「部品の CSS」）
- `.css` 以外のスタイルの拡張子（`.pcss`・`.postcss`・`.scss` など）が 1 つでもあれば落とす
- アプリごとに走査件数 0 件なら落とす（ADR 0014 決定 8）。構文解析に失敗したファイルは飛ばさずに落とす
- **残る穴（名指し）**: `index.html` の `<style>` と `style` 属性・TSX の `style={{}}`・Tailwind のクラス。前 2 つは現状が読み込み中の地だけで、既存のテストが見ている（§3）。Tailwind は #321 で消える

### D9. 申告（`ui-exempt:`）

- 規則の直前のコメント `/* ui-exempt: 理由 */` が、その規則 1 つを免除する
- 理由が空なら落とす。**何も免除していない `ui-exempt:` も落とす**（直したのに書き込みだけ残る腐り方を防ぐ）
- 台帳は `git grep ui-exempt` で引ける。中央の表は持たない

### D10. 画面の CSS への規則

1. **写しの検出**: セレクタのどこかに `select`・`input`・`textarea`・`option` の型、または `::picker(` を含む規則は落とす（申告があれば通す）
   - 型は**大文字小文字を区別せず、エスケープを解いた名前**で比べる。`:is()`・`:where()`・`:not()`・`:has()`・`:global()`・`:-webkit-any()` の引数の中も探す。CSS の入れ子は `&` を解いてから判定する。一覧（`a, b`）は分けて全部を判定する
   - `label` は対象にしない（要素層の `label` があり、画面ごとの配置で触る）
   - **射程**: 機械で止めるのは、要素型のセレクタで書いた入力欄の系の写しだけである。クラス名で書いた写し（`.hub-input` の形や、帯・一言・パネルなど）はレビューと README が担う
2. **16px の下限を崩さない**: `.ui-input`・`.ui-textarea`・`.ui-select` を含むセレクタで `font-size`（と一括指定の `font`）を宣言したら落とす
3. **生の色**（PR 5 で有効にする）: 色の値の許可リスト方式。値に色の直書き（`#` の 3〜8 桁・`rgb` `rgba` `hsl` `hsla` `hwb` `lab` `lch` `oklab` `oklch` `color` の関数（大文字小文字を区別しない）・CSS の名前の色）を含む宣言は落とす。書けるのは `var(--…)`・`transparent`・`currentColor`・`inherit` などとそれらを引数にした `color-mix()`。影の黒などパレット外の値はトークン（`--shadow-*` など）へ寄せ、例外を作らない

### D11. 部品の CSS への規則

1. 一覧を分けた**各セレクタの先頭の複合セレクタが `.ui-` のクラスを含む**。素の要素・擬似クラス単独（`:focus-visible`）・`*`・属性単独・`:root`・`@scope` は落とす（timer を含む全アプリへ漏れるため）。`::picker(select)` は `.ui-select` に続く形でだけ許す
2. `::picker(` を含むセレクタは一覧に他と同居させない
3. `outline` 系の性質を書かない（例外は D4 の 1 つ）
4. つまみ（`--ui-*`）を宣言しない（D6）
5. 生の色を書かない（D10 の 3 と同じ定義）
6. **死んだ部品を置かない**: 定義した `.ui-*` のクラスが、2 つ以上のアプリの `src` 配下の `.tsx` に現れなければ落とす（D1 の条件 2・#280 の経緯）

### D12. CI への配線を確かめる

`scripts/audit-*.mjs` がすべて ci.yml に `node scripts/<名前>` として現れることを、導出で確かめるテストを足す（いまは手で足しているだけで、書き忘れると自己テストだけが緑になる）。

### D13. 依存

- ルートの `devDependencies` に `postcss` と `postcss-selector-parser` を足す。版は依存木に既にある実体（8.5.25・7.1.5）に合わせる。新しい技術ではないが直接の依存の追加なので、ADR 0022 に記録する（憲法 原則 II・ADR 0001 の `@tailwindcss/postcss` の追記と同じ扱い）
- 解決できるかは `env -i` の素の node で確かめる（vitest の中では宣言が無くても解決できてしまう）
- `pnpm audit --audit-level high` と供給網の検証（ADR 0008）を通す

## 7. PR の刻み方

ADR 0013 の既定（1 Issue = 1 PR）から分割する理由は、`docs/guides/pr-granularity.md` の**理由 1（独立して revert したい単位が複数ある）**と**理由 3（危険度の異なる変更が混ざっている）**。部品ごとに見た目の変わる画面が違い、見た目の後退が見つかったらその部品だけを戻したい。

| PR | 中身 |
|---|---|
| **1** | ADR 0022 と旧 ADR の注記・`components/` の骨組み・**入力欄の系**・検査（D8〜D12。D10 の 3 だけは無効のまま）・依存（D13）・README・「2 層」の文の直し。玄関・お題ツールの写しと timer のプルダウン 2 つを置き換える |

| **4** | **招待リンクの表示・象牙の札・Markdown の見た目**。poker・お題ツール |
| **5** | 生の色の仕分けと D10 の 3 を有効にする・ADR 0022 の実施状況の追記・epic の振り返り |

## 9. 各 PR の検証

- **対照実行**: 新しい検査を main の worktree で流し、**§2.1 の既知の写し（お題ツールの `.topic-panel` の入力欄・プルダウン・選択肢、timer の `select` / `option`）が過不足なく名指しで赤に出ること**を確かめる。出ないはずの `.hub-input` は既知の見逃しとして記録する。これが実装の外にある正解になる
- **変異検査**: 検査 1 の逃げ道の族を全部入れる —— 大文字・エスケープ・`:is()` / `:where()` / `:global()`・入れ子・一覧の後ろ側・`@media` の中・2 つ目の CSS ファイル・`.css` 以外の拡張子・新しい Vite アプリ・0 件・空の理由・使われていない申告・部品の CSS の擬似クラス単独 / `*` / 属性 / `oklch()` / `RGBA(`。変異パッチが全件当たることを `git apply --check` で確かめる
- **自己テスト**は bash で回す（zsh は偽の赤を出す）。`pnpm test` に入っていない scripts の自己テストと `pnpm audit` も押す前に回す
- **既存の検査**: E2E の a11y 走査・書体の base 層の検査・文字の大きさ 5 段の検査・構造監査（SC の行は main と並べる）
- **スクリーンショット比較**: main と並べる。§4 D7 の画面は実画面（Chrome）で目視する。PR 1 では #319 で未確認だった timer の通知音のプルダウンも見る
- **計画**には `audit-plan-gate` を当てる
- **レビュー**: 文脈を共有しない `/code-review` を PR 番号を明示して通す
- **配布**: 本番への配布は勝手に行わない。epic の区切りで利用者に諮る
