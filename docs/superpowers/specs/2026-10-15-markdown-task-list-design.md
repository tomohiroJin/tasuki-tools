## 3. 実測した事実（main `f043c07`）

- **解析**は `packages/markdown/src/blocks.ts` の `parseMarkdown` が持つ。箇条書きは `UL_RE = /^\s*[-*]\s+/`、番号付きは `OL_RE = /^\s*\d+\.\s+/` に当たる行の連続で、印を外した残りを行内解析する。項目の型は `items: MdInline[][]`
- `- [ ] 項目` は `[ ] 項目` という文の項目になる。行内解析の `INLINE_RE` のリンクは `\[…\]\(…\)` で、括弧が続かない `[ ]` はリンクにならず素の文として残る
- 改行の正規化は `src.replace(/\r\n?|[  ]/g, '\n')`。解析の結果は元の改行を持たない
- **描画**は `packages/web-kit/src/reader/markdown.tsx` の `Markdown` 1 つ（#371・ADR 0021 の追記）。使い手は 5 か所:
  - topic-web の `TopicSheet`（いまのお題と下書きのプレビューが共有する札）
  - poker-web の `CurrentTopic`
  - timer-web の `TopicCard`・`SharedMemo`・`Session`（お題の札）
- **見た目**は `packages/ui/src/components/markdown.css`（`.ui-md-*`）。部品の CSS のセレクタは `.ui-` のクラスから始める（`scripts/audit-ui-components.mjs`）。画面の CSS に `input` の型を含むセレクタを書くと検査が落とす（#320 の申し送り。Issue のコメント 2026-09-27）
- **お題**を変えるコマンドは `topic.set`（タイトルと説明を丸ごと置き換える）だけで、版を持たない。送れるのはお題ツールの接続だけ（`packages/topic-core/src/schemas.ts`・ADR 0021 決定 3）
- **お題ツールの下書き**は `TopicEditor` の画面の中の状態で、プレビューは `useDeferredValue` を通した値を `TopicSheet` で描く。「このお題にする」で初めて `topic.set` が飛ぶ
- **共有メモ**は timer の snapshot の `handoffNote`。`SharedMemo` は確定（blur・プレビューへの切り替え）で `handoff.note.set` を送り、本文を丸ごと置き換える。timer の参加者は誰でも書ける（`Session.tsx` は常に `onCommit` を渡す）。後から届いた方が勝つ
- `SharedMemo` のプレビューは `note`（サーバーの値）を描く。外から変わったら 1.5 秒の強調と「共有メモが更新されました」の読み上げを出し、自分が送った値と同じなら出さない（`lastCommittedRef`）
- 押せる大きさは 44px 以上（ADR 0025 決定 4。ボタンについての決定）。チェックボックスについての決まりは無い
- 変異検査の `@tasuki/markdown` の登録は m106（リンクの上限）・m107（行区切り）

## 4. 決定

### D1. 全員に共有する付け外しは作らない。付け外しは、もともと書ける面だけに置く

付け外しできるのは次の 2 つだけにする。

| 面 | 付け外しの行き先 | 新しい経路 |
|---|---|---|
| timer の共有メモのプレビュー | いまの `handoff.note.set`（本文を丸ごと送る） | 無し |
| お題ツールの「書く」の下書きのプレビュー | 下書きの説明（画面の中の状態）。場へ出すのは「このお題にする」 | 無し |

いまのお題の札は、どの画面でも押せないチェックボックスで描く。

**理由**: どちらの面も、付け外しは「本文の `[ ]` と `[x]` を打ち直す」ことの近道でしかない。その面ですでに書ける人が、すでにある経路で送る。新しいコマンドも、同時の書き換えの新しい規則も、ADR 0021 決定 3 の見直しも要らない。お題は「お題ツールが書き、全員が読む」のまま一元化が保たれる（利用者の「お題ツール上で共有されているほうが一元化されている」）。

**退けた案**:

| 案 | 退けた理由 |
|---|---|
| お題ツールのいまのお題の札で付け外しし、全員へ配る | 付け外し専用のコマンド（同時の書き換えで相手の変更を消さないため）が要る。実需が見えていない（§2.2） |
| 全画面で付け外しし、全員へ配る | 上に加えて、timer・poker の接続にお題のコマンドを許すことになり、ADR 0021 決定 3（拒否はスキーマの振り分けで行う）を見直す |
| 各自の手元だけで付け外しする | 共有されないチェックは、モブの場で画面ごとに食い違う。端末に残すかどうかの判断も増える |

### D2. 記法は GitHub と同じ `- [ ]`・`- [x]`・`- [X]`。番号付きでも認める

項目の文（印を外した残り）が `[`・空白か `x` か `X`・`]`・1 つ以上の空白・空白でない字、の順で始まるときにタスクの項目にする。箇条書き（`-`・`*`）と番号付き（`1.`）の両方で認める（GitHub と同じ）。

- **文の無い項目（`- [ ]` だけ）はタスクにしない。** 名前の無いチェックボックスになるため（NFR-002）。素の文 `[ ]` のまま出す
- 1 つの列にタスクの項目とそうでない項目が混ざってよい
- コードの囲みと引用の中は解析しない（いまと同じ）

### D3. 解析の結果は、項目ごとに「タスクか、チェック済みか」を持つ

`ul`・`ol` の `items` を `MdListItem[]`（`{ inline: MdInline[]; task: … | null }`）にする。PR 1 の `task` は `{ checked: boolean }`、PR 2 で文書の中の通し番号 `index` を足す。

**理由**: 項目と同じ場所に持てば、描画が並びを取り違えない。`items` と別の配列を並べる案は、片方だけ直したときに位置がずれる。

### D4. 描画は `<label>` で包み、項目の文をチェックボックスの名前にする

```
li.ui-md-task
  label.ui-md-task-label
    input.ui-md-check[type=checkbox]
    （項目の行内要素）
```

- 項目の文がそのままチェックボックスの名前になる（Issue の「支援技術から名前で区別できる」）
- 押せるときは行全体が当たりになる（44px の決まりはボタンについてのもの。チェックボックスは行の高さで当たりを持つ）
- 項目の中のリンクを押してもチェックは変わらない（HTML の仕様。`label` の中の対話的な要素への操作は `label` の働きを起こさない）
- 押せないときは `disabled` にする。支援技術は「チェック済み・使用不可」と読む
- タスクの項目は箇条書きの印を出さない（`list-style: none`）

**退けた案**: `aria-labelledby` で文を指す（文を押しても切り替わらず、当たりがチェックボックスだけになる）。

### D5. 見た目は部品層の `markdown.css` に足す

`.ui-md-task`・`.ui-md-task-label`・`.ui-md-check` を足す。チェックの色はつまみ `--ui-md-check`（置く面が宣言する。既定は象牙の札の上で読める値）で、`--ui-md-edge` と同じ流儀にする。暗い面の timer の共有メモは、いまも `shared-memo.css` が `--ui-md-edge`・`--ui-md-link` を宣言しているので、同じ場所で宣言する。画面の CSS には書かない（#320 の申し送り）。

### D6. 付け外しは「書き換えた本文」を呼び手へ返す。解析と書き換えは同じ規則で行う

PR 2 で次を足す。

- `@tasuki/markdown` に `setTaskChecked(src, index, checked): string`。`index` 番目のタスクの項目の `[ ]`／`[x]` の 1 字だけを書き換え、**それ以外は元の文字列のまま返す**（CRLF・U+2028 などの改行も保つ）。範囲の外の `index` なら元の文字列をそのまま返す
- タスクの項目を見つける規則は `parseMarkdown` と同じ走査を共有する。コードの囲みの中の `- [ ]` を数えない
- `Markdown` に任意の受け口 `onSourceChange?(next: string)` を足す。渡したときだけチェックボックスを押せるようにし、押されたら `setTaskChecked(source, index, checked)` の結果を渡す。渡さなければいまと同じく押せない

**理由**: 呼び手（timer-web・topic-web）は書き換えた本文を、いまある経路（`handoff.note.set`・下書きの状態）へ流すだけで済む。アプリが `@tasuki/markdown` に直接依存せずに済む（依存方向の許可表を変えない）。書き換えは 1 字の置き換えなので、本文の長さは変わらず上限に触れない。

**同時の書き換え**: 共有メモはいまの編集と同じく、後から届いた方が勝つ。ほぼ同時に 2 人が別の項目を付け外しすると、片方の付け外しが消えることがある。消えても画面には残った方の状態が出るので、押し直せば済む。付け外しのためだけに新しい規則（項目を指すコマンド）を作るのは D1 の判断と釣り合わない。

### D7. 共有メモは、付け外しを押した時点で送る

- プレビューは送った値をすぐ描く（サーバーから戻るまでチェックが元に戻って見えないように）。送った値は自分の送信として記録し、外からの更新の知らせを出さない（いまの `lastCommittedRef` の扱い）
- 編集中（書く欄を出している間）は付け外しの面が無い（いまと同じくプレビューにしか Markdown を描かない）

### D8. お題ツールでは下書きのプレビューだけ押せる

`TopicSheet` に任意の受け口を足し、`TopicEditor` のプレビューだけが渡す。いまのお題（`CurrentTopic`）は渡さない。付け外しは下書きの説明を書き換えるだけで、場には出ない。場へ出すのはいまと同じく「このお題にする」。

## 8. 残る問い・申し送り

- **ADR**: どの決定も ADR 0021 の決定を変えない（決定 3 は D1 でそのまま守り、決定 7 の追記の「描画は 1 つ」に乗る）。新しい ADR も要らない（技術の選定が無い）。PR 1 で ADR 0021 を読み直し、追記が要らないことを PR の本文に書く
- **押せないチェックボックスの見た目**: `disabled` のチェックボックスはブラウザが薄く描き、チェック済みかどうかが象牙の札の上で読みにくいことがある。PR 1 の実画面検証で確かめ、読めなければ `--ui-md-check` と `opacity` で補う（押せないものは WCAG 1.4.11 の対象外だが、US1 は状態を読めることが目的）
  - **【PR 1 で解決】** 実画面ではほとんど読めず、`accent-color` も効かなかった。部品が `appearance: none` で枠と印を描く形にした（PR 1 計画の X1）
- **共有メモのプレビューの `aria-live`**: プレビューの区画は `aria-live="polite"` を持つ。チェックの状態の変化は文の変化ではないので読み上げは増えない見込み。PR 2 の実画面検証で確かめる
- **全員に共有する付け外し**: 要るとわかったら別の Issue で、付け外し専用のコマンド（`topic.task.set` のような、項目を指してサーバーが当てる形）から検討する。そのとき `setTaskChecked` をサーバー側でも使える（`@tasuki/markdown` は依存 0 の純粋な関数）
