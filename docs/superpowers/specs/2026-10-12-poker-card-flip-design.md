# poker の札をその場でめくり、お題の出し入れを滑らかにする（#348）— 設計正本

## 1. 目的

### 1.1 利用者の言葉

> カードの表示が投票済みが最後ひっくり返る感じとかもっとカッコよくしたい（2026-10-09・#316 PR 1 の実物確認）

> プランニングポーカーのお題を隠すときと出すときがちらつく。（たぶん何もしてないからだと思う）（2026-10-12・#316 PR 4 の実物確認）

### 1.2 方針

- 票を公開したとき、**場の席の伏せた札そのものがその場でめくれて表の数字が見える**。めくった札がそのまま結果として読める
- お題の読む面を隠す・見せる・届く・下ろされるときに、操作の面が**一度に跳ばず滑る**
- 動きを抑える設定（`prefers-reduced-motion`）では、どちらも即座に終わった姿を出す
- 読み上げは、公開の結果（各自の票・平均・最頻値）を今と同じく読めるままにする

## 3. 決定

### D1. 場の席の札そのものを 3D でめくる

- 席の札（`SeatCard`）を、**回る軸（`.seat-card-rotor`）・裏（`.seat-card-back`）・表（`.seat-card-face`）**の 3 枚にする。裏と表は `backface-visibility: hidden`、表は最初から `rotateY(180deg)` で裏返して置く
- 公開されると札に `.revealed` を付け、回る軸を `rotateY(180deg)` へ **CSS の transition** で回す。表に数字が見える
- **めくりは transition にし、keyframes（animation）にしない。** transition は「状態が変わったとき」だけ走るので、公開後に入室・再読み込みした人には、めくり終えた札が最初から出る。keyframes は描いた瞬間に毎回走る
- **同じ要素がめくれる。** React の key は参加者の id のままにし、投票中から公開への切り替えで席の要素を作り直さない（作り直すと transition の起点が無く、めくれずに表が出る）
- 次のラウンドで投票中へ戻るときは**めくり返さない**（回る軸の transition を `.revealed` の側にだけ置く。投票中の姿は即座に戻る）
- 裏の模様は今の模様（`--card-back` の地に `--gold-edge` / `--gold-glow` の斜めの格子）をそのまま使う。投票したときの `flip-down`（裏が置かれる演出）も残す
- 自動公開で最後の投票者の席は、未投票（点線の枠）から裏が置かれる演出とめくりが同時に始まる（§2 の 6）。裏が置かれてから回るように見えるので、直さない

### D2. めくる順と速さ

- **席順（参加者の並び）に 90ms ずつずらす。** ずらしは 8 席目で頭打ち（最大 0.72 秒）。人数が多い部屋で最後の札が待たされすぎない
- 1 枚のめくりは 0.5 秒（`cubic-bezier(0.3, 0.7, 0.2, 1)`。立ち上がりが速く、表で静かに止まる）
- 席順は画面が `style` の CSS 変数 `--seat-order`（0 始まり）で札に渡す。遅延は CSS が `calc(min(var(--seat-order), 8) * 90ms)` で決める
- **集計（平均・最頻値）は最後の札がめくれてから出す。** 結果の節に `--seat-count`（席の数）を渡し、`calc(min(var(--seat-count) - 1, 8) * 90ms + 0.45s)` 遅らせて 0.3 秒で立ち上げる。札より先に平均が見えると、めくる楽しみが先に割れる

### D3. 結果の行を畳み、結果の節は集計だけにする

- **各自の票は場の席が持つ。** 結果の節（`Results`）から、名前と札の行（`.votes`）を消し、見出し「結果」と集計（平均・最頻値）だけを残す
- 公開後の席: 投票した人は表の札（値）を見せ、「投票済み」のバッジは出さない（札が答えている）。投票しなかった人は点線の枠のまま、字の印「未投票」（今の `.no-vote`）を出す
- 理由: 同じ票が席と結果の行で 2 度出ると、目がどちらを見ればよいか迷う（統括の見立てと同じ）。結果の行が担っていた「名前と票の対応」は、席が名前と札を縦に積んでいるのでそのまま読める

### D4. 席の札の大きさと表の見た目

- 席の札を **22 × 30px → 2.4 × 3.3rem（約 38 × 53px）**にする。表の数字（`--font-size-lg`・最大 22.4px）が読める最小の大きさ。席（`.participants li`）の幅 6.5rem は変えない
- 表は象牙の札（`--card-sheen` → `--ivory` → `--card-shade` のグラデーション・縁 `--card-edge`・字 `--coal`・`--font-display` の斜体 600）。手札の `.card` と同じ材質に見せる
- **`.card` のクラスは当てない。** `.card:hover:not(:disabled)` が `<span>` にも当たり、席の札が手をかざすと浮く（押せない物が押せるように見える）。見た目は poker の CSS にトークンで書く（生の色は書かない）
- 裏模様とめくりは poker の CSS に置く（README の「ここに入れていないもの」の判断を保つ。使うのは poker だけで、ADR 0022 決定 2 の「2 画面以上」を満たさない）

### D5. 動きを抑える設定では遅延も止める

- `packages/ui/src/elements/reset.css` の `@media (prefers-reduced-motion: reduce)` に `animation-delay: 0s !important` と `transition-delay: 0s !important` を足す
- 要素層を読む 3 アプリ（poker・玄関・お題ツール）に効く。玄関の札の登場の遅延（`apps/landing/src/index.css`）も止まり、動きを抑えた人には最初から並んだ姿が出る（今は 0.06〜0.18 秒消えている）
- timer は要素層を読まず、自前の `@media (prefers-reduced-motion: reduce)` を持つ（`apps/timer-web/src/styles/base.css`）。そちらも遅延を止めていないが、**この Issue では触らない**（§10）

### D6. 読み上げ

- 席の札は今と同じ `role="img"`。名前（`aria-label`）は、投票中は「投票済み」「未投票」、**公開後は札の値（手札と同じ `cardLabel`：`5`・`?`・`☕`）**、投票しなかった人は「未投票」
- 回る軸・裏・表は `role="img"` の子なので読み上げに出ない（`img` の子は表示専用）。表の字は目で読むためのもの
- 参加者の一覧（見出し「参加者（N人）」）を辿ると「名前・札の値」の順に読める。結果の節（見出し「結果」）は平均・最頻値を読む。**今と同じく `aria-live` は足さない**（公開は画面の節が入れ替わることで分かる。足すかは別の判断）
- 公開前の秘匿は変わらない。投票中の表は空で、値はサーバーから届かない（`snapshot.ts` の FR-006）

### D7. お題の読む面は、閉じた状態を幅 0 で持つ

- お題があれば、脇の区画（`.ui-workspace-side`）を**閉じても DOM に残す**。区画に `data-state="open" | "closed"` を付け、閉じたら `inert` を付ける
- 切り替えのボタンの `aria-controls` は**いつも読む面の id（`poker-topic-card`）を指す**（指し先が消えない）。`aria-expanded` は今と同じ
- 64rem 以上: poker の段組み（`.room .ui-workspace--reader`）は**列をいつも 2 本持つ**。閉じた状態・お題が無い状態は `minmax(0, 0fr) minmax(0, 1fr)` と間隔 0、開いた状態は今の `minmax(0, 0.75fr) minmax(0, 1fr)` と間隔 `--space-6`。列と間隔を 0.32 秒で移り変わらせる。操作の面はいつも 2 列目に置く
- 46rem の中央寄せは、操作の面の `max-width` を `100%` ⇄ `46rem` で移り変わらせる（`margin-inline: auto` が毎フレーム中央に寄せる）
- 閉じるとき: 札の不透明度を 0.15 秒で落とし、列が縮み切った後（0.32 秒）に `visibility: hidden` にする。開くとき: すぐ見える状態にし、列が広がり始めてから 0.12 秒遅れて不透明度を上げる。縮む間は区画を `overflow: clip` にする（札の中身がはみ出さない）
- 64rem 未満: 区画は縦に積まれているので、閉じた区画は `display: none`（移り変わりは無し・§9）
- 理由: 列の本数が変わらなければ、`grid-template-columns` は値の補間で滑る（列の本数が変わると補間できない・§2 の 5）

### D8. お題が届く・下ろされる瞬間も同じ仕組みで和らげる

- お題が届くと区画が足され、段組みの `:has()` が開いた列の値に変わる。段組みの要素は残っているので**同じ transition が走り、操作の面が右へ滑る**。札は `@starting-style` で不透明度 0 から立ち上げる
- お題が下ろされると区画は DOM から外れる（お題の中身が無いので残せない）。**札は即座に消えるが、操作の面は中央へ滑る**（受け入れた限界・§9）
- #316 §9.2・§10.1 の「受け入れた限界（操作の面が横へ動く）」は、動きは残るが跳ばなくなる

### D9. 手札の 5 × 2 は、脇の有無ではなく操作の面の幅で決める

- `.room-main` をコンテナ（`container: room-main / inline-size`）にし、手札は `@container room-main (width < 39rem)` で 5 列の grid にする（1 行に 10 枚が収まる幅は `10 × 3.4rem + 9 × 0.55rem = 38.95rem`）
- 理由: 脇の有無で切り替えると、切り替えのボタンを押した瞬間に手札が組み替わる（§2 の 5）。幅で決めれば、列が滑る途中で 1 度だけ組み替わる
- 見た目の変化（意図したもの）: 1920px でお題を開いた状態は手札が 1 行に並ぶ（操作の面が約 53rem あるため。今は 5 × 2）。40〜64rem の幅で手札が 9 + 1 に割れていたのが 5 × 2 になる。1280px で開いた状態は操作の面が約 41.1rem（実測。当初の見積もり約 39.4rem は器の余白を見落としていた）で、今の 5 × 2 から 1 行に変わる（§12）
- 部品の内側の並び替えはコンテナクエリで書いてよい（README「幅の段」）

### D10. 消すもの

- `packages/ui/src/elements/card.css` の `.card.small`・`.card.small::after`・`@keyframes flip-in`（使う所が無くなる）
- `apps/poker-web/src/index.css` の `.votes` の規則・`.votes li:nth-child(n) .card.small` の遅延 6 本・`.ui-workspace:has(> .ui-workspace-side) .card-hand`・`.ui-workspace:not(:has(> .ui-workspace-side)) > .room-main`・`.room .ui-workspace--reader:has(> .ui-workspace-side)`（D7・D9 の規則に置き換える）
- `packages/ui/README.md` の約束事から `.card.small` の行を消し、「ここに入れていないもの」を「伏せ札の裏模様とめくり（`.seat-card`）」に直す。約束事の reduced-motion の行に「遅延も止める」を足す

## 4. 退けた案

| 案 | 退けた理由 |
|---|---|
| 結果の行を残し、席と結果の行の両方でめくる | 同じ票が 2 度出る。席の札がめくれた後、目が結果の行へ移る理由が無い |
| 一斉にめくる | 0.5 秒で終わるが、「投票済みが最後ひっくり返る」の手応えが薄い。席順にずらすと、場を順に開けていく卓の所作になる |
| めくった後に札を結果の行へ並べ替える（FLIP の移動） | 札が席から離れると名前との対応が切れる。要素の移動を追う JS（位置の測りと反転）が要る |
| めくりを keyframes（`animation`）で書く | 描いた瞬間に毎回走るので、公開後に入室・再読み込みした人にもめくりが見える。状態の変化だけで走る transition が合う |
| 手札の `.card` を席の札の表に当てる | `.card:hover` が `<span>` にも効いて浮く。打ち消しの規則が要る |
| めくる札・畳める脇を部品層（`packages/ui`）に置く | 使うのは poker だけ（ADR 0022 決定 2）。2 つ目の画面が使うときに部品へ上げる |
| お題の出し入れに View Transitions API（`document.startViewTransition`）を使う | お題が届く・下ろされるのは同期フックから来る状態の変化で、そこを包むには同期の層に手を入れる。ページ全体を写すので、他の人の操作による画面の更新と重なる |
| 64rem 未満でも高さを移り変わらせる（`grid-template-rows: 0fr` の包み） | 区画の中に包みの要素が 1 段要る。ちらつきの訴えは 64rem 以上の横の跳び。縦に積む幅では札が上に出入りするだけで、操作の面は横に動かない |
| 下ろされたお題の札を、消える演出の間だけ残す | 最後に届いたお題を画面が持ち続ける仕組みが要る。下ろされた札を読める時間が残ると、「お題が無い」状態の意味がぼやける |

## 6. a11y

- 動きを抑える設定: めくり・集計の立ち上げ・お題の列の移り変わり・札の不透明度・`visibility` の遅延は、すべて要素層の一括の手当て（D5 で遅延も止める）で即座に終わる
- 閉じた読む面は `inert` と `visibility: hidden` で、Tab の行き先にも読み上げにもならない。`aria-controls` の指し先は残る（D7）
- 切り替えのボタンのフォーカスは押した後もボタンに残る（区画を消さないので、フォーカスが落ちる経路が増えない）
- 席の札の名前（D6）。札の表の字は `--coal` on 象牙（AA を十分に満たす。`poker-a11y.spec.ts` の走査で確かめる）
- 押せる大きさ: 席の札は押せない（`buttons.spec.ts` の対象外）。大きくなった席が 320px で横に溢れないことは `layout.spec.ts` と `buttons.spec.ts` の既存の溢れの検査が見る

## 7. 書体の base 層の実測

`packages/ui/src/tokens/fonts.css` の base の 3 面（400・500・700）の unicode-range に、1 字ずつ当てた（2026-10-12）。

| 文言 | 結果 | 使い道 |
|---|---|---|
| 未投票・投票済み・結果・平均・最頻値 | 収まる | 今の文言をそのまま使う |
| 公開・めくる・表・席 | 収まる | 注釈と文書だけ（画面に出さない） |
| 札・裏・伏・考 | **base に無い** | 画面に出さない（「伏せた札」「裏」などを UI 文言に使わない） |
| ☕ | base に無い（今と同じ） | 手札・結果ですでに出ている記号。和文の書体ではなく端末の絵文字で描かれる。今と変わらない |

**この Issue は画面に新しい文言を足さない。** 「未投票」の印を結果の行から席へ移すだけ。

## 8. 検査: 何を固定するか

### 8.1 ユニット（Vitest・jsdom）

| 固定すること | 正しい実装と誤実装が分かれる局面 |
|---|---|
| 公開後の席の札の名前は値（`5`・`☕`）、投票しなかった席は「未投票」と字の印 | 投票中の名前「投票済み」のまま残す誤り（m142） |
| 投票中から公開へ描き直しても、席の札は**同じ DOM 要素**のまま | key に状態を混ぜて作り直す誤り（m140）。作り直すとめくれない |

## 9. 受け入れた限界

- **64rem 未満でお題を隠す・見せると、札は即座に消える・現れる**（`display: none`）。縦に積む幅では操作の面が横に動かない
- **お題が下ろされると、札は即座に消える**（操作の面は滑る・D8）
- **列が滑る途中で手札が 1 度組み替わる**（5 × 2 ⇄ 1 行・D9）。開いた状態の操作の面が 39rem を下回り、閉じた状態（46rem）との間で境目をまたぐ幅で起きる。器の余白が 3rem に張り付く 1200px 以上では `(幅 - 128) / 1.75 < 624` から約 1220px 未満（実測: 1180px は開いて 5 × 2・閉じて 1 行、1240px は両方 1 行）
- **自動公開で最後の投票者の席は、裏が置かれる演出とめくりが重なる**（D1）
- **公開の瞬間に入室・再読み込みした人には、めくりが見えない**（transition の性質・D1。意図したもの）
- 公開後に参加者が入室・退室すると席の並びが変わるが、めくり直さない（key は参加者の id）
- `@starting-style` を持たないブラウザでは、お題が届くときの札の立ち上げ（不透明度）だけが無くなる（列は滑る）

  - **`fr` の補間は効いている。** 1280px で隠すと、操作の面の左端は 573.7 → 503.8（16ms）→ 387.0（50ms）→ 312.4（100ms）→ 275.9（200ms）→ 272px と滑る。代案（脇の `width` の移り変わり）は要らない。赤は物差しの側で、`slideMidway` が**お題が届いたときの列の広がり（0.32 秒）が終わる前に**「開いた位置」を読み、広がり始めの位置（≒ 閉じた位置）を `from` にしていた（|to − from| = 0）。前の移り変わりの終わりを待ってから測るように直した。同じ理由で「札は操作の面より狭い（約 43%）」も広がる途中の比（0.404）を読む回があったので、お題を開く補助（`openPokerWithTopic` / `openPokerWithTopicTool`）の最後で段組みの移り変わりの終わりを待つ

  - **席の札の表の字を公開後の走査で固定した。** `--coal` on 札の地（165deg の `--card-sheen` → `--ivory` → `--card-shade`）。公開後は手札が無いので、この組を描くのは席の札の表だけ（表の地を単色にすると「測っていない」で落ちることを確かめた）
