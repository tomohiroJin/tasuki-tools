# タスキ v2 UX 再設計 — 設計ドキュメント

**日付:** 2026-06-02
**対象:** TDD Mob Pro Timer（`tdd-mob-pro-timer`、共有ルーム型 WS 同期版）
**ステータス:** 承認済み（ブレスト合意）

## 背景と目的

見た目は参考デザイン（没入型ダークステージ）へ移植済みだが、**体験（どう動かすか）が spec ベースの寄せ集め**で、リモートモブプロの現場で気持ちよく回るかが未検証だった。本設計は「一からどう動かすか」をブレストで合意した結果をまとめ、UX を作り直すための土台とする。

**確定した前提（ブレスト合意）:**
- 利用シーン: **リモート・各自のデバイス**
- 参加: リンク→**名前を入れて「モブに参加」**、最初から editor（ドライバー候補）
- ローテーション: 参加は自由、**本人が「ドライバーに加わる」で明示的に列に入る**（見学と参加を分離）
- 交代: **タイマー切れで自動交代**（手動も併用）
- お題: **AI/定型の自動生成が主**、持ち込みは補助
- 終わり: 何周も回し、区切りで「終了」→**振り返り（周回数・各自のドライバー回数）**
- Setup から**他人のメンバー名一括入力を廃止**し「自分の名前」だけにする

## 中核モデル：参加者 ⊇ ローテーションの2層

UX の核は「**参加者（その場にいる人）**」と「**ドライバーローテーション（実際に交代で打つ人）**」を別概念にすること。リモートモブの「見学者もいる・途中参加もある」を自然に表現する。

- **参加者**（participants）= 名乗って入った全員。見学だけでも参加者。
- **ローテーション**（rotation）= 参加者のうち「ドライバーに加わる」を押した人だけ。実際に回る列。
- 参加者一覧の各人に「**ドライバーに加わる / 列から外れる**」トグル。
- 既存の `driverEligible` / `driver.skip` / `driver.resume` / `addProxy` の rotation 操作をこの「加わる/外れる」に転用する（サーバー実装はほぼ流用可能）。
- これにより従来の混乱（全員 viewer で誰も回れない・ホストが昇格させる手間）が解消される。

## 状態遷移（サーバー権威の room.phase に全員追従）

```
  Setup ──作成──▶ Lobby ──ホスト開始──▶ Session ──区切りで終了──▶ Review
  自分の名前＋        各自が名前で参加      自動交代で                周回数・
  言語/難易度/間隔    ・お題を生成/確認      何周も回る                個人別ドライバー回数
```

## セクション1：参加フロー（最初の30秒）

**ホスト（作成者）:**
1. Setup で「自分の名前＋言語/難易度/間隔」を入力 →「ルームを作成」
2. Lobby へ。作成者は参加者かつホスト、**自動でローテーションに加わる**（空ローテ回避）
3. お題が自動生成され始める（AI 鍵あれば AI、なければ定型）
4. ルームコード/リンク/QR を共有

**参加者（リンクで来た人）:**
1. `?room=ABC123` で開く →「名前を入れてモブに参加」（名前入力＋参加ボタンのみ・1画面完結）
2. 名乗って参加 → 参加者になる（role=editor）。**この時点では見学**（ローテーション未加入）
3. Lobby で「ドライバーに加わる」を押すと列に入る（押さなければ見学のまま）

**実装上の変更:**
- `room.join` を「名前指定・role=editor で join」に変更（現状は viewer 固定・"ゲスト"）。
- 重複名チェックを join に適用（「その名前は使われています」）。
- セッション開始後の参加も可。ローテーション加入は次の周から有効（既存 rotation 追加ロジック流用）。

## セクション2：セッション中（最も長く見る画面）

参考デザインの DriverPanel（円形タイマー＋TeamOrbit）を中核に据える。

**情報の優先順位:**
1. 現ドライバー（最大・最明・Crown＋amber、TeamOrbit 中央上）
2. 残り時間（円形プログレス中央・白・残り10秒で赤＋予告）
3. 次ドライバー（「次: Bob」、一段下）
4. 周回数・経過・交代回数（統計バー）
5. お題（折りたたみ）
6. 参加者一覧（ローテーション参加者と見学者を区別）

**自動交代のリズム:**
- タイマー満了 → サーバーが次の eligible な人へ自動交代 → 全員一斉切替（shake/pulse＋アナウンス）。
- 手動「今すぐ交代」併設。既存 ServerClock・autoSwitch・nextEligibleIndex を流用。

**操作と権限:**
| 操作 | 誰 |
|---|---|
| 一時停止/再開・今すぐ交代 | ローテーション参加者（editor+） |
| ドライバーに加わる/外れる | 本人（現ドライバーが外れたら即次へ） |
| お題編集・やり直し | editor+ |
| 終了/リセット | ホスト（確認つき） |
| 休憩 | ホスト |

**周回数（新概念）:**
- `rounds` = ローテーションが一巡した回数。core に導出を追加（`totalSwitches` とローテ長から導出）。

## セクション3：振り返り（Review）

現 Summary（単発記録）を**ラウンド・個人別**に作り直す。

**表示:**
- 総括: 周回数・総交代回数・所要時間（glass カード）
- **個人別ドライバー回数**: `session.driverCounts[]`（rotation 同順）を名前と紐づけバー表示。偏りが一目で分かる
- お題: タイトル/言語/難易度
- 見学者も「見学」表示で一覧に出す（誰がいたかの記録）
- 終了種別で出し分け（完成=祝祭バナー／中断=控えめ）
- 導線: 「もう一周する」（同メンバー・お題で Lobby へ）／「新しいセッション」（Setup へ）

**永続化:**
- 完成時 IndexedDB 保存（既存 persist 経路）。`CompletionRecord` に `driverCounts`/`rounds`/参加者名を加算的に追加。中断は保存しない。

## 影響範囲（実装の見取り図）

**core（純粋ドメイン・加算的拡張）:**
- `rounds` 導出を追加
- `CompletionRecord` に `driverCounts`・`rounds`・参加者名を追加

**sync（既存能力の転用が中心）:**
- `room.join` を role=editor・名前指定・重複名チェックに変更
- 「ドライバーに加わる/外れる」は既存 `driver.resume`/`driver.skip`・`addProxy` の rotation 操作を流用

**web（UX の主戦場）:**
- Setup: 他人メンバー一括入力を廃止 →「自分の名前＋言語/難易度/間隔」
- 参加画面（新規）: リンクで来た人の「名前を入れて参加」1画面
- Lobby: 参加者一覧に「ドライバーに加わる/外れる」トグル・見学/参加の区別
- Session: 周回数表示・「今すぐ交代」・参加者一覧の加入/離脱
- Review（旧 Summary 改修）: 個人別ドライバー回数バー・周回数・「もう一周する」導線

## スコープ外（YAGNI）

- 同場（同一画面を全員で囲む）モードは作らない（リモート・各自デバイスに集中）
- チーム横断の恒久記録ストア・アカウントは持たない（記録は端末ローカル）
- お題の高度なエディタ（Markdown プレビュー等）は作らない（持ち込みは補助）
- ネイティブ通知・音声読み上げ等は必須としない（画面更新＋aria-live で状態を伝える）

## 非機能（既存方針を継承）

- アクセシビリティ: 色のみ依存しない・AA・キーボード操作・aria-live・モーダルの focus trap
- 演出: 節目（交代・残りわずか）のみ強調、`prefers-reduced-motion` で抑制
- 秘密ゼロ: AI 鍵は端末内のみ（WS/ログ/記録に載せない）
- サーバーは揮発インメモリ（恒久状態を持たない）
