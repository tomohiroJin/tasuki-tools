## 1. 目的

### 1.1 利用者の言葉

2026-09-26（#91 PR 3・#312 の確認時）:

> お題の入力欄が小さいのと、説明プレビューが存在しない。お題についてはアジャイルでよくあるようなお題である「whoとしてWhatをしたい。Whyだからだ」のように長いお題にも入力しやすくしたい

2026-09-30（設計の対話）:

- 画面の案から「広い画面は案B（書く欄とプレビューを並べる）、狭い画面は切り替え」を選んだ
- お題ツールのページは最大 680px で、案B の並べ方が入らないことを伝えたところ、「**この Issue で幅も広げる**」を選んだ

### 1.2 ユーザーストーリー

## 3. 実測した事実（main `ba9249d`）

- **タイトル**は 1 行の `<input className="ui-input">`・`maxLength={MAX_TOPIC_TITLE}`（200）。**説明**は `<textarea className="ui-input" rows={6}>`・`maxLength={MAX_TOPIC_BODY}`（4000）（`apps/topic-web/src/components/TopicEditor.tsx`）
- **ページ幅**: お題ツールは `<main className="page topic-page">`。`.page` は `max-width: 680px`・左右の余白 1.25rem（`packages/ui/src/elements/reset.css`）。中身の幅は最大 640px
- **「書く」と「作る」は横に並ぶ**: `.topic-tools` は `repeat(auto-fit, minmax(min(18rem, 100%), 1fr))`。680px のページでは 2 列になり、「書く」は約 308px（パネルの内側は約 260px）。**案B の並べ方はいまの幅に入らない**
- 玄関の選択画面は `max-width: 1120px`（`apps/landing/src/index.css`）。timer は約 1152px（Tailwind の `max-w-6xl`）
- **いまのお題**は `<article className="ui-sheet">` に `<h3 className="topic-title">` とタイトル、`<Markdown source className="topic-body">` を置く（`CurrentTopic.tsx`）。Markdown の段は 1 つ下げる（`#` → h4）
- 境界スキーマの `titleStr` は長さ（`.length`・UTF-16 の単位）と空白だけを見る。**改行は拒まない**（`packages/topic-core/src/schemas.ts`）。いまの `<input>` は改行を入れられないので、改行を含むタイトルはこれまで作れなかった
- タイトルは玄関・timer・poker・お題ツールで**見出しの素の文字**として出る（`h3` など。`white-space` の指定は無く、改行は空白に畳まれる）
- **書体の base 層**（`packages/ui/src/tokens/fonts.css` の `zkgn-*-base`）を候補の文言に当てた（`apps/topic-web/tests/support/font-base.ts` と同じ判定）:

  | 文言 | 結果 |
  |---|---|
  | 書く・プレビュー・説明の出し方・見え方・Markdown で書けます | 収まる |
  | 説明を書くと、ここに見え方が出ます | 収まる |
  | 字・文字・字数 | **外れる**（字・文） |
  | 長い文は折り返します | **外れる**（長・文・折・返） |

- 例のユーザーストーリー「チームの一員として、スプリントの終わりにふりかえりの結果を一目で見たい。なぜなら、次のスプリントで何を変えるかをその場で決めたいからだ」は 67（`.length`。PR 1 の実画面で実測）
- 編集とプレビューの切り替えの前例は、timer の `SharedMemo` の 1 つだけ。Tailwind で組んだ 1 つのボタン（「編集」／「プレビューに戻る」）で、既定はプレビュー（読み手を優先）
- 部品層に部品を置く条件は「同じ見た目の知識」と「2 画面以上が使う」（#320 正本 D1）。`scripts/audit-ui-components.mjs` は、部品層の `.ui-*` を 2 つ以上のアプリの `.tsx` が使っていないと落とす
- **画面の CSS**では、`textarea` などの入力欄の型を含むセレクタと生の色を書くと `audit-ui-components.mjs` が落とす。配置はクラスで書く
- 要素層の `button` は真鍮の地、`button.secondary` は枠だけ（`packages/ui/src/elements/controls.css`）
- E2E は Chromium だけ（`e2e/playwright.config.ts`）。お題ツールの E2E は、文字のコントラストの走査・Tab の輪郭・16px の下限・幅 320 と 1280 のはみ出しを見ている（`e2e/specs/topic.spec.ts`）
- E2E の `setTopic` は `getByLabel('説明（なくてもよい）').fill(...)` で説明を書く（`e2e/support/topic.ts`）

## 4. 決定

### D1. お題ツールのページだけ、最大幅を 1120px にする

`apps/topic-web/src/index.css` で `.topic-page { max-width: 1120px; }` とする。`@tasuki/ui` の `.page` は変えない。

- **値は玄関の選択画面（1120px）に揃える。** 新しい値を増やさない。#316 が幅を共有の段へ寄せるとき、写し元は玄関とお題ツールの 2 つになる（#316 に申し送る）
- **`.page` を変えない理由**: `.page` は poker も使う。poker の幅を変えるかどうかは #316 の判断で、この Issue では決めない
- ページの幅は画面が持つ配置である（#320 正本 D4）。画面の CSS に書いてよい

### D2. 「作る」を「書く」の上に置き、広いときは 1 行の帯にする（構成案 1）

`.topic-tools` は列の自動配置をやめ、**作る → 書くの順に縦に積む**。どちらも中身の幅いっぱいに置き、横の並びは各面の中で決める。

- **「作る」はボタン 1 つで済む操作**なので、長く書く「書く」より先に置く。DOM の順も入れ替える（CSS の `order` で見た目だけ変えると、読み上げと Tab の順が画面の順とずれる）
- **「作る」の面の幅が 48rem 以上なら 1 行の帯**にする（`.topic-make` の容器クエリ）。言語（14rem）・難易度（10rem）・ボタン・合言葉（右端に寄せ、欄と「解錠する」を横に並べる）。閾値は「書く」の並べる幅（D7）と同じにそろえた。狭いときはこれまでどおり縦に積む
- 帯ではボタンを縮めない（`flex: none`）。縮めると「解錠する」が 2 行に折り返した（実画面で発見）
- **経緯**: 当初は `.topic-write { grid-column: 1 / -1 }` で「書く」を行いっぱいにし、「作る」は 2 行目で行いっぱいに広がると見ていた。実際は `auto-fit` が畳むのはどの行にも項目の無い列だけで、「作る」は 1 列ぶん（約 340px）のまま左に残り、右に空きができた（PR 1 の実画面とレビューで指摘）。利用者と 3 つの構成案（帯・タブ・側列）を比べ、**帯**を選んだ（2026-09-30）。タブは AI で作れることに気づきにくく、側列は「書く」が狭まって D7 の並べる幅に届かない

### D3. タイトルは折り返す複数行の欄にし、改行は入れない

- `<textarea className="ui-input topic-title-field" rows={2}>` にする。`maxLength` は `MAX_TOPIC_TITLE` のまま
- **書いた量に合わせて伸ばす**: `.topic-title-field { field-sizing: content; }`。`field-sizing` に対応しないブラウザは `rows={2}` の高さのまま、縦に伸ばせる（部品の `resize: vertical`）
- **改行は入れない。** タイトルは各画面で見出しの素の文字として出る（§3）。改行を持たせると、画面ごとに崩れ方が変わる
  - **Enter で送る**（いまの 1 行の欄と同じ）。ただし**変換中（`isComposing`）の Enter は送らない**（日本語の確定の Enter で送ってしまう）。Shift+Enter も改行を入れない
  - 貼り付けなどで入った改行（`\r\n`・`\r`・`\n`）は空白 1 つに置き換える（純粋関数 `toSingleLine`・`topic-view.ts`）
  - **置き換えてもカーソルを末尾へ飛ばさない。** 値を書き直すとブラウザはカーソルを末尾へ移すので、書き直した直後に差し込んだ文の後ろへ戻す。欄の値の改行は常に `\n` の 1 字（textarea は `\r\n` をそろえて持つ）なので、空白に置き換えても位置は変わらない（レビューで指摘）
  - **「書き直す」でいまのお題を写すときも 1 行にする。** 境界スキーマは改行を拒まないので、AI や別の接続から改行入りのタイトルが届きうる（レビューで指摘）
- 見出しの字の大きさ（`--font-size-lg`）は使わない。欄の字は部品の 16px のまま（部品の入力欄の字の大きさを上書きしない。`packages/ui/README.md`）

### D4. 書いた量は数字だけで出す

- タイトルは `67 / 200`、説明は `164 / 4000` の形。数は `.length`（境界スキーマと同じ単位）
- **「字」を添えない。** base 層の外（§3）。単位の無い数字は、欄の直下で上限と並べれば読める
- 欄の `aria-describedby` で数字を指す。`aria-live` にはしない（打つたびに読み上げられる）
- 上限に近づいても色を変えない（上限で止まるのは `maxLength` が担う。色だけで知らせる表現を増やさない）

### D5. 説明の欄は書いた量に合わせて伸ばす

- `rows={8}`・`.topic-body-field { field-sizing: content; max-block-size: 32rem; }`。32rem を超えたら欄の中でスクロールする（4000 まで書くと画面が欄で埋まる）
- 欄の下に「Markdown で書けます」と数字（D4）を置く

### D6. プレビューは、いまのお題と同じ札の部品で描く

- `CurrentTopic` の札（`<article className="ui-sheet">` とタイトルと Markdown）を `components/TopicSheet.tsx` に切り出し、**いまのお題とプレビューの両方がこれを使う**。片方だけ直すと「このお題にする前と後で見え方が違う」ことになる（Issue の「書く欄と、掲げた後の見え方が一致しているかを確かめられない」そのもの）
- **プレビューはタイトルと説明の両方を描く**（札の全体）。空白だけのタイトルの見出しは描かない
- タイトルも説明も空の間は、札の代わりに一言「説明を書くと、ここに見え方が出ます」（`.ui-note`）
- プレビューの領域は `<section aria-label="プレビュー">`（見出しを持たない領域）。**`aria-live` にしない**（打つたびに札の全体が読み上げられる）
- 説明は `useDeferredValue` を通して描く。4000 まで書いても打つ手を止めない

### D7. 「書く」の幅が 48rem 以上なら並べ、未満なら切り替える

- `TopicEditor` の説明の部分（説明の欄とプレビュー）を `.topic-compose` で包み、`container-type: inline-size` にする。**ページの幅ではなく「書く」の容器の幅で決める**（ページの幅にすると、並びが変わったときに閾値がずれる）
- **48rem（768px）以上**: 説明の欄とプレビューを 2 列に並べ、切り替えのボタンを出さない
- **48rem 未満**: 切り替えのボタンを出し、選んだ方だけを出す
- 閾値の根拠: 1120px のページでは「書く」の内側が約 1030px（各列 約 500px）。タブレットの縦（768px）では内側が約 680px なので切り替えになる。並べたときの 1 列が 23rem を下回らない
- 並べたときも切り替えのときも、**React の木は同じ**にする。どちらを出すかは CSS（容器クエリと `data-mode`）が決める。jsdom では容器クエリが効かないので、並ぶことは E2E が見る

### D8. 切り替えのボタンは要素層のボタンで組み、部品層に置かない

- `<div role="group" aria-label="説明の出し方">` に `<button type="button" aria-pressed>` を 2 つ（「書く」「プレビュー」）置く。**押している方は要素層の `button`（真鍮）、押していない方は `button.secondary`**。新しい見た目の語彙を作らない
- **部品層に置かない理由**: 使うのはお題ツールだけ（#320 正本 D1 の 2 つ目の条件を満たさない）。timer の `SharedMemo` が #321 で素の CSS へ移るとき 2 つ目の利用者になる。**そのときに部品へ寄せる**（#321 に申し送る）
- プレビューの札は部品の `.ui-sheet` と `.ui-md` をそのまま使う（新しい枠を作らない）

### D9. 切り替えの状態

- 既定は「書く」（`SharedMemo` と逆。こちらは書くための欄で、書く前に見るものが無い）
- 「このお題にする」で欄を空にしたら「書く」へ戻す
- 「書き直す」は状態を変えない（いまのお題を写したあと、プレビューのままなら見え方が出る）
- 状態は端末に残さない

### D10. #315 との分担

- プレビューは `TopicSheet` を通して `Markdown.tsx` で描く。#315 が `Markdown.tsx` にチェックボックスを足せば、プレビューにもそのまま出る
- プレビューの上で付け外しするか（下書きを書き換えるか）は #315 が決める。この Issue ではプレビューを読むだけの表示にする
