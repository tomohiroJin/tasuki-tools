## 確定した主要判断

- ロビー/セッションは **2タブ構成（「ルーム」⇄「お題・設定」）**。お題/設定は**触らなくても既定値で利用可能**なオプション。タブは将来のオプション追加先として拡張する。
- ドライバー不在は **猶予(〜30秒)→自動繰り上げ**。
- 主催者不在は **明示的ホスト移譲 ＋ 自動委譲の可視化**（奪還/co-host は非対象）。
- ルーム破棄の可視化は **運用者専用（ADMIN_TOKEN 保護）の管理ビュー＋/status**。
- ルーム参加強化は **任意のルームパスフレーズ**（承認制は非対象）。
- IP 単位レート制限は**エッジ層**（アプリ層ではない）。

## Epic 1 — タブ化ロビー/セッション（#5・#6・#1）

**概要**: ロビーと（一部）セッションを2タブ化し、お題/言語/難易度を「任意のオプション」へ降格。開始ボタンを常に押しやすく、招待をセッション中も可能にする。

**要件（受け入れ基準）**:
- R1-1: ロビーは「**ルーム**」「**お題・設定**」の2タブを持つ。既定表示は「ルーム」タブ。
- R1-2: 「ルーム」タブは **招待（ルームコード/参加URL/QR・コピー）＋参加者一覧＋セッション開始ボタン**を含み、開始ボタンは**お題本文の長さに関係なく常に視認・操作可能な位置**（上部）に置く。
- R1-3: 「お題・設定」タブは **お題（ProblemEditor）/言語/難易度/交代間隔/詳細設定（ConfigPanel）のフル機能**を提供する。現行で出来ることはすべて出来る。
- R1-4: ユーザーが「お題・設定」タブを**一度も開かなくても**、既定のお題・既定設定でセッションを開始できる（開始は問題未確定でブロックしない＝既定/自動お題で開始可）。
- R1-5: **セッション中も「ルーム」タブにアクセスでき**、招待URL/コード/QR をいつでもコピーできる（#1 解決）。
- R1-6: タブ構造は**オプションを追加しても破綻しない**汎用的な実装（将来のオプションタブ追加が容易）。

**影響範囲（現状）**: `apps/web/src/ui/Lobby.tsx`（現: 2カラムで右=設定→お題→開始）, `apps/web/src/ui/Session.tsx`, `apps/web/src/App.tsx`（mode/renderBody）, `apps/web/src/ui/components/{ProblemEditor,ConfigPanel,RosterPanel}.tsx`。WS 同期・core は変更なし（表示再構成中心）。

**非対象**: お題自動生成（AI）は別件（[[BACKLOG]]）。タブ＝表示構造のみで、既存の config.set/problem.* コマンドは流用。

## Epic 2 — ロール/ライフサイクル（#4・#3）

**概要**: セッション継続性のため、現ドライバー/主催者が落ちたときの挙動を確定し、ホスト管理手段を追加する。

**要件（受け入れ基準）**:
- R2-1（ドライバー不在）: 現ドライバーが切断（presence=offline）になったら、**猶予 `DRIVER_ABSENCE_GRACE_MS`（既定〜30秒）**待つ。猶予内に復帰すれば継続。復帰しなければ**次の eligible ドライバーへ自動繰り上げ**し、新ドライバーのタイマーを開始する。全員 ineligible のときは現状維持（既存 autoSwitch の防御に整合）。
- R2-2: 上記は**サーバー権威**で行う（presence.ts のホスト不在委譲と同型のタイマー機構を踏襲）。クライアントは snapshot/signal に追従するのみ。
- R2-3（明示的ホスト移譲）: 主催者は**離脱前に任意の参加者へホストを手動移譲**できる（role 操作・HOST_ONLY）。移譲後、元主催者は通常ロールになる。
- R2-4（自動委譲の維持＋可視化）: 既存の「主催者切断→30秒→最古オンライン editor へ自動委譲」は維持。加えて、**現在のホストが誰か**を常時明示し、**委譲が発生したことを画面通知**（signal もしくは snapshot 差分のUI表現）する。
- R2-5: ホスト奪還（復帰時の取り戻し）・副主催(co-host) は**今回は非対象**。

**影響範囲（現状）**: `packages/core`（decide/evolve・driver 繰り上げの不変条件）, `apps/sync/src/application/presence.ts`（不在タイマー）, `apps/sync/src/application/schedule.ts`（タイマー）, `apps/sync/src/application/handlers.ts`（role 移譲・authorize）, web（ホスト表示・移譲UI・委譲通知）。

## Epic 3 — 運用可視化（#2）

**概要**: 空ルームが RoomReclaimer で正しく破棄されていることを運用者が確認できるようにする。

**要件（受け入れ基準）**:
- R3-1: RoomReclaimer の回収時に**サーバーログへ構造化記録**（`room <code> reclaimed: idle <ms>` 等）。`journalctl -u tasuki-sync` で追える。
- R3-2: **運用者専用の管理エンドポイント**（例 `/admin/rooms`・`/status`）を提供。内容: アクティブルーム数、ルーム一覧（コード/参加者数/最終活動時刻/作成時刻/ドライバー有無）、**累計回収数**。
- R3-3: 管理エンドポイントは **`ADMIN_TOKEN`（env）必須**。トークン無し/不一致は 401/404。**一般ユーザー・ホストには一切露出しない**（ルームコード＝能力の保護）。
- R3-4: 既存の WS 同期・通常UIに影響を与えない（独立した read-only 運用面）。

**影響範囲**: `apps/sync/src/application/room-reclaimer.ts`（ログ/カウンタ）, `apps/sync/src/server.ts`（HTTP ルート・トークン検証）, `apps/sync/src/config.ts`（ADMIN_TOKEN）, `apps/sync/src/adapters/ws-adapter.ts` or 新 HTTP ハンドラ。`deploy/tasuki-sync.env.example`（ADMIN_TOKEN 追記）。

**非対象**: リッチな管理UI・認証基盤。最小の read-only（JSON または素朴なHTML）で足りる。

## Epic 4 — セキュリティ（#7）

**概要**: 新運用面の保護、参加の強化、エッジでの濫用緩和。

**要件（受け入れ基準）**:
- R4-1: 管理/ステータス面は **`ADMIN_TOKEN` 保護**（Epic 3 R3-3 と一体）。
- R4-2（任意ルームパスフレーズ）: 主催者は**任意でルームにパスフレーズを設定**できる。設定時、`room.join` は**コード＋パスフレーズが一致**しないと拒否（既存の認可/レート制限と整合）。**未設定なら従来どおり**コードのみで参加可（後方互換・既定オフ）。パスフレーズは揮発インメモリのルーム状態として扱い、**スナップショットに平文を載せない**（join 検証用にサーバー保持・全配信には含めない＝トークン同様の扱い）。
- R4-3（IP 単位レート制限・L-1）: **エッジ層**で同一送信元 IP の同時接続/新規接続を制限（Caddy rate_limit プラグイン or ufw/nftables connlimit）。アプリ層の既存上限（接続200/ルーム50）はグローバル維持。値は正規利用（NAT 配下チーム）を壊さない範囲。**運用タスク**として扱う。
- R4-4: 既存の良好な姿勢（Origin 検証・入力長上限・join レート制限・secret-zero・能力トークン非漏洩・HSTS 等）は維持・回帰させない。

**影響範囲**: core（Room にパスフレーズ検証情報・decide/schemas の join 拡張）, sync handlers（join 検証）, server/config（ADMIN_TOKEN）, web（パスフレーズ設定UI・参加画面の入力）, デプロイ（エッジ rate limit・[[BACKLOG]] L-1）。

**非対象**: 参加承認制（待機キュー）。監査ログ。

## Epic 5 — 仕上げ（#8）

**概要**: 体感品質の底上げ。範囲は4観点に限定。

**要件（受け入れ基準・方向性）**:
- R5-1（切断/再接続）: 接続状態を明示（接続中/再接続中/切断）。再接続中の視覚表現と、エラー時の回復導線。StatusStrip の状態語/色を整理。
- R5-2（初回体験/空状態）: 初めて使う人向けの簡潔な説明・空状態の案内（参加者1人・お題未設定・記録ゼロ等）。
- R5-3（モバイル/レスポンシブ）: スマホ幅でのタブ/ボタン/参加者一覧/タイマーのレイアウト最適化・タッチ標的。
- R5-4（アクセシビリティ）: キーボード操作・フォーカス可視/トラップ・コントラスト(AA)・スクリーンリーダー向けラベル/aria の点検と改善。

**影響範囲**: web 全般（既存の primitives・StatusStrip・各画面）。core/sync は原則不変。

**非対象**: 大規模なデザイン刷新（現行の計器テーマは維持）。
