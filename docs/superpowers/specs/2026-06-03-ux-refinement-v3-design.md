# タスキ UX 洗練リファイン（v3 体験改善）— 設計ドキュメント

**日付:** 2026-06-03
**対象:** TDD Mob Pro Timer（`tdd-mob-pro-timer`、共有ルーム型 WS 同期版）
**ステータス:** 承認済み（ブレスト合意）
**前提スペック:** [2026-06-02-ux-redesign-design.md](./2026-06-02-ux-redesign-design.md)（名前のみ Setup・参加者⊇ローテーションの2層モデル）を継承

## 背景と目的

実機での通し利用で 14 件のフィードバックが出た。見た目は改善したが、お題の見せ方・参加導線・AI 設定・タイマーの連続性など「使い込むと気になる」点が残る。本設計はそれらを **即修正バグ** と **方向性を決めた設計判断** に整理し、より洗練された体験へ仕上げる。

## ブレストで確定した方針

1. **お題カード = 課題シート型**（難易度/言語バッジ＋折りたたみ＋明快なアクション言葉）。セッション中は畳んで目立たせない。
2. **ルーム識別 = 「名前＋短い接尾辞」**（例 `morning-mob-7f3`）。覚えやすさと衝突回避・推測困難を両立。
3. **参加導線 = リンク/QR 共有を分かりやすく**。加えて第二参加者が実際に入れるかを E2E 検証し、バグがあれば修正。
4. **AI はいったんなし**（定型お題のみ）。AI 設定 UI とモード切替を撤去。`ByokProvider` 等のコードは将来用に休眠保持。
5. 定型お題は **30 件以上** に拡充し、内容を **具体的** に記述（AI なしのため唯一の出題源）。

## 影響範囲と要件（4 セクション）

### セクション1：お題まわり（FB ⑥⑦⑧⑫＋④）

- **ProblemEditor を課題シート型に再設計**
  - ヘッダー: 難易度バッジ（初級/中級/上級）＋言語バッジ＋タイトル。
  - 本文: 説明文。要件／テスト例／ヒントは `<details>` で折りたたみ（既定は閉じ、要件のみ件数表示）。
  - アクションを**言葉＋アイコン**に変更: `🎲 別のお題にする` / `✏️ 内容を編集` / `📋 貼り付け` / `📄 コピー`。各ボタンに `aria-label` と `title`。
- **セッション中は折りたたみ表示**: Session の上部に「難易度バッジ＋タイトル＋『詳細を開く』」の 1 行バーのみ。展開で全文。お題が主役を食わないようにする（⑫）。
- **AI 撤去（④）**: `AiSettingsModal` を開く導線（「AI 設定」ボタン）と出題モード切替（AI生成/定型）を UI から外す。ステータスの「AI 生成/定型」バッジは**非表示**にする（出題源が一意のため意味を持たない）。お題生成は常に定型バンク。`🎲 別のお題にする` は定型バンクからの引き直し（直近と重複しない選択）。`ByokProvider`/`AiSettingsModal` のコードは削除せず休眠（将来の再有効化に備える）。
- **定型お題バンク拡充（⑤⑥）**: `FALLBACK_PROBLEMS` を 7 → **30 件以上**。各エントリは `title`・具体的な `description`（入出力例や前提を含む）・`requirements[]`（箇条書きで明確）・`exampleTest`（実際のテストコード断片）・`hints[]` を備える。難易度（easy/medium/hard）と言語タグを分散させ、引き直しで偏らないようにする。

### セクション2：ルーム＆参加（FB ①⑩⑪）

- **ルーム名＋接尾辞（①）**
  - Setup に「ルーム名（任意）」入力を追加。未入力ならランダムな形容詞＋名詞等の自動名。
  - サーバーのルームコード生成を「正規化したルーム名（小文字・ハイフン）＋ nanoid 短接尾辞（推測困難な数文字）」に変更（例 `morning-mob-7f3`）。衝突時は接尾辞再生成。
  - 表示・コピー・QR・参加 URL はこの ID を用いる。S1 の「推測困難」は接尾辞で担保。
- **参加導線の明確化（⑩）**
  - ロビーの招待カードに「**このリンクを共有して招待**」を明示（コピー＋QR を主役に、説明文添え）。
  - **第二参加者の実 join を E2E 検証**（2 タブ/2 クライアント相当）。`room.join`→snapshot→ロビー反映が動くか確認し、不具合があれば修正。
- **参加者の削除（⑪）**
  - **host 限定の新コマンド `participant.remove`** を追加し、ホストが参加者（代理含む・自分以外）を一覧から退出させる。rotation に居る場合は rotation からも除外し、現ドライバーなら次へ繰り上げ。rotation 最後の 1 人は不可（BelowMinMembers と同様のガード）。

### セクション3：タイマー＆セッション体験（FB ⑨⑬⑭）

- **自動交代の連続性（⑭）**
  - 時間 0 到達後に「止まって待つ」感を解消。サーバーは従来どおり 1 本の `setTimeout` で発火するが、**クライアントの 0 到達とサーバー発火のズレ**（clockOffset 推定誤差・250ms tick 粒度・RTT）を詰める。
  - 方針: クライアントは残りが 0 を下回っても止めず、次 snapshot まで「まもなく交代」を示しつつカウントを連続的に見せる。サーバー発火を取りこぼさないよう schedule を堅くする。交代後は即新間隔でカウント再開。
- **開始時の表示位置（⑨）**: ロビー→セッション遷移時に**先頭へスクロール**し、タイマー（中核）が最上部に来るようにする。2 カラムでも左メイン＝タイマーが視界に入る初期位置。
- **全体の洗練（⑬）**: 余白・階層・空状態（生成中/未確定）を整理。PC 2 カラムの密度を調整し、左（タイマー主役）と右（参加者・引き継ぎ）のバランスを取る。

### セクション4：細かいバグ（FB ②③）

- **タイトル折り返し（②）**: ブランド見出しが最初の画面（Setup/Join）で意図せず 2 行になる件を修正。**1 行に収める**方針（Setup/Join のコンテナ幅を見出しに合わせて広げる＋`text-wrap:balance`、必要なら見出し用 clamp 上限を調整）。
- **言語・難易度のランダム選択（③）**: ConfigPanel に `🎲`（ランダム決定）ボタンを復活。クリックで言語・難易度をランダムに選ぶ。

## アーキテクチャ方針

- **core**（純粋ドメイン）: `FALLBACK_PROBLEMS` 拡充、ルームコード生成方式の調整（`RoomCodeGen` で名前＋接尾辞）、参加者削除の decide/evolve（必要なら新コマンド）。
- **sync**: `room.create` の config に room 名を受け取り、`code-gen` で ID 生成。`participant.remove`（host 限定）ハンドラ。自動交代スケジュールの堅牢化。
- **web**: ProblemEditor 再設計（課題シート型＋折りたたみ＋明快アクション）、Session のお題折りたたみバー、AI 設定 UI 撤去、ConfigPanel ランダムボタン、Setup ルーム名入力、ロビー招待強調＋参加者削除 UI、遷移時スクロール、タイトル折返し修正。
- **秘密ゼロ維持**: AI 鍵は扱わない方針（今回 UI 撤去）。WS/ログ/記録に機密を載せない。

## スコープ外（YAGNI）

- AI（BYOK/サブスク/managed）の有効化（今回は撤去。将来枠）。
- 同場（同一画面共有）モード。
- チーム横断の恒久記録ストア・アカウント。
- お題の高度な Markdown エディタ。

## テスト戦略

- **core**: `FALLBACK_PROBLEMS` のスキーマ妥当性（全件 `validateProblem` を通す）・件数 ≥30、ルームコード生成（名前正規化＋接尾辞・衝突回避）、参加者削除の decide/evolve・不変条件（rotation≥1）。
- **sync**: `participant.remove`（host 権限・rotation 連動・現ドライバー繰り上げ）、自動交代スケジュールの発火タイミング、room 名付き create。
- **web**: ProblemEditor（バッジ/折りたたみ/アクション ラベル）、Session お題折りたたみ、AI 導線が無いこと、ConfigPanel ランダム、Setup ルーム名、参加者削除 UI、タイトル 1 行。
- **E2E（実機）**: 2 参加者の join 通し、自動交代の連続性、遷移時スクロール。全 `pnpm test`／`pnpm build` 緑、実画面確認。

## 非機能（継承）

- アクセシビリティ: 色のみ依存しない・AA・キーボード操作・aria-live・focus trap・減モーション。
- PC 主役（モバイルは素直に縦積み、PC を縮めない）。
- サーバー揮発インメモリ・秘密ゼロ・full snapshot 同期。
