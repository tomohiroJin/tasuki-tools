## 1. 目的

**進行役だけでなく、ペアやモブの組（2〜4 人）もルーレットでその場で決められるようにする。**
全員の画面で同じ円盤が回り、同じ人たちのところで、同じ順に止まる（#94 から変えない）。

利用者の言葉（2026-10-16）:

- 「今回は複数人が当たるモードを追加する部分に絞って表現したい」
- 「デザインには注意して崩れないようにお願いします」

**崩さないことを設計の一番の制約にする。** 1 人を選ぶ今の画面（#94 で利用者が承認した 3 版）は、
選ぶ人数が 1 のとき**見た目も文言も DOM も 1 画素も変えない**（§6.1）。

## 2. 実測した事実

- `Spin` は `winnerIndex` と `settle` を 1 つずつ持つ（`packages/roulette-core/src/types.ts`）。wire の `spin` も同じ形（`schemas.ts`）
- 一周の規則は `drawWinner` が 1 人ぶんだけ持つ。周を閉じた直後の 1 回目は**直前の当たり**を除く（`draw.ts`）
- 回転中の判定は `SPIN_DURATION_MS`（4000）の定数 1 つ（`roulette.ts` の `isSpinning`）。web は `durationMs` を wire から読み、定数を直接は読まない（`roulette-view.ts` の `elapsedOf`）
- コマンドは `v.strictObject`（余剰の項目を拒む）。項目を足すには新しいコマンドかスキーマの変更が要る
- `ROULETTE_TOO_FEW` の文言は「2 人から回せます」の固定文（`error-messages.ts`）。**文言は引数を取らない**
- 札は縦横比 8:5 固定・幅 `min(100%, clamp(13rem, 50cqi, 16rem))`。名前は 3 段（`card-name-size.ts`）
- 縦積みの円盤の大きさ `clamp(14rem, min(100cqi, 100dvh − 24rem), 32rem)` は、**320×640 で 円盤・札・下端の帯 が 1 画面に入る**ように札の高さ込みで決めてある（#94 spec §6.7 の 3 版）。**札の背を伸ばすと、この予算が崩れる**
- 切り替えのボタンの先例は topic-web の「書く / プレビュー」（`.ui-button--secondary --sm` ＋ `aria-pressed`・`TopicEditor.tsx`）。部品層の README も「選んだ状態を持つ切り替えは `aria-pressed`」と定めている
- 変異の ID は現在 282 まで使っている（`scripts/mutations/`）
- 書体の base 層の実測（`apps/topic-web/tests/support/font-base.ts` の `outsideBase` を node で当てた）:
  - 通る: 選ぶ人数・回すと、2 人が決まります・選ばれた 3 人・選ばれたのは A さん、B さんです・3 人から回せます・お題「X」の 2 人を決めます・ペア・組・この人数は選べません・選ぶ人数の人より、入る人が要ります・回している間は人数を変えられません
  - **外れる**: 「多」「少」「目」（「2 人目」）・「増」「減」。**これらを使わない**

## 3. 範囲

### この設計で行うこと

- 1 回の回転で **k 人（k = 1〜4）** を選ぶ。k はルームで共有する「選ぶ人数」
- 1 回の回転の中で、指し針が **k 回続けて止まる**（1 人目は今と同じ演出、2 人目からは短く送る）
- 結果の札・一言・円盤・一覧を k 人に対応させる
- 一周の規則を k 人に広げる

### やらないこと（#401 の他の候補・この案の外）

- だんだん減っていくモード・目押しモード（#401 の候補 2・3）。**この設計は「モード」の列挙を作らない**（§4 M1）
- 全員をペアに分ける（グループ分け）。§4 の退けた案 Y2
- 結果を timer の交代の輪へ渡す（#401 本文のとおりスコープ外）
- 組の中の役割（ドライバー・ナビゲーター）を決めること。止まった順は見せるが、順に意味を持たせない

## 4. 決定（2026-10-16 利用者が推奨のまま承認。§10）

| # | 決定 | 理由 |
|---|---|---|
| M1 | **「モード」ではなく「選ぶ人数 k」1 つの値で表す**（k = 1 が今の進行役決め、2〜4 がペア・モブ） | 1 人と k 人は同じ抽選の人数違いで、別の遊び方ではない。減るモード・目押しが来たときに要る形は、そのときの実需で決める（原則 X） |
| M2 | **k はルームの状態に持ち、全員で共有する。** 新しいコマンド `roulette.pick.set { count }` で変える | 回す前に全員の画面が「回すと、2 人が決まります」と同じことを言う。回す人ごとに k を持つと、他の人の画面は回り始めるまで何人選ばれるか分からない |
| M3 | **回転は回した時点の k を凍結して持つ。** 回っている間に k が変わっても、その回転は変わらない。画面は回っている間、人数の切り替えを押させない（他の操作と同じ `locked`） | 円盤の席（`wheel`）を凍結するのと同じ考え方。サーバーは回っている間の `pick.set` も受ける（外す・戻すと同じ扱い。受けても回転には効かない） |
| M4 | **組は「k 人を 1 組だけ」** | ペア・モブの「次の組」を決める使い方に足りる。全員を組に分けるのは表示も規則も別物（Y2） |
| M5 | **上限 `MAX_PICK = 4`。回すには入る人が k + 1 人以上要る** | 4 はモブの典型の上限で、札に 4 行が収まる大きさ（§6.3）。入る人がちょうど k 人なら全員が選ばれ、回す意味が無い。k = 1 では今の「2 人から回せます」と一致する |
| M6 | **1 回の回転で k 回続けて止まる。** 1 人目は今と同じ（4000ms・4 周・3 次の減速）。2 人目からは、止まって `STOP_HOLD_MS` 置いてから、次の人の席まで 1 周足して `NEXT_MOVE_MS` で送る | 指し針は 1 本のまま（円盤の幾何を作り直さない）。止まるたびに 1 人ずつ決まる間が、1 人を選ぶときの「誰になるか」の間を保つ。値は §6.2 の見込みで、モックで詰める |
| M7 | **一周の規則: 選ばれた k 人は全員「この一周で選ばれた」に数える。** 1 回の回転で同じ人を 2 度選ばない。周の残りが k に足りなければ残りを全員取り、周を閉じて新しい周から足りない分を引く | 「全員が一周するまで同じ人は選ばれない」（#94 決定 4）を k 人でもそのまま言える |
| M8 | **新しい周から引くときは「この回転ですでに選んだ人」と「直前の回転で選ばれた人」を除く。後者を除くと足りないときは、前者だけを除く** | k = 1 では今の規則（直前の当たりを除く）とちょうど一致する。k ≥ 2 で入る人が少ないとき（例: 入る人 3・k = 2）に引けなくなるのを防ぐ |
| M9 | **wire は項目を足すだけ。** `spin` に `picks: { index, settle }[]` を足し、`winnerIndex` と `settle` は 1 人目の値のまま残す。状態に `pickCount` を足す | `winnerIndex` の意味を変えない（#401 の「意味を変えるなら改名する」に当たらない）。受けるフレームは非 strict なので、古い web は 1 人目だけを当たりとして描く |
| M10 | **選ぶ人数の切り替えは、脇の「ルーレットに入る人」のパネルの見出しの直下に置く。舞台（円盤の面）には足さない** | 舞台の縦の予算（320×640 で 1 画面）に触れない（§6.4）。人数は回すたびに変えるものではなく、入る人と一緒に整える準備である |
| M11 | **k = 1 の画面は #94 の 3 版から 1 画素も変えない** | 利用者の「崩れないように」。差分は k ≥ 2 の分岐の中にだけ置き、k = 1 の撮影の比較を検査にする（§8.4） |

### 退けた案

| 案 | 退けた理由 |
|---|---|
| Y1 回す人が毎回 k を選ぶ（`roulette.spin { count }`） | 他の人の画面が回り始めるまで何人選ばれるか分からない。スキーマの変更は小さいが、画面の言うことが人ごとに割れる |
| Y2 全員を 2 人ずつのペアに分ける | 結果が組の一覧になり、札・一言・円盤のどれも 1 つの場所で見せられない。割り切れない人数の端数の規則も要る。実需が出てから別に決める |
| Y3 指し針を k 本にする | 指し針の位置が k と n で変わり、円盤の外の余白・札の置き場・段組みが k ごとに変わる。崩れる面が最も広い |
| Y4 k 回、続けて普通に回す（4 秒 × k） | k = 4 で 16 秒。#94 の 2 版で「4.8 秒でも 8 秒以上に感じた」と縮めた経緯に逆らう |
| Y5 1 回だけ止め、残りの k − 1 人は同時に光らせる | 指し針が指していない席が当たりになり、「針が指した人が選ばれる」という円盤の約束が崩れる |
| Y6 k ごとに札の背を変える | 人数を変えるたびに円盤の大きさが変わる。回し始めに k が凍結されるので回転中には変わらないが、2 → 3 → 4 と押すたびに舞台が伸び縮みする。§6.3 のとおり組の札は背を 1 つに固定する |

## 5. 設計

### 5.1 `packages/roulette-core`

**状態と型**（`types.ts`）

```ts
export interface Pick { index: number; settle: number }

export interface Spin {
  seq: number;
  wheel: Entry[];
  /** 1 人目（picks[0]）の席。古い web のために残す（意味は変えない） */
  winnerIndex: number;
  settle: number;
  /** 止まる順の当たり。1〜MAX_PICK 件・席は重ならない */
  picks: Pick[];
  spunBy: string;
  startedAt: number;
}

export interface RouletteState {
  // …今の項目
  /** 選ぶ人数（1〜MAX_PICK）。既定 1 */
  pickCount: number;
}
```

`INITIAL_ROULETTE_STATE.pickCount = 1`。**既定が 1 なので、`pick.set` を一度も送らないルームは今と同じに動く。**

**定数**（`limits.ts`）

| 名前 | 値 | 意味 |
|---|---|---|
| `MAX_PICK` | 4 | 選ぶ人数の上限 |
| `STOP_HOLD_MS` | 500（見込み） | 止まってから次へ送り始めるまでの間 |
| `NEXT_MOVE_MS` | 1100（見込み） | 次の人の席まで送る時間 |
| `spinDurationMs(k)` | `SPIN_DURATION_MS + (k − 1) · (STOP_HOLD_MS + NEXT_MOVE_MS)` | 回転の全体の長さ。k = 1 で 4000、k = 4 で 8800 |

`spinDurationMs` は**サーバーの回転中の判定（`isSpinning`）と wire の `durationMs` の両方の正本**にする。
`isSpinning` は `lastSpin.picks.length` から長さを出す（凍結した k を使う・M3）。

**抽選**（`draw.ts`）: `drawPicks(pool, state, k, randomInt)` を足す。

1. 1 人ずつ k 回引く。各回の候補は `pool − drawn − 今回すでに選んだ人`
2. 候補が空なら周を閉じる: `drawn = []`、候補 = `pool − 今回すでに選んだ人 − 直前の回転の picks`。これが空なら `pool − 今回すでに選んだ人`（M8）
3. 返すのは `{ picks: number[]（pool の添字）, drawn }`

**`drawPicks(…, 1, …)` が #94 の 1 人の抽選と同じ結果になることを表で確かめる**（k = 1 の回帰を守る）。
実装は §11 のとおり `drawWinner` を外して `drawPicks` 1 本にした。#94 の単体（`draw.test.ts`）は期待値を変えずに k = 1 の `drawPicks` で緑。

**遷移**（`roulette.ts`）

- `startSpin`: 入る人が `pickCount + 1` 未満なら `ROULETTE_TOO_FEW`（k = 1 では今の「2 人未満」と同じ）。`randomSettle` を k 回引き、`picks` を作る。`winnerIndex`・`settle` は `picks[0]` の写し
- `setPickCount(state, count)`: 1〜`MAX_PICK` の外は `Err(INVALID_PICK_COUNT)`。同じ値なら同じ参照を返す（変わらない操作は配らない・`resetCycle` と同じ）
- `toView`: `pickCount` と `spin.picks` を載せる。`durationMs` は `spinDurationMs(picks.length)`

**エラーコード**: `INVALID_PICK_COUNT` を足す。文言「この人数は選べません」（base 層に収まる・§2）。
**k ≥ 2 の `ROULETTE_TOO_FEW`** は wire の文言が「2 人から回せます」のままになる。web はボタンを押させず、一言で
「{k+1} 人から回せます」を自分で組んで出すので、この文言が画面に出るのは食い違った瞬間だけである。
**それでも正しい文にするため、コードを分ける**: `ROULETTE_TOO_FEW_FOR_PICK`「選ぶ人数の人より、入る人が要ります」（k ≥ 2 のときだけ返す）。

### 5.2 同期サーバー（`apps/tasuki-sync`）

- `roulette-handlers.ts` に `roulette.pick.set` の分岐を足す（`setPickCount` → `commit`。`Err` は `fail(connId, "INVALID_PICK_COUNT")`）
- `roulette.spin` は変えない（`startSpin` が `pickCount` を状態から読む）
- 乱数源のポートは変えない（`randomSettle` を k 回呼ぶだけ）

### 5.3 wire

```ts
// コマンド（strict）
v.strictObject({ command: v.literal("roulette.pick.set"), count: v.number() })   // 範囲はドメインが見る（§11）

// フレーム（非 strict）
state: { …今の項目, pickCount: v.optional(v.number(), 1) }
spin:  { …今の項目, picks: v.optional(v.array(v.object({ index: v.number(), settle: v.number() }))) }
```

**web は `picks` が無いフレームを `[{ index: winnerIndex, settle }]` として読む**（古いサーバーと新しい web が組み合わさる配布の窓）。
`pickCount` が無ければ 1。

**配布の窓**（#94 spec §7.3 と同じく受容する）:

1. **新しいサーバー・古い web**: 古い web は `picks` を知らず、1 人目だけを当たりとして描く。`durationMs` は k 人ぶんなので、1 人目へ向かってゆっくり回る。人数の切り替えは無いので、古い web だけのルームでは k が 1 のまま
2. **古いサーバー・新しい web**: `pick.set` は `INVALID_COMMAND` で拒まれる。配布はサーバー → web の順（今と同じ・`deploy/roulette/NOTES.md`）

### 5.4 揮発

`pickCount` はルームの揮発メモリに置く（ADR-0007）。再起動で 1 に戻る。**複数回の回転にまたがる途中経過は持たない**
（1 回の回転で k 人が決まりきる）ので、#401 の「揮発との折り合い」はこの案では起きない。

## 6. 見た目（崩さないための決め）

### 6.1 変えないもの（k = 1）

k = 1 のとき、次は #94 の 3 版（とその後の #373）のまま。**分岐は `k ≥ 2` の側にだけ書く。**

- 札（8:5・3 段の名前・「次の進行役」「さん」）・一言・ボタンの文言
- 舞台の並び（縦積み / 横並び）・円盤の大きさの式・指し針・下端の帯
- 円盤の演出（4000ms・4 周・3 次の減速・境目で指し針が弾む）

**変わるのは脇に「選ぶ人数」の 1 行が増えることだけ**（§6.4）。この 1 行は脇にあり、舞台の大きさの式に入らない。

### 6.2 円盤の動き（k ≥ 2）

```
経過  0 ─────────── 4000 ── 4500 ──── 5600 ── 6100 ──── 7200 …
      1 人目へ回る    止まる  置く  2 人目へ送る  止まる  置く  3 人目へ送る
                     （札をめくる）            （札に 2 行目）
```

- 純粋関数 `stopsOf(picks, durationMs)` が「i 人目が止まる時刻」の列を返す。`angleAt` を区間ごとの関数に広げる:
  1 区間目は今の `angleAt` そのもの（**k = 1 の角度の列は今と同じ**）、2 区間目からは「直前の止まった角度」を開始角にして
  `finalAngle` を 1 周（`TURNS` ではなく 1）で解き、`NEXT_MOVE_MS` で 3 次の減速
- **どの画面も同じ席で止まる性質は区間ごとに保たれる**: 各区間の止まる角度の 360° の剰余は開始角に依らない（#94 spec §6.4 の `finalAngle` の性質をそのまま使う）
- 境目で指し針が弾むのは送っている間も同じ
- **止まったかの判定は画面の 1 か所のまま**（`phaseOf`）。局面に「i 人目まで決まった」を足す: `revealedCountOf(spin, receivedAt, nowMs)`（0〜k）。札・当たりの席・一言・一覧の「選ばれた」・一周の数は、**この 1 つの値**で同じ瞬間に切り替わる
- 途中から合流した画面は、受け取った経過から区間と角度を出す（`elapsedMs` が 4800 なら 2 人目へ送っている途中）
- 動きを減らす設定: 回さず、k 人を一度に出す（`revealedCount = k`）

### 6.3 札（k ≥ 2: 組の札）

```
k = 1（今のまま）           k = 2〜4（組の札・背は 1 つに固定）
┌─────────────┐            ┌─────────────┐
│ 次の進行役   │            │ 選ばれた 3 人 │
│  健太 さん   │            │ 1  あおい さん│
└─────────────┘            │ 2  健太 さん  │
   8:5                     │ 3  Ren さん   │
                           │              │ ← 4 行ぶんの背を常に取る
                           └─────────────┘
```

- 幅は今の札と同じ（`min(100%, clamp(13rem, 50cqi, 16rem))`）。**背は `MAX_PICK` 行ぶんに固定**し、k が 2・3 でも同じ（Y6）。名前の行は札の中で上下の中央に寄せる
- 見出しは「選ばれた {k} 人」。行は「{順の数字} {名前} さん」。名前は**各行 1 行で … に切る**（全文は直下の一言と脇の一覧が持つ・#373 と同じ考え方）。名前の字は `--font-size-lg`（`md` の段と同じ）で 1 段だけ
- 順の数字は丸数字（①〜④）にせず、Fraunces のイタリックの数字（円盤の中心の数と同じ書体・`--coal-soft`）で置く。丸数字は書体の層を増やす恐れがあり、数字は Fraunces の範囲で済む
- **1 人目が止まった時点でめくる**。2 人目からは行が埋まるだけで、札は動かない（伏せ直さない）。まだ決まっていない行は空けておく（背が先に決まっているので、行が埋まっても段組みは動かない）
- 札を見える位置へ寄せる処理（#94 E22）は**最後の人が止まったとき**に 1 回だけ行う

**組の札の背と円盤の予算**: 組の札は今の札より背が高い（4 行 ≒ 札の中で 4 × 1.6rem ＋ 見出し ＋ 余白 ≒ 10rem・今の 13rem 幅の札は約 8.1rem）。
縦積みの円盤の式の `24rem` は札の背を含むので、**組の札のときだけ、差の分を円盤の式から引く**:

```css
.roulette-stage { --card-extra: 0rem; --wheel-size: clamp(14rem, min(100cqi, 100dvh - 24rem - var(--card-extra)), 32rem); }
.roulette-stage[data-pick='group'] { --card-extra: 2rem; /* 実装で札の背を測って決める */ }
```

`data-pick` は**表示している札の種類**（回したことがあれば `spin.picks.length`、無ければ `pickCount`）で決める。
回っている間は凍結した k なので変わらない。**k = 1 では `--card-extra` が 0 で、式は今と同じ値になる**（M11）。
横並びは札が円盤の中心の高さの行（`auto`）に入り、上下の `1fr` が縮むだけなので式を変えない（円盤は最小 20rem で、組の札より背が高い）。

### 6.4 選ぶ人数の切り替え（脇）

```
┌ ルーレットに入る人  5 ─────────┐
│ 選ぶ人数                        │
│ (1 人)[2 人](3 人)(4 人)         │ ← 副のボタン --sm × 4・選んだものは aria-pressed
│ ☑ あおい                         │
│ …                                │
```

- 部品は topic-web の「書く / プレビュー」と同じ: `.ui-button--secondary --sm` に `aria-pressed`。並びは `role="group"` に「選ぶ人数」の名前を付ける（見出しの `<p>` を `aria-labelledby` で結ぶ）
- 1 行目に「選ぶ人数」、2 行目にボタン 4 つ。**320px でも 1 行目と 2 行目を分けて置く**（4 つのボタン（各 約 3.5rem）とラベルを 1 行に詰めると、脇のパネルの内幅 約 16rem を超える）。広い幅では 1 行に並べてもよいが、並びを幅で変えない方が崩れにくいので**常に 2 行**にする
- 押せないとき（回っている間・切断中）は他の操作と同じく `locked`
- **入る人が足りない k も押せる**（入る人は後から足すことがある）。足りなければ一言が「{k+1} 人から回せます」と言い、回すが押せない
- 押せる大きさは `--sm` の当たり 44px（部品が持つ）

### 6.5 言葉（base 層で実測済み・§2）

| 場所 | k = 1（今のまま） | k ≥ 2 |
|---|---|---|
| お題の添え書き | お題「{t}」の進行役を決めます | お題「{t}」の {k} 人を決めます |
| 回す前の一言 | 回すと、次の進行役が決まります | 回すと、{k} 人が決まります |
| 回している間の一言 | {名前} さんが回しました | （同じ） |
| 結果の一言 | 次の進行役は {名前} さんです | 選ばれたのは {A} さん、{B} さん、{C} さんです |
| 札の見出し | 次の進行役 | 選ばれた {k} 人 |
| 入る人が足りない | 2 人から回せます | {k+1} 人から回せます |
| 切り替え | — | 選ぶ人数 ／ 1 人 ／ 2 人 ／ 3 人 ／ 4 人 |
| エラー | — | この人数は選べません ／ 選ぶ人数の人より、入る人が要ります |

**画面の見出し（h1）「進行役ルーレット」と玄関の札は変えない**（この案は「進行役ルーレットで組も決められる」に留める。名前を変えると玄関の札の 1 行の検査に波及する）。
結果の一言は**最後の人が止まってから**入れる（途中で入れると、読み上げが 1 人ずつ割り込む）。回している間は「{名前} さんが回しました」のまま。

### 6.6 円盤（k ≥ 2）

- 止まった席は順に真鍮の地に変わり、**送っている間も真鍮のまま**（何人目まで決まったかが円盤の上で見える）
- 席の色・仕切り・鋲・中心の数（入る人の数）は変えない
- 「選ばれた」の沈んだ席は、回っている間は**まだ決まっていない今回の当たりを除いて**出す（#94 spec §6.8 と同じ規則を k 人に）

### 6.7 a11y

- 人数の切り替えは `aria-pressed` のボタン。色だけで選んだ状態を示さない（地と内側の線・部品が持つ）
- 結果の一言（`role="status"`）は最後の人が止まってから 1 回だけ言う
- 札は今と同じく `aria-hidden`（読み上げは一言が持つ）
- 送っている間の速さは 1 人目の回転より遅い（1100ms で 1 周強）。点滅（WCAG 2.3.1）に当たる速さにならない

## 8. 検証

### 8.1 EARS

- E1 システムは、常にルームごとに選ぶ人数（1〜4・既定 1）を持ち、そのルームのすべてのルーレットの接続へ同じ値を配ること
- E2 利用者が選ぶ人数を変えたとき、システムは 1〜4 の外の値を拒否し、状態を変えないこと
- E3 利用者がルーレットを回したとき、システムは入る人のうち選ぶ人数ぶんの互いに異なる人を、一周の規則に従って選び、止まる順とともに全接続へ同じ形で配ること
- E4 1 回の回転の途中で一周を閉じる場合、システムはその回転ですでに選んだ人を新しい一周の抽選から除き、除いても足りるなら直前の回転で選ばれた人も除くこと
- E5 入る人が選ぶ人数 ＋ 1 人に満たない場合、システムは回す要求を拒否すること
- E6 回っている間に選ぶ人数が変わった場合、システムはその回転の人数・長さ・結果を変えないこと
- E7 選ぶ人数が 1 の間、システムと画面は #94 と同じ結果・同じ長さ・同じ見た目で動くこと
- E8 選ぶ人数が 2 以上の回転を受け取ったとき、画面は 1 人ずつ止まり、全画面で同じ席・同じ順・同じ時刻に止めること
- E9 回っている間、画面はまだ止まっていない人の名前を、読み上げの領域・札・一覧の印・一周の数に出さないこと
- E10 動きを減らす設定が有効な間、画面は回さずに選ばれた全員をすぐに出すこと
- E11 画面は 320・768・1280・1920px の幅で、選ぶ人数が 1〜4 のどれでも、横に溢れず、押せるものは 44px 以上で重ならず、320×640 で円盤・札・下端の帯が 1 画面に入ること
- E12 画面は、選ぶ人数の切り替えを回っている間と切断中に押させないこと

## 12. 実装で外したこと（2026-10-17・#401 PR 2）

**モックの承認（2026-10-17）**: 利用者は、本物の部品と CSS で描いたモック（1 人の画面はそのまま・2 人以上の部分だけを試作）を
320×640・1440×900 で見て「問題無さそう」と承認した。モックで詰めた値は次のとおりで、実装はこの値を写した。

| 何を | 値 | 決めた理由（モックの撮影） |
|---|---|---|
| 止まってからの間 `STOP_HOLD_MS` | 500ms | 見込みのまま。4 人で約 8.8 秒 |
| 次の人へ送る時間 `NEXT_MOVE_MS` | 1100ms | 同上 |
| 組の札の背 | `10rem`（4 行ぶん・人数によらず固定） | 初版の `10.75rem`・名前 `lg` では、1440 で 4 人の名前が札からはみ出し、320×640 で札が下端の帯に 17px 掛かった |
| 組の札の名前の字 | 2 人は `--font-size-lg`、3〜4 人は `--font-size-base` | 4 行を 10rem に収めるため。1440 では 1 人の札と同じ背に揃った |
| 縦積みの円盤の式から引く `--card-extra` | `1.75rem` | 320×640 では円盤がもう最小（14rem）に近く、引ける分は小さい。4 人の札の下端は帯に約 9px 掛かる（1 人の札も 5px 掛かっている。最後の行の文字は帯の上に見える） |
| 人数の切り替え | 4 つのボタンを等分で 1 行 | 初版の折り返し（flex-wrap）では脇で 2×2 に折れた |

PR 2 で §5・§6 から変えたこと・実装で分かったこと。

- **止まる時刻の表を core に置いた**（`pickStopsMs`）。§5.1 は `spinDurationMs` だけを正本にしていたが、画面も「いつ何人目が
  止まるか」を同じ表から出す必要がある。写しを持つと、サーバーの回転の長さと画面の止まる時刻が片方だけ直る。
  `spinDurationMs(k)` はこの表の最後の値にした
- **画面の時計は、各人が止まる時刻すべてに timer を置く**（`RouletteRoom` の `useNowMs`）。初めは「次の時刻を 1 つ待ち、
  起きたら次を待ち直す」形にしたが、時間を一度に進めるテストで 1 人目の後に止まったままになった。裏のタブで timer が
  遅れて一度に起きたときも同じことが起きる（起きた時点で残りの時刻をすでに過ぎているので、待ち直す先が無い）。変異 m310 が守る
- **真鍮の席・札の行・一覧の「選ばれた」・一周の数は「何人目まで決まったか」（`revealedCountOf`）1 つで切り替わる。**
  円盤の `Wheel` の props は `winnerIndex` から `winners`（決まった席の列）に変えた。これにより #94 の変異 m184
  （舞台が自前の時計で止まる）の元の当て先は壊しても見た目が変わらなくなったので、円盤の真鍮の席だけが自前の時計で数える形へ移した
- **1 人の画面が変わっていないことを画素で確かめた。** 同期フックだけを固定の値に差し替えて本物の `RouletteRoom` を描き、
  変更の前後で舞台（`.roulette-stage`）を 320・768・1440 の幅で撮り比べた。回す前・止まった後とも**画素まで一致**した。
  ページ全体は脇の「選ぶ人数」の行の分だけ高くなる（M11 の「変わるのは脇の 1 行だけ」のとおり）
- **#94 の画面の変異 6 本（m165・m166・m174・m182・m184・m185）は当て先を移した**（壊し方の意図は同じ）。#401 の画面の変異は m307〜m310
- **PR は 2 本に分けず、1 本（PR 1 と同じ枝）に積んだ。** この作業の枝が 1 本に決まっていたため。コミットは PR 1 と PR 2 で分けてあり、
  別々に戻せる
- **E2E は手元で流せていない**（この作業環境に Caddy が無い）。`e2e/specs/roulette.spec.ts` に足した場面（2 人・4 人・320×640）は CI の `e2e` が流す
