## 1. 目的と経緯

**ルーレットで順番を決める。** 回すたびに、まだの人から 1 人が選ばれ（その人の番）、選ばれた人は円盤から抜けていく。
全員の番が来たら回は終わる。例: 発表の順番をルーレットで決め、発表した人は抜けていく。

#401 の言葉: 「チームとして、回すたびに 1 人ずつ抜けていく緊張感のある決め方を選べる」

**経緯（2026-10-17）**: 初版は「抜けていき、最後に残った人が当たり（次の進行役）」として設計し、モック 1 版を作った。
利用者の言葉で考え方を改めた:

- 「選ばれて抜けていく、要は順番に当たっていく感じ。最後の表示も次の進行役って感じではなく無い感じで」
- 「発表者がルーレットで決まって、発表した人間は抜けている感じ」
- 「44 秒かかること自体は OK」（1 回の回転は今と同じ 4 秒）

モック 2 版を見て「ルーレットの周りや減り方はいいが、最後の見せ方が変」「オプションの選択が分かりにくくなってきたので整理してほしい」。
3 版で脇を整理し、終わり方を 2 案にして見比べてもらい、**案 A（最後の 1 人を回さずに出し、円盤を空にする）** に決まった。

**今の「1 回で決める」の舞台（円盤・札・一言・回す）は変えない**（#415 で利用者が承認した画面）。脇は整理する（§5.4）。

## 2. 実測した事実（main `2b40f11b`）

- 回転は 1 回で完結する。複数の回転にまたがる状態は無い（`lastSpin` は最後の 1 回だけ）
- 選ぶ人数 `pickCount`（1〜4）はルームで共有する。切り替え（`PickCountPicker`）は脇の「ルーレットに入る人」の見出しの下
- **選ぶ人数の切り替えは、選んでいるボタンが見た目で分からない。** #415 は「色と枠は部品（副のボタン ＋ `aria-pressed`）が持つ」
  としたが、部品層は `aria-pressed` を飾らない（topic-web は画面の CSS で `--gold-tint` の地と `--gold-deep` の内側の線を当てている）
- 書体の base 層（`outsideBase`）: 「来」「円盤」「目」（「3 番目」）「減」「勝」は外れる。「番」「順番」「済み」「最後」「抜け」は通る

## 3. 決定（2026-10-17 利用者がモック 3 版を見て決めた）

| # | 決定 | 理由 |
|---|---|---|
| T1 | **「決め方」をルームの状態に持つ**（`mode: 'once' \| 'order'`・既定 `once`）。`roulette.mode.set` で変える。全員で共有 | 2 つ目の遊び方が来たので、multi-pick spec M1 の「モードの列挙は実需が出てから」の実需にあたる |
| T2 | **順番に回すときは、押すたびに「まだの人」から 1 人を一様に引く。** 選ばれた人はその回の「済み」になり、次の回転の円盤から抜ける | 順番は順に当たっていくこと自体が結果。先に決めておく人（隠す状態）は要らない |
| T3 | **まだの人が 1 人になったら、回さずにその人を出す**（主ボタン「最後の 1 人」）。円盤は席が無くなって空になる | 1 席の円盤は壊れて見えた（モック 2 版）。減っていく流れが空になるところまで続く（案 A） |
| T4 | **全員の番が来たら回は終わる。** 「次の進行役」のような結果は出さない。主ボタンは「次の回を始める」 | 利用者の言葉（§1） |
| T5 | **回は複数の回転にまたがる状態としてルームに持つ**（`order: { done, finished }`）。揮発（ADR-0007） | 誰が済んだかを回転をまたいで持つ |
| T6 | **まだの人は、いまの入る人（`poolOf`）から済んだ人を除いたもの**。回の途中で入った人も入り、抜けた人は入らない | 後から来た発表者にも番が回る（モック 2 版で利用者に見せた形） |
| T7 | **順番に回すときは 1 回に 1 人**（選ぶ人数は使わない）。一周の規則（`drawn`）も使わず、変えない | 順番の回そのものが一周にあたる。「1 回で決める」の一周の記録を乱さない |
| T8 | **回の途中は決め方を変えられない**（画面は押させず、サーバーも `ROULETTE_ROUND_IN_PROGRESS` で拒む）。「最初からやり直す」で回を捨てる | 途中で決め方が変わると、済んだ人の記録の意味が変わる |
| T9 | **脇を「決め方」「ルーレットに入る人」「仲間を招く」の 3 つの面に分ける。** 決め方ごとの設定と進み具合は「決め方」の面にだけ、選んだ決め方のものだけを出す（§5.4） | 利用者の「オプションの選択が分かりにくい」。設定・進み具合・やり直す操作が入る人の一覧の上下に散らばっていた |
| T10 | **選んでいるボタンに地と内側の線を当てる**（決め方・選ぶ人数。topic-web の「書く / プレビュー」と同じ） | §2 の #415 の見落とし |

## 4. 設計（core ＋ 同期サーバー ＋ wire）

- 状態に `mode`（既定 `once`）と `order`（`{ done: EntryId[]; finished: boolean } | null`）を足す
- `startOrderSpin(state, input)`（`mode === 'order'` の `roulette.spin`）:
  - `order` が無い・終わっていれば新しい回（`done = []`）
  - まだの人 = `poolOf(...) − done`。2 人以上なら 1 人を一様に引いて回す（`lastSpin` は今の `Spin` の形のまま・`picks` は 1 件・`wheel` はまだの人）。`done` に足す
  - 1 人なら回さずに `done` に足し、`finished = true`（T3）。回転中の判定は今のまま
  - 0 人なら `finished = true`（途中で全員が抜けた）。新しい回を始めるのに 2 人未満なら `ROULETTE_TOO_FEW`
- `setMode`（回の途中は拒む）・`resetOrder`（`order = null`）・`prune` は `order.done` からも名簿に居ない人を落とす
- wire: フレームに `mode`・`order` を足す（省略可）。コマンド `roulette.mode.set { mode }`・`roulette.order.reset`（strict）
- **配布の窓**: 古い画面 × 新しいサーバーでは、順番の回転を「次の進行役は ○○ さんです」と読む。決め方を変えられるのは新しい画面だけ。再読込で閉じる

## 5. 見た目

### 5.1 舞台（順番に回すとき）

- **円盤**: 回す前・止まった後は、その回転のまだの人の席（止まった後は選ばれた席が真鍮）。次に押すと選ばれた人が抜けて詰まる。
  最後の 1 人を出した後は**席の無い円盤**。中心の数は**あと何人**
- **札**: 見出しは「{n} 番」、名前と「さん」（今の札の形のまま。見出しだけを変える）
- **一言**（1 行で … に切る。全文は読み上げ）: 回す前「選ばれた人から順に抜けていきます」→ 回っている間「{名前} さんが回しました」→
  止まった後「{n} 番は {名前} さんです」→ 最後「最後は {名前} さんです」
- **主ボタン**: 「次の人を決める」→ まだの人が 1 人「最後の 1 人」→ 終わったら「次の回を始める」

### 5.2 言葉（base 層で実測済み）

決め方 ／ 1 回で決める ／ 順番に回す ／ 1 回回して、選ぶ人数ぶんを決めます ／ 選ばれた人から順に抜けていきます ／
次の人を決める ／ 最後の 1 人 ／ 次の回を始める ／ {n} 番 ／ {n} 番は {名前} さんです ／ 最後は {名前} さんです ／
まだ回していません ／ {k} 人済み・あと {n} 人 ／ 全員の順番が決まりました ／ 最初からやり直す ／ この回の途中は決め方を変えられません（エラー）

### 5.3 脇の一覧の印

順番に回すときは、済んだ人に「{n} 番」（行の名前は薄く）。回っている間は、いま選ばれる人の印を止まるまで出さない

### 5.4 脇の整理（T9）

```
┌ 決め方 ──────────────────┐   ┌ 決め方 ──────────────────┐
│ [1 回で決める][順番に回す]  │   │ [1 回で決める][順番に回す]  │
│ 1 回回して、選ぶ人数ぶんを… │   │ 選ばれた人から順に抜けて…   │
│ 選ぶ人数 [1][2][3][4]      │   │ ─────────────────────── │
│ ─────────────────────── │   │ 2 人済み・あと 4 人         │
│ 全員が一周するまで…         │   │ [最初からやり直す]          │
│ [一周をやり直す]            │   └──────────────────────┘
└──────────────────────┘
┌ ルーレットに入る人  6 ─────┐   ← 人だけ（チェック・印・名前の追加）
┌ 仲間を招く ──────────────┐
```

**「1 回で決める」の舞台は画素まで変えない**（#415 の撮り方で前後比較）。脇は整理の分だけ変わる。

## 6. 検証（要点）

- 単体: まだの人から一様に引く（偽の乱数の表）・途中で入った人が入る・抜けた人が入らない・最後の 1 人は回さない・
  回の途中は決め方を変えられない・やり直すと `order` が消え `drawn` は変わらない・`once` のときは #415 のまま
- 同期サーバー: 2 つの接続に同じ人が同じ順で届く・ほかのツールから新しいコマンドを送ると拒まれる
- 画面: 局面ごとの文言・印・ボタン（純粋関数の表）・空の円盤・脇の 3 つの面
- 変異: 320〜339（並行する枝とぶつからないよう計画に先に書く）
- 「1 回で決める」の舞台の前後比較（画素まで一致）
- E2E: 同じルームの通しに「順番に回す」を 1 回（入る人 3 で 2 回回して最後の 1 人）

## 6.1 実装で決めたこと（2026-10-17）

- `startSpin` が決め方で分ける（順番の回転は `startOrderSpin` の名前で内側に置いた）。同期サーバーの `roulette.spin` は変えない
- 回が「回さずに出す」で終わっても `lastSpin` は前の回転のまま。画面は `order.finished` を見て空の円盤と最後の人の札を出す
- 決め方を変える・やり直すは、回っている間も拒む（`ROULETTE_SPINNING`。回っている円盤が回す前へ跳ぶため）
- 画面は決め方に合わない回転を「回していない」として描く（1 回で決めるときの順番の回転・順番に回すときの回の無い回転）
- 番が決まった人の行は名前を薄くする（外した人と同じ見た目）

## 7. 実装の後で決めること

利用者の方針（§1）のとおり、触ってから決める。

- 終わったときの見せ方（空の円盤で良いか・順番の一覧を舞台にも出すか）
- 「1 回で決める」と「順番に回す」で、一周の記録（`drawn`）をどう関係づけるか（今は関係させない・T7）
- 1 回に 2 人ずつ順番に回す（ペアで発表）か
- お題の添え書きが「お題「…」の進行役を決めます」のまま（順番に回すときの言い方）
