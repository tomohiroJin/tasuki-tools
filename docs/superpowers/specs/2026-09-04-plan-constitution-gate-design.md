`docs/constitution.md` の 2.1.4 の Sync Impact Report は次のように書いている。

そのまま規範文書へ入った形である（[`docs/adr/0002`](../../adr/0002-document-system-three-layers.md)
が言う「記録が正本」の逆流）。

`docs/superpowers/plans/` の最新は **2026-08-28**（#156）である。それ以降の作業

### 3.5 ゲートの様式は揃っていない

3 件のゲートはいずれも「原則ごとの判定表」を持つが、

**したがって「現行の全原則を要求する」検査を過去へ遡って掛けることはできない。**
当時存在しない原則を判定したことにしなければ通らなくなる。

### 3.6 憲法の原則見出しは機械で読める

`docs/constitution.md` は `### I. テスト駆動開発（NON-NEGOTIABLE）` の形で
**11 本の原則見出し**を持つ。ローマ数字は I〜XI で、検査はここから一覧を導出できる。

## 4. 決定

### D1: 対象集合は境界日で切る

**境界日 `2026-09-04` 以降の日付を持つ plan にのみゲートを要求する。**
既存 25 件（批准以降でゲートを持たないもの）は遡らない。

`docs/superpowers/plans/*.md` は全件が `YYYY-MM-DD-` 接頭辞を持つ（実測 47/47）。
日付の判定はこの接頭辞で行い、**接頭辞を持たないファイルは「分類できない」として落とす**。
黙って対象外へ落ちる経路を残さないためである。

### D2: 遡らない。除外表も持たない

- **遡ってゲートを書かない。** 当時通していないゲートを後から書き足すのは、
  「通したことにする」記録の改竄にあたる。`docs/adr/0002` の「記録は当時の記述を保つ」に反する
- **25 件の理由つき除外表を持たない。** 除外表は「空文化している」を列挙し直したものにしかならず、
  維持コストだけが残る（`docs/adr/0014` 決定 2 が想定する「1 件も一致しなくなったら落とす」除外とは性質が違う）

既存 25 件は「境界日より前」という**一様な理由**で対象外になる。理由が 1 つなら宣言も 1 つでよい。

### D3: ゲートの中身は「見出し ＋ 全原則の判定表 ＋ 逸脱の結論」

節が存在するだけで足りるとすると、**空の節を置けば通る**（対策が自分の塞ぐ欠陥を持つ型）。
既存 3 件がいずれも判定表を持つので、それを様式として定める。

| 要求 | 判定 |
|---|---|
| 見出し | `Constitution Check` を含む見出し（レベルは問わない。`## 規約チェック（Constitution Check）` も通す） |
| 判定表 | 節の中に、**憲法から導出した全原則**それぞれのローマ数字で始まる表の行がある |
| 結論 | 節の中の**表の外の行**に `逸脱なし` または `Complexity Tracking` がある |

**（2026-09-04 のレビュー指摘を受けて 3 点を足した。初版はいずれも素通りしていた。）**

- **コードフェンスの中身は読まない。** `docs/guides/plan-writing.md` の様式サンプルを
  そのまま引用しただけの plan が、初版では**問題 0 件で通った**（実測）。
  **ガイド自身が抜け道の供給元になっていた**
- **候補の見出しは全部見て、1 つでも満たせば通す。** 初版は最初に一致した見出しを
  採っていたため、`### Task 1: Constitution Check の節を足す` のような見出しが
  ゲートより前にあると、**正しい plan を偽陽性で落とした**（実測で誤検出 2 件）
- **結論は表のセルで満たさせない。** 初版は節全体へ正規表現を掛けていたため、
  `| I. … | 通過 | 逸脱なし |` の 1 行だけで結論の要求が満たされた（実測）

**（同日の敵対的レビューで、さらに 4 点を直した。いずれも実測で再現させた。）**

- **他の候補を丸ごと含む節は候補にしない。** 文書の題（H1）に `Constitution Check` が
  入ると、下位に H1 が無いので**文書全体が 1 つの節**になる。本物のゲートが空でも、
  別の節に引用した判定表と本文中の「逸脱なし」を拾って通った（実測。problems 0 件）。
  **この機能を扱う実装計画がまさにそう名乗る**
- **コードフェンスは長さを見る**（CommonMark の規則）。3 文字固定で判定していたため、
  ````` ````markdown ````` の内側の ```` ``` ```` を閉じと誤認し、以降が素通りした。
  ガイドの様式サンプルは ```` ```markdown ```` の中にあるので、**引用するには 4 バックティックが
  自然**であり、ちょうど狙われる形だった（実装計画 3 本が現に 4 バックティックを使っている）
- **表の行の定義を 1 つに揃える。** 原則の突き合わせだけが行頭の空白を許さず、
  字下げした判定表が「全原則欠落」で偽陽性になった。**GitHub 上では表に見えているのに
  CI だけが赤くなる**ので原因が追いにくい
- **ローマ数字の直後に空白を求めない**（`| I.テスト駆動開発 |` を落とさない）。
  取り違えは起きない —— `I\.` は `II.` に一致しない

### D4: 原則の一覧は憲法から導出する。検査に直書きしない

`docs/constitution.md` の `### <ローマ数字>. ` 見出しから導出する（§3.6）。
原則が増減しても検査は腐らない。**導出が 0 件なら落とす** —— 憲法の見出し形式が変われば
「原則 0 本を全部満たした」として素通りするため（`docs/adr/0014` 決定 8 の自己適用）。

### D5: 様式の正本は `docs/guides/` に置く

`.specify/templates/plan-template.md` の削除（#71）で、ゲートの様式を定める正本が
無くなっている。`docs/adr/0002` の三層構造では「今日どう書くか」の手順はガイドの領分なので、
`docs/guides/plan-writing.md` を新設する。

### D6: 憲法の誤記は版を上げずに訂正注記で直す

§3.3 の「4 本」は事実の誤りであり、原則にも決定にも触れない。ADR が「訂正」追記で
過去の誤りを直しているのと同じ形にする。**Sync Impact Report の記述自体は残し、
日付つきの注記を添える**（記録を消さずに、誤りだったことを記録する）。

## 5. 設計

### 5.1 `scripts/audit-plan-gate.mjs`

```
main()
  ├ listTrackedFiles(REPO_ROOT, ["docs/superpowers/plans/*.md"])   # 走査対象（0 件ガード）
  ├ extractPrinciples(constitutionText)                            # 憲法から導出（0 件なら落とす）
  ├ classifyPlans(basenames, boundary)                             # dated / undated / required
  └ checkGate(text, principles) を required の各件へ
```

判定はすべて純粋関数、I/O と `process.exit` は `main()` に置く（既存の検査と同じ設計方針）。

走査量は成否によらず出す（`docs/adr/0014` 決定 6）。

```
[audit-plan-gate] 走査対象: plan 47 件 / ゲート要求 0 件（境界日 2026-09-04 以降）
```

**0 件ガードは「plan の総数」と「憲法から導出した原則」に掛ける。**
「ゲート要求」の件数には掛けない —— 0 件が正しい状態でありうる（§3.4）。

### 5.2 CI からの結線 —— `docs` ジョブへ置く（`quality` ではない）

**`quality` ジョブへ置いてはならない。** あちらのステップは `steps.scope.outputs.code == 'true'`
で絞り込まれ、`ci-scope.mjs` の `code` は「`*.md` 以外の変更があるか」で決まる。
**plan は `*.md` なので、ゲートを持たない plan を足すだけの PR はちょうど絞り込みで外れる**
——この検査が捕まえるはずの形そのものが素通りする。

`docs` ジョブは絞り込まない（リンク検査と同じ理由）。`pnpm install` も要らない
（`git ls-files` とファイル読み取りだけ）。

## 6. 検証

### 6.1 EARS

- **E1** WHEN 境界日以降の plan が Constitution Check の見出しを持たない、THE 検査 SHALL 非ゼロで終了し、当該ファイルを名指しする。
- **E2** WHEN その節が憲法の原則をすべて挙げていない、THE 検査 SHALL 非ゼロで終了し、欠けている原則を名指しする。
- **E3** WHEN その節が逸脱の結論を持たない、THE 検査 SHALL 非ゼロで終了する。
- **E4** WHEN plan がファイル名に日付を持たない、THE 検査 SHALL 非ゼロで終了する（分類できないものを黙って対象外にしない）。
- **E5** THE 検査 SHALL 走査量（plan の総数・ゲート要求の件数・境界日）を成否によらず出力する。
- **E6** WHEN 憲法から原則を 1 本も導出できない、THE 検査 SHALL 非ゼロで終了する。
- **E7** WHEN 上記いずれかの検査を壊す、THE CI SHALL 赤くなる（憲法 原則 VII の破壊検証で確認する）。

### 6.2 破壊検証の手順

**要求対象が現在 0 件なので、境界日以降の plan を一時的に置いて確かめる。**
**壊す前にコミットする。** 各項目で対照実行（壊さずに緑になること）を先に取る。

| # | 壊し方 | 期待 |
|---|---|---|
| 1 | 境界日以降の日付を持つ plan を、ゲート無しで置く | E1 で赤 |
| 2 | 節はあるが原則の行が 1 本欠ける | E2 で赤（欠けた原則を名指し） |
| 3 | 節はあるが逸脱の結論が無い | E3 で赤 |
| 4 | 日付接頭辞を持たない plan を置く | E4 で赤 |
| 5 | 憲法の原則見出しの形式を崩す | E6 で赤 |
| 6 | 境界日以降の正しい plan を置く | 緑（偽陽性が無いことの対照） |
