# v2.10 交代音/スキップ/休憩/一覧並び 修正 設計

- 日付: 2026-06-25
- 対象: `tdd-mob-pro-timer`（core / apps/sync / apps/web）
- 種別: バグ修正2件（#1/#3）＋休憩機能撤去（#2）＋UX改善1件（#4）（実機フィードバック4点）
- 前提調査: systematic-debugging で4件すべて根本原因を特定済み。

## 背景（実機フィードバック）

1. **#1 バグ**: 参加者の上下並べ替えでドライバーは交代していないのに交代音が鳴る。
2. **#2 質問→挙動修正**: 一時停止と休憩の違いが分からない。
3. **#3 バグ**: 一時離脱中の人にも手動スキップで交代してしまう。
4. **#4 UX**: 現ドライバーが先頭に来るのは良いが、それ以外の順序・移り方が不自然。

## 根本原因（確定）

- **#1**: `apps/web/src/ui/use-switch-alert.ts` が **`currentIndex`（番号）** で交代を検知する。並べ替え（`evolveMemberMoved`）は同じ人を現ドライバーに保つため currentIndex の番号だけ変わる → ドライバー名不変でも誤発火。
- **#3**: 手動スキップ `session.act SWITCH` は core `decide`（`decide.ts:198`）で `(currentIndex+1) % len` の**単純 +1**。eligibility を見ない。タイマー自動交代（`handlers.autoSwitch`）は `advanceDriver` + `computeIneligibleIndices` で一時離脱/オフラインを飛ばすのに、手動だけ素通り。
- **#2**: `break.start` は `onBreak=true` を立てるだけで**クロックを凍結しない**（`break.start` ハンドラ）。一方 UI バナーは「休憩中 — タイマーは停止しています」と表示。見た目は止まって見えるが内部のクロックは進み続け、休憩終了時に進んだぶん消費済みになる不一致。一時停止（`SessionPaused`→`freezeRunningClock`）は本当に凍結する。
- **#4**: `apps/web/src/ui/components/RosterPanel.tsx` のドライバーソートが「現ドライバー先頭＋以降は rotation 絶対順(0,1,2…)」。交代時に「次の人」が最下部→最上部へ飛ぶ。

## ユーザー確定事項

- **#2**: 休憩を本物の停止に直すと一時停止と機能が重複するため、**休憩機能を撤去する**（無理に意味を持たせない）。休憩リマインダ（N巡ごとの提案）も**一緒に全撤去**。残すのは一時停止のみ。
- **#4**: **巡回順**（現ドライバー起点で 現→次→次々…と環状）に変更。

## #1 交代音の誤発火修正（web）

### 設計
`useSwitchAlert(currentIndex, currentDriverName, opts)` の検知条件を **「currentIndex と currentDriverName の両方が前回から変化したとき」** に変える。
- 並べ替え: 番号のみ変化（名前不変）→ 発火しない。
- 現ドライバーの改名: 名前のみ変化（番号不変）→ 発火しない（現状も番号一致で鳴らないが、名前検知に切替えても誤発火しないよう両方条件にする）。
- 本当の交代: 番号も名前も変化 → 発火する（DriverSwitched は必ず別 index・別名。displayName は一意制約があるため衝突しない）。

実装: `prevIndexRef` に加え `prevNameRef` を持ち、effect 冒頭で両 ref を更新。`prevIndex === currentIndex || prevName === currentDriverName` のとき早期 return（どちらか一方しか変わっていない＝並べ替え or 改名）。

### テスト（`apps/web/test/ui/` jsdom・既存 use-switch-alert.test があれば拡張）
- 番号のみ変化（名前同じ）では playChime/オーバーレイが呼ばれない（並べ替え相当）。
- 名前のみ変化（番号同じ）でも呼ばれない（改名相当）。
- 番号も名前も変化したときだけ呼ばれる（本当の交代）。

## #3 手動スキップの eligibility 対応（sync）

### 設計
`apps/sync/src/application/handlers.ts` の `handleRoomCommand` で、`session.act SWITCH`（手動スキップ）を**自動交代と同じ eligible 判定**に通す。
- decide のバリデーション（`clock.running` 必須）は維持し、SWITCH のときは decide の `+1` の DriverSwitched を **適用せず**、代わりに `advanceDriver(agg, computeIneligibleIndices(targetRoom), now)` で次の eligible へ進める（一時離脱 `driverEligible=false`・オフライン〔非 placeholder〕を飛ばす）。
- 全員が ineligible なら `advanceDriver` が現状維持（交代先なし）＝スキップしても変わらない。これは仕様（離脱者には飛ばさない）。
- driver.skip（現ドライバーが自分を離脱）後の即時繰り上げ（既存・636行付近）はそのまま。`maybeSuggestBreak`/`reconcileSchedule` の既存後処理も維持。

### テスト（`apps/sync/test/`・既存パターン流用）
- 一時離脱（driverEligible=false）の次メンバーがいるとき、手動 SWITCH はその人を飛ばして次の eligible へ進む。
- オフライン〔非 placeholder〕も飛ばす。代理（placeholder）は飛ばさない（v2.8 と一貫）。
- 他全員が ineligible なら手動 SWITCH は現状維持。
- 通常（全員 eligible）は従来どおり +1。

## #2 休憩機能を撤去する（web 配線除去＋sync 提案停止／core は dormant 残置）

### 方針
このコードベースの定石（機能撤去は「ユーザー向けの配線・UI を除去し、core のイベント/コマンド/フィールド定義は破壊的削除せず dormant `@deprecated` で残置」）に倣う。**ユーザー体験から休憩は完全に消す**が、core の event-sourcing 定義（`BreakStarted`/`BreakEnded`・`break.start/end`・`SessionConfig.breakEveryRotations`）はリスク回避のため削除せず残す（既存 core テストは緑のまま）。

### web（ユーザー向け撤去・必須）
- `ui/Session.tsx`: 休憩/休憩終了ボタン・「休憩中」バナー・`onBreakStart`/`onBreakEnd` props・`room.onBreak` 参照（`running`/減光計算）を除去。タイマーの running/減光は `isPaused` のみで判定。
- `App.tsx`: Session へ渡す `onBreakStart`/`onBreakEnd` を除去。`break.start`/`break.end` を送る配線を除去。
- `sync/dispatch.ts`・`sync/client.ts`: `suggest-break` シグナル受信時の演出（トースト等）を除去。
- `ui/announce.ts`・`ui/use-discrete-announcement.ts`: 「休憩を開始/終了しました」アナウンスと `onBreak` 入力を除去。
- `ui/components/SessionConfigPanel.tsx`: 「休憩リマインダ（N巡ごと）」トグルを除去（詳細設定はナビゲーター／強い交代通知の2点に）。
- `solo/roster.ts`・`index.css` 等に休憩固有の参照があれば除去（grep で確認）。

### sync（提案の停止）
- `application/handlers.ts`: `maybeSuggestBreak`（関数＋全呼び出し）を除去し、`suggest-break` シグナルを配信しない。`break.start`/`break.end` コマンドの受理は撤去（UI が送らないため到達不能）。`room.onBreak` は常に false の dormant フィールドとして残してよい（`reconcileSchedule` の `!onBreak` 判定は無害に常時 true）。

### core（dormant 残置・破壊的削除しない）
- `BreakStarted`/`BreakEnded` イベント・`break.start/end` コマンド・`SessionConfig.breakEveryRotations` は**型・定義を残す**（未配線・`@deprecated` 注記）。既存の `core/test/break-freeze.test.ts` 等は緑のまま維持。

### テスト
- web: 休憩ボタン・「休憩中」バナーが**表示されない**（`Session.break.test.tsx` を「休憩 UI が無い」検証へ更新）。SessionConfigPanel に休憩リマインダトグルが無い。
- sync: 巡境界でも `suggest-break` シグナルが配信されない（`break-suggestion.test.ts` を「提案しない」へ更新、または削除して意図を別テストに残す）。
- 既存の break 関連テストのうち撤去対象 UI/挙動を前提にするものは、撤去後の仕様へ更新（アサーション意図＝「休憩は無い」へ）。core の dormant テストは触らない。

## #4 一覧を巡回順にする（web）

### 設計
`RosterPanel` のドライバーソートを「現ドライバー先頭＋絶対順」から **現ドライバー起点の巡回順** に変更。
- 各ドライバーの並び順キー = `(rotationIndex(p) - currentIndex + len) % len`（現=0, 次=1, …）。昇順で並べる。
- 現ドライバーが先頭に来る点は維持（offset 0）。以降は交代順（次・次々…）で、交代のたびにリストが1つ繰り上がる。
- `currentIndex` は現ドライバー名から `rotation.indexOf(currentDriverName)` で求める（RosterPanel は currentDriverName と rotation を受け取っている）。
- 見学グループ（rotation 外）は現状維持（元の相対順）。
- 入場アニメ（animate-pop-in）は現状維持（巡回順なら1つずつ繰り上がる自然な動きと整合）。

### テスト（`apps/web/test/ui/RosterPanel.test.tsx` 拡張）
- rotation=[A,B,C,D,E]・現=D のとき、ドライバーセクションの並びが D,E,A,B,C（巡回順）になる。
- 現ドライバーが先頭である（既存テスト維持）。
- 見学グループは従来どおり。
