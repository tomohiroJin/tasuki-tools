Issue #119 は「1 Issue を 5〜7 本の PR に割る現行運用の固定費が実装コストを上回っている」
という提起である。本文の実測は 2026-08-11 時点のもので、**起票から 3 日のあいだに実運用が
先に動いた**。したがって本設計は新しい規範の発明ではなく、**先行実践の追認と成文化**である。

利用者への確認（2026-08-14）: #116（PR 1 本・10 コミット）と #136（PR 1 本・39 コミット）を
1 本にまとめたのは **意図的な先行実践**であり、その場しのぎではない。実際に出してみて
**レビュー・revert のいずれでも困らなかった**。

### 1.1 Issue 本文の前提のうち、いま成り立たないもの

本設計に着手するにあたり、Issue 本文（2026-08-11）の主張を 1 つずつ叩いた。3 点が古い。

3. **完了条件「#113 の実装計画を、決定した粒度に合わせて改訂したか」** — #113 は

## 2. 実測（数値の正本）

**本設計・実装計画・タスクの範囲では、本節が数値の正本である。** これらの作業文書は
本節から引用し、数値そのものを転記して二重管理にしない。

**成果物の側は別に定める。** 完成後にリポジトリで参照され続けるのは spec ではなくガイドで
あるため、**PR 番号つきの実例表の正本は `docs/guides/pr-granularity.md` とする**（§3.4）。
ADR 0013 には数値表を載せず、決定の根拠となる事実の要約までに留める。
本節とガイドの実例表は同じ実測に由来するが、**役割が異なる**（本節 = この設計の判断根拠 /
ガイド = 今後の判断に使う参照表）。作業完了後に数値を直す必要が生じた場合は、
**ガイドを直す**（spec は作業時点の記録として凍結する）。

### 2.1 起票前後の PR の粒度（2026-08-14 実測）

「本文字÷行」は **PR 本文の文字数 ÷ (additions + deletions)**。差分 1 行あたりの説明コストを表す。

| Issue | PR 本数 | 対象 PR | コミット数 | 差分行 | 本文字÷行 |
|---|---|---|---|---|---|

| #70（8/12） | 6 本 | #129 #130 #131 #132 #133 #134 | 4〜19 | 202〜2,465 | 0.4〜3.2 |
| #116（8/12） | **1 本** | #137 | 10 | 1,411 | **1.0** |
| #136（8/13） | **1 本** | #138 | **39** | 4,835 | **0.9** |

#113 の行には、同 Issue の振り返り PR #127（比 12.4）と、クローズ追従 PR #128（差分 2 行に
本文 562 字 = 比 **281.0**）を**含めていない**。この 2 本を含めると #113 は 9 PR・比 4.0〜281.0 になる。

読み取れること:

- **説明コストは #113 の 4.0〜115.1 から、#116 / #136 の 0.9〜1.0 へ落ちた**
- **コミット数は逆に増えた**（#113 の 1〜3 本 → #136 の 39 本）。論理的変更の内訳が
  PR からコミットへ移った
- **差分規模とコミット数は、支障の有無と相関しなかった**。#138 は 39 コミット・4,835 行・
  52 ファイルだが、レビューでも revert でも問題は起きていない

### 2.2 固定費の内訳と、いま残っているもの

PR 1 本あたりに差分の大きさと無関係に発生する作業は次のとおり。#70 による解消分を反映済み。

| 固定費 | 状態 |
|---|---|
| CI の待ち時間 | **大幅に軽減**（文書のみの PR で 20 秒。#70） |
| CI が 1 PR につき 2 回走る（作業ブランチ push とマージ後 main push） | 残る |
| ブランチを切る → push → PR 本文を書く → マージ | 残る |
| DoD 8 項目の記入 | **「該当なし」表記が既に許容済み**。残るのは一言書く手間 |

**したがって、いま削れる固定費の主体は「PR 本文を書く作業」である。** これは PR 本数に
正比例し、差分の大きさには比例しない。§2.1 の「本文字÷行」が跳ねている PR ほど、
この固定費を強く受けている。

## 3. 決定

### 3.1 どの層に何を書くか

**DoD と同じ書き分けを採る。** ADR 0003 決定 1 は「DoD を運用する」という決定だけを持ち、
8 項目の正本は `docs/guides/definition-of-done.md` に置いて、項目の追加・削除は ADR の改版を
経ずにガイドの更新のみで行う（`docs/adr/0002` の三層の書き分け規則）。粒度にも同じ構造を使う。

| 層 | 置くもの | 変更の重さ |
|---|---|---|
| 憲法 原則 IX | 「1 PR は 1 つの論理的変更」という MUST と、**粒度の正本の指し先** | 改版に ADR が必要 |
| ADR 0013（新設） | 「既定を 1 Issue = 1 PR とする」という**決定そのもの**と、その根拠 | 決定を覆すときだけ |
| `docs/guides/pr-granularity.md`（新設） | **判断基準と実例集** | ガイド更新のみで育てる |

この構造を採る理由は、**次に粒度を見直すとき憲法の改版が不要になる**こと。#119 と同種の
提起がまた来ても、ADR とガイドで閉じられる。

採らなかった案を記録する。

- **憲法の文言そのものを「独立して revert できる単位」に書き換える案** — 粒度の既定が
  反転するため semver が MINOR 以上になり、Sync Impact Report と AGENTS.md 同期が発生する。
  それ以上に、**利用者は #138（4,835 行 1 本）で revert に困っていない**。困っていない
  ことを最上位規範の判断基準に据えるのは順序が逆であり、実測に基づく本設計の方針に反する。
- **憲法を触らず ADR で解釈だけ確定する案** — 憲法 Governance は「改版は ADR を伴う」と
  定めるのみで、解釈の確定が改版に当たるかが曖昧。憲法の字面と実運用が食い違ったまま残り、
  憲法だけを読んだ人が誤解する。Issue 本文の制約「運用でなんとなく緩める形にしない」を満たさない。

### 3.2 憲法 原則 IX の改版（案）

原則 IX には MUST が 3 つあるが、**本設計が触るのは 1 つ目だけ**である
（2 つ目「DoD を満たしてからマージする」、3 つ目「デプロイはまとめて 1 回」は変更しない）。

```diff
 ### IX. 小さく回す

 変更は小さく、確実に積む。

-- 1 PR は 1 つの論理的変更に留める（MUST）
+- 1 PR は 1 つの論理的変更に留める（MUST。粒度の判断基準は
+  `docs/guides/pr-granularity.md` を正本とする）
 - Definition of Done（DoD）を満たしてからマージする（MUST）
 - デプロイは一連の作業がすべて完了した後に、まとめて 1 回で行う（MUST）
```

- **バージョン**: 2.1.1 → **2.1.2（PATCH）**。憲法は「MINOR: 原則・セクションの追加または
  **実質的な拡張** / PATCH: 文言修正・**明確化**」と定める。本改版は原則 IX の **MUST の数・
  強さ・対象を変えない**。「1 つの論理的変更」という既存の語が何を指すかの参照先を示すだけで、
  新しい義務を課さない。よって明確化と判断する。
  **反対の読みも成り立つことを記録しておく**: 参照先の新設を「実質的な拡張」と取れば MINOR に
  なる。前例 2.1.1（原則 XI の文言修正）は純粋な言い換えであり、そのままは援用できない。
  **この判断と理由を Sync Impact Report に明記する**（判断を判断のまま残さない）
- **AGENTS.md**: 転記しているのは見出しのみで「IX. 小さく回す」は不変のため、**同期作業は不要**
  （2.1.1 の Sync Impact Report と同じ判断。§4.3 で実際に確かめる）
- **Sync Impact Report**: 憲法冒頭の HTML コメントに、既存の積み上げ形式で追記する

### 3.3 ADR 0013 — 決定の骨子

`docs/adr/0013-pr-granularity.md` を新設する。テンプレート（`docs/adr/template.md`）の
背景 / 決定 / 影響に従う。

**決定**:

1. **1 Issue に対する PR は 1 本を既定とする（SHOULD）。** 分割は §3.4 の分割理由に
   当たるときだけ行う。
2. **1 本の PR に複数の Issue の変更を混ぜない（MUST）。** 「1 つの論理的変更」の単位は
   Issue 1 件であり、論理的変更の内訳はコミットが担う。
3. **粒度の判断基準の正本は `docs/guides/pr-granularity.md` とする（MUST）。**
   基準の追加・変更は本 ADR の改版を経ずにガイドの更新のみで行う（`docs/adr/0002` の
   書き分け規則に従う）。

1 を SHOULD にするのは、分割が正当な場合（§3.4）を規範として残すためである。既定からの
逸脱に理由を要求する形にし、逸脱そのものを禁じない。

**憲法の MUST と本 ADR の SHOULD が衝突しないことを明示しておく。** 憲法 原則 IX ①
「1 PR は 1 つの論理的変更に**留める**」は**上限の規定**である。すなわち 1 本の PR に複数の
論理的変更（＝複数の Issue）を詰めることを禁じる。細かく割りすぎることは規定していない。
したがって 1 つの Issue を複数の PR に分割しても、憲法の MUST には抵触しない。本 ADR の
決定 1（SHOULD）は、憲法が規定していない**下限側の既定**を足すものである。

**この理由から、決定 2 も上限の形で書く。** 「『1 つの論理的変更』は Issue 1 件を指す」と
等号で書くと、分割した PR は「Issue 1 件」ではないため MUST 違反になってしまう。
「1 本の PR に複数の Issue を混ぜない」と上限で書けば、分割は上限を超えないので抵触しない。
ADR の「決定」節に上記の一段を含める。

**根拠**: §2.1 の実測。特に #116 / #136 の 2 件が意図的な先行実践であり、
説明コストが 0.9〜1.0 に落ち、かつレビュー・revert のいずれでも支障が出なかったこと。

**ADR には数値表を転記しない**（F2 の回避。§3.4 参照）。ADR が持つのは決定と、
その根拠となる事実の要約までとし、PR 番号つきの実例表はガイドを正本とする。

### 3.4 ガイド — 判断基準と実例集

`docs/guides/pr-granularity.md` を新設する。

**既定は 1 Issue = 1 PR。** そのうえで両側を明記する。

**分割してよい理由**（いずれかに当たるときだけ分ける）

1. 独立して revert したい単位が複数ある
2. 段階的に本番へ出す必要がある
3. 危険度の異なる変更が混ざっている
4. レビューが実際に回らなかった実績がある

**分割の理由にならないもの**

- **コミット数が多い** — #138 は 39 コミットで支障なし
- **差分行数・ファイル数が大きい** — #138 は 4,835 行・52 ファイルで支障なし
- **設計 → 実装 → 文書 → 振り返り という工程の違い** — #113 で説明コストが跳ねた主因。
  工程で割ると、どの PR も本文で「これは全体のどこに当たるか」を毎回説明することになる

4 番目の分割理由を「レビューが実際に回らなかった**実績**」と書くのは、
「重そうだから」という事前の見込みで分割することを認めないためである。

**実例集**（PR 番号つき）

**実例集の正本はガイドである**（§2 で役割を整理した）。ADR 0002 決定 2 は
「両方に跨る内容は片方に書き、もう片方からは参照する。二重正本を作らない」と定める。
同 ADR の書き分け（決定の中身と根拠は ADR、**手順・例・チェックリストはガイド**）に従い、
**ADR 0013 には数値表を載せず**、決定の根拠として要約（説明コストが #113 の 4.0〜115.1 から
#116 / #136 の 0.9〜1.0 へ落ちた、という事実）だけを書き、詳細は本ガイドを参照させる。

| Issue | PR | コミット | 差分行 | 本文字÷行 | 分割の理由 |
|---|---|---|---|---|---|
| #136 | 1 本 | 39 | 4,835 | 0.9 | なし（既定どおり） |
| #116 | 1 本 | 10 | 1,411 | 1.0 | なし（既定どおり） |
| #70 | 6 本 | 4〜19 | 202〜2,465 | 0.4〜3.2 | CI 自体を変えるため段階的な確認が要った（理由 2・3） |
| #113 | 7 本 | 1〜3 | 20〜928 | 4.0〜115.1 | 依存の危険度で束ねた（PR-1）。ただし工程分割の分は説明コストが跳ねた |

## 4. 検証

### 4.1 破壊検証（憲法 原則 VII）

新しい検査は足さないが、**新設ガイドへのリンクが `check-links` の検査対象に乗ることを、
壊して確かめる**。憲法から `docs/guides/pr-granularity.md` へのリンクを意図的に壊し、
`check-links` が赤くなることを確認してから戻す。

**このとき `git add` を先に行う。** `scripts/check-links.mjs` は走査対象の一覧を
`git`（`scripts/check-links.mjs:216-220`）から取得するため、**未追跡ファイルは検査されない**。
本設計の作成中に実測した（§4.5）。新規文書を足した状態でローカル検査を回すと、
**追跡に入れるまでは何を壊しても緑になる**。

### 4.2 数え上げが腐る箇所（手で直す）

ガイドを名前で列挙している箇所が **2 つ**ある。どちらもリンク切れではないので
**`check-links` は検出しない**。手で直す。

| 箇所 | 現在の列挙 | 状態 |
|---|---|---|
| `docs/README.md:24` | DoD・EARS・振り返り・アーキテクチャ・開発手順・セキュリティ（6 本） | 現行と一致 |
| `AGENTS.md:36` | DoD・EARS・振り返り・アーキテクチャ・開発手順（**5 本**） | **既に古い** |

**`AGENTS.md:36` は本作業を待たずに既に腐っている。** `docs/guides/security.md` は #136 で
新設されたが、AGENTS.md の列挙へ反映されなかった。ここへ粒度ガイドを足すと 5/7 になり、
腐りが深まる。**本作業で security の欠落もあわせて直す**（#136 の積み残しの回収）。

`docs/guides/` は現在 6 本（architecture / definition-of-done / development / ears-writing /
retrospective / security）。本作業で **7 本**になる。

### 4.3 憲法改版の手続き（Governance の MUST）

- 版が 2.1.2 になっていること
- Sync Impact Report が既存の積み上げ形式で追記されていること
- 依存テンプレート（`.specify/templates/` の plan / spec / tasks）への影響を確認し、
  Sync Impact Report に記載すること
- **AGENTS.md の原則見出し 11 本が憲法と一致していること**を実際に照合すること
  （見出し不変という判断を、判断のまま残さない）。**2026-08-14 時点で照合済み**:
  `AGENTS.md:11-21` が I〜XI の 11 本、IX は「小さく回す」で憲法と一致している
- **本設計の実装計画に Constitution Check ゲートを設けること。** 憲法 Governance は
  「すべての plan は Constitution Check ゲートを通過しなければならない」と定めるが、
  `docs/superpowers/` でこれを持つ文書は **4 件しかない**。最新かつ最大の
  `docs/superpowers/plans/2026-08-13-security-norms.md`（#136・11 タスク）にも無い。
  **この MUST は実運用で空文化している**（#135 の「静かに効かなくなる規範」の一例。
  検査が無いため誰も気づかない）。本作業は憲法を改版する作業であり、自分の計画が
  同じ MUST を踏み外すわけにいかない。**#135 への申し送り候補**とする

### 4.4 検査の実行

文書のみの変更のため、CI は docs ジョブが対象になる（#70 の実績で 20 秒台）。
`check-links` を含む文書系の検査を通す。

### 4.5 本設計の作成中に実測したこと（2026-08-14）

`check-links` は **git 追跡下のファイルのみを走査する**。本 spec を未追跡のまま
リンクを 2 箇所壊しても `リンク検査 OK（走査 202 ファイル）` のまま緑だった。
`git add` 後は走査 203 ファイルとなり、同じ壊し方で 2 件を検出した。

これは検査の欠陥ではなく仕様（gitignore 対象を検査しないための設計）だが、
**新規文書を含む変更では、ローカル確認だけが騙される**という性質を持つ。CI は
コミット済みの状態で走るため影響を受けない。既知の同型（`node_modules` が最新だと
供給網検証が短絡する等）と同じ「ローカルだけが緑になる」型である。

**#135（検査が静かに効かなくなる経路）への申し送り候補**とする。

## 5. 完了条件の閉じ方

Issue #119 の完了条件 4 項目に対する対応。

| 完了条件 | 対応 |
|---|---|
| 粒度についての決定が ADR に記録されている | ADR 0013 を新設（§3.3） |
| 憲法 原則 IX の文言・`docs/guides/` のいずれか・PR テンプレートが更新されている | 憲法とガイドの 2 つを更新。**PR テンプレートは変更しない**（§1.1 の 2） |
| 決定後の粒度で PR を 1 本以上出し、固定費が実際に下がったことを実測した | **本 Issue の PR 自身を実測台にする**。1 Issue = 1 PR で出し、本文字÷行と CI 実行時間を測って ADR 0013 に記録する |
| #113 の実装計画を改訂したか、改訂不要と判断した理由が記録されている | **改訂不要**。#113 は 2026-08-11 に完了・クローズ済みで、改訂対象の計画は実行し終えている（§1.1 の 3）。この理由を ADR 0013 の「影響」節に記録する |

**完了条件 2 の読みについて（2026-08-14・利用者判断）**: 原文「決定に応じて、憲法 原則 IX の
文言・`docs/guides/` のいずれか・PR テンプレートが更新されている」は、「**3 つのうち決定に
応じて必要なものだけ**」と読む。「3 つすべて」とも読めるが、冒頭の「決定に応じて」が列挙
全体にかかると解する。本設計は憲法とガイドの 2 つを更新し、PR テンプレートは変更しない
（変更が不要な理由は §1.1 の 2）。

### 5.1 DoD の該当性

### 5.2 EARS を書かない理由

ADR 0003 決定 2 は「**機能系** Issue の『振る舞い』節は EARS 記法で書く（MUST）。調査・chore 系の
Issue には強制しない」と定める。#119 は規範と文書の変更であり、利用者から見える振る舞いを
変えないため、EARS の対象外とする。Issue #119 本文にも「振る舞い」節は無い。

## 6. この設計で決めないこと

- **原則 IX の 2 つ目・3 つ目の MUST**（DoD・デプロイ 1 回）は変更しない
- **PR テンプレートの構成**（§1.1 の 2 のとおり、既に「該当なし」が許容されている）
- **コミットメッセージの粒度・書式** — 論理的変更の内訳をコミットが担う以上、
  コミットの書き方が重要になるが、既存の規約（Conventional Commits）を変える提起は
  #119 に含まれていない。必要なら別 Issue とする
- **積み上げ PR の運用そのもの** — 分割する場合の手順（base を都度 main へ張り替える等）は
  既存の運用を変えない
