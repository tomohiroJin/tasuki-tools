## 1. 何のために作るか

利用者が最初に使う場面は **KPT のふりかえり（1 時間）** である。

> K を出すのに 5 分、P を出すのに 7 分、投票に 1 分、Try に対する議論の時間をリーンコーヒーのように取りたい。
> タイマーを毎回セットしなおしたり、実行を忘れたり、入れ忘れたりして時間通りに進まない。そのうえ全体で 1 時間という約束が過ぎて困る。（利用者・要旨）

Try の議論では、ファシリテーターが時間をずるずると延長してしまうことがある（利用者の経験から作った例。特定の会の出来事ではない）。
これを止めやすくするのは**道具による強制ではなく見えること**だ、というのが利用者の考えである。

> 現在の時間の進捗とオーバーした時間の長さが見えていれば止めやすい。（利用者）

したがってこの道具の芯は次の 2 つ。

1. **組んでおけば、あとは迷わず進む。** 区切りの名前と長さを前もって並べておく。当日は「開始」を押すだけで、区切りごとにセットし直す手間・押し忘れが無くなる
2. **約束の 1 時間に対して、いまどこにいるかが全員に見える。** 押し・巻き・超過・終わる見込みを、隠さずに数字と形で出す

### あるべき姿（#429 から）

- **進行役**として、会議の前に区切りとその時間を組んでおき、当日はボタン 1 つで始めて、区切りごとに迷わず次へ進められる
- **参加者**として、いま何の時間で、あと何分で、この後に何が続き、会がいつ終わる見込みかが分かる
- **チーム**として、予定より押したときに気づき、どこを詰めるかをその場で決められる

### 2.3 やらないこと（反目標）

- **延長を道具で止めない。** 延長の回数・合計に上限を設けて強制しない。判断はチームに任せ、道具は見せることに徹する（§1）。ただし入力の健全性のための数値の上限（§6）はこれとは別
- **上限の無い延長の道を作らない。** 延長は必ず「何分足すか」を決めて入れる。0 を過ぎたあとの超過は数字として見え続ける
- **役割を持ち込まない。** 進行役だけが押せる、のような段差は作らない（#95）。ルームにいる誰でも押せる
- **サーバーにシナリオや記録を残さない**（原則 III）
- **timer の交代の輪に混ぜない。** timer は改造しない

## 3. 使う場面（利用者の言葉から）

- **リモートで、各自が自分の画面で開く**のが基本。全員の画面で同じ時計が動く
- 集まっているときは、**代表の人の画面、または全員に見えるスクリーンに映す**。手元のノート PC でも、部屋の奥からスクリーンでも読めなければならない
- 利用者: 「できるだけスタイリッシュでカッコイイが求められる」
- シナリオを組むのは、**会の冒頭、みんながルームに入る前**（利用者）。進行役が先にルームを作って組んでおき、後から入った人は開始前に今日の進行表を見られる

## 4. 振る舞い

### 4.1 言葉

この節の語は**設計上の語**である。画面の文言は §7.6 の対訳表に従う（書体の制約・U9）。

| 語 | 意味 |
|---|---|
| シナリオ | 区切りの並びと、会の名前。端末に保存して使い回す単位 |
| 区切り | 名前・長さ・時間切れの振る舞いを持つ 1 行。進行の中で変わらない ID を持つ |
| 進行 | ルームでシナリオを 1 回走らせている状態 |
| 予定の合計 | 開始時点の区切りの長さの合計（飛ばしたものも含む。開始後は動かない） |
| 予定の終わり | 開始した瞬間 ＋ 予定の合計 |
| 実時間の経過 | 開始してからの経過。**一時停止の間も進む**（J5） |
| 区切りの計時 | 区切りの残り時間を数えるための経過。**一時停止の間は止まる** |
| 区切りの所要 | その区切りがいまの区切りだった間の実時間（**一時停止の間を含む**）。終えた区切りでは確定値、いまの区切りでは増え続ける。飛ばした区切りは 0 |
| 区切りの持ち時間 | 長さ ＋ 延長の合計 |
| 残り | 持ち時間 − 区切りの計時。0 未満になったら、その絶対値が**オーバー** |
| 終わる見込み | 実時間の経過 ＋ max(残り, 0) ＋ まだ始まっていない区切り（飛ばしたものを除く）の持ち時間の合計 |
| 押し巻き | 終わる見込み − 予定の合計。正なら押し、負なら巻き |

**不変条件（MUST）**: 終えた区切りの所要の合計 ＋ いまの区切りの所要 ＝ 実時間の経過。したがって終了時には、区切りごとの差（所要 − 長さ）の合計 ＝ 押し巻き になる（飛ばした区切りは「所要 0・差 −長さ」の行として数える）。終了の一覧はこの等式が成り立つ数字だけを出す。

**状態ごとの見込み**:

| 状態 | 終わる見込み | 押し巻き |
|---|---|---|
| 開始前 | 出さない（組む画面では「いま始めたら hh:mm に終了見込み」を予定の合計から出す） | 出さない |
| 進行中 | 上の式 | 上の式 |
| 一時停止中 | 上の式（実時間の経過が増えるので、止めている間も押しが増える） | 同左 |
| 終了 | 確定値（終了した瞬間の実時間の経過） | 確定値 |

### 4.2 準備（開始前）

1. ルームでこのツールを開くと、ルームのシナリオが空なら**組む画面**が出る。空の状態では見本（§4.2 の 5）を一番上の大きな札にして、1 回押せば読み込めるようにする
2. 区切りを並べる。各区切りには**名前・長さ（分）・時間切れの振る舞い**がある。区切りの追加・削除・並べ替えは開始前ならできる（並べ替えはドラッグに加えて上へ／下へのボタンも置く）
3. 組んでいる間、プレビューの盤に**合計の分数と、いま開始したときの終了見込みの時刻**を大きく出す（約束の 1 時間に収まっているかを、組みながら確かめられる）
4. **組んでいる内容は手元の下書きであり、「ルームに反映」を押したときに初めてルームのシナリオを置き換える**【判断】。1 文字ごとには送らない。他の人がルームのシナリオを置き換えたら、組む画面に「シナリオが変わりました」と知らせ、手元の下書きは消さない
5. **見本として「KPT のふりかえり」を 1 つ同梱する**【判断】: K を出す 5 分 → P を出す 7 分 → 投票 1 分 → Try の議論 40 分 → 予備 7 分（合計 60 分・全区切り「押すまで待つ」）。K・P・投票の長さは利用者の言葉、Try と予備は 60 分に収まるよう設計者が置いた
6. 「この端末に保存」で名前を付けて保存する。保存済みの一覧（名前・合計の分数・区切りの数を 1 行で）から選ぶと、手元の下書きに読み込む。ルームに反映するのは 4 と同じ操作
7. シナリオは**ルームの共有状態**であり、後から入った人にも開始前の進行表として見える。置き換えはルームの誰でもでき、**シナリオ全体の置き換え 1 種のコマンド**で表す（後勝ち）【判断】

### 4.3 進行

- 誰かが「開始」を押すと、全員の盤が一斉に動き出す。1 つ目の区切りが始まる
- 「次へ」でいまの区切りを終え、次の（飛ばしていない）区切りへ移る。時間が来る前に押せば、そのぶん巻く。次が無ければ**終了**になる
- 「一時停止」「再開」ができる。一時停止の間、区切りの計時（残り）は止まるが、実時間の経過は進むので**押しは増える**【判断 J5】（約束しているのは実際の時計の 1 時間なので、隠さない）
- **一時停止中に「次へ」を押すと、次の区切りは動いている状態で始まる**（一時停止は解ける）【判断】。止めて話していた後に「次へ進もう」と押す場面を想定する
- 終了すると、区切りごとの予定・延長・所要・差の一覧と、合計の押し巻きが出る（Markdown のコピーは後続）
- 「最初から」で進行を捨て、シナリオだけ残して開始前に戻す（確認を挟む）【判断 J6】
- 進行中・一時停止中・終了の間は、シナリオの置き換えはできない。置き換えたいときは「最初から」で開始前に戻す

### 4.4 時間切れ（利用者の決定）

利用者: 「両方をオプション選択できるとうれしい。きっと基本は押すまで超過を数えながらでしょうが、LT は流れ続けるのがうれしい」

区切りごとに次のどちらかを持つ。

| 振る舞い | 既定 | 残りが 0 に達したとき |
|---|---|---|
| **押すまで待つ** | ○ | 合図（§4.7）を 1 回出す。0 で止めず、オーバーを「+0:42」のように数え続ける。誰かが「次へ」を押すまで次へ移らない |
| **自動で次へ** | | 合図を出し、次の区切りへ移る。次が無ければ終了する |

- **自動で次へ移す判断はサーバーが行う（MUST）。** 画面ごとに判断すると、閉じている画面・遅れている画面で割れる
- **自動で移った次の区切りは、期限の時刻ちょうどに始まったものとして記録する**（発火の遅れを持ち込まない）【判断】。前の区切りの所要は期限ちょうどで確定する
- 延長で残りが正に戻ったあと、もう一度 0 に達したら、合図をもう一度出す（0 に達するたびに 1 回）【判断】

### 4.5 延長と飛ばす（利用者の決定）

- **延長**: いまの区切りに +1 / +3 / +5 分を足す【判断 J7】。何度でも押せる。延長は区切りの長さと**別に**記録し、盤・一覧では「予定 7 分 ＋ 3 分」と分けて見せる。延長した瞬間に終わる見込みと押しが動く
  - オーバー中に延長すると、残りが正に戻りうる（リーンコーヒーの「区切り直す」に近い使い方。第 3 段で本格的に扱う）
  - 「自動で次へ」の区切りでも延長できる。サーバーは期限を張り直す
  - 2 人がほぼ同時に +3 を押したら、**両方足す**（+6）【判断】。足した分は盤と一覧にそのまま見えるので、隠れた延長にはならない
- **飛ばす**: **まだ始まっていない**区切りを「やらない」にする。飛ばした区切りの持ち時間は終わる見込みから外れ、巻きとして表れる。まだ始まっていない間は「戻す」ができる【判断 J8】。いまの区切りを早く終えるのは「次へ」で、飛ばすではない
  - 残りの区切りをすべて飛ばしたら、いまの区切りが最後になる。そこで「次へ」を押す（または自動で次へ）と終了する
- 順番の入れ替え・区切りの追加は第 1 段ではやらない
- **延長したぶんを後ろの区切り（予備など）から自動で削ることはしない**【判断 J17】。削るかどうかはチームが「飛ばす」で決める（§2.3 の「道具は見せることに徹する」）

### 4.6 状態 × 操作

すべての進行の操作は、**どの区切りに対する操作かを区切りの ID で持つ**（§5.3）。いまの区切りと違う ID の「次へ」「延長」は**何もせず成功として扱い、送り主にだけいまの全体を 1 通送る**（状態は変わらないので全員へは配らない。ルーレットの `commit` が「変わらなければ配らない」のと同じ）（ルーレットの `roulette.stop` が `seq` で古い押下を捨てるのと同じ考え方。`packages/roulette-core/src/roulette.ts` の `stopPress`）。これで、2 人がほぼ同時に「次へ」を押しても、自動で次へ移った直後に古い画面の「次へ」が届いても、進むのは 1 つだけになる。

| 操作 ＼ 状態 | 開始前 | 進行中 | 一時停止中 | 終了 |
|---|---|---|---|---|
| シナリオの置き換え | 受ける | 拒む（進行中） | 拒む（進行中） | 拒む（終了。「最初から」が先） |
| 開始 | 受ける（区切りが 1 つ以上） | 拒む | 拒む | 拒む |
| 次へ（区切り ID） | 拒む | 受ける。ID 違いは何もしない | 受ける（次は動いて始まる）。ID 違いは何もしない | 何もしない |
| 一時停止 | 拒む | 受ける | 何もしない | 何もしない |
| 再開 | 拒む | 何もしない | 受ける | 何もしない |
| 延長（区切り ID・分） | 拒む | 受ける。ID 違いは何もしない | 受ける。ID 違いは何もしない | 何もしない |
| 飛ばす／戻す（区切り ID） | 拒む（開始前は削除で足りる） | まだ始まっていない区切りだけ受ける。いま・済みの区切りは拒む | 同左 | 拒む |
| 最初から | 何もしない | 受ける | 受ける | 受ける |

「拒む」はエラーコード付きで送り主にだけ返す（コード名は実装者が決める）。「何もしない」は成功として扱い、送り主にだけいまの全体を 1 通送る。

### 4.7 合図

- 残りが 0 に達した瞬間に、**音と画面の合図を 1 回**出す（§7.4 の時打ち）。途中で入った・再接続した画面では、過去の 0 に対して鳴らさない
- 音は既存の timer の交代チャイム（`apps/timer-web/src/platform/sound.ts`）と同じ考え方で鳴らす（`AudioContext` を利用者の操作で解錠する）【判断 J14】
- 解錠には操作が要るので、**操作しない画面（スクリーンに映しているだけ・途中で入っただけ）は鳴らない**。そこで**盤の隅に「音あり／音なし」の切り替えを常に置き、押すことが解錠を兼ねる**【判断】。既定は「音なし」で、押すと「音あり」になり解錠する
- 段階的な合図（残り 1 分で色など）・音の種類の選択は第 2 段

### 4.8 途中で入った人・再接続・スリープ明け

- 途中で入った人・再接続した人は、**参加の応答として進行の全体を 1 通受け取り**、次の変化を待たずに同じ盤から合流できる
- 画面が隠れていた・端末がスリープしていたあとに表示に戻ったとき（`visibilitychange`）、画面は**サーバーにいまの全体を求め直す**【判断】。区切りが 40 分ある間はフレームが 1 通も来ないことがあり、スリープ中に端末の単調時計が進まないブラウザもある（推測）ため、手元の時計だけで描き続けない
- ルームは揮発で、再起動・デプロイ・アイドルの破棄で進行は消える（原則 III・受容）。シナリオは保存した端末から読み直せる
- **終了の一覧もルームの状態にしか無く、全員が抜けると消える。** #429 の「会のあとに見返せる」は第 1 段では満たさない（後続の Markdown コピー・#408 で扱う）

## 5. 設計

置き場所は**独立したツール**とする【判断 J1】。timer のモードにはしない —— timer はモブプロの交代の輪が中心で、区切りの並びとは形が違う（#429 の「実装時に決めること」2 の見立てと同じ）。
新しい文脈を足すので **ADR を通す（原則 II）**。番号は `docs/adr/` の次（現時点で 0027）。ルーレット（`docs/adr/0026`）と同じ形で足す。

| 層 | 置き場所（仮名） | 中身 |
|---|---|---|
| ドメイン | `packages/agenda-core` | シナリオの検証・展開・進行の遷移・見込みの計算。純粋関数（原則 VI）。`room-core` を含むどの `@tasuki/*` にも依存しない（`docs/adr/0026` 決定 1 と同じ。依存の向きの正本は `scripts/audit-dependency-direction.mjs` の `ALLOWED`） |
| 同期サーバー | `apps/tasuki-sync` | 接続の種類 `?tool=agenda`（綴りの正本は `application/tool-id.ts`）。ストア・ハンドラ・配信・期限の予約。ルームの破棄で一緒に消す |
| 画面 | `apps/agenda-web` | 組む画面・進める画面・映す表示・終了の一覧。端末の保存 |
| 玄関 | `apps/landing` | ツールの札を 1 枚足す |
| 配備 | `deploy/` | ルーレットと同じ形 |

名前（`agenda`・画面上の呼び名）は仮。**画面上の呼び名は「進行タイマー」を仮置きする**【判断 J2】（書体の base 層に入ることは実測済み。§7.6）。

### 5.1 ドメイン（`packages/agenda-core`）

**シナリオ（定義）と進行の計画（展開済みの並び）を分ける。** これが第 2 段への継ぎ目である。

- `Scenario` = 会の名前 ＋ `items`。第 1 段の `items` の要素は区切り（`Step`）だけ
- `expand(scenario) → PlannedStep[]` が展開済みの平らな並びを返す。第 1 段では区切りをそのまま写すだけ
- **進行の遷移はすべて `PlannedStep[]` の上で行う**。第 2 段で `items` に「繰り返しの組」を足すときは `expand` と検証だけが変わり、進行の遷移・見込みの計算・wire の進行部分は変えずに済む
- **各 `PlannedStep` は進行の中で変わらない ID を持ち、操作は位置（添字）ではなく ID で区切りを指す（MUST）。** 第 3 段（リーンコーヒー）で進行中に区切りを末尾へ足しても、既存の ID と操作が壊れない
- **長さは core・wire・保存のすべてで秒（整数）で持つ（MUST）。** 第 1 段の画面と入力の検証で「分の整数」に絞る。第 2 段で LT の入れ替え 30 秒などが要っても、検証を緩めるだけで済み、wire と保存の形は変わらない
- 第 1 段で `items` を判別共用体（`kind: 'step'`）にしておくかは実装者の判断。ただし**抽象の先取りはしない**（原則 X）。「繰り返し」の型そのものは第 2 段で足す

進行の状態（案。名前は実装者が決めてよい）:

- 開始前 / 進行中 / 一時停止中 / 終了
- 展開済みの並び（各区切りの ID・長さ・時間切れの振る舞い・飛ばしたか・延長の合計・確定した所要）
- いまの区切りの ID と、その区切りの計時（`runningSince` ＋ 積算。timer-core の `accumulatedElapsedMs` と同じ考え方）と、その区切りが始まった瞬間（所要の基準）
- 開始した瞬間（実時間の経過の基準）

純粋関数で出すもの: 残り・オーバー・終わる見込み・押し巻き・自動で次へ移る期限・終了の一覧。時計は引数で受ける（原則 VI）。§4.1 の不変条件を性質テストで守る。
表現は `room-core`・`topic-core`・`roulette-core` と同じ**直接遷移関数 ＋ `Result`**（`docs/adr/0016` 決定 1 が求める記録は ADR 0027 に書く）。

### 5.2 時計

**この設計書の「実時間」は「一時停止を除かない経過」の意味であり、`WallClock` ポートのことではない。** サーバーでの経過・期限・開始してからの経過は、すべて **`MonotonicClock`**（`apps/tasuki-sync/src/ports/monotonic-clock.ts`）で測る（MUST）。`WallClock` は NTP の調整で戻りうるので、間隔の計測に使わない（`ports/wall-clock.ts` の注記）。

**期限の予約**: 自動で次へ移る期限は、サーバーが予約して発火させる。

- 既存の `Scheduler`（`apps/tasuki-sync/src/application/schedule.ts`）は timer 専用である。**サーバー全体で 1 つのインスタンス**（`create-sync-server.ts`）を持ち、**ルームのコードを鍵にした 1 つの Map** で予約を上書きし、`WallClock` で期限を測る。agenda がこれを共有すると、同じルームで timer と agenda が互いの予約を上書きする
- したがって **agenda 専用の予約**を持つ（MUST）。単調時計を受ける形にする。`Scheduler` の「長い単発の `setTimeout` を最大 1 秒刻みで区切り、毎回残りを計算し直す」自己補正の考え方は写す。共通化するかは実装者の判断（原則 X）
- 予約は一時停止・再開・延長・次へ・飛ばす・最初から・ルームの破棄で張り直す／消す
- **ルームの破棄（`application/destroy-room.ts`）へ渡す agenda の状態と予約は、必須の依存にする（MUST）。** 同じファイルで `scheduler` だけが省略可能（`scheduler?:`）になっていて、`rounds`・`topics`・`roulettes` は「optional にしてはならない」と注記されている。agenda は後者に倣う（配線から落ちてもテストが緑のまま残るのを防ぐ）

**画面への配り方**: ルーレットの「経過を配る」（`docs/adr/0026` 決定 3）を採る【判断 J9】。往復の測定が要らず、絶対時刻を wire に載せない。フレームには**送る時点で計った**次の値を載せる（§5.3）。端末は受け取ってからの経過（`performance.now()`）を足して描く。

**終了見込みの時刻**（「15:02 に終了見込み」）は、終わる見込みの経過を端末の壁の時計に足して出す。数秒のずれは表示上受容する【判断】。

### 5.3 wire

- 操作はすべて `agenda.*` のコマンド: シナリオの置き換え・開始・次へ・一時停止・再開・延長・飛ばす・戻す・最初から。**次へ・延長・飛ばす・戻すは区切りの ID を載せる**（§4.6）
- サーバーは変化のたびに、また参加の応答として、**進行の全体を 1 本のフレームで**配る。フレームが載せるもの（名前は実装者が決めてよい）:
  - シナリオ（会の名前・区切りの並び。各区切りの ID・名前・長さ〔秒〕・時間切れの振る舞い・飛ばしたか・延長の合計〔秒〕・確定した所要〔秒〕）
  - 状態（開始前／進行中／一時停止中／終了）・いまの区切りの ID
  - **送る時点で計った**: 実時間の経過・いまの区切りの計時・いまの区切りの所要
  - 開始した瞬間・`runningSince` などの単調時計の値は**載せない**（`docs/adr/0026` 決定 3 と同じ）
- 画面からの「いまの全体を求め直す」要求（§4.8）を 1 つ持つ。応答は同じフレーム
- 境界は Valibot で検証する（原則 IV）。**agenda のコマンドは agenda の接続のスキーマにだけ置く**（`docs/adr/0026` 決定 7 と同じ。ハンドラでも「agenda として在席しているか」を確かめる。接続の受理は `onConnect` を通す）
- **受けるフレームは非 strict にする**（`docs/adr/0026` の #401 追記と同じ）。第 2・第 3 段で項目を足しても古い画面が落ちない
- **お題のフレームは agenda の接続にも配る**（`docs/adr/0021` 決定 2「宛先はツールを問わない」・`application/topic-broadcast.ts` の `TOPIC_RECIPIENT_TOOLS` に足す）。agenda-web は agenda 固有のスキーマより先に `TopicFrameSchema` で見分ける（同決定の MUST）。第 1 段の画面がお題を表示するかは実装者の判断
- 名簿の配信先に agenda を足すかは実装者の判断（在席の表示に要るなら足す）

### 5.4 端末の保存

- 保存先は **localStorage**【判断 J10】（timer の設定 `apps/timer-web/src/prefs/local-prefs.ts` と同じ考え方。シナリオは小さく、IndexedDB の非同期は要らない）
- 保存するのはシナリオ（会の名前・区切り）だけ。進行の結果は保存しない（第 1 段）
- 読むときは保存の中身も**境界として Valibot で検証する**。保存の形には版を持たせる（第 2 段で `items` が広がるため）
- **古い版は新しい形へ移して読む（MUST）。** 版が上がったときに、利用者が前の段で保存したシナリオを黙って消さない。読み飛ばすのは壊れている項目（どの版のスキーマにも合わない）だけ【判断 J15】
- 保存は**ルームの誰でも、自分の端末に**できる

## 6. 守り（原則 XI・`docs/adr/0011`・`docs/adr/0012`）

区切りの名前・会の名前は**利用者由来のテキスト**である。区切りの名前には「田中さんの発表」のように人の名前が入りうる。

- **分類は「個人に紐づく」とする**【判断 J18】（`docs/adr/0011` 決定 1 の表で、poker の見積もりのアイテム名〔#93〕と同じ欄）。表への追記は PR 1 の作業に含め、ADR 0027 からも参照する。端末の保存は分類の扱いの対象外（同表の注記）
- 描画は既定のエスケープだけ。`dangerouslySetInnerHTML` を使わない
- サーバーのログに名前を出さない（ログの語彙 `application/log/vocabulary.ts` に載せない）
- 上限【判断 J11】（数値は実装者が既存と突き合わせて確定してよい）:

| 項目 | 上限 | 根拠 |
|---|---|---|
| 定義の項目の数 | 20 | 1 時間の会で 7 前後。#429 の表 |
| 展開後の区切りの数 | 第 1 段では定義と同じ（20） | 第 2 段の繰り返しで別の上限を決める（LT 10 人で 22 区切りになる） |
| 区切りの名前 | 40 字 | 表示名 `MAX_DISPLAY_NAME = 40` に揃える |
| 会の名前 | 60 字 | ルーム名 `MAX_ROOM_NAME = 60` に揃える |
| 区切りの長さ | 第 1 段は 60〜7200 秒で 60 秒の倍数（1〜120 分） | 投票 1 分が下限。第 2 段で刻みを緩める（§5.1） |
| 予定の合計 | 180 分 | 合計の健全性の上限。延長はこれとは別 |
| 延長を含めた 1 区切りの持ち時間 | 240 分 | 数値の健全性の上限。運用の上限ではない（§2.3） |

- 名前の空文字・前後の空白・制御文字の扱いは、お題・表示名の既存の規則に揃える
- **コマンドの頻度の上限は設けない**【判断 J16】。既存のレート制限が数えるのは入室・`ai.unlock` の失敗と poker の入口だけで、普通のコマンドの頻度を抑える仕組みはどのツールにも無い（効くのはメッセージの大きさの上限 `MAX_MESSAGE_BYTES` だけ）。agenda も他のツールと同じ扱いにし、そのことを ADR 0027 に書く

## 7. 見た目（利用者: 「カードテーブルの世界観の中で磨き上げる」）

実装時は `frontend-design` の指針に沿い、**PR 3 の前にモックを作って利用者に見せる**（§9）。ここに書くのは、モックを作る人が迷わないための**盤の文法と決まりごと**である。質感・寸法の細部はモックで詰める。

### 7.1 方向: 会議の懐中時計

利用者は「カッコイイと思ったのはオールドクラシックな懐中時計」と言い、カードテーブルとは合わせにくいと考えていた。
設計者の見立て【判断 J12】: **合う。** Tasuki の強調色は真鍮（`--gold` 系）、数字はセリフ体の Fraunces で、どちらも懐中時計の素材そのものである。
timer はすでにクロノグラフの目盛り盤・計測弧・運針を持つ（`apps/timer-web/src/styles/circular-progress.css`・`base.css` の `chrono-hand`）。ルーレットは真鍮の縁のグラデーションを持つ（`apps/roulette-web`）。

### 7.2 盤の文法（MUST。モックはこの上で作る）

| 部品 | 意味 | 動き |
|---|---|---|
| **12 時の竜頭** | 予定の終わり（約束の 1 時間） | 動かない |
| **外の環** | 予定。開始時点の区切りの長さで盤を割った区画。**1 周 = 予定の合計** | **開始後は動かない**（延長・飛ばすでも変えない。約束を揺らさない） |
| **内の環** | 実際。終えた区切りの所要 ＋ いまの区切りの所要。区画の色は区切りごと | 実時間で伸びる |
| **針** | 実時間の経過。**内の環の先端と常に一致する**（§4.1 の不変条件による） | 実時間で進む（一時停止中も進む） |
| **縁の三角（終了見込みの印）** | 終わる見込みの位置 | 延長・飛ばす・オーバーで動く |
| **6 時のスモールセコンド** | 区切りの計時が動いているか | 動いている間は秒針が回る。一時停止中は止まる |

- **押し巻きは、竜頭（12 時）と終了見込みの印の位置関係だけで読める**ようにする。印が 12 時より手前なら巻き（印を `--jade` で縁取る）、12 時を過ぎたら押し（印と、12 時から印までの縁を `--rose-bright` で塗る）
- 針が外の環のどの区画の上にいるかが「本来いるはずの場所」、内の環のいまの区画が「実際にいる場所」である
- **1 周を超えたとき**（延長・オーバー・一時停止で実時間が予定の合計を超えたとき）: 盤は回り込ませない。12 時を超えた分は、外の環のさらに外側の細い**オーバーの軌道**（3 本目の環）に `--rose-bright` で伸ばす。軌道が 1 周満ちたら満ちたままにし、あとは数字（「予定より +1:04:10」）に任せる
- **飛ばした区切り**: 外の環の区画は残す（約束は動かさない）。中を抜いて輪郭と斜線だけにし、進行表の行の番号に打ち消し線を引く。終了見込みの印がそのぶん手前へ動く
- **延長**: 外の環は変えない。内の環のいまの区画の先に、`--gold-edge` の細い「足し」の区画を伸ばす。盤の下に「予定 7 分 + 3 分」と添える
- **盤の上の目盛りには区切りの番号だけを置く**（`aria-hidden`）。名前は盤の中央と進行表に任せる（60 分の盤で 1 分の区切りは 6° しかなく、名前が入らない）

### 7.3 文字の優先順位と配置

| 順位 | 内容 | 置き場所 |
|---|---|---|
| 1 | 残り時間、またはオーバー（`+0:42`） | 盤の中央・最大 |
| 2 | いまの区切りの名前（2 行まで。溢れたら「…」） | 盤の中央 |
| 3 | 予定より ±n 分（押し巻き） | 盤の中央・数字の下 |
| 4 | 次の区切りの名前・「15:02 に終了見込み」 | 盤の下 |

利用者が一番欲しがっているのは「進捗とオーバーした長さが見えること」（§1）なので、押し巻きは 3 番目に置き、映す表示では 2 番目と同じ大きさまで上げる。

**数字**: 残り時間は桁が揺れないこと（MUST）。`font-variant-numeric: tabular-nums lining-nums` を指定し、自己ホストしている Fraunces のサブセットに `tnum` が残っているかを実測する。残っていなければ、1 桁ずつ固定幅の箱で組むか、残りだけ `--font-mono` にするか（timer の `.tabular` と同じ）をモックで選ぶ。コロンは別の箱にする。

### 7.4 状態ごとの色と形

**色だけに頼らない（MUST）。** 金と赤銅は明度がほぼ同じで（`--gold`／`--rose` で 1.73:1、`--gold-bright`／`--rose-bright` で 1.63:1）、色覚の多様性では見分けられない。すべての状態に形・記号・文言のどれかを添える。

| 状態 | 色 | 色以外の手がかり |
|---|---|---|
| 予定（外の環） | `--pewter` の目盛り・`--gold` の仕切り | — |
| 済んだ区切り（内の環） | `--gold-deep` 系 | 進行表で「済」の印 |
| いまの区切り | `--gold-bright` | 進行表で強調・針の位置 |
| 巻き・予定どおり | `--jade`（`--felt-700` の上には乗せない） | 「予定より −2 分」の文言 |
| オーバー・押し | **`--rose-bright`**（`--rose` はフェルトの上で 4.21〜2.27:1 で文字に使えない。`packages/ui/src/tokens/palette.css`） | 数字に必ず「+」・「オーバー」の小札・別の軌道・太さ 1.5 倍・刻み付きの模様 |
| 飛ばした区切り | 輪郭だけ・`--ivory-faint` | 斜線・打ち消し線・「スキップ」 |
| 一時停止 | 残りの数字を `--ivory-dim` に | スモールセコンドが止まる・「一時停止中」の札 |

- **時間切れの瞬間（時打ち）**: 縁の真鍮を `--gold-glow` で 1 度光らせる（600ms）。数字は `0:00` から `+0:00` に切り替わって `--rose-bright` になり、中央の地は `--rose-tint` になってそのまま残る。**点滅しない。1 秒に 3 回を超える明滅は禁止**。「自動で次へ」の区切りは、名前の横に「自動で次へ」の小札を始まる前から出して驚かせない
- **質感**: 縁はルーレットと同じ真鍮のグラデーション（`--gold-lift` → `--gold` → `--gold-deep` → `--gold-bright`）。針はブレゲ針風で `--gold-bright`、縁取りは `--gold-deep`、`--gold-glow` の drop-shadow。文字盤の地は `--felt-950` に周辺減光
- **開始前の盤**: 針は 12 時、中央に予定の合計（例「60:00」）と「開始」
- **終了の盤**: 内外の環の全体と「予定より +4 分」、一覧への入口

### 7.5 段組みと映す表示

- 320px〜1920px の段組みは `docs/adr/0025` に従う
- **手元（375px）**: 盤は 300px 前後。下に「予定より ±」の札、その下の固定帯に「次へ」（主・大きく）・一時停止・+1 / +3 / +5。進行表は折りたためる。**「スキップ」は進行表のまだ始まっていない行にだけ置き、主の操作「次へ」の近くに置かない**（押し間違いを防ぐ）
- **映す表示**【判断 J13】: 盤（短い辺の 70vmin 前後）・区切りの名前・残り／オーバー・予定より ±n 分・次の区切り・終了見込み を残し、進行表・保存・延長のボタン・在席を落とす。第 1 段では CSS の段組みとしての切り替えで持ち、ブラウザの全画面表示 API と Wake Lock は第 2 段
  - **字の段**: 既存の 5 段（最大 1.9rem）ではスクリーンに足りない。映す表示専用の段を、理由付きの例外としてトークンに足す（案: 数字 `clamp(4rem, 16vmin, 14rem)`・名前 `clamp(1.5rem, 5vmin, 4rem)`・補助 `clamp(1rem, 2.6vmin, 2rem)`。値はモックで詰める）
  - **操作**: キーボードで Space ＝ 一時停止／再開、→ ＝ 次へ、Esc ＝ 映す表示を抜ける。マウスを動かしたときだけ薄い操作帯を 3 秒出す
  - **明るい部屋のプロジェクター**ではフェルトの濃淡（`--felt-700` と `--felt-900` で 1.64:1）が潰れうる（一般的な傾向・推測）。**象牙のエナメル文字盤**（`--card-sheen` → `--card-shade`、字は `--coal` で 12:1）を案 B としてモックで比べる。その場合オーバーは `--card-back`（6.3:1）にし、役割名のトークン（例 `--overrun-on-enamel`）を足す。`--rose`（3.14:1）・`--gold`（1.82:1）は象牙の上では使えない
- 新しい生の色を足さない（デザインシステムの検査が止める）。足りない色・字の段・模様は `packages/ui` のトークンに役割名で足し、コントラストを測る

### 7.6 文言（書体の base 層・利用者の決定 U9）

**画面の固定文言は書体の base 層に入る字だけで作る（MUST）。** base 層は広げない。2026-10-19〜20 に `packages/ui/src/tokens/fonts.css` の Zen Kaku Gothic New（400・500・700）の base の unicode-range で実測した。

- 入らない字の例: 区切り（区）・延長・超過（超）・巻き（巻）・飛ばす（飛）・実績（績）・足す（足）・早め（早）・遅れ（遅）・前倒し（倒）・見本（本）・実際（際）・時刻（刻）・長さ（長）・合図（図）・確認・差・置き換え（換）・誰でも（誰）・全体（体）
- 対訳表（設計上の語 → 画面の文言）:

| 設計上の語 | 画面の文言 |
|---|---|
| 区切り | ステップ |
| 延長 | 群の見出し「このステップに」＋ ボタン「+1 分」「+3 分」「+5 分」 |
| 飛ばす／戻す | スキップ／戻す |
| 超過 | オーバー／`+m:ss` |
| 押し巻き | 予定より +3 分／予定より −2 分 |
| 見本 | サンプル（「サンプル：KPT のふりかえり」） |
| 長さ | 欄の名前を置かず、数字の入力欄に「分」を添える |
| 所要（実際） | かかった時間 |
| 終了見込みの時刻 | 「15:02 に終了見込み」（「時刻」の語は出さない） |
| 最初から（確認） | 「最初からやり直しますか」 |
| ルームに反映 | 実装者が base 層で組む（例「ルームに読み込む」） |

- 最終の文言は実装者が決め、各アプリの `copy-fits-font-base` の検査（例: `apps/roulette-web/tests/copy-fits-font-base.test.ts`）と同じ検査を agenda-web にも置いて機械で守る
- 利用者が入力する名前（区切りの名前・会の名前）と、同梱するサンプルの区切りの名前（「Try の議論」など）はこの制約の外（利用者由来のテキストと同じく ext 層で描く）

### 7.7 a11y と動き

- 盤の SVG は `aria-hidden` にし、同じ情報を文にした要約を持たせる（例「Try の議論、残り 12 分、予定より 3 分押し」）
- `aria-live="polite"` で読み上げるのは 4 つだけ: 区切りの切り替わり・時間切れ（1 回）・一時停止／再開・押し巻きが 0 をまたいだとき。毎秒の残りは読み上げない。要約をいつでも聞けるボタン（またはキー）を置く
- **動きを減らす設定**（`prefers-reduced-motion`）: 時打ちの光を出さず、地の色と札の切り替えだけにする。針と弧は連続して動かさず 1 秒ごとに描き替える。**針は消さない**（既存の `chrono-hand` は reduced-motion で `display: none` だが、agenda では針が押し巻きを読む要なので残す）
- 押せる部品は 44px 以上。「最初から」は部品層の危険の役割にし、確認を挟む

## 8. 検証

### 8.1 振る舞い（EARS の材料。計画で番号を振り、検査との対応表を作る）

時計は注入して検査する。期待値は §4.1 の式で書く（例: KPT のサンプルで P の途中に +3 分を押すと、押し巻きが +3 分になる）。

- 準備: シナリオの区切りが 1 つ以上あり上限内のとき、開始を受け付ける。上限超え・空の名前・制御文字・範囲外の長さは拒む
- 状態 × 操作: §4.6 の表の各マス（受ける・拒む・何もしない）がそのとおりになる
- 同時押し: いまの区切りの ID を持つ「次へ」が 2 通届いても、進むのは 1 つ。自動で次へ移った後に届いた古い ID の「次へ」は何もしない
- 次へ: 時間が来る前に押すと、そのぶん巻きになる。最後の区切りで押すと終了する
- 一時停止: 一時停止中は残りが止まり、押しは実時間で増え続ける。一時停止中の「次へ」で、次の区切りは動いて始まる
- 押すまで待つ: 残りが 0 に達したとき、合図を 1 回出し、オーバーを数え続け、次へ移らない
- 自動で次へ: 残りが 0 に達したとき、サーバーの判断で次の飛ばしていない区切りへ移る（最後なら終了）。次の区切りは期限ちょうどに始まったものとして記録される
- 延長: 区切りの延長の合計を増やし、終わる見込みと押し巻きを更新し、自動で次へ移る期限を張り直す。2 人分の延長は両方足される。延長で残りが正に戻った後に再び 0 に達したら、合図をもう一度出す
- 飛ばす／戻す: まだ始まっていない区切りを飛ばすと、その持ち時間が終わる見込みから外れる。戻すと元に戻る。いま・済みの区切りは拒む。残りをすべて飛ばすと、いまの区切りの「次へ」で終了する
- 最初から: 進行を捨て、シナリオを残して開始前に戻る
- 不変条件: 任意の操作の列のあとで、所要の合計 ＝ 実時間の経過。終了の一覧の差の合計 ＝ 押し巻き（性質テスト）
- 合流: 途中で入った・再接続した端末は、参加の応答として進行の全体を 1 通受け取る。過去の時間切れの合図は鳴らさない。表示に戻ったときに全体を求め直すと、同じフレームが返る
- 境界: agenda 以外の接続から agenda のコマンドが来たら拒む。お題のフレームが agenda の接続にも届く
- 破棄: ルームの破棄で、agenda の状態と期限の予約が消える
- 保存: 端末に保存したシナリオを読み直せる。古い版は新しい形へ移して読む。どの版にも合わない項目は、落ちずに読み飛ばす
- 画面: 固定文言が書体の base 層に収まる。時打ちは点滅しない。reduced-motion では針を残して 1 秒ごとに描く。`aria-live` の読み上げは 4 種だけ

### 8.2 実画面（原則 V）

- 2 つのブラウザで同じルームを開き、KPT のサンプルを走らせて、残り時間・オーバー・押し巻きが揃うこと
- 「自動で次へ」の区切りで、操作していない画面も同時に移ること
- 2 つの画面でほぼ同時に「次へ」を押して、1 つしか進まないこと
- 映す表示を 1920px で、手元を 375px で見ること。映す表示を部屋の奥から読める大きさか、モックの段階で利用者に見てもらう
- 変異検査（原則 VII）の ID の帯は計画で台帳から予約する

## 12. 実装で実測して外したこと・決めたこと（2026-10-20）

§10 の「実装者に任せること」の答えと、実装で実測して §1〜§11 から外したこと。§1〜§11 は書き換えない（決定当時の記録）。
決定の経緯は SDD の台帳（Ruling）に残した。ここには結論と、外れたときに直す場所だけを書く。

### 12.1 §10 の答え

- **期限の予約**: `Scheduler` と共通化せず、`apps/tasuki-sync/src/application/agenda-deadlines.ts` に別の型・別のインスタンスで持った。最大 1000ms 刻みで待ち、毎回残りを計算し直す自己補正は `Scheduler` から写した。時計は合成ルートで 1 つの `MonotonicClock` を共有する
- **名簿は agenda の接続に配らない**。名簿の宛先（`timer-ws-broadcaster.ts` の `rosterRecipientsOf`）は玄関とルーレットのまま。お題は配る（ADR 0027 決定 9）
- **第 1 段の画面はお題を表示しない**。`topic` フレームは `agenda` より先に見分けて同期フックが保持する（ADR 0021 決定 2 の MUST）が、画面には出さない
- **音は timer-web から写し、共通化しない**（`apps/agenda-web/src/platform/sound.ts` の冒頭に写しの出所を書いた）。解錠されていない `AudioContext` には時打ちを予約しない（次に触った瞬間に遅れて鳴らないため）
- **「ルームに反映」の文言は「ルームに読み込む」**。§5 の文言の表のとおり
- **盤の細部はモックの案 A（フェルトの盤）で決めた**。案 B（象牙のエナメル盤）は作っていない。利用者には撮影と一緒に見せる（§9 の「着手の前に見せる」は、利用者の「推奨の形で作りきってよい」の指示で後回しにした）
- **上限の値**は §6 のまま（正本は `packages/agenda-core/src/limits.ts`）

### 12.2 実測して外したこと

- **自己ホストの Fraunces のサブセットには `tnum` が無い**（実測: `tabular-nums` を指定しても `1111` が 72.8px・`0000` が 106.6px）。§7.3 の選択肢のうち「1 桁ずつ固定幅の箱」を採り、残り時間の数字は 1 桁ずつ 1ch 相当の箱に中央揃えで組み、コロンは別の箱にした（`TimeDigits.tsx`）。外れたら箱の幅を直すだけ
- **針が中央の数字を横切って読めなかった**（6 局面の撮影）。中央に台座（`.dial-plate`）を置いて針の軸の内側を覆い、数字と名前にフェルトの縁取り（halo）を付けた。台座の外の軸が数字の左右の端に重なる局面は残る（縁取りで読めるので受容）
- **飛ばした区画の斜線は SVG の属性では描かれなかった**（CSS の `stroke` が属性に勝つ）。`style` で当てた
- **広い幅と映す表示で盤が約 180px に潰れ、終了の画面では盤が消えた**（中央揃えの器で `figure` が一行の幅まで縮んだ）。盤の器を幅いっぱいにし、広い幅の進める画面では `clamp(20rem, 38vw, 32.5rem)`、映す表示では `70vmin` にした。いずれもテストでは出ず、撮影で見つかった
- **映す表示の字の段は `packages/ui` のトークンに上げず**、`apps/agenda-web/src/run.css` のローカル変数＋理由つきの `scale-exempt` にした（§7.5 の「トークンに足す」から外した）。使うのが agenda-web だけで、原則 X（抽象は実需で）に合う。外れたらトークンへ移す
- **映す表示は 2 列**（盤が左、押し巻き・次・終了見込みが右の列）。押し巻きは右の列の最上段に、§7.3 の「2 番目と同じ大きさ」より大きく置いた。部屋の奥から一番読みたい数字だから
- **開始前の盤の中央の添え書きは「開始前」**（§7.4 の「開始」ではない）。「開始」はボタンの名前と同じで、押せるものと紛れる
- **押し巻きの丸めは押しと巻きで揃えた**（−30 秒は −1 分）。オーバーの最初の 1 分の要約は「オーバー」だけにし、「オーバー 0 分」と読ませない。終了見込みの印はオーバーの軌道の外へ出した
- **並べ替えのドラッグ（§4.2）は入れていない**。上へ／下へのボタンだけにした。ステップは 7 前後で足り、ドラッグはキーボード操作と a11y の手当てが重い。外れたら `StepEditorRow` に後から足す
- **サンプルの札にはステップの名前と分を出す**。同梱の名前は §7.6 のとおり書体の制約の外なので、書体の検査（`rendered-text-fits-font-base`）から外した。急いでいる進行役が中身を見て選べる
- **盤のプレビューの「今日の進行 5 ステップ」が「ステッ／プ」で折れた**。「今日の進行」「n ステップ」を塊で組み、語の中で折らない（`keep-all`。長い名前だけ `anywhere`）
- **端末の保存は valibot（`v.safeParse`）で検証する**（agenda-web の依存に valibot を足した。timer-web と同じ）。Standard Schema の `~standard.validate` は Promise を返しうる分岐が fail-open になる。保存の前にも検証し、読めない保存・将来の版・どの版にも合わない項目は**書き込みで消さず生のまま残す**（J15 の「黙って消さない」を書き込みの側にも広げた）
- **「自動で次へ」で移った瞬間の時打ちの取り逃しは受容した**。合図は前のステップで 0 をまたいだ側で出す（`crossedZero`）ので、フレームの間でまたぐと鳴らないことがある。外れたらサーバーのフレームに時間切れの印を載せる
- **玄関の札の pip は「予定」**（計画の「進行」から変えた）。ルーレットの札の pip が「進行」で、玄関で 2 枚の左上が同じ字になる。「予定」は base 層で実測済み。札が 5 枚になり、64rem 以上で札名「TDD Mob Pro Timer」が 2 行に折れたので、札を折り返して中央に寄せた（3＋2）

### 12.5 最終レビューで決めたこと（2026-10-21）

- **wire の所要（`spentMs`）は ms である。** §5.3 は「確定した所要〔秒〕」と書いたが、実装は終了の一覧の差（所要 − 予定）を ms で出すので、フレームの各区切りの `spentMs` は ms の整数で載せている。長さ（`durationSec`）・延長（`extensionSec`）は §5.3 のとおり秒。§5.3 は書き換えず、ここを正本にする
- **§12.2 の「自動で次へで移った瞬間の時打ちの取り逃しは受容」を取り消す（I-1）。** 手元の時計はサーバーより片道の遅れの分だけ遅れるので、手元で 0 をまたぐ描画より先に「移った」フレームが届き、取り逃しは例外ではなく常態だった（動きを減らす設定の 1 秒ごとの描き直しではほぼ鳴らない。最後の区切りが自動で終わるときは、次が進行中でないので一度も鳴らない）。サーバーのフレームに印は足さず、画面が次の条件で「時間切れで移った」と見分けて鳴らす（`apps/agenda-web/src/timeout-signal.ts`）:
  - 前に描いた盤で、いまの区切りが「自動で次へ」・動いている・残りが正（まだ鳴らしていない）
  - 届いたフレームで、その区切りの所要が確定しており、**所要 − 一時停止していた分 = 持ち時間（長さ＋延長）**。サーバーは期限ちょうどで確定する（J20・`advanceIfDue`）ので等しくなり、持ち時間より前の「次へ」では足りない。一時停止していた分は前の盤の `stepSpentMs − stepTimerMs`。単調時計は小数なので 1ms 未満の差は等しいとみなす
  - 次の区切りへ移ったときも、終了へ移ったときも鳴らし、読み上げに「時間切れです」を入れる（終了なら「時間切れです、終了しました」）
  - 手元で先に 0 をまたいで鳴らしていれば、前の盤の残りが正でないので二度は鳴らさない。最初の描画（前の盤が無い）では鳴らさない（§4.7）
- **音の設定は「覚えた設定」と「解錠」を分けて見せる（I-2）。** 「音あり」を覚えた端末で開き直すと `AudioContext` は解錠されておらず鳴らないのに、ボタンは「音あり」と出ていた。解錠前は「音を有効に」（押されていない状態）と出し、1 回押すと解錠して「音あり」になる（音なしへは倒さない）。画面のどこかに触れて解錠されたときも「音あり」に変わる。鳴らすのは解錠済みの「音あり」のときだけ。「音を有効に」は書体の base 層で実測した（§7.6 の表に足す）
- **フレームの時間切れの振る舞い（`onTimeout`）は開いた文字列で受ける（M-2）。** 第 2 段以降のサーバーが振る舞いを足しても、古い画面がフレームごと捨てて盤が止まらないように。知らない値は「押すまで待つ」として読む（画面が勝手に鳴らしたり進めたりしない側）。コマンドとシナリオの入力（`StepInputSchema`）は列挙のまま。ADR 0027 決定 3 に一行足した
- **操作の失敗の表示は、届いた `agenda` フレームのたびには下ろさない（M-1）。** 他の人の操作のフレームで、自分の失敗の文が読む前に消えていた。下ろすのは自分の次の操作が通ったフレームと、いまの区切りが変わったフレームだけ
