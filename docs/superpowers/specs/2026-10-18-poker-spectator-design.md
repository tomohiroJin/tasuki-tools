## 1. 何のために作るか

#95 でホストの役割をなくしてから、ルームに居る人は全員が投票者になった。
ところが見積もりの場には、**見積もりには加わらず見ているだけの人**が居る（PO の同席者、入ったばかりのメンバーなど。#93 のブレインストーミングで利用者が発案・2026-10-17）。

今その人が居ると困るのは 2 つ。

1. **自動の開票が来ない。** 自動公開は「接続中の全員が投票済み」で立つので、投票しない人が 1 人居るだけで、毎回だれかが「票を公開する」を押す羽目になる
2. **未投票の席が残る。** 席の一覧に伏せ札の無い席が並び、「まだ誰か出していない」ように見える

## 2. 目標・目標にしないもの・失敗とみなすもの

**目標**

- 自分で「見学する」に切り替えられる。見学者は手札を持たない
- 見学者は自動公開の判定（接続中の全員が投票済みか）の数から外れる
- 見学から投票へ、投票から見学へ、いつでも自分で戻せる
- 席の一覧で、見学者と投票者が見分けられる

**目標にしないもの**

- 他人を見学にする・見学から戻す操作（役割は #95 で廃止した。他人の票を黙って消せる操作を作らない）
- 参加する前（玄関・ハブ）で見学を選ぶ欄（名乗る場所は玄関に 1 つで、3 ツール共有。poker だけの項目を持ち込まない。入ってから 1 回押せば足りる）
- ルームの既定を「見学で入る」にする設定
- timer・roulette への見学の概念の持ち込み（名簿は共有だが、見学は poker の状態である）

**失敗とみなすもの**

- 見学者が居るせいで自動公開が来ない／見学者を外したのに来ない
- 見学に切り替えた人の票が、投票中に集計へ残る
- 見学の切り替えで、すでに開いた票・記録（#93）が書き換わる
- 古いサーバーにつながった新しい画面が `room-state` を捨てる（#216 の前方互換が崩れる）

## 3. 用語

| 語 | 意味 |
|---|---|
| 見学者 | そのルームの poker で「見学する」を選んでいる参加者。手札を持たない |
| 投票者 | 見学者でない参加者（既定） |
| 自動公開の分母 | 自動公開の判定で「全員が投票済みか」を数える集合。**poker に在席し、かつ見学者でない人** |

## 4. 振る舞い（EARS）

- **S-1** 参加者が「見学する」を押したとき、サーバーはその参加者を見学者にし、ルームの全員へ配信する
- **S-2** 見学者が「投票に加わる」を押したとき、サーバーはその参加者を投票者に戻し、配信する
- **S-3** 投票中に見学へ切り替えたとき、サーバーはその人の票を捨てる。続けて自動公開を判定し直す（残った投票者が全員出していれば、その場で開く）
- **S-4** 開票後に見学へ切り替えたとき、サーバーは票を変えない（開いた票・集計・記録はその開票の事実として残る）
- **S-5** 投票中に投票へ戻ったとき、その人は未投票から始まり、出すまで自動公開は来ない
- **S-6** 自動公開の判定は、poker に在席している投票者だけを数える。在席している投票者が 0 人なら自動公開は立たない（今の番人のまま。手動の「票を公開する」は誰でも押せる）
- **S-7** 見学者が `vote` を送ったとき、サーバーは票を受けず、エラー `spectating` を返す（画面は手札を出さないので、別のタブの切り替えとの競合でしか届かない）
- **S-8** 見学者も、票を公開する・再投票・次のアイテムへ・アイテム名・ポイントの操作はできる（PO が進行役を務めることがある。役割は #95 で廃止した）
- **S-9** 同じ状態への切り替え（見学者が「見学する」を送る）は何も変えずに配信する（冪等）
- **S-10** 見学の状態は参加者 ID に付く。再接続・再読み込み・選択画面を経由した出入りでも保たれる（ルームが消えれば消える。揮発インメモリ）
- **S-11** 名簿から外された人（`participant.remove`）は見学者の集合からも外す
- **S-12** 新しく入った人は投票者として入る

## 5. 画面

### 5.1 席の一覧

- 見出しは見学者が居るときだけ `参加者（N人・見学M人）`、居なければ今のまま `参加者（N人）`（N は見学者を含む全員）
- **投票者を先に、見学者を後に並べる**（それぞれの中は今の順）。見学者の行は席の札を持たず、`見学` の印を付ける
- **開票後、見学者が票を持っているときは札を見せる**（S-4 で票は残るので、集計に入っている札を隠さない）
- 切断中の印は今と同じく見学者にも付く
- 札がめくれる順（`--seat-order`）と結果の待ち（`--seat-count`）は、**札を持つ席だけ**で数える

### 5.2 自分の切り替え

- 席の一覧の見出しの脇に、自分の状態に応じて `見学する`／`投票に加わる` のボタンを 1 つ置く（投票中・開票後のどちらでも出す）
- 投票中に自分が見学者なら、`あなたのカード` の手札の代わりに `見学中です。投票には加わりません。` の一文を出す
- 切断・再接続中はほかの操作と同じく押せない

### 5.3 文言と書体

上の文言はすべて書体の base 層に収まる（2026-10-18 実測。`packages/ui/src/tokens/fonts.css` の `-base` の `unicode-range`。対照として「整」「古」が欠けると出ることを確かめた）。
**外れた字**: 「札」「簿」（「手札を持たずに見る」「名簿から外す」は使わない）。
エラー文言 `見学中は投票できません` も収まる。

## 6. 作りの制約（実装役が守ること）

- **見学は poker の状態として `Round` に持つ**（`spectators`: 参加者 ID の集合）。`@tasuki/room-core` の名簿には持ち込まない（timer・roulette に意味が無い。依存方向の許可表で poker-core は room-core を知らない）
- ドメインは `packages/poker-core` の純関数＋`Result`（`round.ts` と同じ形）。切り替えは `setSpectator(round, participantId, spectator)`。投票中に見学へ切り替えたら票を捨てる（`discardVote` と同じ規則）
- 自動公開の判定（`shouldAutoReveal`）は**ラウンドの見学者の集合を見て分母から外す**。`VoterView` に見学の項目を足さない（見学はラウンドが持つ。名簿の断片へ写すと、写し忘れたテストが恒真になる）
- 見学者の `vote` は `castVote` が `{ code: 'spectating', op: 'vote' }` で拒む。`ERROR_CODES` に `spectating` を足し、`messageForRoundError` に文言を足す
- wire: クライアント→サーバーに `{ type: 'set-spectator', spectator: boolean }`（`v.strictObject`）。サーバー→クライアントの `ParticipantView` に `spectator` を足す。**`v.optional(v.boolean(), false)`**（新しい画面が古いサーバーに当たっても捨てない・`docs/poker/adr/0004`）。サーバーは常に送る
- `set-spectator` は既存の `commitRoomAction` を通す（not-joined の検査・自動公開の再評価・配信を共有する）
- 退出の経路（`handleParticipantRemoved`）で見学者の集合からも外す
- **データ分類（ADR-0011 MUST）**: 見学かどうかは「どの利用者がいま見積もりに加わっているか」で、在席と同じく **「個人に紐づく」（揮発のみ・ログへ出さない）** に当てる。分類表へ書き足す
- 新しい操作のレート制限は足さない（`set-item` などと同じく、参加済みの接続の操作であり、入室の総当たりとは別物）

## 7. 今の poker との関係

- **見積もりの記録（#93）は変わらない。** 記録は開いた票の枚数だけを数え、誰が出したかを持たない。見学者は票を持たないので、行の枚数にも分布にも入らない。開票後に見学へ切り替えても、すでに足された行は変わらない（S-4）
- 割れたときの促し（#405）は票から引くので変わらない。開票後に見学へ切り替えた人の名前も、票が残る以上は出る
- 席の札のめくり（#348）は、札を持つ席だけで順を振り直す（§5.1）

## 7a. 同じ PR で直す申し送り: poker の幽霊の片付けと同名の呼び分け

**出所**: #95 の振り返り（`docs/retrospectives/2026-09-23-issue-95-shared-identity-and-rooms.md` の申し送り表）。
「poker で幽霊を片付けられず、同名を呼び分けられない」を受容し、**次に poker-web を触る Issue（#92 / #419）で直す**ことを利用者が承認している（2026-09-23）。
席の一覧（§5.1）を作り替えるのと同じ場所なので、ここで直す。

### 7a.1 同名の呼び分け（G-1〜G-3）

- **G-1** poker の席の一覧で、見え方の同じ名前（`nameSkeleton` が一致する）が 2 人以上居るとき、その全員の名前に識別子を添える。形は timer と同じ `名前（ID: xxxx）`
- **G-2** 呼び分けの規則（曖昧かの判定・識別子の短縮）は **`@tasuki/room-core` に 1 つだけ置き**、玄関・timer・poker が同じものを使う。`apps/landing/src/hub/participant-label.ts` と `apps/timer-web/src/ui/participant-label.ts` の写しは消す（timer の `labelPool` は `@tasuki/timer-core` の `Seat` に依存するので timer-web に残す）
- **G-3** 識別子は **ID の末尾 4 文字**に揃える。玄関はいま先頭 4 文字（`slice(0, 4)`）を出しているが、timer とハブの入口で作られる参加者 ID は `p_` ＋ nanoid（`apps/tasuki-sync/src/adapters/nanoid-code-gen.ts`）なので、**その人たちの先頭 2 文字は全員同じ `p_`** で、見分けに使えるのは 2 文字しかない（poker の入口で作られる ID は `crypto.randomUUID()`・`adapters/poker-crypto-id-gen.ts` で、末尾でも先頭でも見分けられる）。玄関の見え方は `あや（p_tY）` から `あや（ID: xxxx）` に変わる（不具合の修正として扱う）
- **G-3a** 判定の意味は timer のもの（見え方の同じ人が 2 人以上、**または対象が一覧に居らず見え方の同じ人が 1 人だけ居る**）を room-core に置く。玄関は対象を必ず一覧から渡すので、玄関の見え方は G-3 の形の変化だけで、付く・付かないは変わらない

### 7a.2 幽霊の片付け（G-4〜G-8）

- **G-4** poker の席の一覧で、**どこにも接続していない人**（席の一覧で `切断中` の人。poker の一覧に出る切断中の人は、`showsInPoker` の規則により接続を 1 本も持たない人だけ）の行に、自分以外なら `退出させる` を出す。押すと確認を挟む（timer の `RemovalConfirmDialog` と同じ型の確認。文言は「〈呼び名〉 さんを退出させますか？」）
- **G-5** 接続している人は poker から外せない。サーバーも拒む（エラー `not-removable`）。理由: poker の画面には「外された」本人へ知らせて画面を移す経路が無い。生きているタブを黙って名簿から落とすと、その人は動かない画面に取り残される。接続している人を外したいときは今までどおり timer の名簿から行う
- **G-6** 外したときの結果は **timer の名簿から外したときと同じ**にする（名簿から外す・timer の状態があれば輪の席を外し必要なら見学者を繰り上げる・poker の票と見学を捨てる・自動公開を測り直す・名簿が空になるならルームごと破棄）。**ルームから人を外す処理は 1 つにする**。今の `apps/tasuki-sync/src/application/command-handlers/participant-remove.ts` は timer の状態を必須にしている（`RoomState` の `timer` が必須・`handlers.ts` の `loadState` は timer が欠けると `undefined`）ので、次のように分ける:
  - **中核**（ツールに依らない）: 名簿から外す・空なら破棄・poker の票と見学を捨てる。結果は `Result` で返し、**送信はしない**
  - **timer の後段**（timer の状態があるときだけ）: 輪の席を外す・繰り上げ・スケジュールの突き合わせ・timer の在室者への「〈実行者〉が〈対象〉を退出させた」の知らせ・外された本人の接続への通知
  - **poker の入口は timer の状態を作らない**（`timers.put` を timer の状態が無いルームで呼ばない。呼ぶと `join-room.ts` の遅延生成が走らなくなり、後から timer を開いた人に壊れた状態を見せる）
  - エラーは**入口ごとに自分のコードへ訳して、自分の送信口で返す**（timer は今の `PARTICIPANT_NOT_FOUND` などのまま。poker は G-7 のコード）
  - poker の入口から外せるのは**名簿の人だけ**（timer の輪の代理は poker の一覧に出ないので外させない）
- **G-6a** poker の在室者へは知らせのフレームを足さない。一覧から行が消えるのが知らせである（新しいフレームの `type` は古いバンドルが捨てて「同期できていません」を出す・`docs/poker/adr/0004`。timer の在室者への知らせは今のまま届く）
- **G-7** wire: クライアント→サーバーに `{ type: 'remove-participant', participantId: string }`（`v.strictObject`）。エラーは名簿に居ない相手なら新しい `participant-not-found`、接続している相手（G-5）と自分自身なら `not-removable`。中核が輪の席の都合で拒んだとき（`BelowMinMembers`。外す相手は接続 0 本で実行者が名簿に居るので繰り上げの候補は必ず居て、理屈の上では届かない）も `not-removable` に畳む
- **G-8** 自分自身を poker から外す操作（抜ける）は作らない（今の poker に無い。抜けるのは選択画面へ戻る導線で足りる）

### 7a.2b 名簿から外された人の poker のタブ（既存の穴・G-9）

- **G-9** poker の操作（`vote`・`set-spectator`・`reveal` ほか `commitRoomAction` を通るものすべて）は、**送った人がいま名簿に居るか**を確かめ、居なければ `not-joined` を返して状態を変えない。今は確かめておらず、timer の名簿から外された人の poker のタブが投票でき、その票が集計に入る（builder check が実測・`poker-commit-room-action.ts` の `commitRoomAction`）。見学の集合（S-11）へ外された人が戻るのもこれで塞がる

### 7a.3 作りの制約

- `poker-handlers.ts` の `handleParticipantRemoved` の注記（「退出はルームの出来事なので poker の wire には対応するコマンドが無い」）は、入口が増えたことに合わせて書き直す。**出来事がルームのものであることは変わらない**（入口が 2 つになるだけ）
- 呼び分けは表示だけの話で、wire は変えない（`ParticipantView` の `id` と `name` で足りる）
- `退出させる`・`さんを退出させますか？`・`接続している人は外せません` は base 層に収まる（実装役が `estimate-copy-fits-font-base.test.ts` と同じ型の検査を足して固定する）

## 8. Issue 本文の「実装時に決めること」への答え

| 問い | 答え |
|---|---|
| 席の見え方 | 投票者の後ろに並べ、札の代わりに `見学` の印。開票後に票を持っていれば札を見せる。見出しに見学の人数（§5.1） |
| 途中で見学から参加へ（またはその逆へ）切り替えられるか | 自分でいつでも両方向に切り替えられる。投票中に見学へ移ると票を捨て、開票後なら票は残す（S-1〜S-5） |
| 見積もりの記録（#93）への影響 | 無い。記録は開いた票の枚数だけを数える（§7） |

## 9. 設計者が決めたこと（利用者の確認なし）

1. 見学は `Round` が持つ（名簿へ持ち込まない）
2. 切り替えは本人だけ。参加前（玄関）では選ばない。入るときは投票者
3. 投票中の切り替えは票を捨てる。開票後は票を残す
4. 見学者の票はエラー `spectating` で拒む（自動で投票者へ戻さない）
5. 見学者もそれ以外の操作はすべてできる
6. 席は投票者の後ろ、`見学` の印、見出しに人数
7. 切り替えのボタンは席の一覧の見出しの脇
8. PR は 1 本（`docs/guides` の PR の粒度の既定）
9. 申し送りの「幽霊の片付けと同名の呼び分け」を同じ PR で直す（直すこと自体は利用者承認済み・2026-09-23。形は設計者の判断）
10. 呼び分けの識別子は末尾 4 文字・`（ID: xxxx）` の形に 3 つのアプリで揃える（玄関の見え方が変わる）
11. poker から外せるのは接続を 1 本も持たない人だけ（G-5）
12. 外す処理は「中核（ツールに依らない）」と「timer の後段」に分ける。poker の入口は timer の状態を作らない（G-6）
13. poker の在室者への退出の知らせは足さない（G-6a）
14. 名簿に居ない人の poker の操作を拒む（G-9・既存の穴）
15. 配布は同期サーバー（`deploy.sh timer`）を先、poker の web を後にする。新しい画面が古いサーバーに当たる短い窓（`set-spectator` などが `invalid-message` になる）は許す（再起動でルームは全部消えるため。#93 と同じ判断）

## 10. 実装役に任せること

- 型・関数・CSS クラスの名前（`spectator` の語で揃えることだけ守る）
- ボタンの見た目の細部（`ui-button--secondary ui-button--sm` を基準に）
- テストの粒度
