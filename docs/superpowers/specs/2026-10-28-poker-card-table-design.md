## 1. 何のために作るか

プランニングポーカーに、**知っている人だけが入れる遊び**を 1 つ置く（イースターエッグ）。目的は遊び心だけで、
見積もりの機能には影響させない。

## 2. 目標・目標にしないもの・失敗とみなすもの

**目標**

- プランニングポーカーの操作だけで入れる、ただ 1 つの入口。端末（キーボード・タッチ）でも人数（1 人・複数人）でもやり方が変わらない
- ジョーカーなしの 52 枚で 5 枚を配り、1 回だけチェンジして、全員の手と役を一斉に開く
- 本物のトランプに見える札（形・角の文字・マークの並び・絵札・裏面）
- 自分の手は、開くまで他の人の画面（と、他の人の手元の JS）に届かない

**目標にしないもの**

- チップ・賭け・勝ち負け（役を出すだけ）
- 2 回以上のチェンジ・テキサスホールデム
- 入口を秘密にすること（**隠しは入口が見えないだけで、アクセス制御ではない**）
- timer・roulette への持ち込み

**失敗とみなすもの**

- 手が、開く前に本人以外へ届く（wire のどのフィールドにも載る）
- 入口の手順を踏んでいないのにポーカーが始まる（普段の見積もりで ☕ が続いただけで始まる、など）
- ポーカーの最中・後に、見積もりの記録・見学が壊れる
- 古いサーバーにつながった新しい画面、新しいサーバーにつながった古い画面が `room-state` を捨てる

## 3. 用語

| 語 | 意味 |
|---|---|
| 投票者 | 見積もりで札を出す人（見学者でなく、poker に接続している人）。`shouldAutoReveal` の分母と同じ集合 |
| 全員 ☕ の開票 | 投票者の全員が ☕ を出し、それが開かれた開票（手動・自動どちらでも） |
| 入口の構え | 全員 ☕ の開票が 1 回あり、まだポーカーが始まっていない状態 |
| ゲーム | 配ってから「見積もりに戻る」までのポーカー。ルームに 1 つ |
| プレイヤー | ゲームの始まりに手を配られた人（最大 10 人） |
| チェンジ | 手から 0〜5 枚を選んで捨て、同じ枚数を引く。1 人 1 回 |

## 4. 振る舞い（EARS）

### 入口

- **E-1** 全員 ☕ の開票が起きたとき、サーバーは入口を構える
- **E-2** 入口を構えている間に「再投票」が押され、続く開票も全員 ☕ だったとき、サーバーはゲームを始める（このときの投票者がプレイヤー）
- **E-3** 入口を構えている間に「次のアイテムへ」が押されたとき、または全員 ☕ でない開票が起きたとき、サーバーは構えを解く
- **E-4** 投票者が 1 人のルームでも、入口の手順は同じである（1 人で ☕ → 開く → 再投票 → ☕ → 開く）
- **E-5** 手動の「票を公開する」で開いた開票は、投票者の全員が ☕ を出しているときだけ全員 ☕ と数える（出していない人が居れば数えない）

### ゲーム

- **G-1** ゲームが始まったとき、サーバーはジョーカーなしの 52 枚をよく切り、プレイヤーへ 5 枚ずつ配る
- **G-2** 投票者が 10 人を超えるとき、サーバーは席順の先頭 10 人をプレイヤーにする（52 枚で 5 枚ずつ配れるのは 10 人まで）。残りの人は見るだけ
- **G-3** 開く前、サーバーは各受信者へ**その人の手だけ**を送る。他の人について届くのは「チェンジを済ませたか」だけである
- **G-4** プレイヤーがチェンジを送ったとき、サーバーは選ばれた札を捨て、山から同じ枚数を引いて手に戻す。0 枚のチェンジ（このまま）も 1 回として数える
- **G-5** 山が足りないとき、サーバーは捨て札（誰の手にも無い札）を切り直して山に足す
- **G-6** チェンジを済ませたプレイヤーがもう一度チェンジを送ったとき、サーバーは状態を変えず `table-exchanged` を返す
- **G-7** 全プレイヤーがチェンジを済ませたとき、サーバーは全員の手と役を全員へ配信する（勝ち負けは付けない）
- **G-8** プレイヤーが poker から抜けた・ルームから外れたとき、サーバーはその人をプレイヤーから外す。残りが全員チェンジ済みなら G-7 へ進み、プレイヤーが居なくなったらゲームを終える
- **G-9** 開いたあと「もう一度」が押されたとき、サーバーはいまの投票者（上限 10 人）で G-1 からやり直す
- **G-10** 「見積もりに戻る」が押されたとき、サーバーはゲームを終え、見積もりを投票中（票なし）へ戻す。これはゲームの最中でも押せる（席を離れたまま戻らない人が居ても止まらないように）
- **G-11** ゲームの最中、見積もりの投票・公開・再投票・次のアイテムへは `table-in-play` で拒む。アイテム名の設定・記録の切り替え・見学の切り替えは受ける
- **G-12** ゲームに関わらない人（見学者・途中で入った人・11 人目以降）は、テーブルと各プレイヤーの「チェンジ済み」を見るが、手は開くまで見えない

## 5. 画面

### 5.1 入口

画面に入口らしいものは置かない。見積もりの操作（☕・公開・再投票）だけで入る。判定はすべてサーバーが行うので、
画面に入口の検出のコードは無い。

### 5.2 テーブル

ゲームの間は、操作の面（`.room-main`）の手札・結果・下端の帯を**テーブルに置き換える**。席の一覧・お題・記録は残す。

- 卓（フェルトの面）の上に、プレイヤーごとの席。自分の席は手前に大きく
- **配る**: 山から札が 1 枚ずつ席へ滑って伏せたまま着き、自分の札だけが表へ返る
- **チェンジ**: 自分の札を押すと少し持ち上がり（選んだ印）、「n 枚チェンジ」で捨てて引く。選ばなければ「このまま」。済んだ人の席に「チェンジ済み」
- **開く**: 全員が済んだら、他の人の札が席順にめくれ、各席に役の名前が出る
- 帯: 開いたあとは「もう一度」「見積もりに戻る」。最中も「見積もりに戻る」は控えめに置く（「配」は書体の base 層から外れるので「もう一回配る」とは書かない）
- 動きは `prefers-reduced-motion` で止める（配る・めくるは即座に置く）

### 5.3 札の見た目

本物のトランプ（ポーカーサイズ 63 × 88 mm）に寄せる。札はすべて SVG で描き、書体に頼らない。

- **形**: 縦横比 63:88、角丸。象牙の地に細い縁（既存の `.card` と同じ材質のトークン）
- **角の文字**: 左上に数字とスート、右下に同じものを 180° 回して置く
- **マークの並び**: A〜10 は実物と同じ配置（下半分のマークは 180° 回す）。スペードの A は大きな飾りのマーク
- **絵札**: J・Q・K は古典的な上下対称の絵（王は冠、女王は花、ジャックは羽根）。4 スートで色を変える
- **裏面**: 唐草風の格子の模様（既存の伏せ札 `--card-back` と同じ地）
- **色**: 黒のスートは `--coal`、赤のスートは `--suit-red`（象牙の地の暗い端 `--card-shade` の上で 5.0:1）。絵札の衣・顔・髪は `--court-blue` / `--court-skin` / `--court-hair`（`packages/ui/src/tokens/palette.css` に足した）
- **読み上げ**: 札ごとに「ハートのA」の形の名前、伏せた札は「ふせたカード」（「裏」は書体の base 層から外れる）。チェンジで選ぶ札は `aria-pressed`

### 5.4 書体

スートと絵札を SVG で描くので、札は書体に頼らない。文言（役の名前・ボタン・案内）は書体の base 層に収まる字で書き、
検査（`*-fits-font-base.test.ts`）で確かめる。

### 5.5 普段の利用者の負担

テーブル・札の SVG・文言は `React.lazy` で別の塊へ分け、ゲームが始まった（`room-state.table` が届いた）ときにだけ読み込む。
入口の判定はサーバーにあるので、初回の読み込みに増えるのは `table` のスキーマだけである。

実測（`vite build`・2026-10-28）: 初回の JS は 274.78 kB → 274.93 kB（gzip 85.99 → 86.05 kB）、初回の CSS は 57.78 kB → 57.86 kB（札の色のトークン 4 つ）。
テーブル・札の SVG・文言・見た目は別の塊（JS 13.81 kB・CSS 5.98 kB）で、ゲームが始まるまで取りに行かない（実ブラウザで 1 回目の ☕ の開票のあとも要求が 0 件であることを確かめた）。

## 6. 状態とプロトコル

### 6.1 状態

ゲームと入口の構えは見積もりの集約ルート `Round` に持つ。保管（`RoundStore`）・配信・破棄の経路は見積もりと同じ 1 本を通す
（ルームが消えればゲームも消える）。

```ts
interface Round {
  // …既存のフィールド…
  /** 入口の構え（全員 ☕ の開票が 1 回あった）。E-1〜E-3 */
  coffeeArmed: boolean;
  /** ゲーム。無ければ見積もりだけ */
  game: CardGame | null;
}

interface CardGame {
  status: 'exchanging' | 'shown';
  players: readonly string[];                      // 席順
  hands: ReadonlyMap<string, readonly PlayingCard[]>;
  exchanged: ReadonlySet<string>;
  deck: readonly PlayingCard[];                    // 残りの山（wire には出さない）
  discards: readonly PlayingCard[];                // 捨て札（wire には出さない）
}
```

乱数は配る・切り直すドメインの関数へ注入する（憲法 原則 VI）。本番は timer のシャッフル・ルーレットと同じ `RandomSource`（`node:crypto`）。

### 6.2 C→S（すべて `v.strictObject`）

| type | 形 | エラー |
|---|---|---|
| `table-exchange` | `{ "discard": [0, 3] }`（手の位置 0〜4・重複なし・0〜5 個） | `table-not-player` / `table-exchanged` / `table-no-game` |
| `table-deal` | `{}`（開いたあとのもう一回） | `table-no-game` / `table-in-play` |
| `table-close` | `{}`（見積もりに戻る） | `table-no-game` |

**札も順列も受け取らない**。配るのも引くのもサーバーである。

### 6.3 S→C（`room-state.table`）

**ゲームが無いときは載せない**（普段の wire は 1 バイトも変わらない）。受信側は `v.optional`。

```json
{
  "status": "exchanging",
  "players": [
    { "participantId": "p1", "exchanged": true },
    { "participantId": "p2", "exchanged": false }
  ],
  "yourHand": [{ "suit": "S", "rank": 14 }],
  "hands": []
}
```

- `yourHand`: 受信者がプレイヤーのときだけ値（5 枚）。それ以外は `null`
- `hands`: `shown` のときだけ中身がある。`{ participantId, cards, category }`。勝ち負けは載せない
- 札: `suit` は `S` `H` `D` `C`、`rank` は 2〜14（11=J 12=Q 13=K 14=A）。`category` は `high-card` 〜 `royal-flush` の 10 分類
- 山と捨て札は載せない

## 7. データ分類（憲法 原則 XI）

手と「チェンジ済み」は**ゲームの状態**で、個人を識別しない。ただし参加者に結びつくので、見学と同じく
**個人に紐づく**の段に置く（揮発のみ・ログへ出さない・配信はする）。ハンドラはゲームの状態も参加者 ID もログへ書かない。

## 8. 試験

- ドメイン: 役の判定（10 分類・A を 1 として使うストレート）、入口の構えと解除（E-1〜E-5）、配る・チェンジ・山の切り直し・開く・抜ける（G-1〜G-11）、秘匿の投影（G-3・G-12）
- 境界: 3 コマンドの受理と拒否（位置の範囲・重複・余分なキー）、`table` の省略と受理
- サーバー（実プロトコル）: ☕ → 開く → 再投票 → ☕ で始まる／手が本人にしか届かない／全員チェンジで開く／見積もりに戻る
- 画面: テーブルの出し分け、チェンジの選択、開いたあとの帯、札の SVG（各ランクのマークの数・絵札・角の文字・読み上げ）、文言の書体
- E2E: 2 人のブラウザで入口 → チェンジ → 開く → 見積もりに戻る。1 人のルームで入口

## 10. 改訂の記録

**2026-10-28 初版 → 改訂（利用者の確認）**。初版は設計者の推奨で次のように決めていた。利用者の指示で改めた。

| 項目 | 初版 | 改訂 | 理由（利用者） |
|---|---|---|---|
| 入口 | コナミコマンド（キーボード）と見出しの 5 回押し（タッチ） | 全員 ☕ を 2 回（間に再投票） | 端末でやり方が変わるのは面白くない。1 人でも複数人でも同じ動きにする |
| チェンジ | なし | 1 回 | 役を出せればよいが、チェンジは 1 回入れる |
| 勝ち負け | 「いちばん強い手」の印 | 付けない | 役を出すだけでよい |
| 席 | 入口を開いた人だけが席に着く | 入口を踏んだ投票者の全員 | 入口がルーム全員の操作になったため |
| 見た目 | 文字（`A♠`）の札 | SVG で本物のトランプ（形・マークの並び・絵札・裏面）、配る・めくる動き | 見た目と形にこだわる |
