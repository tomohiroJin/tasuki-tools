## スクリプトの決まり

- node 標準ライブラリだけ（`node:fs`・`node:path`・`node:child_process` ほか）。依存を足さない
- 第 1 引数にリポジトリのルート（相対でよい）。結果は標準出力へ JSON。**出力は整列し、同じ入力で同じ出力**になること
- **走査の母集合は `git ls-files`**（`execFileSync("git", ["ls-files", "-z"], { cwd: root })`）。`readdirSync` で歩かない。この環境の FS は大文字小文字を区別しない
- 対象の拡張子は `.ts` `.tsx` `.mjs`。テストは `*.test.*` `*.spec.*` と `tests/` `test/` `e2e/` 配下で、ソースと分けて数える
- 単語で引くときは単語境界（`\b`）を使い、当たった行の種類（import・識別子・文言・設定の値）を列に持つ
- 手で数えない。目で見つけた項目は「目で」と印をつける

## 報告の原稿（report-*.md）の決まり

- 一覧の各項目は 5 欄: **場所・観点・何が問題か・直すと何がよくなるか（4 つの目標のどれに効くか）・直す量（触るファイル数）**
  - 4 つの目標: **読みやすい**（構造とテストが読める）・**足すのが速い**（新しい道具・やり方・デッキを足すとき触る場所が少ない）・**続けられる**・**バグが減る**
- 各表の上に、流したコマンド・所要（秒）・実測時点（`git rev-parse --short HEAD`）を書く
- 測れなかったものは理由つきで最後に書く
- 一般の原則とこのリポジトリの決まりが食い違う箇所は「決まりを変える候補」として別の見出しに書き、直す候補には入れない
