## 1. 何のために直すか

v4.1.0 から 30 コミット分の機能（#93 見積もりの記録・#402 timer の休憩・#401/#420 ルーレット・#419 見学者ほか）が、まだ配布されていない。総合試験で、自動の検査はすべて緑だった。一方、実画面では欠陥が 2 件見つかった。さらに、利用者が別セッションで機能を触ってフィードバックを 5 件出した。**配布の前にまとめて直し、1 回の配布で出す**ことがこの Issue の目的である。

## 2. 目標・目標にしないもの・失敗とみなすもの

**目標**
- 総合試験で見つかった欠陥（§3 の A・B）を直す
- 利用者のフィードバック（§4 の C〜F）を入れる
- #419 の残り（§5 の G・H）を片付ける

**目標にしないもの**
- 新しい機能の追加。フィードバックの範囲を超えて広げない
- ルーレットの別の公平性の仕組み（重み付けなど）。利用者は「同じ人が何度も当たることがあるのがルーレット」と言っている

**失敗とみなすもの（動いていても失敗）**
- 記録を切っている poker の画面に、記録・アイテム名・ポイントの欄が少しでも残る
- ルーレットの「1 回で決める」で、同じ人が続けて当たらない（引き方に偏りが残っている）
- 円盤の色が、当たり以外の何かの状態を表してしまう
- 外された人のタブが、どのツールでも操作できる画面のまま残る

## 3. 総合試験で見つかった欠陥

### A. 外された人のタブが、timer 以外ではルームに残る

**いまの振る舞い**: timer で B を外すと、サーバーは B の**全接続**へ `REMOVED_FROM_ROOM` / `LEFT_ROOM` を送る（`command-handlers/participant-remove.ts` の `notifyRemovedTarget`）。B の timer のタブは退出の画面へ移る。一方、poker のタブは手札が押せるまま残り、押すと「ルームに参加していません」の帯だけが出る。ハブのタブは何も変わらない（2026-10-18 実画面で再現）。

**原因**: この符号を扱っているのは timer-web と、共通のフック（`packages/web-kit/src/sync/use-tool-room-sync.ts` → `@tasuki/sync-client` の `planForJoinError`）だけである。topic と roulette はこの共通のフックを使う。poker は独自の `useSync` を持ち、未知の符号を捨てている。ハブ（`apps/landing/src/hub/use-hub-sync.ts`）も扱っていない。

**直したあと**: 外された人・自分で抜けた人のタブは、**どのツールでも**退出したことが分かる画面へ移る。そこから操作できる画面に戻らない。行き先と文言は、timer と共通のフックがすでに決めている振る舞いにそろえる（「〈名前〉さんにより退出させられました」の告知を持って、ハブの作成・参加の画面へ。#290 の `?left=`）。topic と roulette が本当にそうなるかは、実装の前に実画面で確かめる。

### B. 320px で長い名前の休憩のバナーが、覆いの見出しと時計に重なる

**いまの振る舞い**: 表示名が 39 字のとき、「〈名前〉さんが休憩を始めました。」のバナーが 320px で 3 行（高さ 95px）に折り返す。覆いの見出し「休憩中」と時計の `00:00` がバナーの下に隠れる（`elementFromPoint` は `app-banner` を返す）。#402 の申し送りどおりの欠陥である。

**直したあと**: 表示名の長さ（上限 40 字）に依らず、覆いの見出し・時計・「休憩を終える」が、上端の帯にもバナーにも隠れない。直し方（覆いをバナーの下から始める、バナーの名前を切り詰める、など）は実装役に任せる。ただし、**名前を切り詰めるなら誰の休憩かが分かる長さを残す**こと。

E2E `timer-break.spec.ts` の 320px のテストに、40 字の名前の場合を足す。

## 4. 利用者のフィードバック

### C. 見積もりの記録の欄の見た目（64rem 以上の脇）

**いまの振る舞い**（1280×800 で実測）:
- 記録の欄だけ、スクロールバーが札の内側の余白（左右 24px）の中に出る（`.estimate-log-body` の `overflow-y: auto`）。そのため記録の中身はお題の札より左へ寄って見え、ポイントのプルダウンとスクロールバーの隙間は約 7px しかない
- 同じ画面で、お題の札の高さが足りず、本文が記録の札の裏へはみ出して切れていた（`section.topic` の `scrollHeight 145 > clientHeight 114`・`overflow: visible`）

**直したあと**:
- お題の札と記録の札は、**左右の余白・中身の幅・端の位置がそろって見える**
- 記録のスクロールバーは札の右端に寄り、中身（プルダウンを含む）とくっつかない
- お題の本文が、記録の札の裏へはみ出さない。お題が長いときは札の中でスクロールするか、札が伸びて記録が下へ詰まる。どちらにするかは実装役に任せる。ただし #93 §5.1 の「札が開いているときも記録の見出しが見える高さを残す」は守る

### D. 記録を切り替えられるようにする（既定は切る）

利用者の言葉: 「常に見積もり記録出したくないので切り替えれるようにしてほしい。デフォルト見積もり記録なしで名前とかも入れない感じにしたい」。切り替えは**ルームの全員に効く**（利用者・2026-10-18）。

**振る舞い**
- ラウンドの状態に「記録する／しない」を持つ。**新しいルームは「しない」で始まる**
- 在室者なら誰でも切り替えられる（ホストは無い。アイテム名・ポイントと同じ）。切り替えはルームの全員の画面に配られる
- **記録しない間**:
  - 画面に出さないもの: 記録の欄（脇・下の足・シート）、「いま見積もっているもの」の欄、「次のアイテムへ」の横のポイントの欄
  - 開票しても記録に行を足さない
  - 開票後の操作は「再投票」と「次のアイテムへ」のまま残す（ポイントの欄だけ出さない）
  - 64rem 以上の配置は #93 より前の規則に戻る。脇はお題の札だけを持ち、お題が無い・隠すときは操作の面を中央に寄せる（#348 D7〜D9）
- **記録する間**: いまの #93 の振る舞いのまま
- 切り替えても、それまでの記録・アイテム名・束は消さない。「しない」から「する」へ戻すと、残っていた記録がまた見える
- **切り替えると、見積もり中の束（open）をポイントなしで閉じる（どちらの向きでも）。** 閉じないと、切り替えをまたいで別のアイテムの行が同じ束に混ざり、束の見出しも化ける（`recordReveal` は末尾の open の束へ行を足す）
- **ポイントの欄は、見積もり中の束があるときだけ出す。** 開票した後に「する」へ戻したとき、その開票は行になっていないので束が無い。欄を出すと、選んだ値が黙って捨てられる（`closeOpenGroup` は open の束が無ければ何もしない）
- 「しない」の間の「次のアイテムへ」は今と同じ `nextItem`（open の束があれば閉じ、アイテム名を空にする）。上の規則により、「しない」の間に open の束は無い
- **新しい画面が古いサーバーの snapshot を受けたら**（配布の途中で、記録の切り替えの欄が無い）、「する」と読む。古いサーバーは毎回記録するので、それが本当の状態である。wire のスキーマでは欄を省略可にして既定値を与える
- 切り替えの置き場所は poker の見出しの並び（「お題を隠す」の隣）を推す。押せるボタンで、いまの状態が分かる形（`aria-pressed` など）にする。文言は書体の base 層に収まるかを実測してから決める（「記録」はすでに画面にある字）

**作りの制約**
- 状態はサーバーのラウンド（poker-core の `Round`）に持ち、wire の snapshot で配る。切り替えは新しいクライアントの操作として足す（名前は実装役が決める）
- 古い画面（配布の途中で再読み込みしていないタブ）は、知らない欄を読み捨てる（valibot の `v.object`）。古い画面では記録の欄が出たままになるが、再読み込みで直るので受け入れる
- 記録を「しない」間の開票の行は、ドメインで足さない（画面で隠すだけにしない）。「記録なし」を選んだ人のルームに記録が溜まらないことが、利用者の言う「記録なし」である

### E. 記録のアイテム名を後から直せるようにする

利用者の言葉: 「見積もりの記録の名前も後から修正可能にしたいです」。

**振る舞い**
- **閉じた束**の見出しのアイテム名を、在室者なら誰でも書き換えられる。ポイントの後からの入れ直し（#93 §4.3）と同じ扱いである
  - 同時に 2 人が書き換えたら、後に届いたほうが勝つ
  - 束がもう記録に無いときは、画面の文言を伴うエラーで返す（ポイントの `estimate-not-found` と同じ）
  - 空にしてもよい。空なら「（名前なし）」と出す
- **見積もり中の束**の名前は、いままでどおり「いま見積もっているもの」の欄で直す（その束の最後の行に写る・#93 §4.1）。記録の欄の見出しからは直せない
- 書き換えると束の見出しが新しい名前になる。束の中の各行が持つ名前をどう直すか（全部の行を書き換えるか、束に名前を持たせるか）は実装役に任せる。ただし、**束の見出しが「その束の最後の開票時点のアイテム名」から決まる規則（#93 §4.4）と食い違わないように**、正本の文を一緒に直す
- 入力の検証（不可視文字の除去・前後の空白・上限 `MAX_ESTIMATE_ITEM`）は、いまのアイテム名と同じ関数を通す
- 確定は Enter・フォーカスが外れたときに 1 回送る（#93 §4.1 と同じ）。押すと編集になる形にして、うっかり書き換わるのを防ぐ

### F. ルーレットを「普通のルーレット」に戻し、色を整える

利用者の言葉: 「全員が1周するまで、同じ人は選ばれない機能は要らない……同じ人が何度も当たることあるのがルーレットなので、全員が一週するまでなら人が抜けていく順番に回すで十分です」「ルーレットの色が変な感じでついているのでカッコよくしてください（たぶん選ばれた人が無意味についている感じがします）」。

**事実の確認**: 「一周するまで同じ人を選ばない」規則は #401 で入ったものではない。#94 の最初のルーレット（ADR-0026 決定 4・spec R6）からある規則で、**v4.1.0 で本番にも出ている**。直すと本番の挙動が変わる。これは利用者の決定（2026-10-18）として扱う。

**振る舞い**
- **「1 回で決める」は毎回、入る人から一様に引く。** 直前の当たりも、これまでの当たりも除かない。同じ人が続けて当たってよい
- 選ぶ人数が 2〜4 人のときは、**1 回の回転の中では同じ人を 2 度選ばない**（円盤の上で 1 席が 2 回当たることは表せないため）。これは設計者の判断である
- 「順番に回す」（`order`）と「止めて決める」（`press`）は変えない。もともと一周の記録を使っていない
- 外すもの:
  - 一周の記録（`RouletteState.drawn`）と、それを使う引き方（`draw.ts` の周の処理）
  - `resetCycle` と、クライアントの操作 `roulette.cycle.reset`
  - 画面の「この一周で選ばれた人 n / m」「一周をやり直す」、一覧の「選ばれた」の印、円盤の「沈んだ席」（`.wheel-segment--drawn`・`.wheel-label--drawn`）
- **古い画面との互換**: wire の `drawn` は配布の後も**空の配列のまま送る**。古い画面の受け取り側のスキーマが欄を必須にしているなら、外すと読めなくなるため。`roulette.cycle.reset` は受けて何もしない。どちらも、外してよいかを実装役が古い画面のスキーマで確かめる。外せるなら外す（#93 の `next-round` を残したのと同じ考え方）

**色**
- 円盤の席の色は、**止まった席（当たり）かどうかだけ**を表す。当たりは今の真鍮（`--gold`）の地に炭の字のまま
- 当たり以外の席は、円盤全体がひとつのまとまりに見える落ち着いた濃淡にする。いまの `--felt-700` と `--felt-900` の交互は明度の差が大きく、まだらに見える。さらに「沈んだ席」の `--felt-950` が混ざって、3〜4 段の色が意味なく並んでいた
- 具体の色の組み（近い 2 段の交互にする、仕切りの線で分ける、など）は実装役に任せる。守ること:
  - 字は全部の席で AA（`timer-a11y` 系の検査と同じ基準。`scripts/` のコントラストの走査が通ること）
  - 生の色を書かない（デザインのトークンを使う → `audit-ui-components`）
  - 奇数の席のとき、最初と最後の席が同じ色で隣り合わない
- **仕上げで利用者に実画面を見てもらう**。テストは釣り合いを見ていない。複数の案を撮って並べて見せてよい

**直す正本**: ADR-0026 の決定 4 は、この Issue で「撤回」と書き足す（消さない。いつ・なぜ変えたかを残す）。#94・#401 の spec の該当箇所には、ADR を指す注記だけを足す。

## 6. 作りの制約（全体）

- 画面の新しい文言は、書体の base 層に収まるかを実測してから決める
- 変異検査: 新しい振る舞い（D の「記録しないときは行を足さない」、E の名前の書き換え、F の一様な引き方）には変異を足す。F で消える変異（一周の規則を守っていたもの）は宣言の表から外す。宣言の表を触るので `--changed` は全件に倒れる。手元では `--id` で足した分だけ確かめ、全件は CI に任せる
- E2E: `poker-estimate-log.spec.ts` は「記録する」に切り替えてから始めるよう直す。D の既定（切っている）と切り替えを確かめる E2E を足す。ルーレットの E2E のうち一周の印を読むものは直す
- 1 つの PR にまとめる（利用者の指示: 同じ Issue で直す）。コミットは項目ごとに分ける

## 8. 統括の判断（利用者に確認していないもの）

| # | 判断 | 理由 |

| J1 | ルーレットで 2〜4 人を選ぶとき、1 回の回転の中では同じ人を重ねない | 円盤の 1 席が 2 回当たることを表せない |
