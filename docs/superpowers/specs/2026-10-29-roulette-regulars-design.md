## 1. いまの姿（コードで確かめたもの）

### 1.1 名前を足す

- 画面は 1 件ずつ（`apps/roulette-web/src/components/GuestForm.tsx` → `roulette.guest.add`）。まとめて入れる手段は無い
- 同期サーバー（`apps/tasuki-sync/src/application/roulette-handlers.ts`）は名前に表示名の規約（`applyDisplayNameRule`）を当て、通らなければ `INVALID_GUEST_NAME`。通れば中核の `addGuest` へ
- 中核（`packages/roulette-core/src/roulette.ts` の `addGuest`）は `guests.length >= MAX_GUESTS` で `TOO_MANY_GUESTS`、**名簿の全参加者（在室を問わない）と既存のゲスト**に同じ名前があれば `GUEST_NAME_TAKEN`。同じ名前かは `room-core` の `conflictsWithExisting` を引数で受けて決める（ADR 0026 決定 8）

### 1.2 同じ名前の 2 段

| 時点 | 規則 | 画面 |
|---|---|---|
| 足すとき | 名簿（在室を問わない）・既存のゲストと同じ名前は拒む（`GUEST_NAME_TAKEN`） | エラー文「この名前はすでにいます」 |
| 回すとき（`poolOf`） | **在室者と同じ名前のゲストは入る人から外す**（在室者が勝つ）。状態からは消さない | 行に「同じ名前の人がいます」（`TWIN_MARK`）・チェック不可 |

### 1.3 上限

| 定数 | 値 | 効く所 |
|---|---|---|
| `MAX_GUESTS` | 12 | `addGuest`・エラー文 `TOO_MANY_GUESTS`（定数から組む）・ADR 0011 S7 の文 |
| `MAX_WHEEL` | 24 | 3 つの決め方の回す処理（`ROULETTE_TOO_MANY`）・エラー文 |

**画面は 24 人を超えたことを先に言わない。** 回すボタンは押せて、押すとサーバーの `ROULETTE_TOO_MANY` が返る。ゲストが 12 人のうちは参加者が 13 人以上いないと起きないので目立たなかった。

### 1.4 端末への保存の前例

agenda の `apps/agenda-web/src/storage/saved-scenarios.ts`（#429）。版つきの 1 キー・読み込みは投げない・合わない項目は生のまま残して一覧に出さない・読めない保存は上書きしない・書けなければ `write-failed`。表示名（`tasuki:display-name`）も端末に持つ。**どちらもサーバーには残さない**。

## 3. 振る舞い（EARS）

- **E1** 利用者が組を選んで「入れる」を押したとき、システムは、その組の名前のうち**ルームにまだいない名前**をすべて、1 つのコマンドでゲストとして足す
- **E2** 組の名前が名簿の参加者（在室を問わない）か既存のゲストと同じ名前のとき、システムはその名前を**拒まずに飛ばし**、残りを足す
- **E3** 入れたとき、システムは足した人数・同じ名前で飛ばした人数・上限で入らなかった人数を知らせる（§6）。知らせは画面が §4.1 の同じ関数で出す（ルーレットの通信には返事が無い）
- **E3b** 入れた結果、入る人が `MAX_WHEEL` を超えたとき、システムは知らせの末尾で「チェックを外す」ことを促す
- **E4** 足すと `MAX_GUESTS`（24）を超えるとき、システムは**入る分だけ前から足し**、残りを足さない。画面は入らなかった人数を知らせる（1 人も入らなくてもエラーフレームは返さない）
- **E5** 組の名前のうち 1 つでも表示名の規約に通らないとき、システムは 1 人も足さずに `INVALID_GUEST_NAME` を返す
- **E6** 入る人が `MAX_WHEEL`（24）を超えているとき、システムは回すボタンを押せなくし、一言で「24 人までで回せる・チェックを外して減らす」ことを示す（3 つの決め方すべて）
- **E7** 利用者はいま輪にいるゲストの名前から、名前をつけて組を作れる。同じ組名は上書きする
- **E8** 利用者は組の名前を変え、組の中の名前を足し・消し、組を消せる
- **E9** 保存が読めない（壊れた JSON・知らない版）とき、システムは組を 0 件として画面を出し、**保存を上書きしない**（組を作る・直す操作は失敗を知らせる）
- **E10** 端末が保存を許さない（容量超過・保存禁止）とき、システムは失敗を知らせ、画面の操作は続けられる
- **E11** 組はサーバーへ送らない。送るのは「入れる」を押したときの名前だけ（今の 1 件ずつの追加と同じ扱い）

## 4. 中核・wire・同期サーバー

### 4.1 中核 `addGuests`（`packages/roulette-core/src/roulette.ts`）

```ts
export interface GuestBatch {
  /** 足した後の状態。足す名前が 0 件なら渡した状態と同じ参照 */
  state: RouletteState;
  /** 足した名前（並びは渡した順） */
  added: string[];
  /** 同じ名前がいたので飛ばした名前（並びは渡した順） */
  skipped: string[];
  /** 上限（MAX_GUESTS）で入らなかった名前（並びは渡した順） */
  overflow: string[];
}
export function addGuests(
  state: RouletteState,
  names: readonly string[],
  members: readonly Member[],
  conflicts: NameConflict,
): GuestBatch;
```

- 名前は**正規化済みで受ける**（`addGuest` と同じ線引き）
- 前から順に、名簿の全参加者＋既存のゲスト＋**この束で先に足すと決めた名前**と比べ、同じ名前なら `skipped` へ。束の中の重複も同じ判定で飛ぶ
- 同じ名前でない名前は、ゲストが `MAX_GUESTS` に達するまで `added` へ、達した後は `overflow` へ（同じ名前の判定が先。上限に達した後でも、同じ名前なら `skipped`）
- **失敗を返さない**（全域関数）。1 人も足せなくても状態は同じ参照で返る
- ID は `addGuest` と同じ採番（`g-${nextGuestSeq}` を順に）
- **`addGuest` は残す**（1 件ずつの欄はそのまま）。判定の写しを持たないよう、`addGuest` の同名判定と `addGuests` の 1 件ぶんの判定は同じ内部関数を通す
- **画面も同じ関数で押す前の見込みを出す**（`poolOf` と同じく「サーバーと web が同じ関数」）

### 4.2 同じ名前（D6）の決め方

足すときの比べる相手は**今の `addGuest` と同じ**（名簿の全参加者・既存のゲスト）。違いは**拒まずに飛ばす**ことだけ。

- 理由: 1 件ずつの欄では、打った本人に「その名前はすでにいる」と返すのが正しい（打ち間違いかもしれない）。束では、ファシリテーター自身が組に入っている・誰かがすでにルームに入っている、が**普通の状況**で、1 人の重複で束全体を拒むと「いつものメンツ」が使えない
- 足した**後**に同じ名前の人が参加したときは、今のまま `poolOf` が在室者を勝たせ、行に「同じ名前の人がいます」を出す。ゲストは消さない（その人が抜ければまた入る）
- 在室していない名簿の参加者（離席・切断）と同じ名前も飛ばす（`addGuest` と同じ。その人の行は名簿にあり、戻れば入る）

### 4.3 wire

- コマンド `{ command: "roulette.guest.addMany", names: string[] }`（`v.strictObject`）。`names` は 1〜`MAX_GUESTS` 件（境界で縛る。巨大な配列を名前の規約の前に落とす）。各名前の長さは境界で縛らない（`roulette.guest.add` と同じ線引き）
- 新しいエラーコードは足さない（`INVALID_GUEST_NAME` だけを使う。上限は §4.1 のとおり入る分だけ足すので `TOO_MANY_GUESTS` は返さない）
- 配るフレームは変わらない（`guests` が増えるだけ）
- **配布の順**: 同期サーバーが先（`deploy.sh timer`）、roulette-web が後。逆だと古いサーバーが新しいコマンドを `INVALID_COMMAND` で拒む

### 4.4 同期サーバー（`roulette-handlers.ts`）

`roulette.guest.addMany` の分岐: 各名前に `applyDisplayNameRule`。1 つでも通らなければ `INVALID_GUEST_NAME`。通れば正規化した名前の列で `addGuests` し、`commit`（足す名前が 0 件なら同じ参照なので配らない）。ログは書かない（ADR 0011 のデータ分類）。

### 4.5 上限（D2）

- `MAX_GUESTS` を 12 → **24**。エラー文は定数から組むので自動で変わる
- **`MAX_WHEEL` を公開する**（`index.ts`。#365 で「要るようになったら載せる」としていた）。画面の E6 と、組の名前の数の上限に使う。`MAX_GUESTS` も組の上限と見込みに使うので公開する
- ADR 0011 S7 の「12 件まで」を直す（§7）。状態の大きさは名簿＋ゲストで頭打ちのまま（24 件・1 件 40 字）。1 コマンドで足せるのも最大 24 件で、メッセージの上限（64KB）に遠い

## 5. 端末の保存（`apps/roulette-web/src/storage/regulars.ts`）

agenda の `saved-scenarios.ts` の形に倣う（読み込みは投げない・版つき・合わない項目は生のまま残す・読めない保存は上書きしない）。

- キー `tasuki.roulette.regulars`・版 `1`。中身 `{ version: 1, items: [{ id, name, usedAt, members: string[] }] }`（`id` は作ったときの `crypto.randomUUID()`。直す・消すは `id` で指す。名前を変えても同じ組）
- 組名: 前後の空白を除き、1〜`MAX_DISPLAY_NAME`（40）字・制御文字なし。**作る欄で同じ組名があれば `name-taken` で止める**（画面「同じ名前のメンツがもうあります」。直す欄で自分の名前のままなら上書き）
- 名前: 1〜`MAX_GUESTS` 件。各名前は `normalizeDisplayName` を通した形で持ち、空・`MAX_DISPLAY_NAME` 超え・`rendersAsNothing` は合わない項目として扱う。組の中の同じ名前（`conflictsWithExisting` の判定）は保存のときに 1 つに畳む
- 名前が 1 人も無い・`MAX_GUESTS` を超える組は `invalid`（画面は理由ごとの文）
- 組の数: `MAX_GROUPS`（10）まで。11 組目は `full`（直すのは数えない）
- 並び: 最後に使った（入れた・保存した）組を先頭に（`usedAt` を「入れた」ときにも更新する）
- 公開する関数: `loadGroups`・`saveGroup`（`id` が無ければ作る・あれば直す）・`deleteGroup`・`touchGroup`。結果は `{ ok: true; items } | { ok: false; reason: 'invalid' | 'unreadable' | 'write-failed' | 'full' | 'name-taken' }`
- 複数行欄の文字列を名前の列にする `parseMemberLines`（空行を捨て・前後の空白を落とし・`normalizeDisplayName`・組の中の同じ名前を 1 つに畳む）も同じファイルに置く
- `localStorage` の取得そのものが投げる環境（保存禁止）も、読み込みは 0 件・書き込みは `write-failed`

## 6. 画面（デザインの相談役の案から選ぶ）

相談役の提案の全文は [`2026-10-29-roulette-regulars-screen.md`](2026-10-29-roulette-regulars-screen.md)。**置き場所・構成・流れ・文言・CSS・a11y は提案のとおりとする**。変えた点だけを書く。

- **知らせの出どころ**: 提案は「サーバーの返事の件数」を前提にしたが、ルーレットの通信に返事は無い。画面は押した時点の状態（受け取ったルーレットの状態と名簿）で `addGuests` を呼び、その `added`・`skipped`・`overflow` から知らせを組む。サーバーも同じ関数で決めるので、間に誰かが名前を足していなければ一致する（ずれは知らせの数だけで、状態はサーバーが正）
- **入る人が 24 を超えたとき**（E6）: 提案の知らせに加え、回すボタンを押せなくし、舞台の一言を `回せるのは ${MAX_WHEEL} 人までなので、チェックを外してください`（提案の知らせの後半と同じ文）にする。3 つの決め方すべて（`captionOf`・`orderCaptionOf`・押して止めるの一言）
- **入れる札を押したら組の `usedAt` を更新する**（並びが変わる）。フォーカスは札に残す（`id` で追う）
- E2E: `e2e/specs/buttons.spec.ts` に**独立した test** を 1 本足し、0 組・2 組・欄を開いた状態の 3 場面を測る（既存の test に相乗りしない。並行する #406 も同じファイルを触る）
- 部品・文言は `copy.ts` と `index.css`（提案 §3・§4）。数は定数から組む

## 9. 統括が決めた細部

- **R1 上限で入らない人は入るだけ入れる**（全部拒まない）: 提案の知らせ（「6 人を入れました。…3 人は入りませんでした」）に合わせた。全部拒むと、1 人分の空きが無いだけで組が使えない
- **R2 知らせは画面が同じ関数で出す**: 返事（ack）を足すと wire に新しい種類のフレームが要り、古い画面の互換を考える量が増える。`poolOf` と同じ「サーバーと画面が同じ関数」の形で足りる
- **R3 組は `id` で指す**: 名前を変えたときに、別の組を上書きしたり、消したと見なしたりしない
- **R4 組の名前の上限は 40 字**（`MAX_DISPLAY_NAME`）: 提案のとおり。行は省略記号で切る
- **R5 束の大きさは境界で 1〜24 件**: 名前の規約（NFKC）を当てる前に、巨大な配列を落とす
