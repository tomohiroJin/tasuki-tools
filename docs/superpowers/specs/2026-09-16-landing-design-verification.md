## 見直し（2026-09-17・敵対的レビューを受けて）

PR #278 を独立した5観点でレビューし、7件の指摘を確信度で採点した。
閾値（80）に達した指摘は無かったが、4件が 75 で、うち2件は実測で裏が取れたため直した。
**上の「変更」のうち2項目は、この見直しで覆っている。**

### 覆した判断

- **札とワードマークの地をグラデーションへ戻した。** 単色化は設計正本 §5.7 の
  「手札の意匠は変えない」に反していた。単色にした理由は「実際の背景色で計測できる
  ようにする」ことだったが、**その前提が誤っていた** —— `background: linear-gradient(…)`
  は `background-color` を透明にするため、`sampleInPage` は札の層を飛ばして祖先まで遡り、
  札の上の文字を羅紗と比べて測っていた。単色化しても「測れるようになる」のではなく
  「別のものを測る」だけだった。共有ヘルパ側の穴は #279 として起票した。
  測り方は spec 側で閉じた（下記）。
- **狭い画面の札を縦積みにした。** 横に2枚並べると 320px で札が 131px しか取れず、
  文字の入る幅 115px に対し一行説明は 133px 必要で、最後の1文字だけが次行へ落ちていた。
  横並びのまま収めるには 10.5px まで縮める必要があり、配色トークンが前提にしている
  「12px の本文で AA」を割る。縦積みなら札が 218px 取れて、道具名も説明も1行に収まり、
  高さ 900px で2枚とも画面内に残る。

### 直したその他の指摘

- コントラストの下限を `requiredRatio()` に揃えた（大きい文字は 3:1）。
  Issue #270 の完了条件が指定する「`timer-a11y.spec.ts` と同じ測り方」に一致させた。
- 参加用 URL の入力を等幅にした（`--font-mono` の定義コメントが名指しする用途）。値は変えていない。
- `font-size` の直値17箇所を5段のスケールへ寄せ、見出しに `--line-tight` を入れた。
  残す直値はワードマーク専用の2つだけである。
- `.hub-invite-status` の高さ確保を戻した。**#269 が置いた `min-height: 1.5em` では
  足りていなかった** —— 本文の行間が 1.7 なので、実測で 2.72px 動いていた。
  `calc(1em * var(--line-normal))` にして 0px になった。
- 右列（参加者・招待）は引き伸ばさず、パネルの間を詰めた。参加者が1人のときに
  中身の無いパネルを作るほうが悪いと判断した。
- 撤去されていた「押せないボタンを押せると見せない」の警告コメントを書き戻した。
- CSS の節見出しを画面名から役割へ変えた。`.hub-*` は4画面で共有しているため、
  画面名で切ると使用箇所と食い違う。

### 見直しで却下した指摘

- **「見出しと罫が札とそろっていない」は誤りだった。** 実測すると罫は列幅いっぱい
  （x=104→728）に伸びており、文字もその中央に置かれていた。画像からの見当違いである。
- **下端の空白は詰めない。** 上 32px に対し下 126px で上寄りだが、中央寄せにすると
  QR を開いたときに画面全体が 40px 飛ぶ（実測）。参加者が増えたときも同じで、
  `justify-content: flex-start` は意図的に正しい。空白はレイアウトが動かないことの対価である。

### 測り方の変更

グラデーションで塗られた面と字を、spec 側で扱えるようにした。

- 下地が色で取れない要素を数え上げ、許可リスト（札の面のみ）と突き合わせる。
  新しくグラデーションの地が増えたら赤くなる。札が出ている画面では、
  地が本当にグラデーションであることも対照として見る。
- 札の面の文字は、地の**一番暗い停止点**を下地にして測る。
- 字そのものをグラデーションで塗る要素（`background-clip: text`）は、
  **停止点すべて**で下限を満たすことを見る。`color` が透明なので、
  そのまま測ると比が 1.0 になって落ちる理由が嘘になる。
- 札の文字は行箱の数で1行に収まっていることを見る。**札は 4° 傾けて配ってあるため
  `getBoundingClientRect()` は回転後の外接矩形を返し、1行でも2行と数えた。**
  `Range` の矩形は1行につき1つなので傾きに影響されない。

### 検証

- 標準の `pnpm e2e` が**通った**（54件）。上の「検証環境の制約」は解消している
  —— 8787 を使っていたのは利用者の `pnpm dev` で、停止後は preflight を通過した。
- `pnpm typecheck` / `pnpm lint` / `pnpm test` も緑。
- 追加した検査はそれぞれ壊して赤を確認し、対照実行が緑であることも見た。
  札の地を単色に戻す変異は2件を落とし（許可リストの対照が発火）、
  ワードマークの停止点を羅紗の色にする変異は停止点を名指しして 1.64 < 3 で落ちた。
  一行説明の1文字残りは、物差しを直した後に 1280 が緑・320 が赤で切り分けた。
- いずれも原状復帰した。本番デプロイは行っていない。

## 追記（2026-09-19・#279）

**上の「測り方の変更」に書いた spec 側の回避は、もう無い。**
グラデーションの取りこぼしは共有ヘルパ（`e2e/support/contrast.ts`）で塞いだので、
許可リストとの突合（`checkGround`）も札の面を測り直す仕掛け（`checkCardFace`）も
畳んである。いまは下地も字も「候補の集合」として扱い、最も不利な組み合わせで測る。
取りこぼしは祖先へ黙って抜ける代わりに「測れない」として赤くなる。
経緯と実測は #279 を参照。
