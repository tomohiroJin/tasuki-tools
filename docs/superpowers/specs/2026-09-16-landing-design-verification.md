# #270 玄関の意匠 — 再現と検証

対象: [Issue #270](https://github.com/tomohiroJin/tasuki-tools/issues/270)。
変更前の基点は `c3c784f`（#269 のコピー・QR が入った状態）。

## 読み込んだ前提

憲法、DoD、開発ガイド、アーキテクチャガイド、ADR 0015・0019 と、
玄関の3画面・共有 UI トークン・既存の玄関／招待共有／a11y テストを確認した。
共有ルームで名乗り、道具を行き来する操作と、同期フックの責務は維持する。
新しい技術・依存・共有設定は追加しない。

## 再現

1. 玄関 `/` を開き、ルーム名「朝会」、名前「あや」で作成する。
2. 別のブラウザー文脈で参加用 URL を開き、「いずみ」で参加する。
3. 2人目が Planning Poker を開き、選択画面の在席表示を確認する。
4. 幅 1280px と 320px、高さ 900px で作成・参加・選択を撮影する。

変更前は参加者と招待操作の後に道具が並び、1280px 幅でも道具の下部まで
スクロールが必要だった。招待の金色ボタンが道具選択より先に目に入った。
また、既存の「に居ます」の「居」が base 層の範囲外で、在席表示時に
`zkgn-400-ext.woff2` を取得していた。

## 変更

- 作成・参加はフォームをひとつの面にまとめ、送信を主操作として示す。
- 選択は上部にルーム、主領域に道具、補助領域に参加者と招待を置く。
  狭い画面は同じ DOM 順で1列にし、道具の札は横に2枚並べる。
- コピー・QR は補助操作の配色にし、既存の機能と入力のアクセシブル名を保つ。
- 切断中を文字でも示す。在席文言は「にいます」にして ext の取得を防ぐ。
- 色・余白・角丸は共有トークンを参照する。文字コントラストを実際の背景色で
  計測できるよう、札とワードマークのグラデーションをトークンの単色に揃える。

## 検証と証跡

`e2e/specs/landing-design.spec.ts` は実サーバーで上記の経路を再現し、
3画面の画像を `testInfo.outputPath()` に保存する。
画像を検証環境に残す扱いは既存の E2E 証跡手順に合わせる。
今回の変更前後12枚と横並びの比較ページは、ローカルの
`e2e/test-results/issue-270/comparison.html` に保存した（Git 管理外）。

- 追加した領域テストが旧実装で失敗することを確認してから実装した。
- 幅 1280px / 320px で3画面を撮影・目視し、横にはみ出さないことを検査した。
- timer と同じ `e2e/support/contrast.ts` で文字の背景を合成し、4.5:1 以上を検査した。
  切断中表示も測定対象に含めた。
- `document.fonts.ready` と実際のフォントリクエストを使い、玄関3画面・在席表示・
  QR 表示まで ext の取得がないことを確認した。
- 玄関・招待共有・timer a11y の E2E 計17件が通過した。
- 文字色を背景と同じ色にする変異で追加 E2E の2件が失敗し、招待入力のラベルを
  壊す変異で既存テストを含む5件が失敗した。いずれも原状復帰した。
- 復元後の `pnpm test`（14タスク）、`pnpm lint`（14タスク）、
  `pnpm typecheck`（16タスク）、玄関のビルド、追加 E2E の2件が通過した。
- web 同期境界監査は違反0件。構造監査も実行し、SC031 の2件などの
  未達指標を含む出力を確認した（すべての指標が0という意味ではない）。

### 検証環境の制約

標準の `pnpm e2e` は、別の Python プロセスが 8787 を使用しており、
preflight で停止した。他のプロセスは止めず、検証専用の一時設定で
玄関を 15175、同期サーバーを 18787 に立てて同じ spec を実行した。
したがって今回の画面検証は実 Vite・実同期サーバー経由であり、標準の
Caddy・ビルド成果物経由の検証とは区別する。初回の timer 読み込みに1件の
タイムアウトがあり、再実行で17件すべてが通過した。

本番デプロイは行っていない。
