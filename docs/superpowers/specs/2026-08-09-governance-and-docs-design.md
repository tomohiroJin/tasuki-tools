## 背景と目的

Tasuki には判断の拠りどころが揃っていない。ADR は timer の 10 件と横断の 1 件
（`docs/adr/0001`、#78 で先行新設）に分かれ、規範文書 `.specify/memory/constitution.md` は
poker MVP の憲法のまま「既存の timer には手を入れない（MUST NOT）」という
現状と矛盾する条項を含む。docs/ は plans / specs / adr / experiments が混在し、
どれが現行の正本か読み取れない。リポジトリには AI エージェント向けの入口文書
（AGENTS.md / CLAUDE.md）が存在せず、規範を作っても AI が毎セッション読む導線が無い。

この設計は、次の二本柱を第一の目的として掲げるプロジェクトの土台を作る。

1. **実用ツール集** — チーム開発の現場で実際に使われる道具を提供し続ける
2. **AI 駆動開発の実践場** — AI エージェントと人間の協働でどこまで高品質な開発が
   できるかを実践・実証する。プロセスと規範自体が成果物

**この Issue は「決める」だけで、アプリケーションコードには触れない。** 適用は #72。

## 文書体系 — 三層構造

変更頻度で層を分ける。

| 層 | 役割 | 変更の重さ |
|---|---|---|
| **憲法**（`.specify/memory/constitution.md`） | 「何を守るか」の宣言。原則 10 本・各数行 | めったに変えない。改版は ADR を伴う |
| **ADR**（`docs/adr/` ほか） | 「なぜそう決めたか」の不変の記録 | 追記のみ。覆すときは Superseded |
| **ガイド**（`docs/guides/`） | 「今日どう書くか」の手引き | 育ち続ける。ADR 改版なしに更新してよい |

**書き分けの規則**（ADR 0002 に明記する）:

- 決定の中身と根拠 → ADR。手順・例・チェックリスト → ガイド。両方に跨るときは
  片方に書き、もう片方からは参照する（二重正本を作らない）
- ガイドの中身（DoD の項目等）は ADR 改版なしに育ててよい。**「DoD を運用する」という
  決定自体**を覆すときだけ ADR を書く

## 憲法 — Tasuki 全体憲法

前文に二本柱（D1）を宣言し、原則は 10 本。

**制約: 原則 III と IV の意味を保存する。** コード内の「憲法原則 N」参照 7 箇所は
III（揮発インメモリ・1 箇所）と IV（型安全なエラー処理と境界検証・6 箇所）のみ。
新憲法でも III・IV の意味を維持することで、コードに触れずに完了条件
「参照が壊れていない」を満たす。

| # | 原則 | 骨子 | 現憲法との関係 |
|---|---|---|---|
| I | テスト駆動開発（NON-NEGOTIABLE） | Red-Green-Refactor。テストより先に実装を書かない | I を継承 |
| II | 技術選定は ADR を通す | 現行スタックを基本とし、追加・変更は ADR で記録してから | II「固定」を緩和（コード参照なし） |
| III | 揮発インメモリと単純運用 | 本番は永続化を持たない。再起動でルームが消える前提で設計し、デプロイは束ねて行う | **意味保存** |
| IV | 境界の型安全 | 外部入力は Valibot で検証、ドメイン操作は `Result` で返す。ドメインは例外を投げない。DbC は「事前条件 = 境界検証・不変条件 = 型」で表す | **意味保存** |
| V | 実画面検証 | テスト緑・typecheck 通過だけで完了と言わない。利用者が通る実経路で確かめる | V を継承 |
| VI | 依存は内向き | ドメイン（`packages/*-core`）は純粋。I/O・時計・乱数はアダプタに置いて注入。同期サーバーはポート/アダプタ構成を標準とする | 新設 |
| VII | 検査は壊して確かめる | 新しい検査はわざと壊して赤を見る。実装を書き換えたら既存テストの恒真化を変異で確かめる | 新設 |
| VIII | 記録が正本 | 決定は ADR、要求は Issue（EARS）、教訓は振り返りへ。正本は一意（SOT）。契約には単一情報源を宣言する | 新設 |
| IX | 小さく回す | 1 PR = 1 論理変更。DoD を満たしてからマージ。デプロイは全工程後に 1 回 | 新設 |
| X | 抽象は実需で | 利用者が 1 つのものを抽出しない。20 行未満は抽出しない。パターンは変更容易性のためだけに採る | 新設 |

- SOLID・DRY 等の一般論は原則として立てず、このプロジェクト固有の判断を含む形
  （VIII・X）に織り込む
- BDD（Given/When/Then）は原則に上げず、ADR 0006（テスト規約）と構造監査 SC032 の
  関係として記録する（すでに機械が守っているため）
- 「既存の timer には手を入れない」「3 パッケージ構成」等の矛盾条項は書き直しで消える
- 憲法冒頭の Sync Impact Report（spec-kit の慣行）は書き直し内容で更新する

## ADR — 横断 6 本と昇格

採番規約: 横断は `docs/adr/` で 0001 からの連番、アプリ固有は `docs/<app>/adr/` で
独立採番。参照は必ず置き場つき（例: `docs/adr/0005`）。`docs/adr/README.md` が
既に実践している形の追認であり、#78 からの申し送りをこれで解消する。

| # | タイトル（案） | 内容 | 由来 |
|---|---|---|---|
| 0002 | 文書体系の三層構造 | 憲法 / ADR / ガイドの役割分担・書き分け規則・採番規約。**加えて設計文書（spec/plan）の置き場の現行を宣言し、timer ADR 0010 の全体向け宣言を横断へ昇格・置換する**（新規の設計文書は `docs/superpowers/` に日付つきで置く現行運用を追認。`docs/plans/` は SDD 期の記録） | 本設計 |
| 0003 | アジャイル運用の形式化 | DoD・EARS・振り返り・バックログ一本化を運用として採る決定 | D2・D3 |
| 0004 | 同期サーバーはポート/アダプタ構成を標準とする | timer-sync 型に寄せる。テスト時にアダプタを差し替えられることが実 WS 試験（#80）で効いた。poker-sync の再編は #72 | 非対称の解消 |
| 0005 | 境界の型安全と関数型中心 | Result + Valibot の境界検証を全体標準に | timer ADR 0006 の昇格 |
| 0006 | テスト規約 | TDD/BDD・Given/When/Then（SC032）・変異検査・「検査は壊して確かめる」 | timer ADR 0009 の昇格 + 運用実績 |
| 0007 | 抽象の導入基準 | 20 行未満は抽出しない・利用者 1 つは抽出しない・パターン抑制 | #20 の判断の昇格 |

**昇格の形式**: timer ADR 0006 / 0009 / 0010 の先頭に「`docs/adr/000X` へ昇格。
timer 固有の詳細は本文のまま有効」という注記を足す（Superseded と同じ様式）。
timer 側の本文は削除しない。0010 は全体向けの宣言をアプリ固有の置き場でしていた
（横断 ADR の置き場が無かった時期の産物）ため、横断 0002 が後継となる。

ADR テンプレート（`docs/adr/template.md`）: Michael Nygard 形式
（背景 / 決定 / 影響 / ステータス）+ ステータスの語彙
（Proposed / Accepted / Superseded by NNNN）。

## 検証方法

1. **憲法参照の保存**: `grep -rn "憲法原則"` の 7 箇所すべてについて新旧の意味の
   突き合わせ表を作り PR-2 に添付する
2. **リンクの実在**: 新設・変更した文書内の相対リンクを一時スクリプトで辿り全件実在を
   確認する。恒久のリンクチェック CI は #70 へ申し送り（コードを変えない原則のため
   ここでは足さない）
3. **`pnpm test` 全緑の維持**: docs しか触らない PR でも回す。テストが docs のパスに
   依存していないことの確認を兼ねる
4. **spec-kit との整合**: 憲法書き直し後、`.specify/templates/` の Constitution Check が
   動的参照のまま壊れないことを確認する
5. **敵対的検証**: スペック・各 PR の完成後に、①事実照合（主張をコマンドで裏取り）
   ②「この体系で判断に迷う実例を挙げる」の 2 観点で自分の成果物を潰す
