## この置き場の位置づけ

**繰り返す作業の手順の正本はここです**（#489・[`docs/adr/0030`](../../adr/0030-ai-driven-development-operations.md) 決定 3・5）。
人が読んでも AI のエージェントが読んでも同じ手順で作業できるように、**特定のツールに依らない書き方**で書きます。

ガイドの一部なので、ADR の改版なしに育ててよい（[`docs/adr/0002`](../../adr/0002-document-system-three-layers.md) 決定 2）。
**決定と根拠は ADR に、規則の正本は [`AGENTS.md`](../../../AGENTS.md) と憲法に置き、手順書はそれを指します。**
手順書の中で新しい規則を作りません（作りたくなったら ADR か `AGENTS.md` へ）。

## スキルとの関係

ツールが「スキル」（呼び出すと手順が読み込まれる仕組み）を持つときは、**スキルは手順書へ向ける薄い入口にします。**
規則の正本を `AGENTS.md` に置き、`CLAUDE.md` ほかを薄い入口にしたのと同じ考え方です（`docs/adr/0030` 決定 3）。

- スキルの置き場は `.claude/skills/<名前>/SKILL.md`（Claude Code）。中身は frontmatter の `name`（ディレクトリ名と同じ）と
  `description`（いつ使うかの一文）と、**手順書へのリンクを持つ数行の本文だけ**にする
- スキルに手順を書かない。`SKILL.md` 以外のファイル（スクリプト・参照文書）も置かない。手順を直すときは手順書を直す
- スキルを持たないツールは、`AGENTS.md` の文書地図からここへ辿る。**スキルが無くても手順書だけで作業できる**ように書く
- `scripts/audit-agent-entries.mjs`（CI の `docs` ジョブ）が、スキルが手順書（この置き場の追跡下のファイル）へ向いていること・
  薄いこと（本文の空でない行の数と文字数・description の文字数）・`SKILL.md` 以外のファイルが無いことを見る。
  **上限の中に手順を書けば通る**。検査は歯止めであって証明ではない（`docs/adr/0030` 決定 3 と同じ残余）

## 外部のスキル運用との分担

これまで、設計文書を書く・計画を実行するといった手順の一部は、リポジトリの外のスキル（`superpowers:*`。
出力先を `docs/superpowers/` にしているもの）とエージェントの記憶に頼っていました。場所が変わると同じ手順で作業できる保証が
無いので、次のように分けます（#489 で決めた）。

- **リポジトリに持ち込む**: このリポジトリに固有の手順（上の一覧）。検査のコマンド・ポート・変異の宣言の表のように、
  リポジトリの中身を知らないと書けないもの
- **外に残す**: どのリポジトリでも同じ汎用の進め方（発想を広げる・計画を書く・計画を順に実行する・サブエージェントで分担するなど）。
  使うかどうかは作業する人とエージェントが選んでよい。**使わなくても、このリポジトリの規則と手順書だけで作業を終えられる**ことを保つ
- **置き場は外のスキルに依らない。** 設計文書は外のスキルを使ったかどうかによらず `docs/superpowers/` に日付つきのファイル名で置く
  （`docs/adr/0002` 決定 4 と追記（#71）。0002 はこの置き場を「現行のスキル運用の出力先の追認」として決めたが、
  置き場の決まりそのものは今も変わらない。スキルの名前は置き場の名前に残っているだけで、スキルを使う義務は無い）
- 外のスキルの指示とこのリポジトリの規則が食い違ったら、**このリポジトリの規則（憲法・ADR・`AGENTS.md`・ガイド）が正しい**

## 手順書を足すとき

1. 2 回以上繰り返した手順だけを書く（1 回きりの作業は ISSUE や PR に残せば足りる。憲法 原則 X）
2. ここに `<内容>.md` を置き、上の一覧に足す。冒頭に「いつ使うか」と拠り所を書く
3. スキルも置くなら `.claude/skills/<名前>/SKILL.md` を足す（上の「スキルとの関係」）。置かなくてもよい
4. `node scripts/audit-agent-entries.mjs` と `node scripts/check-links.mjs` を流す（新しいファイルは `git add` してから。
   どちらも存在の判定は追跡下だけで行う）
