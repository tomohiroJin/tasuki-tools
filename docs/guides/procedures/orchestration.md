# 並行実装のまとめ役

## いつ使うか・拠り所

実装やレビューを複数のエージェントに分けて頼み、自分は束ねる側（まとめ役）に回るときに使う。
拠り所は [`docs/adr/0030`](../../adr/0030-ai-driven-development-operations.md) 決定 3・5 と
[`AGENTS.md`](../../../AGENTS.md)「AI 運用規則」。新しい規則はここで作らない。

人の承認を待つ操作（デプロイ・ADR の採択・検査を弱める変更ほか）は、まとめ役もサブエージェントも自分で決めない。

## 1. 分ける前に

- 依頼の ISSUE・関係する ADR を読み、分け方を決める。**計画には、検証の時間の見積もりを書く**
  （`docs/guides/plan-writing.md`「計画に書く数値・期待値・時間」）
- 同じ ISSUE の開いた PR・マージ済みの PR・リモートの枝を確かめる（`AGENTS.md`「作業の始めに」）
- 変異 ID の帯を、**分けた作業ごとに多めに**先に予約する（`docs/guides/procedures/mutations.md` の「2. 番号を決める」）。
  どの作業も `MUTATIONS` の末尾へ足すので、後から入る側は末尾で衝突する。両側を残して解き、番号は付け直す
- 実装役への指示（ブリーフ）に、完了条件を**機械で確かめられる形**で書く。その検査コマンドは、先に自分で流して期待値を確かめる
- 積み上げの作業（下の PR が上の PR の土台）は、土台がマージされたら
  `git rebase --onto origin/main <旧い土台の先頭>` で載せ直す

## 2. 作業ツリーを分ける

- 作業ごとに専用の作業ツリー（`git worktree add`）を切る。**同じ作業ツリーを 2 者が触る形にしない**
  （片方の復元が、もう片方の実験の途中を消す。読むだけのつもりのレビューも変異検査を流すと書き換える）
- 依存の入れ方は、置き場で分かれる。作業ツリーを切ったら、依存を入れる前に、**その作業ツリーに対して `stat -f` で 9p かどうかを測る**
  （`docs/guides/development.md`「9p 越しで実行するときは依存の実体を逃がす」）。
  - **9p の上**: 依存の実体を逃がす手順に従う。逃がし先は作業ツリーごとに分ける（同「落とし穴 5 つ」）。`--store-dir` だけでは実体は 9p に作られ、遅い
  - **9p でない置き場**（コンテナ側に切った作業ツリー）: ストアを共有して `pnpm install --frozen-lockfile --offline --store-dir "$(pnpm -C <元の作業ツリー> store path)"`
    （`docs/guides/procedures/mutations.md` の手順 5）
  - どちらの場合も、サブエージェントに素の `pnpm install` を打たせない（置き場が既定に戻る）
- 長い実行（E2E 全件・変異の全件・撮影の比較）は**まとめ役が流す**。ポートが衝突するのは E2E と dev サーバーだけで、
  単体テストは並べて流せるが、高負荷では vitest のワーカーが起動しないことがある（「未実行」であって失敗ではない。`docs/guides/development.md` の高負荷の項）。並べる数を絞り、未実行と失敗を分けて数える。サブエージェントに禁じた作業（E2E・実画面・PR・マージ）は、禁じた側の TODO になる
- 一時ファイルの置き場は作業ツリー内の `tmp/` と決めて指示に書く

## 3. サブエージェントへの指示に毎回書くこと

禁止は共通のファイルへの参照だけで済ませず、**指示の本文にも 1 行で繰り返す**。禁止を書いた回は守られ、書かなかった回に事故が起きた。
ただし書いても守られない個体がいる。**書いたことを検証の代わりにしない。**

- **読み取りと計測だけの役**は、「commit・push・マージ・ブランチ削除・PR と ISSUE への書き込みをしない」と書く
- **プロセスを止めない**（`kill`・`pkill`・シェルの中断をしない。自分の起動したものが残ったら止めずに報告する）。dev サーバー・E2E を起動しない
- **ブランチを切り替えない。作業ツリーやコミットを巻き戻す git 操作は全部しない**
  （`checkout`・`switch`・`stash`・`reset`・`restore` を含む。`checkout -- <file>` だけ禁じると `checkout HEAD -- <file>` が抜ける）。
  代わりの手段を併記する: 過去の版は `git show <rev>:<path>` で読む・戻すなら `git apply -R` か手で直す・新しいコミットを足す。
  例外は、手順書（[敵対的レビュー](./adversarial-review.md) の手順 3・[実画面で確かめる](./live-check.md)）が指示する
  `checkout`・`restore` を、その役だけが使う作業ツリーで使うときだけ（レビュー役でも、実画面の確認を任せた実装役でも）。
  その場合は、指示の本文に作業ツリーのパスと許す操作を明示する
- **`rm` を使わず、ファイルは上書きで書く**（確認待ちで止まらないため）。消す必要があるものは、まとめ役が `git ls-files <dir>` で追跡下かを見てから消す
- push・PR 作成・ISSUE 起票・マージは**まとめ役だけが行う**。閉鎖キーワードも書かせない
- `pnpm install` をしない・他の作業ツリーは読むだけ・他人の未コミットの変更を復元しない
- 逐語で写させる文は、**貼り先の構文で有効な形**で渡す。表のセルや YAML の値は 1 行で書く（折り返すと表の後半が表の外へ落ちた）
- 背景にタイマーや待ちのループを置かない・入力待ちを起こす書き方（heredoc の終端忘れなど）をしない・長いコマンドは 1 つずつ（各 5 分以内）
- **Bash は 1 呼び出しに 1 操作。確認と操作をつながない。別の作業ツリーの git は `git -C <パス>`（`-C` は 1 つ・パスはそのまま書く）。**
  まとめ役自身も同じ決まりで動く（正本は `AGENTS.md` の「コマンドの書き方」。#612）。指示の本文にもこの行を写す。
  ただしサブエージェントの `git -C <パス> checkout|switch|reset|worktree …` は、`-C` が 1 つでも止まる。
  `checkout [<rev>] -- <path>`・`reset --soft`・`worktree add` は `-C` の無い形なら通るが、決定 2 の「単純な安全な形」が `-C` を読まないので止まる。
  `switch`・`checkout --detach` ほかの枝の操作・`reset --hard`・`worktree remove` は、`-C` が無くても決定 2 の宣言で止まる（`docs/adr/0037`。下の作業ツリーの作成と同じ）。
  レビュー役の手順 3 の取り出しは、`adversarial-review.md` の `git show` の形を使う
- **ファイルを書く呼び出しと、それを実行する呼び出しを分ける。** git と `node -e` などのスクリプトを 1 つの呼び出しに混ぜない。
  サブエージェントの Bash は PreToolUse のフック（`docs/adr/0037`）が文字列全体を走査する。heredoc の本文やスクリプトの中にある
  `git` と `.push(`・`reset` などの語が危ない操作に見えて、人の確認で止まる（#603 の実測では、止まった 33 件のうち約 15 件がこの形だった）。
  - ファイルは Write ツールで書く。heredoc で書くなら、本文を文章として扱うのは次の形だけ（`scripts/lib/agent-guard.mjs` の `CAT_HEREDOC_LINES`）:
    `cat > <パス> <<'EOF'`（終端の名前は英字と `_` だけで、単一引用符で囲む。パスは引用しない。前に置けるのは `mkdir -p <パス> &&` だけ）で、終端の行の後ろに何も続けない。
    `<<EOF`・`<<"EOF"`・`cd … && cat > …`・`tee` は本文も読まれる
  - `node -e` の本文に `"git"` と `.push(` があると、それだけで止まる。スクリプトはファイルに書いてから流す
- 作業ツリーの作成をサブエージェントに任せるときは、`git -C <パス> worktree …` と書かず、本体を cwd にして流す（`-C` つきは止まる）。
  作業ツリーの削除（`git worktree remove`）は、単独でもサブエージェントでは止まる。まとめ役が行う
- 指示したパスへの書き込みは許可済みで、指示の本文が共通ファイルに優先する、と書く
- コミットメッセージの末尾の attribution の行は、正確な 1 行を指示に書く
- 計画やブリーフの数値・期待値・テスト名・変異は現物で裏を取ってから渡す（[`plan-writing.md`](../plan-writing.md)「計画に書く数値・期待値・時間」）

### Claude Code の場合

- 「Agent ツールが無い」と判断する前に、`ToolSearch` で `select:Agent` を引く。道具の不在は引いてから言う
- 敵対的レビュー役に `/code-review` を使うなら、引数なしでは**カレントブランチ**を見る。別の作業ツリーの PR は番号を渡す
- `/code-review` が作業ツリーを detached HEAD にすることがある。流した後は `git branch --show-current` で確かめる

## 4. 返ってきた報告を裏取りする

報告は自己申告である。**まとめ役が自分で確かめる。**

- 実装役の「検査を通した」は、終了コードを自分で見る。検査の件数は、実行して出る行（`--plan` の件数行ほか）を読み、表を grep で数えない
- 実装役が申告した Red は、実装だけ戻して赤→戻して緑を自分で再現する。前後で `git status --porcelain` が空かも見る
- 委譲から戻ったら `git status --porcelain` と `git diff --stat` を見る。`git add -A` は他人が残した変異ごと取り込む
- 黙った push は `git ls-remote origin <枝>` で拾う（`origin/<枝>` は手元の台帳で、ずれる）。実装役が残した `git stash`・終わらない待ち・入力待ちは止める
- 実装役を長い修正ループで再開し続けない（文脈が尽きて未コミットが消える）。2 回目以降は、指摘をファイルに書き出して新しい実装役へ渡す
- 依存の向きなどの検査の登録は、タスクごとの検査でなく、**全件の監査（`pnpm check:fast`）で確かめる**。タスク単位では登録漏れが見えない
- 共通の決まりや報告を置く作業用のファイルは、まだ動いている実装役がいる間は消さない（完了時に消すと、報告の置き場が消える）
- 各タスクの終わりに経過時間を確かめる。**1 人に渡す差分は大きくしない**（領域で割り、割れたことをファイル数の合計で突き合わせる。
  未クォートの展開が単語分割されず「変更なし」に見えた例がある）。仕上げ（PR・CI の待ち・ISSUE の起票・振り返り）を 1 つの依頼に束ねない
- CI の待ちはまとめ役が境界つきで行う。エージェントに `gh pr checks --watch` を書かない

## 5. レビューの往復の終わり方

始める前に基準を決める。決めずに回すと収束しない。基準は
[敵対的レビュー](./adversarial-review.md)の「往復の終わり方」。レビュー役への指示に、そのまま書く。

## 6. PR を立てたあと

- push のたびに、PR のインラインコメントとレビューを読んで返す
  （`gh api repos/<owner>/<repo>/pulls/<番号>/comments`・`.../reviews`）。指摘ごとに返信する
- 閉鎖キーワード（Closes ほか）は **PR 本文に裸で 1 行**書く。バッククォートの中では効かず、コミットメッセージの地の文に書くと squash で勝手に閉じる。
  マージ後に ISSUE の state を見る
- 積み上げの PR の扱い（`--delete-branch` を使わない）は [`docs/guides/pr-granularity.md`](../pr-granularity.md) の「派生した作業の扱い」
- squash マージした PR は、`git merge-base --is-ancestor` では未マージに見える。`gh pr view` の state で見る
- CI の結果の読み方（headSha から読む・check-runs が全部 completed か）は [`docs/guides/development.md`](../development.md) の「CI の結果を読むとき」
- 採点を伴うレビュー（Claude Code の `/code-review`）が走っている間は、指摘を直さない。直ったあとの状態が採点され、指摘が空振りになる

## 7. 長い実行を待つとき

長い実行は背景で起動し、完了の通知を待つ。待つ側のコマンドで `pgrep -f <パターン>` を使うと、**自分自身の引数に当たる**。
PID で待つか、`pgrep -f '[p]attern'` と書く。Claude Code の背景実行は、終了時に通知が届く。ポーリングしない。

## 8. 終わりの前の棚卸し

報告の前に、次を確かめる。

```bash
git worktree list          # 自分が作った作業ツリーが残っていないか。サブエージェントが消したと申告しても実体が残ることがある
git branch --show-current  # 枝が切り替わっていないか
ss -tlnp                   # 起動した dev サーバーが残っていないか
git status --porcelain
```

自分が作った作業ツリーとブランチだけを片付ける。他人のもの、人が使っているプロセスは触らない（止まっていたら、勝手に立て直さず人へ知らせる）。
報告は `AGENTS.md` の 3 区分（変えたこと・確かめたこと・確かめられなかったこと）で書く。
