# 実際の利用シーンと作らないもの

## このガイドの位置づけ

**次に作る機能を選ぶときの物差しである。** 機能を提案する前に読む。
ここは**利用者の判断を書き留めた指針**（2026-10-25 に利用者から聞いた内容）で、ADR の決定ではない。
義務を足すものでもない。古くなったら、聞き直して書き換える（[`docs/adr/0002`](../adr/0002-document-system-three-layers.md) の三層構造のうち、ガイドの層）。

## 使われている場

聞いた時点（2026-10-25）で、次のような**その場で集まって進める作業**に使われていた。
その後に足したツール（例: チェックイン）は、この表に載っていない。

| 場 | 使うツール |
|---|---|
| ペア・モブでの作業 | timer |
| お題を決めて、モブで取り組む勉強会 | topic で選び、timer で回す |
| スクラムのリファインメント（見積もり） | poker |
| 朝会の進行役などの順番決め | roulette |
| 会議の進行 | agenda（聞いた時点では、作ったばかり） |

スクラムのふりかえりのように、書いて並べて残す作業は、既存のホワイトボード型の道具に任せている。

## 作らないもの

- **サーバー側の保存・履歴は作らない。** 同期サーバーの共有状態は揮発インメモリで、永続化しない（憲法 原則 III）。
  この方針で、ふりかえりのボードを本命にする案は退けられた。
  端末側の保存（agenda の保存済みシナリオ、roulette のいつものメンツ、設定など）は、原則 III の対象外で、既にある
- **キャンバスや、型の多さで競う機能は作らない。** ホワイトボード型の道具と同じ土俵では、機能で負ける。ふりかえりの型を増やすほど負ける
- 持ち出しが要るときは、サーバーに保存するのでなく、**コピー**（Markdown など）で、ほかの道具へ渡す形にする

## Tasuki が勝てる性質

機能は、次の性質のどれかを伸ばすものに絞る。

- その場で使える・全員が同時に見られる
- アカウントが要らない
- 終われば消える
- 同期する
- 時間を区切る
- 順番を回す

## 提案のときに

提案には、使われている場のどれを深めるか、勝てる性質のどれを伸ばすかを書く。
サーバー側の保存・キャンバス・型の多さが要る案は、この物差しに合わないので、出す前に利用者へ聞く。
