# 実装計画ガイド（Constitution Check ゲート）

## このガイドの位置づけ

**実装計画の Constitution Check ゲートの様式の正本はこのガイドです。**
「すべての plan は Constitution Check ゲートを通過しなければならない」という MUST は
[`docs/constitution.md`](../constitution.md) の Governance が定め、**どの集合に課すか**は
[`docs/adr/0003`](../adr/0003-agile-operations.md) の追記（2026-09-04・#155）が定めています。
様式の追加や更新は ADR の改版を経ずにこのガイドの更新のみで行います
（`docs/adr/0002` の三層構造・書き分け規則）。

**このガイドは #71 で失われた宛先を埋めるものです。** ゲートの様式は
`.specify/templates/plan-template.md` が持っていましたが、spec-kit 経路の廃止で
テンプレートごと削除され、様式を定める正本が無い状態が続いていました。

## いつ書くか

`docs/superpowers/plans/` に実装計画を置くときです。**境界日 `2026-09-04` 以降の日付を
持つ実装計画にゲートを要求します**（決定と理由は `docs/adr/0003` の追記）。
それより前の既存の実装計画へは遡りません。

**設計正本（`docs/superpowers/specs/`）と振り返り（`docs/retrospectives/`）は対象外です。**
憲法の MUST は plan を名指ししています。

## どこへ書くか

実装計画のファイル名は `docs/superpowers/plans/YYYY-MM-DD-<topic>.md` です。
**日付の接頭辞は必須です。** 境界日で分類できないファイルは検査が落とします
（黙って対象外へ落ちる経路を残さないため）。

ゲートは計画の**冒頭近く**（背景や Global Constraints より前、または直後）に置きます。
計画を書き始める前に通すのがゲートの趣旨です。

## 様式

見出しに `Constitution Check` を含めます。日本語を添えても構いません
（`## 規約チェック（Constitution Check）` は実在する形です）。

節には次の 2 つを置きます。

1. **憲法の全原則についての判定表**（原則のローマ数字で始まる行）
2. **逸脱の結論** —— `逸脱なし` と書くか、`Complexity Tracking` で正当化する

```markdown
## Constitution Check

憲法（[`docs/constitution.md`](../../constitution.md) v2.1.4）のコンプライアンスゲート。

| 原則 | 判定 | 根拠 |
|---|---|---|
| I. テスト駆動開発 | 通過 | 判定は純粋関数にし、Red → Green で書く |
| II. 技術選定は ADR を通す | 該当なし | 新しい依存を足さない |
| III. 揮発インメモリと単純運用 | 該当なし | 同期サーバーの状態管理に触れない |
| IV. 境界の型安全 | 該当なし | 境界検証に触れない |
| V. 実画面検証 | 該当なし | 利用者の通る経路は変わらない |
| VI. 依存は内向き | 該当なし | ドメイン層に触れない |
| VII. 検査は壊して確かめる | 通過 | 破壊検証を Task 3 で行う |
| VIII. 記録が正本 | 通過 | 決定は ADR、様式はガイド、実測は設計正本へ |
| IX. 小さく回す | 通過 | PR 1 本。デプロイは伴わない |
| X. 抽象は実需で | 通過 | 新しい抽象を作らない |
| XI. 秘密と個人情報を持ち込まない | 該当なし | 秘密・個人情報を扱わない |

**逸脱なし。** Complexity Tracking での正当化を要する項目はない。
```

**判定は「通過 / 該当なし / 逸脱」の 3 通りで書きます。** 該当しない原則を
表から落とさないでください —— 落とすと「考えたが該当しなかった」と
「考えていない」が区別できなくなります。それがゲートの本体です。

**逸脱するときは Complexity Tracking を書きます。** 憲法 Governance は
「原則からの逸脱は Complexity Tracking での正当化なしに認めない」としています。
逸脱を隠すのではなく、逸脱と理由を残してください。

## 検査

`node scripts/audit-plan-gate.mjs` が次を見ます（CI の `quality` ジョブで自動実行）。

| 見るもの | 落ちる条件 |
|---|---|
| 見出し | 境界日以降の plan に `Constitution Check` を含む見出しが無い |
| 判定表 | 節の中に、憲法の原則のローマ数字で始まる行が欠けている |
| 結論 | 節の中に `逸脱なし` も `Complexity Tracking` も無い |
| ファイル名 | `YYYY-MM-DD-` 接頭辞が無い |

**原則の一覧は `docs/constitution.md` の見出しから導出します。** 検査に原則名を
直書きしていないので、原則が増減しても検査は腐りません。

**判定の中身は読みません。** 全原則の行があり結論があることまでしか見ないので、
「該当なし」で埋めた表は通ります。ゲートは人が考えるためのもので、検査が守るのは
**考える場所があること**です。

**突き合わせはローマ数字だけで行います。** 原則名まで一致を求めると、憲法の
文言修正のたびに過去の実装計画が赤くなります。
