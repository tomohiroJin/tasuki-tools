# Example Map: お題出題と代表生成・縮退

> 対象ユーザーストーリー: US3（TDD のお題を出題する）

## 🟨 ストーリー（黄）

モブの参加者として、言語・難易度に応じた TDD のお題を出題してほしい。なぜなら、毎回お題を
考える手間なくセッションを始めたいからだ。共有ルームでは全員に同一のお題が反映されてほしい。

## 🟦 ルール（青）

- ルールA: お題を要求すると、言語・難易度に沿ったお題（タイトル・説明・要件・例示テスト・ヒント）が提示される（FR-021, US3-AC1）
- ルールB: AI 生成が利用不可・失敗・不正な形式なら、定型お題へ縮退し、画面を壊さない（FR-024, US3-AC3, SC-003）
- ルールC: 共有ルームでお題が確定すると、全参加者へ同一のお題が反映される（FR-025, US3-AC4）
- ルールD: 代表候補が期限内に投入できなければ、次候補へ再委譲し、全候補が失敗したら定型で確定する（FR-026）
- ルールE: お題再生成（リロール）は、旧依頼をキャンセルする（FR-027）

## 🟩 具体例（緑）

### ルールA: お題の提示

- **正例**: 利用者が選択した言語・難易度でお題を要求すると、タイトル・説明・要件一覧・例示テスト・ヒントを備えたお題が提示される — _根拠: spec §FR-021, §US3-AC1_

### ルールB: 定型への縮退

- **正例（縮退）**: AI 生成が不正な形式を返したとき、利用者は定型お題を受け取り、画面は壊れない — _根拠: spec §FR-024, §US3-AC3, §SC-003_
- **正例（縮退）**: AI 生成が利用不可のとき（鍵がない等）、利用者は定型お題を受け取る — _根拠: spec §FR-024, §SC-003_

### ルールC: 共有ルームでの同一お題

- **正例**: 共有ルームでお題が確定すると、在室する全参加者が同一のお題を見る — _根拠: spec §FR-025, §US3-AC4_

### ルールD: 再委譲と定型確定

- **正例**: 先頭の代表候補が期限内にお題を投入しないとき、次の候補へ依頼が移る — _根拠: spec §FR-026_
- **正例（収束）**: 全ての代表候補が期限内に投入しないとき、定型お題で確定する — _根拠: spec §FR-026_
- **負例**: 現在の代表候補でない参加者がお題を投入しても、その投入は受理されない — _根拠: spec §FR-025（代表が投入）／実装の保護。spec に明記薄のため下の赤に再掲_

### ルールE: リロール

- **正例**: お題の再生成（リロール）を要求すると、それ以前の依頼に対する投入は受理されない — _根拠: spec §FR-027_
