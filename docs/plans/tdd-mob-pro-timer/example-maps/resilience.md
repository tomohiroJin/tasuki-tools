# Example Map: 再接続・復帰とホスト不在耐性

> 対象ユーザーストーリー: US6（再接続・復帰とホスト不在耐性）

## 🟨 ストーリー（黄）

リモート参加者として、回線切断後に自動で復帰し、主催者が落ちてもセッションが続いてほしい。
なぜなら、不安定な環境でもモブを止めたくないからだ。

## 🟦 ルール（青）

- ルールA: 復帰トークンで再接続すると、同一参加者・同一役割として扱われる（FR-019, US6-AC1）
- ルールB: 再接続が成功すると、最初に受信する状態で完全に同期する（US6-AC2, SC-005）
- ルールC: 主催者が猶予時間を超えて不在になると、在室する最古の編集者へ主催者権限が自動委譲される（FR-018, SC-006, US6-AC3）
- ルールD: 主催者が猶予内に復帰すれば、委譲は起きない（FR-018 の含意）

## 🟩 具体例（緑）

### ルールA / B: 同一参加者・同一役割での復帰

- **正例**: 主催者が切断し、復帰トークンを用いて別の接続で再参加すると、同一参加者・主催者の役割のまま復帰する — _根拠: spec §FR-019, §US6-AC1_
- **正例**: 再接続した参加者は、最初に受信する状態でルームの最新状況に完全同期する — _根拠: spec §US6-AC2, §SC-005_
- **負例**: 無効な復帰トークンで参加すると、新規参加者（観覧者）として扱われる — _根拠: spec §FR-016（既定観覧者）, §FR-019（同一性は有効トークンに限る）_

### ルールC: ホスト委譲

- **正例**: 主催者が切断し猶予時間を超えて不在のとき、在室する最古のオンライン編集者が新しい主催者になり、全参加者に反映される — _根拠: spec §FR-018, §SC-006, §US6-AC3_

### ルールD: 猶予内復帰での非委譲

- **正例**: 主催者が切断しても猶予時間内に再接続すれば、主催者権限は委譲されず元の主催者のままである — _根拠: spec §FR-018（猶予を超えた場合のみ委譲）_
