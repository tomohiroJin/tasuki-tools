# Example Map: 一時停止・再開・完成・リセット

> 対象ユーザーストーリー: US4（一時停止・完成・リセット）

## 🟨 ストーリー（黄）

参加者として、セッションを一時停止/再開し、完成時に記録を残し、必要ならリセットしたい。
なぜなら、中断や達成を正しく扱い、所要時間を正確に測りたいからだ。

## 🟦 ルール（青）

- ルールA: 一時停止するとカウントダウンが止まり、経過時間の積算も止まる（FR-005, FR-006）
- ルールB: 再開すると停止時点の残り時間からカウントダウンが続く（FR-005）
- ルールC: 完成記録の所要時間は、停止時間を除いた稼働時間と一致する（SC-004, FR-006）
- ルールD: 完成が確定すると、お題・言語・難易度・所要時間・メンバー・総交代回数・完成日時を含む記録が生成される（FR-028）
- ルールE: リセットすると、セッションは初期（設定）状態へ戻る（US4-AC4, FR-001）

## 🟩 具体例（緑）

### ルールA / B: 一時停止と再開

- **正例**: 稼働中のセッションを一時停止すると、全参加者の残り時間が停止時点で固定される — _根拠: spec §FR-005, §US4-AC1_
- **正例**: 一時停止したセッションを再開すると、停止時点の残り時間からカウントダウンが再開する — _根拠: spec §FR-005, §US4-AC2_

### ルールC: 所要時間の停止除外

- **正例**: 60秒稼働 → 一時停止して30秒待機 → 再開して40秒稼働 → 完成、のとき、記録される所要時間は停止30秒を含まない100秒である — _根拠: spec §FR-006, §SC-004_
- **境界（緑）**: 一時停止を一度も挟まずに完成したとき、所要時間は開始から完成までの実時間と一致する — _根拠: spec §FR-006_

### ルールD: 完成記録の生成

- **正例**: お題が確定したセッションを完成として確定すると、お題タイトル・言語・難易度・メンバー・総交代回数・完成日時を含む記録が生成される — _根拠: spec §FR-028, §US4-AC3_
- **負例**: 完成を二度要求しても、記録は重複して生成されない（同一セッションの完成は一度きり） — _根拠: spec §FR-028（記録生成）／実装の冪等性。spec に明記がないため下の赤に再掲_

### ルールE: リセット

- **正例**: 進行中のセッションをリセットすると、現ドライバー・交代回数・お題が初期状態に戻り、設定段階へ戻る — _根拠: spec §US4-AC4, §FR-001_
- **正例**: リセットしても、過去に生成した完成記録は失われない — _根拠: spec §FR-020（ローカル記録の保持）, §前提（記録は端末ローカル）_
