# 受け入れ基準: ルーム作成・参加と共有タイマーでの交代

> 段階2-1。各基準は独立テスト可能・Pass/Fail 明確・外部から観測可能。
> 対象: US1 / US2。観測点: 同期サーバーのコマンド処理結果（snapshot / error）。

## ストーリー
モブプロのファシリテーターとして、ルームを作成して仲間を招き、設定した間隔でドライバーが
自動交代する共有タイマーを使いたい。

## 受け入れ基準

### ルールベース（チェックリスト形式）
- [ ] ルーム作成時、作成者は主催者として登録される。
- [ ] ルーム作成時、一意のルームコードが割り当てられる。
- [ ] 交代間隔は 3 / 5 / 7 / 10 / 15 分から選べ、既定は 5 分である。
- [ ] あらゆる操作後、ローテーション人数と各人の担当回数配列の長さが一致する。
- [ ] あらゆる操作後、現ドライバー指標は有効範囲内に収まる。

### シナリオ形式（Given-When-Then）

#### AC-1: 有効なコードで参加すると最新状態を受け取る
- **前提** 主催者がメンバー構成を変更している
- **もし** 別の利用者が有効なコードで参加する
- **ならば** その参加者は変更後のメンバー構成を見る

#### AC-2: 無効なコードでの参加は拒否される
- **前提** 存在しないルームコードがある
- **もし** 利用者がそのコードで参加する
- **ならば** 参加は拒否され、ルームが見つからない旨が提示される

#### AC-3: 交代間隔の経過で自動交代する
- **前提** 3人のセッションが進行中である
- **もし** 交代間隔が経過する
- **ならば** 現ドライバーは次の参加者へ進み、在室する全参加者が同一の現/次ドライバーを見る

#### AC-4: 末尾ドライバーの交代は先頭へ折り返す
- **前提** 末尾の参加者がドライバーである
- **もし** 交代が起きる
- **ならば** 先頭の参加者が新しいドライバーになる

#### AC-5: 手動スキップは残り時間を待たない
- **前提** 残り時間が十分あるセッションが進行中である
- **もし** 参加者がスキップを要求する
- **ならば** 次の参加者がただちにドライバーになる

#### AC-6: 遅延参加者が現在の状態に追従する
- **前提** セッションが進行中である
- **もし** 利用者が途中から参加する
- **ならば** その参加者は現在の現ドライバーと残り時間に追従する

> 残り時間の一致判定: 決定論ハーネス（擬似クロック共有）で**完全一致**を期待値とする。
> SC-001 の ±1秒は実環境向け非機能要件で、統合テストでは同一スナップショット導出のため差は 0。
