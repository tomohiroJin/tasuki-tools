# 受け入れ基準: 役割・権限と観覧

> 対象: US5。観測点: コマンド処理結果（拒否=error / 受理=snapshot）、参加者の役割。

## ストーリー
主催者として、参加者の役割（主催者・編集者・観覧者）を管理し、見学だけの参加も許したい。

## 受け入れ基準

### ルールベース（チェックリスト形式）
- [ ] 新規参加者の既定の役割は観覧者である。
- [ ] 権限はコマンドごとに検証される。
- [ ] 主催者限定操作: 完成・リセット・役割変更・フェーズ変更・休憩。
- [ ] 編集者以上の操作: 設定変更・お題操作・セッション操作・引き継ぎメモ。

### シナリオ形式（Given-When-Then）

#### AC-1: 観覧者はセッション操作を行えない
- **前提** 利用者が観覧者として参加している
- **もし** 観覧者がセッションの開始を要求する
- **ならば** その操作は拒否される

#### AC-2: 観覧者はリセットを行えない
- **前提** 利用者が観覧者として参加している
- **もし** 観覧者がリセットを要求する
- **ならば** その操作は拒否される

#### AC-3: 観覧者はフェーズ変更を行えない
- **前提** 利用者が観覧者として参加している
- **もし** 観覧者がフェーズの変更を要求する
- **ならば** その操作は拒否される

#### AC-4: 観覧者は他者の役割を変更できない
- **前提** 利用者が観覧者として参加している
- **もし** 観覧者が他の参加者の役割変更を要求する
- **ならば** その操作は拒否される

#### AC-5: 編集者へ昇格すると操作できる
- **前提** 主催者が観覧者を編集者へ昇格させている
- **もし** その参加者がセッションの開始を要求する
- **ならば** その操作は受理される

#### AC-6: 主催者の役割は剥奪できない（人間確定）
- **前提** 主催者がルームに在室している
- **もし** 主催者が自身の役割変更を要求する
- **ならば** その操作は拒否され、主催者の役割は維持される
