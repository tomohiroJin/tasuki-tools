# 機能仕様: ロビーの自己退出導線 ＋ ロビー在席状態の sr-only テキスト
**ブランチ/ディレクトリ:** `fix/issue-37-42-lobby-leave-a11y` ・ **ステータス:** Draft ・ **フロー:** 要件優先

対応 Issue: [#37](https://github.com/tomohiroJin/tasuki-tools/issues/37)（退出導線）、
[#42](https://github.com/tomohiroJin/tasuki-tools/issues/42)（在席状態の a11y）。

どちらも `Lobby.tsx` の参加者行を触るため1ブランチにまとめるが、要件・実装・コミットは
Issue ごとに独立させる（#37 と #42 は互いに依存しない）。

## 概要

セッション開始前のロビー画面（`Lobby.tsx`）には2つの独立した欠落がある。

1. **(#37)** 参加者が自分の意思でルームから抜ける手段が無い。セッション画面
   （`RosterPanel.tsx` まわり）には `SelfDriverToggle` / `SpectatorSelfActions` 経由の
   自己退出導線があるが、ロビーの参加者一覧（インライン実装）にはこれに相当するものが無い。
   気が変わった参加者はタブを閉じる（＝切断。オフラインとして残り続け、ローテーションの
   枠も残る）しかない。
2. **(#42)** 参加者の在席状態（オンライン/離席/オフライン）は色つきドットのみで
   表現されており、スクリーンリーダー利用者には伝わらない。セッション画面
   （`RosterPanel.tsx`）には `presenceLabel()` を使った `sr-only` テキストが既にあるが、
   ロビー画面には無い。これは `docs/plans/roster-row-unification/spec.md` で
   「利用者に見える変更ゼロ」の制約により意図的にスコープ外とされ、別 Issue としての
   起票が推奨されていた事項である（同 spec.md 218行目）。

いずれもサーバー側・共有ロジック側（`@tasuki/timer-core` の `canRemoveParticipant`、
`presence.ts` の `presenceLabel()`）は既に実装済みで、ロビー画面の描画コードに
呼び出しが無いだけである。新しいドメインロジックの追加は発生しない。

## ユーザーシナリオとテスト *(必須)*

### ユーザーストーリー1 — ロビーで自分からルームを抜ける（#37・優先度: P1）

参加者として、セッション開始前のロビーで気が変わったとき、自分の意思でルームから
抜けられるようにしたい。なぜなら、タブを閉じるしかない現状では自分がオフラインの
幽霊として残り続け、ローテーションの枠も塞ぎ続けてしまうから。

**受け入れ基準（EARS）:**
1. ロビーの参加者一覧で自分の行を見ているとき、システムは「ルームから抜ける」ボタンを
   表示しなければならない。
2. 参加者が「ルームから抜ける」ボタンを押したとき、システムは確認ダイアログを介さず
   直ちに自己退出（`onRemoveParticipant(自分の participantId)`）を実行しなければならない。
3. もし自分が退出すると在室する編集者以上（host/editor）が0名になるなら、システムは
   「ルームから抜ける」ボタンを無効化し、理由を `title` 属性で提示しなければならない。
4. もし自分の退出後も在室する編集者以上が1名以上残る、または自分の退出後に
   在室者そのものが0名になる（＝最後の1人が抜ける）なら、システムは「ルームから抜ける」
   ボタンを有効のままにしなければならない。
5. ホストが他の参加者を退出させる既存の操作（`canRemoveParticipant` from
   `participant-label.ts` ＋ `RemovalConfirmDialog`）は、本要件によって変更されては
   ならない。

### ユーザーストーリー2 — ロビーの在席状態をスクリーンリーダーで確認する（#42・優先度: P2）

スクリーンリーダー利用者として、ロビーの参加者一覧で各参加者の在席状態
（オンライン/離席/オフライン）を音声で確認したい。なぜなら、現状は色つきドット
（`aria-hidden`）だけが在席状態を表しており、視覚に依存しない手段が無いから。

**受け入れ基準（EARS）:**
1. ロビーの参加者一覧の各行が描画されるとき、システムは当該参加者の在席状態に対応する
   `presenceLabel()` のテキストを、スクリーンリーダーに読み上げ可能な形
   （`sr-only` クラスの `<span>`）で当該行に含めなければならない。
2. 在席状態が変化して行が再描画されるとき、システムは新しい `aria-live` 領域を
   ロビーの参加者一覧に追加してはならない（在席状態が変わるたびに読み上げが
   割り込む煩わしさを避けるため。現状の「読み上げは行が最初にフォーカス/参照
   されたときのみ」という挙動を維持する）。
3. `PresenceDot` コンポーネントの視覚的な描画（ドットの色・`aria-hidden`）は、本要件に
   よって変更されてはならない。

## 機能要件 *(必須)*

- **FR-001**: システムはロビーの参加者一覧の自分の行に「ルームから抜ける」操作を
  提供しなければならない（#37）。
- **FR-002**: システムは自己退出の可否を、セッション画面の自己退出（`SelfDriverToggle`）
  と同じ不変条件判定関数（`@tasuki/timer-core` の `canRemoveParticipant(participants, targetId)`：
  在室する編集者以上が1名以上残るか、または在室者そのものが0名になるなら許可）で
  判定しなければならない（#37）。
- **FR-003**: システムは自己退出が不変条件により拒否される場合、操作を無効化し、
  理由をユーザーに提示しなければならない（#37）。
- **FR-004**: システムは自己退出に確認ダイアログを課してはならない（#37・FR-079 の
  既存判断を踏襲）。
- **FR-005**: システムはホストによる他参加者の退出操作（確認ダイアログつき）を
  本要件により変更してはならない（#37）。
- **FR-006**: システムはロビーの参加者一覧の各行に、在席状態に対応する
  `presenceLabel()` のテキストを `sr-only` として含めなければならない（#42）。
- **FR-007**: システムは `PresenceDot` コンポーネント自体（責務・シグネチャ・描画）を
  変更してはならない（#42）。
- **FR-008**: システムはロビーの参加者一覧に新規の `aria-live` 領域を追加しては
  ならない（#42）。

## 非機能要件

- **アクセシビリティ**: #42 は WCAG 1.4.1（色のみに依存しない情報伝達）の既存欠落を
  ロビー画面についても解消する。セッション画面（`RosterPanel.tsx`）と同じ達成水準に揃える。
- **一貫性**: #37 のボタン文言・title 文言はセッション画面の自己退出導線
  （`SelfDriverToggle` / Session.tsx の Room タブ内インライン実装）と同一にする。
- **回帰防止**: #42 の変更は `PresenceDot` を経由しないため、`RosterPanel.tsx` の
  既存テストへの影響はない（部品の変更をしないため）。

## 主要エンティティ

新規エンティティは無い。既存の `Participant`（`@tasuki/timer-core`）、`Room` をそのまま使う。

## 成功基準 *(必須・技術非依存)*

- **SC-001**: ロビーで参加者が自分の行の「ルームから抜ける」を押すと、確認なしで
  ルームから退出でき、退出後は入口画面（Setup）に戻る（#37。遷移自体は既存実装）。
- **SC-002**: 在室する編集者以上が自分1名しかいないロビーでは、「ルームから抜ける」が
  無効化され、理由が読み取れる（#37）。
- **SC-003**: スクリーンリーダーでロビーの参加者一覧を読み上げたとき、各行の在席状態
  （オンライン/離席/オフライン）が音声で確認できる（#42）。
- **SC-004**: 既存の `RosterPanel.tsx` 関連テストがすべて回帰なく通過する（#42。
  `PresenceDot` 無改修の裏取り）。

## スコープ外 / 非目標 *(必須)*

- `App.tsx` の変更（退出後の遷移・`LEFT_ROOM` 受け側は実装済みでスコープ外）。
- `apps/sync/**` の変更（サーバー側の `participant.remove` 自己対象は FR-079 で
  既に正規経路として認められており、変更不要）。
- `apps/web/src/ui/presence.ts` の `presenceLabel()` 自体の変更（既存のものを呼ぶだけ）。
- `apps/web/src/ui/components/PresenceDot.tsx` の変更（FR-007）。
- ロビーへの `SelfDriverToggle` / `SpectatorSelfActions` コンポーネントそのものの導入
  （下記「検討した代替案」を参照。不採用）。
- ドライバー指名・改名・代理追加など、ロビーへの新機能の追加
  （`docs/plans/roster-row-unification/spec.md` の既存の非目標を踏襲）。
- `RowIconButton` 等の見た目の統一・リファクタリング（本仕様の対象外）。
- ホストが他参加者を退出させる既存フロー（`RemovalConfirmDialog` 経由）の変更。

### 検討した代替案（#37・不採用）

ロビーの参加者一覧まるごとを `RosterPanel.tsx` ＋ `SelfDriverToggle` /
`SpectatorSelfActions` に置き換える案を検討したが、不採用とした。理由:
`docs/plans/roster-row-unification/spec.md` がまさに「Lobby と RosterPanel は
実装まで一致している部分だけを共有部品に切り出す」方針を確定させたばかりであり、
ロビーには「ドライバー加入/離脱」「参加者一覧に確認ダイアログ」など RosterPanel と
異なる既存の挙動があるため、コンポーネントごと差し替えると影響範囲が本 Issue の
対象を超えて広がる。ロビーの自分の行に「ルームから抜ける」ボタンを1つ追加する方が、
影響範囲が最小で済み、既存の「利用者に見える変更ゼロ」の教訓（roster-row-unification）
とも整合する。

## 前提

1. 「ルームから抜ける」ボタンの表示位置は、参加者行の既存の操作エリア
   （`isMe` ブロック内、「列から外れる/ドライバーに加わる」の隣）とする。
   Issue #37 は「自分の行を第一候補とする」としており、既存のセッション画面
   （Room タブのインライン実装）と統一感がある。
2. ボタンの文言・title は Session.tsx の既存インライン実装（197〜210行目付近）と
   完全に一致させる（「ルームから抜ける」／有効時 title「この端末をルームから外します。
   招待から再参加できます。」／無効時 title「進行できる人がいなくなるため抜けられません。
   他の人が進行に加わってから操作してください。」）。
