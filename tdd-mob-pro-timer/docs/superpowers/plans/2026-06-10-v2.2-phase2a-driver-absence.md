# v2.2 Phase 2a: ドライバー不在の自動繰上 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development（推奨）または superpowers:executing-plans。各ステップは TDD・`- [ ]` で追跡。

**Goal:** セッション中に現ドライバーが切断したら、短い猶予(30秒)後に次の eligible ドライバーへサーバー権威で自動繰り上げる（v2.2 Epic 2 / R2-1・R2-2）。

**Architecture:** 既存の「ホスト不在委譲」(presence.ts `scheduleHostAbsence`)をミラーし、presence に「ドライバー不在タイマー」を追加。繰り上げ自体（advanceDriver＋タイマー再アンカー）はスケジューラを持つ handlers が担い、presence は猶予タイマー発火時にコールバックで handlers を呼ぶ。`computeIneligibleIndices` に「オフライン」を加え、autoSwitch も含めオフライン driver を飛ばす。core 変更なし（sync 限定）。

**Tech Stack:** TypeScript, Bun(ws), vitest（FakeClock + SpyBroadcaster + fake timers）, neverthrow。

**正本spec:** `docs/superpowers/specs/2026-06-10-v2.2-experience-lifecycle-security-design.md`（Epic 2 / R2-1・R2-2）

**作業ディレクトリ:** `tdd-mob-pro-timer/`。sync テストは `~/.local/bin/pnpm --filter @tdd-mob/sync exec vitest run <file>`。

## 設計の要点（前提知識）

- **現状**: `autoSwitch`（handlers）が interval ごとに `advanceDriver(agg, computeIneligibleIndices(room))` で交代。`computeIneligibleIndices` は現状 `driverEligible===false` のみ ineligible 扱い（**オフラインは対象外**）。`reconcileSchedule` がタイマーを再アンカー。`Scheduler.schedule` は同 code の既存タイマーを clear してから再アーム。
- **ホスト不在パターン**（presence.ts）: 切断で offline 化→`scheduleHostAbsence`（30秒 setTimeout）→発火時にホストが依然 offline なら最古オンライン editor へ委譲。`clearRoomTimers` で回収時に解除。
- **本 Phase の方針**:
  1. `computeIneligibleIndices` に **オフラインも ineligible** を追加（autoSwitch も advanceForAbsence もオフライン driver を飛ばす）。
  2. handlers が **`advanceForAbsence(roomCode)`** を公開（＝既存 `autoSwitch` を露出。再フェッチ＋running 判定＋advance＋snapshot/switch signal＋reconcile を行う）。
  3. presence に **`DRIVER_ABSENCE_GRACE_MS` / driverAbsenceTimers / scheduleDriverAbsence**（猶予後に **stale-check**＝現ドライバーが依然同一名かつ offline かつ running のときだけ `onDriverAbsence` を呼ぶ）を追加。`onDriverAbsence` は server.ts で `handlers.advanceForAbsence` に配線。
  4. handleDisconnect で「現ドライバー切断 ＋ clock.running」のときだけ schedule（非稼働や非ドライバーでは何もしない＝既存テストに干渉しない）。handlePing で現ドライバー復帰時に解除。clearRoomTimers で解除。

function computeIneligibleIndices(room: Room): Set<number> {
  const ineligibleNames = new Set(
    room.participants
      // driver.skip で一時離脱した人、または切断中(offline)の人は交代対象から外す（R2-1）。
      .filter((p) => p.driverEligible === false || p.presence === "offline")
      .map((p) => p.displayName),
  );
  const set = new Set<number>();
  room.session.rotation.forEach((name, i) => {
    if (ineligibleNames.has(name)) set.add(i);
  });
  return set;
}

(e) `scheduleDriverAbsence` と `clearDriverAbsenceTimer` を追加（`scheduleHostAbsence` の近く）:
```typescript
  /**
   * ドライバー不在猶予後に次の eligible ドライバーへ繰り上げる（R2-1）。
   * 発火時に stale-check（現ドライバーが依然同一名・offline・稼働中）を行い、
   * 既に交代/復帰済みなら何もしない（古いタイマーの誤発火を防ぐ）。
   */
  private scheduleDriverAbsence(roomCode: string, driverName: string): void {
    this.clearDriverAbsenceTimer(roomCode);

    const timer = setTimeout(() => {
      this.driverAbsenceTimers.delete(roomCode);
      const room = this.store.get(roomCode);
      if (!room || !room.clock.running) return;
      // 現ドライバーが依然 driverName か？（autoSwitch 等で既に交代していたら no-op）
      const curName = room.session.rotation[room.session.currentIndex];
      if (curName !== driverName) return;
      // その人がまだ offline か？（復帰していたら no-op）
      const driver = room.participants.find((p) => p.displayName === driverName);
      if (driver?.presence !== "offline") return;
      this.onDriverAbsence?.(roomCode);
    }, DRIVER_ABSENCE_GRACE_MS);

    this.driverAbsenceTimers.set(roomCode, timer);
  }

  private clearDriverAbsenceTimer(roomCode: string): void {
    const timer = this.driverAbsenceTimers.get(roomCode);
    if (timer !== undefined) {
      clearTimeout(timer);
      this.driverAbsenceTimers.delete(roomCode);
    }
  }
```

  clearRoomTimers(roomCode: string): void {
    this.clearHostAbsenceTimer(roomCode);
    this.clearDriverAbsenceTimer(roomCode);
  }
