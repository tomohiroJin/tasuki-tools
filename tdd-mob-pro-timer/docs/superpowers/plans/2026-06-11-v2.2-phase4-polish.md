# v2.2 Phase 4: 仕上げ（接続状態・空状態・モバイル・a11y） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development（推奨）または superpowers:executing-plans。各ステップは TDD・`- [ ]` で追跡。

**Goal:** 体感品質を底上げする 4 観点の仕上げ — 接続状態の明示（banner 結合の解消）、初回体験/空状態の案内、主要画面のモバイル最適化、アクセシビリティの的を絞った改善（v2.2 Epic 5 / R5-1〜R5-4）。

**Architecture:** web 限定（core/sync は不変）。R5-1 は WS クライアントが接続状態を明示的に通知し、App が banner 由来の推測をやめて純粋関数で StatusStrip 状態を導出。R5-2 は再利用可能な空状態ヒントを主要 3 スポットに追加。R5-3/R5-4 は **主要画面（Session/Lobby/Join/Summary）に絞った監査＋的を絞った修正**で、過剰な網羅はしない（ユーザー方針: 実用十分）。

**Tech Stack:** TypeScript, React 18, Tailwind, @testing-library, vitest, playwright（360px 目視）。

**正本spec:** `docs/superpowers/specs/2026-06-10-v2.2-experience-lifecycle-security-design.md`（Epic 5 / R5-1〜R5-4）

## 設計の要点（前提知識）

- **R5-1 現状の脆さ**: `App.tsx` の `connectionStatus` は `sessionLost ? "lost" : banner?.kind === "warn" ? "reconnecting" : "online"`。banner は休憩提案・操作エラー等 接続無関係の warn でも立つため、それらで「再接続中」と誤表示される。WS クライアント（`client.ts`）は `onConnected`/`onDisconnected` と `scheduleReconnect`（ExponentialBackoff）を持つので、**接続状態を明示的に通知**させ App はそれを使う。
- **R5-2 現状**: 空状態の案内はほぼ無い。主要 3 スポット（ロビーで自分1人・お題未設定・初回の使い方）に簡潔なヒントを足す。
- **R5-3 現状**: `PrimaryButton`(px-6 py-3≈48px) は十分だが `GhostButton`(py-2≈36px)・`IconButton`(モバイル40px) はタッチ標的 44px 未満。レスポンシブクラスは 25 箇所。主要画面の 360px 監査＋タッチ標的/オーバーフロー修正。
- **R5-4 現状**: primitives は focus-visible リング完備（良好）。aria-label 39・focus trap（useFocusTrap）あり。アイコンのみボタンの SR ラベル・コントラスト・タブ順を主要画面で点検し既知の不足のみ直す。
- **既存テーマは維持**（spec 非対象: 大規模デザイン刷新しない）。

- [ ] **Step 3: 実装（純粋関数）** — `apps/web/src/ui/connection-status.ts`

```ts
/**
 * StatusStrip の接続表示を、WS クライアントの接続状態とセッション喪失から導出する（R5-1）。
 * banner（操作エラー/休憩提案など接続無関係の通知でも立つ）に結合しない。
 */
import type { ConnectionStatus } from "./components/StatusStrip.js";

/** WS クライアントが通知する接続状態。 */
export type ClientConnState = "online" | "reconnecting";

export function deriveConnectionStatus(
  sessionLost: boolean,
  connState: ClientConnState,
): ConnectionStatus {
  if (sessionLost) return "lost";
  return connState;
}
```

- [ ] **Step 4: クライアントの接続状態通知** — `apps/web/src/sync/client.ts`

`SyncClientOptions` に追加:
```ts
  /** 接続状態の変化通知（R5-1）。online=確立、reconnecting=切断後の再接続待ち。 */
  onConnectionChange?: (state: "online" | "reconnecting") => void;
```
`this.ws.onopen` 内（`onConnected?.()` の隣）に `this.options.onConnectionChange?.("online");` を追加。
`this.ws.onclose` 内（`onDisconnected?.()` の隣・`!this.disposed` のとき）に `this.options.onConnectionChange?.("reconnecting");` を追加（dispose 時は通知しない）。

**プレースホルダ:** R5-1/R5-2 は exact code。R5-3/R5-4 は**監査＋的を絞った修正**という性質上、具体修正（primitives のタッチ標的・EmptyHint・既知の focus/label 不足）は明示しつつ、追加修正は「主要画面で見つかった具体的不足のみ・テーマ改造なし」と境界を明記（ユーザー承認のスコープ）。検証（360px 目視・キーボード動線）が受け入れ条件。
