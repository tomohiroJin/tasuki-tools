# ADR-0004: full snapshot による状態同期（差分なし）

- **ステータス**: Accepted
- **関連要件**: FR-013, FR-015, SC-005

## 背景

複数端末がリアルタイムに同じセッション状態を共有します。差分同期（patch/revision）は帯域効率が
良い一方、ギャップ検知・順序保証・部分ロールバックといった整合性管理が必要で、バグの温床になります。
本ツールの共有状態は小さい（数百バイト〜数 KB 程度）と見積もられています。

## 決定

状態同期は **full snapshot のみ**とします。状態が変化するたびに、サーバーは在室する全参加者へ
ルーム全体（`Room`）を配信し、受信側は丸ごと置き換えます。差分・revision・ギャップ検知は行いません。

- サーバー→クライアントの状態同期手段は `snapshot` ただ 1 つ。
- 演出（交代・完成・need-problem）は `signal` として分離。欠落しても整合に無害。
- プレゼンス（オンライン/離席/オフライン）は状態に含めるが、単なる生存確認（ping）では配信を
  間引き、遷移・入退室時のみ snapshot を送る。

## 影響

- **利点**: 受信側は「置き換えるだけ」で常に正しい状態に収束する。再接続時も最初の snapshot で
  完全同期でき（SC-005）、復旧ロジックが不要。冪等で順序非依存。
- **代償**: 状態が大きくなると帯域効率が落ちる。本ツールの規模では許容範囲。将来大きくなったら
  差分同期エンジンの導入を再検討する（その場合は本 ADR を Superseded する）。
- 設計原則「データ同期（snapshot）≠ 一時イベント（signal）」を採用し、両者を型・経路で分離している。
