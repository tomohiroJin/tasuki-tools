# ADR-0001: モノレポ + 共有 core パッケージ

- **ステータス**: Accepted
- **関連要件**: FR-031（ソロと共有で同一ロジック）, FR-008

## 背景

共有セッション（サーバー経由）とソロモード（ローカル完結）の両方で、同じセッション遷移ロジック
（交代・一時停止・経過時間積算・不変条件）を使う必要があります。ロジックがサーバーとフロントで
二重実装されると、両者の挙動がずれ、「ソロでは通るが共有では壊れる」類のバグを生みます。

## 決定

pnpm workspaces + Turborepo のモノレポとし、純粋ドメインを `@tdd-mob/core` に集約します。
`apps/sync`（サーバー）と `apps/web`（フロント／ソロ）の双方が core を依存に持ち、
同一の `decide`/`evolve`/時刻導出を共有します。

- `packages/core` — 純粋ドメイン・スキーマ・お題・記録・i18n
- `apps/sync` — 同期サーバー（core を再利用）
- `apps/web` — フロント（core を再利用、ソロは core を直接駆動）

## 影響

- **利点**: ドメインが 1 箇所に集約され、共有/ソロの挙動一致が保証される。WS メッセージ契約
  （Valibot スキーマ）も front/server で同一物を共有でき、契約のズレが起きない。
- **代償**: ビルド/型解決の設定（workspace 参照・Vitest/Vite の alias）が増える。本リポジトリでは
  `@tdd-mob/core` のサブパス（`/aggregate` 等）を各 vitest/vite config の alias で解決している。
- ドメインは外部依存ゼロを保つ（時刻・I/O・乱数に依存しない）。これが [ADR-0002](./0002-decider-pure-domain.md) の前提となる。

## 更新 (2026-07-31)

- Issue #28（T009）により、ソロモード（`apps/web/src/solo/`）は撤去された。上記「背景」「決定」
  「影響」節に記載されているソロモードへの言及は、当時の判断の経緯を示す記録であり、
  この追記によって削除・書き換えを行うものではない。
- 「決定」（`packages/core` を共有パッケージにする）は依然として有効である。現在も
  `apps/sync`（サーバー）と `apps/web`（フロント）の双方が `packages/core` を依存に持ち、
  同一の `decide`/`evolve`/時刻導出を共有している。
- 決定を支える根拠は、「ソロと共有の一致」から「サーバー（`apps/sync`）と共有フロント
  （`apps/web`）の一致」へと変わった。ソロモードという利用形態が無くなったことで根拠の
  対象は変わったが、決定そのもの（core をモノレポの共有パッケージとして集約する）が
  覆ったわけではない。
- 上記「背景」「決定」「影響」節（ソロモードへの言及を含む）は、この追記が過去の経緯を
  記録するためのものであり、削除・書き換えの対象ではない。ADR は不変の記録であるため、
  判断が覆った場合は新しい ADR で `Superseded` するのが原則であり、本追記はその原則に
  従い既存本文を維持したまま経緯のみを補足するものである。
