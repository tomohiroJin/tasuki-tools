# Quickstart: プランニングポーカー MVP — 検証ガイド

**Date**: 2026-07-16 | **Plan**: [plan.md](./plan.md) | **Contract**: [contracts/ws-protocol.md](./contracts/ws-protocol.md)

本書は「機能が end-to-end で動くこと」を証明する検証手順を定義する。
実装詳細は tasks.md / 実装フェーズに委ねる。

## 前提

- Bun 1.x / Node.js 20+ / pnpm 9+ がインストール済み
- ポート: web 開発サーバー `5173`、sync サーバー `3311`（既存サービスと重複しない任意の空きポート）

## セットアップ

```bash
cd /workspaces/claym/local/Tasuki-poker/planning-poker
pnpm install
```

## 1. 自動テスト（憲法原則 I）


**期待結果**:

- `packages/core`: 単体テストが全件グリーン（デッキ・Room 集約・ラウンド状態機械・集計）
- `apps/sync`: プロトコル結合テストが全件グリーン
  （[契約の結合テスト観点 1〜10](./contracts/ws-protocol.md#結合テスト観点apps-sync-research-r7) をカバー）

## 2. 開発サーバー起動

```bash
pnpm --filter sync dev     # ターミナル1: WS サーバー（:3311）

```

- ブラウザで `http://localhost:5173/poker/` を開く

## 3. 実画面検証シナリオ（憲法原則 V — フロント完了の必須条件）

2つのブラウザウィンドウ（通常 + プライベート）で実施する。

### S1: ルーム作成と参加（US1）

1. ウィンドウ A: `/poker/` で名前「たろう」を入力しルーム作成 → ルーム画面へ遷移し招待リンクが表示される
2. ウィンドウ B: 招待リンクを開き名前「はなこ」で参加 → 両ウィンドウの参加者一覧に 2 人が即時表示される
3. 不正リンク `/poker/room/zzzzzzzz` を開く → エラーメッセージとトップへの導線が表示される

### S2: 秘匿投票と一斉公開（US2）

1. A がカード「5」を選択 → A には選択中の「5」が見える。**B には「投票済み」表示のみで値が見えない**
2. DevTools の Network → WS フレームを目視し、**B への配信に A の選択値が含まれない**ことを確認（SC-004）
3. A が「8」に選び直し → B 側は引き続き「投票済み」のみ
4. B も投票 → 全員投票で両ウィンドウが同時に公開表示へ切り替わる
5. 次ラウンドで B だけ投票 → ホスト A の「公開」操作で即公開。A は未投票として表示される

### S3: 結果表示と次ラウンド（US3）

1. 公開画面に各票・平均・最頻値が表示される（例: 5 と 8 → 平均 6.5、最頻値は 5 と 8 の両方）
2. 「?」「☕」を含めて公開 → 票は表示されるが平均の計算から除外される。全員が ? / ☕ なら平均は「—（算出不能）」
3. ホストが「次のラウンド」→ 両ウィンドウが投票前状態に戻る

### S4: 切断・再接続・ホスト繰上（US4）

1. 投票中にウィンドウ A（ホスト）を閉じる → B にホスト操作（公開・次ラウンド）が現れる（5 秒以内、SC-005）
2. A で同じルーム URL を開き直す → 同一参加者「たろう」として復帰し、公開前なら票も残っている（一般参加者として。ホスト権限は戻らない）
3. A・B 両方を閉じてから招待リンクを再度開く → 「ルームが見つかりません」（即時破棄、FR-014）

### S5: モバイル幅・サブパス確認

1. DevTools のデバイスモード（375px 幅）でカード選択〜公開まで操作できる
2. すべてのアセット・WS が `/poker/` 配下の URL で読み込まれている（コンソールに 404 がない）
