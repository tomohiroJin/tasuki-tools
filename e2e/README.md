# @tasuki/e2e

本番と同一の Caddy 断片・実ビルド成果物・実 sync サーバーをローカルに立ち上げ、
`/`・`/timer/`・`/poker/` の 3 系統が**外から見て**正しく振る舞うことを確認する
パッケージです。経路（ルーティング・資材配信・WebSocket のブロック・ヘッダ）に加え、
実ブラウザ 2 文脈での同期と、過去に壊れた振る舞いの回帰を検証します。

設計の正本は `docs/superpowers/specs/2026-08-07-e2e-foundation-design.md` です。

## 実行方法

```bash
# リポジトリルートから
pnpm build            # web アプリのビルドが必要（^build として依存）
pnpm e2e              # ローカル環境に立てて全シナリオを実行
pnpm e2e --grep @smoke   # @smoke タグのシナリオだけ実行

# 本番を外から確認する（何も起動しない。既に動いているサーバーへ当てるだけ）
TASUKI_E2E_BASE_URL=https://<公開ドメイン> pnpm e2e:prod
```

## VSCode の Playwright 拡張を入れている場合

拡張（`ms-playwright.playwright`）は `playwright.config.ts` を**自分で検出して
直接読み込みます**。`TASUKI_E2E_TARGET` を渡しているのは `e2e/package.json` の
`e2e` / `e2e:prod` スクリプトだけなので、拡張はそれを受け取れません。config は
読み込みの時点で `resolveTarget(process.env)` を呼ぶため、**テストを 1 件も
走らせる前に** `e2e/harness/target.ts` で落ち、テストエクスプローラが
赤くなり続けます。

**これは不具合ではありません。** ターゲットに既定値を持たせない設計
（本番向けの変数が残ったシェルで、ローカルを本番と取り違える事故を防ぐ）が
意図どおり発火しています。

赤を消すには、各自の `.vscode/settings.json` に次を置きます。`.vscode/*` は
`.gitignore` の対象なので、リポジトリには入りません。

```json
{ "playwright.env": { "TASUKI_E2E_TARGET": "local" } }
```

拡張が提供する設定に、config の検出そのものを止めるものはありません。
設定を置かずに済ませたい場合は、テストエクスプローラの「Playwright」パネルで
この config のチェックを外すか（Toggle Playwright configs）、拡張を
ワークスペースで無効化してください。

### テストエクスプローラの ▶ は押さないでください

赤が消えても、拡張から実行できる状態にはなっていません。穴が 2 つ残ります。

- **古いビルド成果物に対して走ります。** ビルドを与えているのは `turbo.json` の
  `dependsOn: ["^build"]` だけで、拡張は turbo を経由しません。そのとき置いてある
  dist に対して走るので、何に対する結果なのかがわからなくなります
- **ハーネスが起動したまま残ります。** `globalSetup` は初回だけ走り、teardown は
  `Run global teardown` を明示的に叩くまで走りません。Caddy と sync がポートを
  掴んだままになり、次の `pnpm e2e` が preflight で止まります

押してしまった場合は「終了後の確認コマンド」で状態を確かめ、残骸があれば
「異常終了で残骸が出たときの復旧」の手順で撤去してください。

**実行は必ずルートからの `pnpm e2e` を使ってください。** 拡張からも正しく走る
ようにする作業は Issue #162 で扱います。

## シナリオとタグ

| タグ | 内容 | `local` | `production` |
|---|---|:-:|:-:|
| `@smoke` | 経路・リダイレクト・ヘッダ・**WS が SPA に吸われていないこと**（ブラウザを使わない HTTP 確認） | ✓ | ✓ |
| `@core` | 最小の通し（LP の描画・poker の秘匿と自動公開・timer のドライバー交代） | ✓ | ✓ |
| （タグ無し） | 手作業や敵対的検証で見つけた壊れ方の回帰防止 | ✓ | — |

**タグ無しを本番で走らせないのは意図です。** 実ルームを作って消えるまで見る種類の
もので本番の枠（`maxRooms`）を消費しますし、`poker` の回帰はルームが消えることを
確かめるので本番で走らせる意味がありません。これを支えているのは `package.json` の
`e2e:prod` に書かれた `--grep` ひとつなので、**`tests/spec-tags.test.ts` が
その絞り込みとタグの綴りを機械的に固定しています**（`pnpm test` で走ります）。

### タグ無し（`local` 専用）の回帰防止

**この表は手作業で保つものです。件数は書きません**（足すたびに腐るため）。
ここに載るのは「壊れ方を見つけて塞いだ」種類のシナリオで、タグ無しの `describe`
すべてではありません（a11y・レート制限・書体などの検査も同じくタグ無しです）。

| # | シナリオ | 由来 | 判定の要点 |
|---|---|---|---|
| 10 | 玄関の札を選ぶと `/timer/`・`/poker/` が開く | #73 | 行き先の URL だけでなく、**そのアプリにしか無いもの**が見えることまで見る |
| 11 | 招待パネルに表示された URL でそのまま参加できる | #76 F-1 | **表示された URL の pathname を固定する。** 開けるかどうかでは検出できない（下記） |
| 12 | timer を再読込しても参加画面に戻らない | #76 F-3 | **2 人目で検証する。** 作成者だと縮退先と正解が一致して緑になる |
| 13 | poker の消えたルームのリンクが行き止まりにならない | #76 J-1 | 名前を入れる前に知らされ、戻る道があること |
| 209 | 捨てた同期フレームが画面から分かる | #209 | **実際に固まらせて見る。** 壊すのは `routeWebSocket` で、製品コードにテスト用の経路は作らない |
| 212 | poker でも捨てたフレームが画面から分かる | #212 | 同上（壊すのは `room-state`。名簿が古いまま固まることまで見る） |

#### #11 が pathname を見る理由

`deploy/timer/caddy/40-timer-legacy-room.conf` が旧共有リンクを救済しているため、
招待 URL が `/?room=CODE`（F-1 の壊れ方）に戻っても **301 で `/timer/?room=CODE`
へ送られ、参加は成立します**。実測でも、F-1 を再現したうえで pathname の判定 1 行を
外すと**全シナリオが緑に戻りました**。開けることを見るだけでは、この回帰は永久に
検出できません。

## 注意: `pnpm dev` と同時に走らせられません

このパッケージは Caddy（`18080`）と timer-sync（`8787`）・poker-sync
（`3311`）を実際に起動します。`pnpm dev` と同じポートを共有するため、
**両方を同時には実行できません**。`pnpm dev` を止めてから `pnpm e2e` を
実行してください。

## 終了後の確認コマンド

正常終了・異常終了に関わらず、以下でポートと設定が解放されていることを
確認できます。

```bash
ss -tlnp | grep -E ':(8787|3311|18080)'   # 無出力なら解放済み
ls -d /etc/caddy/tasuki                    # 無ければ撤去済み
```

## 異常終了で残骸が出たときの復旧

SIGKILL（`kill -9` など、捕捉できないシグナル）で終了した場合や、想定外の
異常があった場合は後始末が走らず残骸が残ることがあります。次回の起動時に
`preflight` が残骸を検出して必ず落とすので、その指示に従って手動で撤去
してください。

```bash
sudo rm -rf /etc/caddy/tasuki
```

`/var/www/tasuki` などの symlink は次回起動時に `linkWebRoots()` が張り
替えるため、通常は放置して問題ありません。
